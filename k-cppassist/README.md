# K-CppAssist

Visual Studio 2022 / 2026 用の拡張です。宣言していない変数に代入したとき、キー 1 つで**型を付けて宣言**します。

メンバー関数の中で `stride_ = device->GetDescriptorHandleIncrementSize(type);` と書くと、Visual Studio は `E0020: 識別子 "stride_" が定義されていません` と赤い波線を出します。直すには、ヘッダーを開いて、`GetDescriptorHandleIncrementSize` の戻り値が何だったかを調べて（`UINT`）、`UINT stride_;` を書き足して、元のファイルに戻る、という手間がかかります。K-CppAssist は、この往復を 1 回のキーにします。

## 使い方

| キー | コマンド | することと例 |
|---|---|---|
| Alt+W | メンバー変数として宣言する | クラスのヘッダー（`.h`）に `型 名前;` を足す |
| Alt+Q | ローカル変数に型を付ける | その場の `count = 0;` を `int count = 0;` にする |
| Alt+E | ゲッター・セッターを作る | `stride_` の `GetStride()` と `SetStride(...)` を、クラスの `public:` の末尾に足す |
| Alt+G | 宣言と定義の引数を合わせる | ヘッダーの宣言と cpp の定義の引数を、変えた側に合わせる。変えると自動でも合わせる（下の「宣言と定義の引数を合わせる」） |
| Alt+F | `#include` を足す | カーソルの識別子（`std::vector`、`ComPtr`、`Camera`）のヘッダーを探して `#include` を足す。入力中の自動挿入もある（下の「`#include` を足す」） |

どちらも、**その行のどこにカーソルがあっても**押せます。行頭の `名前 = 右辺;` の左辺が対象です（`this->名前 = ...;` は Alt+W だけ）。コマンドは、キーだけで使います。拡張機能 メニューに出るのは「K-CppAssist の設定...」の 1 つで、クリックすると設定画面（下の「設定」）が開きます。

```cpp
// Alloc.cpp
Alloc::Alloc(Dev* device, int type) {
    stride_ = device->GetStride(type);   // この行のどこでも Alt+W
}
```

```cpp
// Alloc.h(Alt+W のあと。private: の末尾に入る)
 private:
  int capacity_;
  unsigned int stride_;
```

Alt+W は、カーソルのある `Class::Func` の `Class` を宣言から探して、そのクラスの末尾に足します。`private:` が最後でなければ、末尾に `private:` を作ってから足します。ヘッダーはエディターで開いたままになり（保存はしません）、作業中のファイルへ戻ります。挿入は 1 回の編集なので、Undo も 1 回です。

## #include を足す（Alt+F・入力中の自動）

カーソルの識別子（`std::vector`、`ComPtr`、`Camera` など）のヘッダーを探して、`#include` を 1 行足します。すでにあれば足しません。

ヘッダーは、次の順に決めます。

1. **表。** 標準ライブラリ（`std::vector` → `<vector>`）、Windows（`UINT` → `<Windows.h>`）、DirectX（`ID3D12Device` → `<d3d12.h>`、`XMFLOAT3` → `<DirectXMath.h>`）の固定の対応表。
2. **ソリューションの索引。** ヘッダーから集めた、`class` / `struct` / `enum` / `using X =` / `typedef` の定義。関数、メソッド、変数、クラスの中の入れ子の型は入れないので、`Instance()` のような名前がヘッダーに引かれることはありません。
3. 索引で複数見つかったら、選ぶ欄を出します（自動では足しません）。

足す場所は、ファイルにある `#include` の並びに合わせます。空行でグループが分かれていればグループごとに（自分のヘッダー、C、C++ 標準、その他の `<>`、プロジェクトの `""` の順）、分かれていなければ 1 つの塊の中で並び順に。フォルダーは、2 つのファイルの共通の親からの相対（`"core/scene.h"`）で書きます。挿入は 1 回の Undo です。

### 書き方（`""` か `<>` か）

プロジェクトのヘッダーは `""`、標準・Windows・DirectX は `<>` です。`""` のパスは、プロジェクトが実際に使っている基準に合わせます。ソリューションの既存の `#include "a/b.h"` が、どの親フォルダーから開けるかを数えて、いちばん多く使われている基準からの相対で書きます（`Engine/Source` が基準なら `"Prest/Core/GraphicsModule.h"`）。同じフォルダーかその下なら、そこからの相対。基準が分からないときは、このファイルからの相対（`"../Core/x.h"`）にするので、必ず開けます。

### 入力中の自動挿入

設定の「`#include` を足すしかた」を `Auto` にすると、入力中に自動で足します。次を**すべて**満たすときだけです。

- 識別子を打ち終えた（`<` `::` `*` `(` 空白などの区切りを打った）あと、入力が止まって約 0.9 秒たった。
- 補完リストが出ていない、ビルド中でない、カーソルがその識別子の上にない。
- コメント・文字列・`#` の行の中ではなく、**型として使われている形**（`Foo x` / `Foo*` / `Foo<` / `Foo::` / `new Foo` など）。`.名前` `->名前` `Foo::Instance()` のような呼び出しは対象外。
- その識別子に、IntelliSense の**エラーの波線**が付いている（ほかのヘッダー経由ですでに見えているものには足さない）。
- ヘッダーが 1 つに決まる。索引から引く名前は、拒否リスト（`Instance` `Get` `Data` `Type` など。設定で変えられる）にないもの。
- `.h` の中では、表（標準・Windows・DirectX）のものだけ。足すと循環するヘッダーは足さない。

PCH（プリコンパイル済みヘッダー）経由でもう見えている型には、波線が出ないので、自動では足しません。足したいときは、型の上で Alt+F を押してください（Alt+F は波線を見ずに足します）。

足したあと 40 秒以内に、その識別子を消したり書き換えたりしたら、足した `#include` も戻します（ほかの場所でまだ使っていれば戻しません）。足すたびに、ステータスバーに理由を出し、`vsix.log` に残します。

初期値は `ManualOnly`（Alt+F だけ）です。`Auto` にすると、入力中の自動も動きます。`Off` にすると、どちらも止まります。ヘッダーを探さないフォルダー（`third_party` `build` など）も、設定で変えられます。

## 宣言と定義の引数を合わせる（Alt+G・自動）

ヘッダーの宣言か cpp の定義（コンストラクターを含む）の引数を変えると、相手の引数も同じに書き換えます。引数の型・数・名前の変更、並べ替え、追加、削除に対応します。

```cpp
// Alloc.h
Alloc(Dev* device, int type = 0);          // ← float scale = 1.0f を足す
// Alloc.cpp
Alloc::Alloc(Dev* device, int type) {...}  // ← 自動で (Dev* device, int type, float scale) になる
```

- **自動（設定の「宣言と定義の引数を合わせるしかた」が `Auto`、初期値）**: 括弧の中を編集すると、すぐに（待ちは 0 ミリ秒。設定の「自動で合わせるまでの待ち」で変えられます）、相手を書き換えます。相手がエディターで開いていなければ、開いて書き換え、作業中のファイルへ戻ります。
- **Alt+G**: カーソルの関数の引数を、相手に写します。相手が開いていなければ開いて書き換えます。引数が違う相手が複数あれば、選ぶ欄を出します。
- ヘッダー → cpp: 既定値（`= 0`）は cpp に付けません。残る引数は、cpp の書き方（名前・`const` の位置）のまま残します。cpp の本文が引数の名前を使っているので、ヘッダーで改名しても、cpp には写しません。型だけ変えたときは、cpp の名前を残して、型だけ新しくします。
- cpp → ヘッダー: 残る引数の既定値と書き方は、ヘッダーのものを引き継ぎます。cpp で引数を改名したときだけ、ヘッダーにも新しい名前を写します。新しい引数に既定値は付きません。既定値のある引数のあとに、既定値のない引数ができたときは、ステータスバーで知らせます（C++ では書けない形です）。
- どの関数かは、名前と、`const` の有無と、`namespace` とクラスの並びと、変える前の引数の型で決めます。同じ名前のオーバーロード（`Add(int)` と `Add(float)`、`Get() const` と `Get()`）や、別の `namespace`・別のクラスの同名の関数は、取り違えません。cpp が `using namespace` で修飾を省いていても、ほかに合うものがなければ見つかります。見つからない・複数ある・書きかけ（末尾のカンマなど）のときは、何もしません。
- 書き換えは、相手側の 1 回の Undo です。相手のあとでもう一度戻されることはありません。
- 呼び出し側（`Alloc(dev, 1)` など）は書き換えません。戻り値の型の変更も対象外です。

## ゲッター・セッター（Alt+E）

メンバー変数の宣言行（`UINT stride_;`）にカーソルを置くか、`.cpp` の `stride_ = ...;` の行にカーソルを置いて押します。名前は `stride_` から末尾の `_` を外して、先頭を大文字にします（`cpu_start_` は `GetCpuStart` / `SetCpuStart`）。

```cpp
 public:
  Alloc(Dev* device, int type);

  unsigned int GetStride() const { return stride_; }

  void SetStride(unsigned int value) { stride_ = value; }
```

ゲッターの前と、ゲッターとセッターの間の空行は、設定（下の「設定」）で切り替えられます。同じ名前がすでにあるときは足しません。`public:` がなければ、クラスの先頭に作ります。

型によって、書き方を変えます。

| 型 | ゲッター | セッター |
|---|---|---|
| `int`・`float`・ポインター・`UINT` のような大文字の型・ヘッダーに `enum` の定義がある型 | 値 | 値 |
| `std::string`・`std::vector`・構造体など | `const T&` | `const T&` |
| `bool`（名前が `is_` / `has_` で始まる） | `IsVisible()` / `HasXxx()` | `SetVisible(...)` / `SetHasXxx(...)` |
| `ComPtr<T>` | `T*`（`.Get()`） | 作らない |
| `std::unique_ptr<T>` | `T*`（`.get()`） | 作らない |
| `std::shared_ptr<T>` | `T*`（`.get()`） | 値で受けて `std::move` |
| `std::weak_ptr<T>` | `std::shared_ptr<T>`（`.lock()`） | `const&` |
| `std::atomic<T>` | `T`（`.load()`） | `T`（`.store()`） |
| `const` メンバー・参照メンバー | 作る | 作らない |
| `std::mutex`・`std::thread` など | 作らずに断る | 作らずに断る |

配列と `static` のメンバーは対象外です。

## 設定

拡張機能 メニューの「K-CppAssist の設定...」から開けます（ツール → オプション → K-CppAssist → 全般と同じ画面です）。

- **ゲッターとセッターの間に空行を入れる**（初期値は True）。True のときは、ゲッターの前（直前がメンバーの行のとき）とゲッターとセッターの間に、空行を 1 行入れます。
- **書き換えた場所を小さなウィンドウで見せる**（初期値は True）。引数を相手のファイルへ写したとき、書き換えた場所（前の引数と、書き換えたあとの行）を、いま打っている位置の少し上（上に収まらなければ下）に、約 3 秒だけ見せます。フォーカスは奪いません。
- **キー。** 5 つのコマンドのキーを、ここで変えられます。「Alt+Q」「Ctrl+Alt+M」のように書き、OK を押すと Visual Studio のキー割り当てに反映されます。空にするとキーを外します。開いたときは、今の割り当てが表示されます。

## 型の決め方

右辺から、次の順に決めます。

1. **式そのもの。** `0` は `int`、`1.0f` は `float`、`true` は `bool`、`"abc"` は `const char*`、`static_cast<T>(...)` は `T`、`std::make_unique<T>(...)` は `std::unique_ptr<T>`、`new T` は `T*`。
2. **Quick Info（ホバーの内容）。** 関数呼び出しなら、戻り値の型を取り出します。`virtual UINT __stdcall ID3D12Device::GetDescriptorHandleIncrementSize(...)` から `UINT` を取ります。変数や引数なら、その型を取ります。
3. **どちらでも決まらないとき。** Alt+W は、型の入力欄を出します。Alt+Q は `auto` を入れます。

演算子を含む式（`a + b`、`x < y`、`!flag`、`(float)n`、`&x`）は、部分ごとに 1 と 2 で型を決めて、組み立てます。比較と論理演算は `bool` です。算術は C++ の通常の算術変換で、`int + float` は `float`、`float * double` は `double` になります。`UINT + UINT` や `size_t * size_t` のように綴りがそろっていれば、その綴りのままです。`char` や `short` は `int` になります。クラスの型が混じるときは、最初のクラスの型（`XMFLOAT3 * float` も `float * XMFLOAT3` も `XMFLOAT3`、`std::string + "x"` は `std::string`）、ポインターに整数を足せば、そのポインターの型です。シフトは左の型になります。

右辺が `cond ? A : B` の形のときは、A と B を順に試して、最初に型が決まったほうを使います。`{}` と `nullptr` の枝は、型を持たないので飛ばします。

`const` と参照は外して、値の型にそろえます（`const UINT&` は `UINT`）。ポインターの `const` は残します。

## 制限

- 対象は `名前 = 右辺;` の形の文です。`int x = 0;` のように、すでに型があるものは対象外です。右辺が何行に分かれていても、ラムダの中の 1 文（`[this] { count_ = 1; }`）でも、その文のどこにカーソルがあっても働きます。`;` をまだ書いていない行は、続きの行がなさそうなら、そこまでを 1 文として読みます。
- Alt+W と Alt+E は、`Class::Func(` の形の定義の中と、クラスの本体に直接書いた関数（ヘッダーのインライン関数）の中で働きます。字下げされていても、引数が複数行に分かれていても見つかります。ラムダの中は、囲んでいる関数のクラスに足します。クラスに属さない関数の中では使えません。
- ヘッダーは、いまのファイルの中にクラスの定義があればそれ、なければソリューションのフォルダーの下から探します。cpp と同じ名前の `.h` を先に見て、そこに 1 つだけ合えば決めます。なければ `class Class {` を含む `.h` を探します。
- クラスが入れ子（`Outer::Inner::Func`）のときは、`Outer` が外側にあるクラスだけを選びます。同じ名前のクラスが別の `namespace` にもあるときは、cpp を囲む `namespace` と外側の名前が末尾から多く一致するほうに足します。決められなければ、選ぶ欄を出します。cpp が `using namespace` だけで修飾を省いているときは、`namespace` が分からないので、選ぶ欄になることがあります。
- 演算子を含む右辺は、部分の型から組み立てます（上の「型の決め方」）。ユーザー定義の演算子が別の型を返すとき、`enum` と整数の演算、型の分からない部分が混じるときは、決められず、入力欄（Alt+W）か `auto`（Alt+Q）になります。
- Alt+W は、Visual Studio の「ウィンドウ」メニューのアクセスキーと重なります。効かないときは、設定のキーで別のキーに付け替えてください。
- 失敗したときは、ステータスバーに理由が出ます。詳しいログは `%LOCALAPPDATA%\K-CppAssist\vsix.log` です。

## インストールとビルド

`bin\K-CppAssist.vsix` をダブルクリックして、Visual Studio を再起動します。作るには、次を実行します。事前に、Visual Studio の「Visual Studio extension development」ワークロードが要ります。

```powershell
.\build.ps1
```
