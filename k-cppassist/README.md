# K-CppAssist

Visual Studio 2022 / 2026 用の拡張です。宣言していない変数に代入したとき、キー 1 つで**型を付けて宣言**します。

メンバー関数の中で `count_ = items.size();` と書くと、Visual Studio は `E0020: 識別子 "count_" が定義されていません` と赤い波線を出します。直すには、ヘッダーを開いて、`items.size()` の戻り値が何だったかを調べて（`size_t`）、`size_t count_;` を書き足して、元のファイルに戻る、という手間がかかります。K-CppAssist は、この往復を 1 回のキーにします。

## 使い方

| キー | コマンド | することと例 |
|---|---|---|
| Alt+W | メンバー変数として宣言する | クラスのヘッダー（`.h`）に `型 名前;` を足す |
| Alt+Q | ローカル変数に型を付ける | その場の `count = 0;` を `int count = 0;` にする |
| Alt+E | ゲッター・セッターを作る | `stride_` の `GetStride()` と `SetStride(...)` を、クラスの `public:` の末尾に足す |
| Alt+N | ファイル名をまとめて変える | ヘッダーか cpp の名前を変え、相手のファイル・`#include`・CMake も同じ名前に直す。名前を変えると自動でも直す（下の「ファイル名をまとめて変える」） |
| Alt+G | 宣言と定義の引数を合わせる | ヘッダーの宣言と cpp の定義の引数を、変えた側に合わせる。変えると自動でも合わせる（下の「宣言と定義の引数を合わせる」） |
| Alt+F | `#include` を足す | カーソルの識別子（`std::vector`、`ComPtr`、`Camera`）のヘッダーを探して `#include` を足す。入力中の自動挿入もある（下の「`#include` を足す」） |

どちらも、**その行のどこにカーソルがあっても**押せます。行頭の `名前 = 右辺;` の左辺が対象です（`this->名前 = ...;` は Alt+W だけ）。コマンドは、キーだけで使います。拡張機能 メニューに出るのは「K-CppAssist の設定...」と「K-ErrorLog (エラーログ)を開く」の 2 つで、設定のほうをクリックすると設定画面（下の「設定」）が開きます。

```cpp
// Alloc.cpp
Alloc::Alloc(Dev* device, int type) {
    stride_ = device->GetStride(type);   // この行のどこでも Alt+W
}
```

```cpp
// Alloc.h(Alt+W のあと。private: の末尾に入る)
 private:
  int capacity_;
  unsigned int stride_;
```

Alt+W は、カーソルのある `Class::Func` の `Class` を宣言から探して、そのクラスの末尾に足します。`private:` が最後でなければ、末尾に `private:` を作ってから足します。ヘッダーはエディターで開いたままになり（保存はしません）、作業中のファイルへ戻ります。挿入は 1 回の編集なので、Undo も 1 回です。

## #include を足す（Alt+F・入力中の自動）

カーソルの識別子（`std::vector`、`ComPtr`、`Camera` など）のヘッダーを探して、`#include` を 1 行足します。すでにあれば足しません。

ヘッダーは、次の順に決めます。

1. **表。** 標準ライブラリ（`std::vector` → `<vector>`）、Windows（`UINT` → `<Windows.h>`）、DirectX（`ID3D12Device` → `<d3d12.h>`、`XMFLOAT3` → `<DirectXMath.h>`）の固定の対応表。
2. **ソリューションの索引。** ヘッダーから集めた、`class` / `struct` / `enum` / `using X =` / `typedef` の定義。関数、メソッド、変数、クラスの中の入れ子の型は入れないので、`Instance()` のような名前がヘッダーに引かれることはありません。
3. 索引で複数見つかったら、選ぶ欄を出します（自動では足しません）。

足す場所は、ファイルにある `#include` の並びに合わせます。空行でグループが分かれていればグループごとに（自分のヘッダー、C、C++ 標準、その他の `<>`、プロジェクトの `""` の順）、分かれていなければ 1 つの塊の中で並び順に。フォルダーは、2 つのファイルの共通の親からの相対（`"core/scene.h"`）で書きます。挿入は 1 回の Undo です。

### 書き方（`""` か `<>` か）

プロジェクトのヘッダーは `""`、標準・Windows・DirectX は `<>` です。`""` のパスは、プロジェクトが実際に使っている基準に合わせます。ソリューションの既存の `#include "a/b.h"` が、どの親フォルダーから開けるかを数えて、いちばん多く使われている基準からの相対で書きます（`Engine/Source` が基準なら `"Prest/Core/GraphicsModule.h"`）。同じフォルダーかその下なら、そこからの相対。基準が分からないときは、このファイルからの相対（`"../Core/x.h"`）にするので、必ず開けます。

### 入力中の自動挿入

設定の「`#include` を足すしかた」を `Auto` にすると、入力中に自動で足します。次を**すべて**満たすときだけです。

- 識別子を打ち終えた（`<` `::` `*` `(` 空白などの区切りを打った）あと、入力が止まって約 0.9 秒たった。
- 補完リストが出ていない、ビルド中でない、カーソルがその識別子の上にない。
- コメント・文字列・`#` の行の中ではなく、**型として使われている形**（`Foo x` / `Foo*` / `Foo<` / `Foo::` / `new Foo` など）。`.名前` `->名前` `Foo::Instance()` のような呼び出しは対象外。
- その識別子に、IntelliSense の**エラーの波線**が付いている（ほかのヘッダー経由ですでに見えているものには足さない）。
- ヘッダーが 1 つに決まる。索引から引く名前は、拒否リスト（`Instance` `Get` `Data` `Type` など。設定で変えられる）にないもの。
- `.h` の中では、表（標準・Windows・DirectX）のものだけ。足すと循環するヘッダーは足さない。

PCH（プリコンパイル済みヘッダー）経由でもう見えている型には、波線が出ないので、自動では足しません。足したいときは、型の上で Alt+F を押してください（Alt+F は波線を見ずに足します）。

足したあと 40 秒以内に、その識別子を消したり書き換えたりしたら、足した `#include` も戻します（ほかの場所でまだ使っていれば戻しません）。足すたびに、ステータスバーに理由を出し、`vsix.log` に残します。

初期値は `ManualOnly`（Alt+F だけ）です。`Auto` にすると、入力中の自動も動きます。`Off` にすると、どちらも止まります。ヘッダーを探さないフォルダー（`third_party` `build` など）も、設定で変えられます。

## 宣言と定義の引数を合わせる（Alt+G・自動）

ヘッダーの宣言か cpp の定義（コンストラクターを含む）の引数を変えると、相手の引数も同じに書き換えます。引数の型・数・名前の変更、並べ替え、追加、削除に対応します。

```cpp
// Alloc.h
Alloc(Dev* device, int type = 0);          // ← float scale = 1.0f を足す
// Alloc.cpp
Alloc::Alloc(Dev* device, int type) {...}  // ← 自動で (Dev* device, int type, float scale) になる
```

- **自動（設定の「宣言と定義の引数を合わせるしかた」が `Auto`、初期値）**: 括弧の中を編集すると、すぐに（待ちは 0 ミリ秒。設定の「自動で合わせるまでの待ち」で変えられます）、相手を書き換えます。相手がエディターで開いていなければ、開いて書き換え、作業中のファイルへ戻ります。
- **Alt+G**: カーソルの関数の引数を、相手に写します。相手が開いていなければ開いて書き換えます。引数が違う相手が複数あれば、選ぶ欄を出します。
- ヘッダー → cpp: 既定値（`= 0`）は cpp に付けません。残る引数は、cpp の書き方（名前・`const` の位置）のまま残します。cpp の本文が引数の名前を使っているので、ヘッダーで改名しても、cpp には写しません。型だけ変えたときは、cpp の名前を残して、型だけ新しくします。
- cpp → ヘッダー: 残る引数の既定値と書き方は、ヘッダーのものを引き継ぎます。cpp で引数を改名したときだけ、ヘッダーにも新しい名前を写します。新しい引数に既定値は付きません。既定値のある引数のあとに、既定値のない引数ができたときは、ステータスバーで知らせます（C++ では書けない形です）。
- どの関数かは、名前と、`const` の有無と、`namespace` とクラスの並びと、変える前の引数の型で決めます。同じ名前のオーバーロード（`Add(int)` と `Add(float)`、`Get() const` と `Get()`）や、別の `namespace`・別のクラスの同名の関数は、取り違えません。cpp が `using namespace` で修飾を省いていても、ほかに合うものがなければ見つかります。見つからない・複数ある・書きかけ（末尾のカンマなど）のときは、何もしません。
- 書き換えは、相手側の 1 回の Undo です。相手のあとでもう一度戻されることはありません。
- 呼び出し側（`Alloc(dev, 1)` など）は書き換えません。戻り値の型の変更も対象外です。

## ゲッター・セッター（Alt+E）

メンバー変数の宣言行（`UINT stride_;`）にカーソルを置くか、`.cpp` の `stride_ = ...;` の行にカーソルを置いて押します。名前は `stride_` から末尾の `_` を外して、先頭を大文字にします（`cpu_start_` は `GetCpuStart` / `SetCpuStart`）。

```cpp
 public:
  Alloc(Dev* device, int type);

  unsigned int GetStride() const { return stride_; }

  void SetStride(unsigned int value) { stride_ = value; }
```

ゲッターの前と、ゲッターとセッターの間の空行は、設定（下の「設定」）で切り替えられます。同じ名前がすでにあるときは足しません。`public:` がなければ、クラスの先頭に作ります。

型によって、書き方を変えます。

| 型 | ゲッター | セッター |
|---|---|---|
| `int`・`float`・ポインター・`UINT` のような大文字の型・ヘッダーに `enum` の定義がある型 | 値 | 値 |
| `std::string`・`std::vector`・構造体など | `const T&` | `const T&` |
| `bool`（名前が `is_` / `has_` で始まる） | `IsVisible()` / `HasXxx()` | `SetVisible(...)` / `SetHasXxx(...)` |
| `ComPtr<T>` | `T*`（`.Get()`） | 作らない |
| `std::unique_ptr<T>` | `T*`（`.get()`） | 作らない |
| `std::shared_ptr<T>` | `T*`（`.get()`） | 値で受けて `std::move` |
| `std::weak_ptr<T>` | `std::shared_ptr<T>`（`.lock()`） | `const&` |
| `std::atomic<T>` | `T`（`.load()`） | `T`（`.store()`） |
| `const` メンバー・参照メンバー | 作る | 作らない |
| `std::mutex`・`std::thread` など | 作らずに断る | 作らずに断る |

配列と `static` のメンバーは対象外です。

## 呼び出しの引数をビルド前にチェックする（自動）

`std::make_unique<SwapChain>(a, b, c)` のように、**引数の個数がどのコンストラクターにも合わない**呼び出しに、ビルドの前に、エディターで赤い波線を引きます。波線にカーソルを置くと、「`SwapChain` のコンストラクターに 3 個の引数を受け取るものがありません」と、候補のコンストラクターが出ます。

- **調べる呼び出し。** `std::make_unique<T>(…)`、`std::make_shared<T>(…)`、`new T(…)`。入力が止まって 0.7 秒たつと調べます（設定で変えられます）。
- **コンストラクターの探し方。** `T` がいまのファイルで定義されていればそれ、なければソリューションのヘッダーの索引で 1 つに決まるヘッダーから読みます。ヘッダーを編集中（保存前）でも、エディターの内容で調べ、ヘッダーを直すと開いている cpp の波線もやり直します。既定の引数と、`...`（可変長）は数えます。
- **波線の位置。** 引数が多いときは、余った引数から。足りないときは、`( )` 全体です。入力中の呼び出しには、「足りない」とは言いません（まだ打っている途中のため）。キャレットが外へ出ると出ます。
- **確実なものだけ出します。** 個数だけを見て、型の違い（`const`・暗黙の変換・参照）は見ません。次のクラスは、調べません: コンストラクターを書いていないクラス（集成体）、テンプレートのクラス、`using Base::Base;` で継承したコンストラクターのあるクラス、マクロが書かれているクラス、定義が 1 つに決まらないクラス、`std::` の型。1 個だけ渡していて、リテラルでなければ、コピー・ムーブかもしれないので出しません。引数の中に `...`（パック展開）があるときも出しません。
- **間違って出るとき。** 設定の「調べないクラス」に、そのクラスを書くと出なくなります。「波線の色」を Warning にすると、緑の波線（警告）になります。設定の True / False で、全体も `make_unique` / `new` も切れます。

この波線は、エディターだけのものです。エラー一覧には出ず、ビルドの結果にも影響しません。型の違いまで知りたいときは、ビルド後のエラーログ（下）が、呼び出しの行と候補のコンストラクターを並べます。

## ファイル名をまとめて変える（Alt+N・自動）

ヘッダー（`Foo.h`）か cpp（`Foo.cpp`）の名前を変えたとき、ほかに直す所を、まとめて直します。

- **相手のファイル。** `Foo.h` を `Bar.h` にすると、同じフォルダーの `Foo.cpp`（`.cc` `.cxx`）も `Bar.cpp` にします。cpp を変えたときは、`Foo.h`（`.hpp` `.hh` `.hxx`）も同じです。新しい名前がすでに使われているときは、相手には触れません。プロジェクトに入っているファイルは、プロジェクトごと名前を変えます。
- **`#include`。** ソリューションの全ファイルの `#include "Foo.h"` を、`#include "Bar.h"` に直します。フォルダーつき（`"core/Foo.h"`）も、フォルダーを保ったまま直します。指しているのが、本当に名前を変えたファイルかを確かめます。コンパイラと同じ順（そのファイルのフォルダー、プロジェクトの `#include` の基準）で探して、同じ名前の別のファイルには触れません。
- **CMake。** `CMakeLists.txt` と `.cmake` の `src/Foo.cpp` なども直します（`MyFoo.cpp` や `Foo.cpp.in` のように、名前の一部だけが同じものには触れません）。直したあとは、CMake の再構成が要ります。
- **文字コード。** エディターで開いていないファイルは、元の文字コード（UTF-8、BOM つき UTF-8、シフト JIS）のまま書き換えます。開いているファイルは、エディターの文字を書き換えます（Undo できます。保存はしません）。

**自動で動きます**（設定の「ヘッダー・cpp の名前を変えたときのしかた」が `Auto`、初期値）。Alt+N を押す必要はありません。名前を変えたことを、次の 2 つで見つけます。

- **Solution Explorer** での名前変更（F2）。
- **フォルダーの監視**。フォルダー ビュー（CMake）、エクスプローラー、`git mv`、別のツールでの名前変更も見つけます。ヘッダーと cpp どうしの名前変更だけを見て、保存の一時ファイルなどは見ません。

次の場合は、自動では直しません。

- **一括の操作。** 3 秒の間に、設定の件数（初期値 4）より多くの名前変更が起きたときは、git のブランチ切り替えなどとみなして、何もしません（ステータスバーで知らせます）。
- **取り消された変更。** 通知のあと、元に戻された・すでに別の名前になったときは、何もしません。
- **設定で止めたとき。** 「直す前に確認する」を True にすると、ダイアログで確認してから直します。

**Alt+N** は、開いているヘッダー（か cpp）の新しい名前（拡張子なし）を入力欄で決めて、同じことを行います（自動を切っているとき用です）。

名前を変えるのは、ファイルだけです。クラス名、インクルード ガード（`FOO_H`）、ファイルの中の文字は、直しません。フォルダーを動かす操作や、別のフォルダーへの移動も、対象外です。

## エラーログ（K-ErrorLog）

C++ のビルドエラーを、**色つきの専用ログ窓**に整理して出します。「出力」ウィンドウのとなりにタブで並びます。ビルドが終わると、エラーがあるときだけ前に出ます（入力の邪魔はしません）。拡張機能 メニューの「K-ErrorLog (エラーログ)を開く」から、いつでも開けます。

- **未解決の外部シンボル（LNK2019 / LNK2001）を、原因ごとにまとめる。** 同じシンボルを 1 つにして、起動関数がない・`.lib` が足りない（ビット数違いや `dllimport` の食い違いも指摘）・Windows / DirectX の `.lib`・vtable や static メンバーの定義漏れ・定義はあるのにリンクされていない、などを判定し、何をすれば直るかまで書きます。`.lib` はソリューションの下を読み（シンボルの索引だけを読むので速い）、定義の探索はソースの文字列検索です。**推測**なので、「原文」表示と見比べてください
- **そのほかのリンカー エラー。** `LNK2005`（二重定義）、`LNK2038`（`RuntimeLibrary` や `_ITERATOR_DEBUG_LEVEL` の不一致を並べて表示）、`LNK1104` / `LNK1181` など
- **テンプレートのエラーを読みやすくする。** `std::basic_string<char, …>` → `std::string`、`std::unique_ptr<T, std::default_delete<T>>` → `std::unique_ptr<T>` のように型名を短くし、渡した型と期待する型を 2 行に並べ、テンプレート引数を 1 行ずつに分けます
- **原因の場所と経路。** エラーが `<memory>` の中で出ていても、自分のコードの呼び出し行を探してリンクにします。「see reference to function template instantiation … being compiled」の連なりは、自分のコードの行を強調し、ライブラリの中の段は畳みます（「経路を全部表示」で展開）。オーバーロードの候補と落ちた理由（`C2672`、`C2784` など）も並べます
- **読みやすさのための案内。** エラーが複数あるときは、先頭に「まず一番上のエラーから直す」と出します。同じ原因から続いているエラーには「連鎖の可能性」と書き、原因の候補（上のエラー）へのリンクを出します（未定義の名前を含むエラー、同じファイルの構文エラーより後ろのエラー）。名前入りの説明（`「GraphicsModule」は、この場所から見えていません…`）と、直し方の例（修正前と修正後のコード）が付くコードもあります。ヒントがあるコードは約 220 個で、ないコードにも「公式のページで調べる」案内が出ます
- **警告がエラーになっているとき（C2220）。** `/WX` で、警告がエラー扱いになっています。原因の警告を、リンクつきで並べます
- **二重定義（LNK2005）。** 変数なら「ヘッダーに `extern` なしで書いた」、関数なら「`inline` なしで本体を書いた」と、原因を分けて説明します
- 主なエラー コードに、日本語の見出しとヒントを付けます。日本語版・英語版の Visual Studio の出力と、GCC / Clang の形式を読みます
- 色は Visual Studio のテーマ（ダーク / ライト）に合わせて変わります。ファイルの場所を押すとその行へ飛び、シンボルの横の「宣言を検索」で、ソリューション全体から探して「検索結果 1」に出します
- <strong>1 件を 2〜3 行で見せる。</strong> 1 行目は「エラー コード・日本語の見出し・場所」で、`C2065` のようなコードを押すと、公式のページ（検索）が開きます。続けて、メッセージ、ソースの 1 行、ヒントが 1 行だけ出ます。経路・候補・補足・例・同じ内容の別の場所は、行頭の「▸」を押すと開きます。連鎖の可能性があるエラーは、見出しの 1 行だけに畳みます。
- <strong>ファイル別の目次。</strong> エラーのあるファイルが 2 つ以上のとき、先頭に「ファイル別」の一覧（ファイル名と件数）が出ます。押すと、そのファイルの最初のエラーへ移ります。
- <strong>窓の高さ。</strong> 下のパネルが低いとき、自動で開くたびに高くします（高くしてあるときは触りません）。
- 窓の上の**警告も表示**と**原文**（整理せずに色だけ付ける）で表示を切り替えます。**コピー**は、いま見えている内容を文字にします。「…」のメニューに、**すべての詳細を開く**・**経路を全部表示**・**原文を併記**・**原文をコピー**（AI や質問に貼る用）があります

ビルド欄の文字を読むので、ビルドのあとで「出力」を消すと「再読み込み」で何も出ません。`.lib` の探索はソリューションのフォルダーの下だけです。以前に別の拡張として配布していた K-ErrorLog と K-CppErr は、この拡張に統合しました。K-ErrorLog を入れている場合は、二重に出ないように、Visual Studio の「拡張機能の管理」から外してください。

## 設定

拡張機能 メニューの「K-CppAssist の設定...」から開けます（ツール → オプション → K-CppAssist → 全般と同じ画面です）。

- **ゲッターとセッターの間に空行を入れる**（初期値は True）。True のときは、ゲッターの前（直前がメンバーの行のとき）とゲッターとセッターの間に、空行を 1 行入れます。
- **書き換えた場所を小さなウィンドウで見せる**（初期値は True）。引数を相手のファイルへ写したとき、書き換えた場所（前の引数と、書き換えたあとの行）を、いま打っている位置の少し上（上に収まらなければ下）に、約 3 秒だけ見せます。フォーカスは奪いません。
- **エラーログを使う**。初期値は True。False にすると、ビルドが終わってもエラーログを作りません（窓も自動では開きません）。ビルドを重くしたくないときや、エラーログが要らないときに切ります。
- **エラーがあるとき、窓を自動で前に出す**。初期値は True。False のときは、拡張機能 メニューの「K-ErrorLog (エラーログ)を開く」から開きます。
- **原因を探す (.lib とソースの検索)**。初期値は True。未解決の外部シンボル（LNK2019 など）について、ソリューションの `.lib` とソースを探して、原因を言い当てます。時間がかかるときは False にします。「探す時間の上限 (秒)」（初期値 6）と「読む .lib の数の上限」（初期値 800）も変えられます。
- **型名を短くする**。初期値は True。`std::basic_string<char, …>` を `std::string` のようにします。False にすると、コンパイラの出した型名のまま出します。
- **日本語のヒントを出す**。初期値は True。エラー コードごとの見出しの下に、対処のヒントを出します。
- **エラーログ（窓の初期値）**。「警告も表示」「経路を全部表示」「原文を併記」「原文」の、窓を開いたときの初期値です。窓の上のチェックボックスと「…」のメニューは、開いたあとで切り替えられます。
- **#include を足すしかた / 宣言と定義の引数を合わせるしかた**。それぞれ `Off`（何もしない）・`ManualOnly`（キーを押したときだけ）・`Auto`（入力中に自動）。初期値は `#include` が `ManualOnly`、引数の同期が `Auto` です。
- **ヘッダー・cpp の名前を変えたときのしかた**。`Off` / `ManualOnly`（Alt+N だけ）/ `Auto`（Solution Explorer での名前変更も自動）。初期値は `Auto`。
- **相手のファイルも同じ名前にする**。初期値は True。False にすると、`#include` と CMake だけを直します。
- **CMake の書き方も直す**。初期値は True。
- **ステータスバーに知らせる**。初期値は True。#include を足した、引数を写した、ファイル名を直した、などを 1 行出します。False でも、失敗の知らせは出ます。
- **ログを残す**。初期値は True。動作の記録を `%LOCALAPPDATA%\K-CppAssist\vsix.log` に書きます。
- **標準・Windows・DirectX の表を使う / ソリューションのヘッダーの索引を使う**。どちらも初期値は True。`#include` を決める 2 つの元を、別々に切れます。
- **自分で決める対応 (名前=ヘッダー)**。`Vec3="math/vec3.h";Json=<nlohmann/json.hpp>` のように、`;` か改行で区切って書きます。組み込みの表より先に使います。自動でも使われます。
- **.h でも、ソリューションの型を自動で足す**。初期値は False。ヘッダーに自動で足すのは、標準・Windows・DirectX の表と、自分で決めた対応のものだけです（循環 include を避けるため）。True にすると、ソリューションの型も足します。
- **自動で足した #include を戻すまでの秒数**。初期値は 40。足した直後に識別子を消したら戻す、その猶予です。0 で、戻しません。
- **#include も新しい名前に直す / ファイルの名前変更を、フォルダーの監視でも見つける / 多数の名前変更を、自動では直さない件数 / 直す前に確認する**。ファイル名の同期の細かい設定です。初期値は True / True / 4 / False。
- **先頭に「まず一番上から」の案内を出す / 連鎖の可能性を示す / 直し方の例を出す / 一度に出すエラーの数の上限**。エラーログの表示の設定です。初期値は True / True / True / 400。
- **引数の個数をビルド前にチェックする**。初期値は True。`make_unique` / `make_shared` / `new` の引数の個数が合わない呼び出しに波線を引きます。「波線の色」（Error / Warning。初期値は Error）、「入力が止まってから調べるまでの待ち」（初期値 700 ミリ秒）、「`make_unique` / `make_shared` を調べる」「`new T(…)` を調べる」（どちらも True）、「調べないクラス」（カンマ区切り）があります。
- **キー。** 5 つのコマンドのキーを、ここで変えられます。「Alt+Q」「Ctrl+Alt+M」のように書き、OK を押すと Visual Studio のキー割り当てに反映されます。空にするとキーを外します。開いたときは、今の割り当てが表示されます。

## 型の決め方

右辺から、次の順に決めます。

1. **式そのもの。** `0` は `int`、`1.0f` は `float`、`true` は `bool`、`"abc"` は `const char*`、`static_cast<T>(...)` は `T`、`std::make_unique<T>(...)` は `std::unique_ptr<T>`、`new T` は `T*`。
2. **Quick Info（ホバーの内容）。** 関数呼び出しなら、戻り値の型を取り出します。`size_t std::vector<int>::size() const` から `size_t` を取ります。変数や引数なら、その型を取ります。
3. **どちらでも決まらないとき。** Alt+W は、型の入力欄を出します。Alt+Q は `auto` を入れます。

演算子を含む式（`a + b`、`x < y`、`!flag`、`(float)n`、`&x`）は、部分ごとに 1 と 2 で型を決めて、組み立てます。比較と論理演算は `bool` です。算術は C++ の通常の算術変換で、`int + float` は `float`、`float * double` は `double` になります。`UINT + UINT` や `size_t * size_t` のように綴りがそろっていれば、その綴りのままです。`char` や `short` は `int` になります。クラスの型が混じるときは、最初のクラスの型（`XMFLOAT3 * float` も `float * XMFLOAT3` も `XMFLOAT3`、`std::string + "x"` は `std::string`）、ポインターに整数を足せば、そのポインターの型です。シフトは左の型になります。

右辺が `cond ? A : B` の形のときは、A と B を順に試して、最初に型が決まったほうを使います。`{}` と `nullptr` の枝は、型を持たないので飛ばします。

`const` と参照は外して、値の型にそろえます（`const UINT&` は `UINT`）。ポインターの `const` は残します。

## 制限

- 対象は `名前 = 右辺;` の形の文です。`int x = 0;` のように、すでに型があるものは対象外です。右辺が何行に分かれていても、ラムダの中の 1 文（`[this] { count_ = 1; }`）でも、その文のどこにカーソルがあっても働きます。`;` をまだ書いていない行は、続きの行がなさそうなら、そこまでを 1 文として読みます。
- Alt+W と Alt+E は、`Class::Func(` の形の定義の中と、クラスの本体に直接書いた関数（ヘッダーのインライン関数）の中で働きます。字下げされていても、引数が複数行に分かれていても見つかります。ラムダの中は、囲んでいる関数のクラスに足します。クラスに属さない関数の中では使えません。
- ヘッダーは、いまのファイルの中にクラスの定義があればそれ、なければソリューションのフォルダーの下から探します。cpp と同じ名前の `.h` を先に見て、そこに 1 つだけ合えば決めます。なければ `class Class {` を含む `.h` を探します。
- クラスが入れ子（`Outer::Inner::Func`）のときは、`Outer` が外側にあるクラスだけを選びます。同じ名前のクラスが別の `namespace` にもあるときは、cpp を囲む `namespace` と外側の名前が末尾から多く一致するほうに足します。決められなければ、選ぶ欄を出します。cpp が `using namespace` だけで修飾を省いているときは、`namespace` が分からないので、選ぶ欄になることがあります。
- 演算子を含む右辺は、部分の型から組み立てます（上の「型の決め方」）。ユーザー定義の演算子が別の型を返すとき、`enum` と整数の演算、型の分からない部分が混じるときは、決められず、入力欄（Alt+W）か `auto`（Alt+Q）になります。
- Alt+W は、Visual Studio の「ウィンドウ」メニューのアクセスキーと重なります。効かないときは、設定のキーで別のキーに付け替えてください。
- 失敗したときは、ステータスバーに理由が出ます。詳しいログは `%LOCALAPPDATA%\K-CppAssist\vsix.log` です。
- 呼び出しのチェックは、引数の「個数」だけを見ます。型の違い（`const`・暗黙の変換）は、ビルドして初めて分かります。`T` のコンストラクターを読めないとき（マクロ・テンプレート・継承したコンストラクター・定義が複数）は、何も出しません。`emplace_back` や `T x(…)` の宣言は、まだ調べません。
