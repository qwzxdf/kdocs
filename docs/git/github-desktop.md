# GitHub Desktop（迷わない画面ツール）

Git を初めて使う人が最初につまずくのは、コマンドの数と、エラーメッセージの読みにくさです。GitHub Desktop は、GitHub が作っている無料の画面ツールで、<strong>できることを絞って、迷わない</strong>ことを重視しています。clone、変更の確認、コミット、プッシュ、プルリクエストの作成まで、ボタンを順に押せば進められます。

その代わり、履歴を整理する操作などは、あまり出てきません。このページは、画面の見方、毎日の使い方、できないことを順に説明します。

!!! tip "ポイント"
    - 上部の 3 つの欄（リポジトリ、ブランチ、同期）が基本。ここを見ると、いまの状態が分かる
    - 変更は左の一覧のチェックボックスで選び、左下の「Commit to ブランチ名」で確定する
    - ボタンに枝の名前が出るので、違う枝にコミットする事故を、押す前に気づける
    - 履歴を整理する操作は少ない。必要になったら、SourceTree などに移ればよい

!!! info "このページを読む前に"
    - [Git の考え方](concepts.md)
    - [GitHub を使う](github.md)（アカウントとリポジトリ）

## 入れる・サインインする {#setup}

公式サイト（desktop.github.com）からインストーラーを入れます。初回の起動で、GitHub にサインインします。ブラウザーが開き、許可すると、認証情報が保存されます。Git 本体も同梱されているので、別に入れなくても動きます。

名前とメールアドレスは、サインインしたアカウントから自動で設定されます。変更したいときは、「File → Options」の「Git」で直せます。

## リポジトリを開く {#open}

左上の「Current repository」をクリックすると、持っているリポジトリの一覧が出ます。

- 「Add」→「Clone repository」：GitHub にあるリポジトリを選んで、手元に持ってくる
- 「Add」→「Add existing repository」：手元にすでにあるフォルダーを登録する
- 「Add」→「Create new repository」：新しいリポジトリを作る

GitHub にサインインしていれば、自分のリポジトリが一覧に出るので、選ぶだけで clone できます。

## 画面の見方 {#layout}

画面の上に 3 つの欄が並びます。

| 欄 | 見えるもの | 対応するコマンド |
| --- | --- | --- |
| Current repository | どのリポジトリで作業しているか | （フォルダーの選択） |
| Current branch | いまの枝。クリックで切り替え、新規作成 | `git branch`、`git switch` |
| Fetch / Push / Pull | リモートとの同期。状態によって名前が変わる | `git fetch`、`git push`、`git pull` |

左側には「Changes」と「History」の 2 つのタブがあります。Changes は、いまの変更です。History は、過去のコミットの一覧で、`git log` に当たります。

中央には、選んだファイルの差分が出ます。`-` の行が消えた行、`+` の行が増えた行で、色が付いています。

## 変更をコミットする {#commit}

Changes タブに、直したファイルが並びます。それぞれにチェックボックスが付いていて、チェックが入ったものが、次のコミットに入ります。`git add` に当たる操作を、チェックボックスで行います。

左下に、次の 2 つを書きます。

- 一番上の欄：コミットの題名（1 行目）。必須
- その下の欄：説明（理由など）。任意

書いたら「Commit to ブランチ名」を押します。ボタンに<strong>いまの枝の名前が出ている</strong>ので、押す前に必ず見てください。違う枝にコミットする事故を、ここで防げます。

ファイルの一部の行だけをコミットに入れたいときは、差分の行の左端をクリックして、入れる行を選べます（`git add -p` に当たる）。

直前のコミットのメッセージを直したいときは、Historyで右クリックして「Amend commit」です（push 前のみ）。

## プッシュ・プル・フェッチ {#sync}

右上の同期のボタンは、状態によって名前が変わります。

| ボタンの表示 | 意味 | 押すとどうなるか |
| --- | --- | --- |
| Fetch origin | 最新を確認していない | リモートの様子を更新する |
| Pull origin | リモートに新しいコミットがある | 取り込んで合体する |
| Push origin | 手元に、送っていないコミットがある | リモートへ送る |
| Publish branch | その枝をリモートに作っていない | 新しい枝をリモートに作って送る |

ボタンを見れば、「いま、何をすべきか」が分かる作りです。コマンドの `git status` で `ahead`、`behind` を読み取るのと同じ情報が、ボタンの名前で出ています。

## ブランチを切る・合体する {#branch}

「Current branch」をクリックして、「New Branch」を押し、名前を入れて作ります。作る元の枝を選ぶ画面も出ます。作ると、自動でその枝に移ります。

作業が終わったら、`main` に合体します。メニューの「Branch」→「Merge into current branch」で、取り込む枝を選びます。向きは、<strong>いま選んでいる枝が取り込む側</strong>です。先に `main` に切り替えてから、取り込む枝を選んでください。

チームで使うなら、合体は GitHub 上のプルリクエストで行うのが普通です。枝を push したあと、メニューの「Branch」→「Create pull request」を選ぶと、ブラウザーで GitHub のプルリクエストの画面が開きます。[GitHub を使う](github.md#pr) の流れに続きます。

不要になった枝は、「Branch」→「Delete」で消せます。

## 変更を一時退避する {#stash}

作業中の変更があるまま枝を切り替えると、Desktop が確認を出します。

- 「Leave my changes on ブランチ名」：変更を元の枝に置いておく（stash される）
- 「Bring my changes to ブランチ名」：変更を移動先に持っていく

「Leave」を選ぶと、変更は自動で stash に入ります。元の枝に戻ったときに、「Restore」で戻せます。[stash](stash.md) の仕組みを、画面が代わりに操作しています。

## コンフリクトを直す {#conflict}

マージやプルで、コンフリクトが起きると、衝突したファイルの一覧が出ます。「Open in Visual Studio Code」などのボタンで、エディターに渡します。

エディターで、目印（`<<<<<<<` など）を直します。直し終えたら、Desktop に戻ります。全部の衝突を直すと、「Continue merge」のボタンが押せるようになります。押すと、コミットまで済みます。直し方の考え方は、[コンフリクト](conflict.md) と同じです。

## 履歴を見て取り消す {#history}

History タブでは、コミットを選ぶと、そのコミットの変更ファイルと差分が見えます。

右クリックで、次の操作ができます。

- 「Revert changes in commit」：打ち消すコミットを作る（`git revert`）。共有済みでも安全
- 「Create Branch from Commit」：そのコミットから枝を作る
- 「Cherry-pick commit...」：別の枝のコミットを複製する（枝をドラッグでも可）
- 「Squash and merge」など：コミットの合体の機能もある

`reset --hard` のように履歴を切り捨てる操作や、対話的な rebase は、機能として用意されている範囲が狭いです。そうした整理が必要になったら、[SourceTree](sourcetree.md) などに移ります。同じリポジトリを開けるので、途中で乗り換えて構いません。

## できないこと・向かない場面 {#limits}

GitHub Desktop は、絞った機能を提供するツールです。

- 履歴の細かい整理（`rebase -i` の並べ替え）は、機能がない、または限定的
- `.gitignore` の追加は、画面から簡単にできるが、複雑な設定は手で書く
- GitHub 以外のサーバーも扱えるが、GitHub と連携した機能（プルリクエストの作成など）は GitHub 専用
- 複数のリポジトリや、枝の状況の一覧のような、俯瞰する画面は少ない

一人で GitHub に載せる、あるいは Git に慣れるための最初のツールとしては、向いています。

## よくあるミス {#mistakes}

??? failure "違う枝にコミットしていた"
    ボタンの「Commit to ブランチ名」を見ずに押すと起きます。push 前なら、History で右クリックして「Undo」し、枝を切り替えてからコミットし直します。

??? failure "チェックを外し忘れて、不要なファイルをコミットした"
    コミット前に、左の一覧のチェックを目で確認します。ビルド生成物が出るなら、`.gitignore` が足りません。[.gitignore](gitignore.md) を見直してください。

??? failure "Push が拒否された"
    他の人が先にプッシュしています。先に Pull してから、もう一度 Push します。強制プッシュは、共有している枝では使いません。[事故と対処](accidents.md#force)

## これだけ覚える {#summary}

- 上部の 3 つの欄（リポジトリ、枝、同期）を見れば、状態が分かる
- チェックボックスで選んで、「Commit to ブランチ名」で確定
- コミットする前に、ボタンの枝の名前を見る
- 履歴の整理が必要になったら、他のツールに移る
