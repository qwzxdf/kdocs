# Visual Studio から Git を使う

C++ のゲームを作るときは、ほとんどの時間を Visual Studio の中で過ごします。コードを直すたびに別のツールへ移るのは面倒ですし、コマンドを打つのも、慣れるまでは手間です。Visual Studio には Git の操作が組み込まれていて、コミット、枝の切り替え、プッシュ、コンフリクトの解決まで、エディターから離れずに済みます。

中身は同じ Git です。ボタンの名前は、コマンドとほぼ対応しているので、前のページで覚えた言葉がそのまま使えます。

!!! tip "ポイント"
    - 「Git の変更」ウィンドウに、変更したファイルが並ぶ。ファイルの横の「+」が `add`、メッセージ欄と「コミット」ボタンが `commit`
    - 右下のブランチ名から、枝の切り替えと新規作成ができる
    - コンフリクトは「マージ エディター」が 3 画面で表示する
    - 画面の表示が何を意味するか迷ったら、`git status` で状態を見ると読み取れる

!!! info "このページを読む前に"
    - [Visual Studio の準備](../vs/setup.md)（Git は、インストール時に選ぶ項目の 1 つ）
    - [Git の考え方](concepts.md)、[記録する（status・add・commit）](commit.md)

メニュー名や配置は、Visual Studio のバージョンで少し変わります。このページは Visual Studio 2026 の日本語版を基準にしています。名前が違うときは、同じ意味の項目を探してください。

## リポジトリを作る・開く {#create}

プロジェクトを新規作成するとき、ダイアログの下のほうに「Git リポジトリを作成」の項目があります。選ぶと、`.gitignore` が C++ 用のものとして置かれ、最初のコミットまで作られます。

すでにあるプロジェクトを、あとから Git に入れるときは、Visual Studio の右下にあるステータス バーの「↑ 発行」（またはメニューの「Git」→「リポジトリを作成」）を使います。ローカルのみのリポジトリにするか、GitHub に載せるかを選べます。

GitHub にあるリポジトリを持ってくるには、スタート画面の「リポジトリのクローン」を使い、URL と保存先を入力します。

## 「Git の変更」ウィンドウ {#changes}

メニューの「表示」→「Git の変更」で開きます。ここが、毎日の作業の中心です。

上から、次の部分に分かれます。

| 部分 | 役割 | 対応するコマンド |
| --- | --- | --- |
| メッセージ欄 | コミットメッセージを書く | `git commit -m` |
| 「コミット」ボタン | ステージした変更を確定 | `git commit` |
| 変更の一覧 | 直したファイル。クリックで差分が開く | `git status` と `git diff` |
| ステージ済みの一覧 | 次のコミットに入るファイル | `git diff --staged` |

ファイルの横の「+」を押すと、そのファイルがステージされます（`git add`）。「−」を押すと、ステージから外れます（`git restore --staged`）。

「+」を押さずにメッセージを書いて「コミット」を押すと、<strong>すべての変更が一度にコミット</strong>されます（`git commit -a` に近い動き）。ビルド生成物などが混ざっていないか、一覧を見てから押す習慣にしてください。

変更したファイルをクリックすると、右にエディターが開き、左右の比較（差分）が出ます。ここで、コミット前に自分の変更を読み返せます。差分の画面で変更を元に戻すこともできますが、これは `git restore` と同じで、取り消せません。

## 枝を切り替える・作る {#branch}

ステータス バーの右下に、いまの枝の名前が出ています。クリックすると、枝の一覧が開きます。

- 一覧から枝を選ぶ：その枝に切り替わる（`git switch`）
- 「新しいブランチ」：いまの場所から枝を作る（`git switch -c`）
- 枝の右クリック：マージ、リベース、削除ができる

枝を切り替えるとき、変更があって移れない場合は、コミットするか、スタッシュ（変更の一時退避）を選びます。stash の考え方は [stash](stash.md) にあります。

マージは、取り込む側の枝（たとえば `main`）に切り替えてから、取り込む枝を右クリックして「現在のブランチにマージ」を選びます。順序は [マージ](merge.md#basic) と同じで、<strong>いまいる枝が取り込む側</strong>です。

## プッシュ・プル・フェッチ {#sync}

Git の変更ウィンドウの上部に、上向きの矢印と下向きの矢印が並びます。

| ボタン | 動き | 対応するコマンド |
| --- | --- | --- |
| 下向きの矢印（フェッチ・プル） | リモートの新しい記録を取り込む | `git fetch` / `git pull` |
| 上向きの矢印（プッシュ） | 自分のコミットを送る | `git push` |

矢印の横の数字は、未送信のコミット数と、未取り込みのコミット数です。`ahead` と `behind` に当たります。

新しい枝を最初にプッシュするときは、「ブランチを発行」の確認が出ることがあります。リモートの枝を作ることの確認なので、そのまま進めて構いません。

## 履歴を見る {#history}

メニューの「表示」→「Git リポジトリ」を開くと、ブランチ別の履歴が、図つきで出ます。枝の分かれ目と合流が線で描かれているので、`git log --oneline --graph --all` を画面にしたものです。

コミットを右クリックすると、そのコミットの内容を見る、そこから枝を作る、取り消す（revert）、cherry-pick する、といった操作ができます。

ファイルを開いて、エディターの上部にある「変更履歴」を使うと、そのファイルを変えたコミットの一覧が出ます。エディターの左端に、各行の作者を表示する機能（blame に当たる）もあります。「この行は誰がなぜ書いたか」を、`git blame` を打たずに確かめられます。

## コンフリクトを直す {#conflict}

マージやプルでコンフリクトが起きると、Git の変更ウィンドウに、衝突しているファイルが並びます。ファイルを開いて「マージ エディターを開く」を押すと、3 つの画面が出ます。

- 左：取り込もうとしている側（相手）
- 右：いまの枝（自分）
- 下：結果

衝突している箇所ごとに、チェックボックスがあります。どちらの内容を使うか、あるいは両方を使うかを選ぶと、下の結果が更新されます。結果の画面を直接編集して、独自の形にもできます。全部の衝突を決めたら、「マージの承諾」を押します。そのあと、変更の一覧にファイルが戻るので、コミットすれば完了です。

直し方の考え方は、[コンフリクト](conflict.md) と同じです。ツールが助けてくれるのは目印の処理だけで、どちらが正しいかは自分で判断します。

## .gitignore と Git の設定 {#config}

「Git の変更」ウィンドウの右上のメニューや、「Git」メニューの「設定」から、名前、メールアドレスなどを設定できます。画面で設定した内容は、[最初の設定](install.md#user) で説明した `git config` と同じ場所に保存されます。

`.gitignore` や `.gitattributes` は、ソリューション エクスプローラーの「すべてのファイルを表示」に切り替えると見えます。テキストとして開いて編集してください。

## 画面ツールとの使い分け {#choose}

Visual Studio の Git 機能は、日常の「コミットする、枝を切る、プッシュする」には十分です。一方で、履歴の整理（`rebase -i` など）や、複数のリポジトリを並べて見る使い方は、専用の画面ツールのほうが得意です。

- 日常の作業は、Visual Studio の中で済ませる
- 履歴を整理する、枝が多い場合は、[SourceTree](sourcetree.md) を併用する
- 一人で GitHub に載せるだけなら、[GitHub Desktop](github-desktop.md) も選べる

同じリポジトリを、複数のツールで開いても問題ありません。中身は同じ Git だからです。

## よくあるミス {#mistakes}

??? failure "全部のファイルを一度にコミットして、ビルド生成物まで入った"
    ステージの確認をせずにコミットすると起きます。`.gitignore` が足りないのが原因です。[.gitignore](gitignore.md) を見直してください。

??? failure "違う枝でコミットしていた"
    押す前にステータス バーの枝の名前を見る習慣がないと起きます。push 前なら、正しい枝へ移って `cherry-pick` するか、元の枝で `reset --soft` して、やり直します。

??? failure "「Git の変更」に何も出ない"
    リポジトリの外のフォルダーを開いているか、`.git` が存在しません。「Git」→「リポジトリを作成」でリポジトリにするか、正しいフォルダーを開いてください。

## これだけ覚える {#summary}

- 「Git の変更」で、「+」がステージ、「コミット」ボタンが確定
- 右下の枝名から、切り替えと新規作成
- コンフリクトはマージ エディターで、3 画面から選ぶ
- 履歴の整理や、枝が多いときは SourceTree が楽
