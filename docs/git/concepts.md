# Git の考え方（スナップショットと 3 つの場所）

ゲームを作っていると「昨日まで動いていたのに、いま動かない」が必ず起きます。フォルダーを `MyGame_最終`、`MyGame_最終2`、`MyGame_本当に最終` とコピーして逃げる方法はすぐに破綻します。どれが新しいのか分からなくなりますし、チームで作るなら同じファイルを 2 人が別々に直して、片方が消えてしまいます。

Git は <strong>ファイルの変更を履歴として残し、好きな時点に戻せる</strong>道具です。複数人が別々に直した内容をあとから合体させる仕組みも持っています。コマンドの使い方を覚える前にこのページで頭の中の模型を作っておくとあとの全部のページが「あの模型のこの部分の話」として読めます。

!!! tip "ポイント"
    - コミットは差分ではなく<strong>その時点のプロジェクト全体の写真</strong>。変わらない部分は使い回すので、容量は小さい
    - ファイルは 3 つの場所（作業フォルダー、ステージ、リポジトリ）を移動する。コマンドは「どの場所からどの場所へ動かすか」で整理できる
    - ブランチはコミットを指す<strong>ただの名札</strong>。作るのも消すのも一瞬で軽い
    - 自分のパソコンのリポジトリ（ローカル）と GitHub などの共有場所（リモート）は別物

!!! info "このページを読む前に"
    - 前提はありません。Git を触ったことがなくても読めます

## 最初に知っておく言葉 {#terms}

Git の説明は言葉でつまずきがちです。先によく出る 7 つを押さえます。あとのページで出てきたらここに戻ってください。

- リポジトリ: プロジェクトのフォルダーとその履歴を丸ごと入れた入れ物。フォルダー内の `.git` に履歴が入っている
- コミット: ある時点の状態を 1 つ記録したもの。メッセージと作った人と日時が付く
- ブランチ: 履歴の枝。`main` から枝を分けて作業し終わったら戻す
- マージ: 別々の枝の変更を 1 つに合体すること
- リモート: GitHub などの共有場所にあるリポジトリ。ふつう `origin` という名前で呼ぶ
- HEAD: 「いま自分がいる場所」を指す目印。ふつうはブランチの先頭を指している
- ステージ: 次のコミットに入れるファイルを選んで置いておく場所。インデックスとも呼ぶ

## 差分ではなく写真を残す {#snapshot}

履歴管理と聞くと「変更点（差分）を順に積んでいく」仕組みを想像しがちです。Git は違います。コミットのたびに <strong>その時点のプロジェクト全体の状態</strong>を 1 枚の写真として記録します。

「全部を毎回保存したら容量が膨らむのでは」と思うかもしれません。Git はファイルの中身から計算した ID（ハッシュ）で保存するので、変わっていないファイルは前の写真と同じものを指すだけで済みます。1 ファイルだけ直したコミットはそのファイルの分だけが増えます。

```text title="コミットは写真が連なったもの"
コミット1        コミット2        コミット3
 Player.cpp(A)    Player.cpp(B)    Player.cpp(B)   ← 変わっていないので使い回し
 Enemy.cpp (X)    Enemy.cpp (X)    Enemy.cpp (Y)
```

この作りのおかげで「3 つ前の状態に戻す」が、差分を逆向きにたどる計算ではなく、写真を取り出す操作になります。ブランチを移ったときに作業フォルダーが一瞬で別の状態に入れ替わるのも同じ理由です。

各コミットは <strong>1 つ前のコミットへの参照</strong>を持っています。この参照をたどると履歴が 1 本の鎖として読めます。マージで作られるコミットは前が 2 つあります。

## 3 つの場所 {#three-areas}

ファイルは次の 3 つの場所を移動します。Git の基本のコマンドはほぼ全部が「どの場所から、どの場所へ動かすか」の話です。

```text title="3 つの場所とコマンド"
作業フォルダー ──git add──▶ ステージ ──git commit──▶ リポジトリ
  (編集する所)          (次の記録に入れる所)         (履歴の保管所)
       ◀──────────────git restore / git switch────────────
```

<strong>作業フォルダー</strong>はふだん編集している普通のフォルダーです。エディターや Visual Studio で保存した変更は、まずここに現れます。この時点では Git はまだ何も記録していません。

<strong>ステージ</strong>は「次のコミットに入れるもの」を選んで置いておく場所です。`git add` で作業フォルダーから移します。ステージがあるおかげで 5 ファイル直していても、「今回の記録は 2 ファイルだけ」と選べます。1 つのコミットを 1 つの目的にそろえやすくなります。

<strong>リポジトリ</strong>は確定した写真の保管所です。`git commit` でステージの中身が 1 枚の写真になって、ここに入ります。

この 3 つを区別しておくと `git diff`（作業フォルダーとステージの差）と `git diff --staged`（ステージと最後のコミットの差）が別の結果を出す理由も、すぐ分かります。

## ブランチは名札 {#branch}

ブランチは「コピーしたフォルダー」ではありません。<strong>あるコミットを指す名札</strong>です。`main` というブランチは「`main` と書かれた名札が、いちばん新しいコミットに付いている」という状態を指します。コミットを作るといまいるブランチの名札が新しいコミットへ進みます。

```text title="枝を作ると、名札が 1 枚増える"
●───●───●   main
         \
          ●───●   feature/enemy
```

名札は数十バイトの小さな情報なので、枝を作るのは一瞬です。「ちょっと試したいから枝を切る」を気軽にやってかまいません。詳しい使い方は [ブランチ](branch.md) で説明します。

HEAD はいまどの名札の上にいるかを示す目印です。ふつうはブランチの名前を指します。コミットの ID を直接指す状態（detached HEAD）になることもあり、[事故と対処](accidents.md#detached) で扱います。

## ローカルとリモート {#remote}

自分のパソコンにあるリポジトリを<strong>ローカル</strong>、GitHub などサーバー上にあるリポジトリを<strong>リモート</strong>と呼びます。両方とも履歴を丸ごと持った完全なリポジトリです。

重要なのは <strong>push するまで、あなたのコミットは他の人には見えない</strong>ことです。ローカルで何度コミットしても、リモートは変わりません。逆に、他の人がリモートに push した内容もあなたが取り込む（`fetch` や `pull`）まで、手元には来ません。

このおかげでネットワークがなくても、コミットも履歴の閲覧も枝の切り替えもできます。共有するときだけリモートとやり取りします。やり取りの手順は [リモートと push・pull](remote.md) で説明します。

## ゲーム制作と Git の相性 {#game}

Git はテキストファイル（ソースコード、設定、シェーダー）の管理がとても得意です。一方で、画像・モデル・音声のようなバイナリは、中身が少し変わるだけでファイル全体が別物になるので、履歴が太りやすくなります。これは Git の弱点で対策は [Git LFS](git-lfs.md) のページにあります。

また、ビルドで生成されるファイル（`x64/`、`.vs/` など）は管理に入れません。入れないための仕組みが [.gitignore](gitignore.md) です。

## これだけ覚える {#summary}

- コミットは差分ではなく写真。いつでも取り出せる安全な地点
- 作業フォルダー → ステージ → リポジトリ。`add` と `commit` で順に進める
- ブランチは名札。軽いので気軽に作ってよい
- push するまで他人には見えない
