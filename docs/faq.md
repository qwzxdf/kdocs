# よくある質問

C++ には同じことをする道具が複数あり、「どれを使えばいいの？」が必ず出ます。ここでは、ゲーム制作でよく聞かれる選び方を、結論から先に並べます。理由は、それぞれのページに書いてあります。

!!! info "このページを読む前に"
    - [学習ロードマップ](roadmap.md)（どの順に読むか）

## 言語・STL {#lang}

### コンテナはまず何を使えばいい？ {#container}

`std::vector` です。迷ったら `vector`。連続したメモリに並ぶので、CPU のキャッシュに乗りやすく、ゲームのような大量の要素の処理で速いです。`list` は、挿入が速いように見えて、実際は遅いことが多いです。詳しくは [vector](stl/containers/vector.md)。

### `new` と `std::make_unique` のどちら？ {#new}

`make_unique` です。`delete` を書かずに済み、例外が起きてもリークしません。複数の持ち主がいるときだけ `shared_ptr` を考えます。

### 配列は `std::array` と `vector` のどちら？ {#array}

サイズがコンパイル時に決まっているなら `std::array`、実行中に増減するなら `vector` です。

### `struct` と `class` は？ {#struct}

動作の違いは、メンバーの既定の公開範囲だけです。データを束ねるだけなら `struct`、内部を隠して操作をそろえるなら `class` と、慣習で使い分けます。

### 例外は使うべき？ {#exception}

ゲームでは、例外を切って（`/EHs-c-`）使わない流儀が多いです。エラーは戻り値（`std::expected` や `optional`）で返します。使うなら、ファイル読み込みのような、まれな失敗に限ります。

## 道具・ビルド {#tool}

### ライブラリの入れ方は？ {#lib}

vcpkg です。`vcpkg.json` に書けば、Visual Studio が自動で入れます。手でヘッダーを置く方法もあります。[外部ライブラリの入れ方](vs/libraries.md) を見てください。

### Debug と Release は？ {#config}

開発中は Debug、速さを測るときと配布のときは Release です。速度の計測を Debug でしても、意味がありません。

### Git で何を管理する？ {#git}

ソースと設定は Git、ビルドの生成物は管理しません。大きなアセットは [Git LFS](vs/git-lfs.md) を使います。

## 描画・数学 {#graphics}

### DX11 と DX12 はどちらから？ {#dx}

DX11 です。API が単純で、描画の仕組みを学ぶのに向きます。DX12 は、速さを引き出せる代わりに、管理することが多く、DX11 で描画の仕組みを知ってからのほうが理解しやすいです。このサイトの [DirectX](directx/index.md) は、2 つが独立しています。

### 行列は行ベクトルと列ベクトルのどちら？ {#matrix}

このサイトの 3D ゲームのページは、行ベクトル（`v * M`）で、掛ける順は左から右です。座標系は右手系・Y-up です。ライブラリを混ぜるときは、どちらの流儀か最初に確かめます。

### 角度は度とラジアンのどちら？ {#angle}

内部の計算はラジアンです。度は、ユーザーに見せる画面と設定ファイルだけにします。

## パフォーマンス {#perf}

### 速くするには、何から？ {#speed}

測ることです。推測で直しても、効かない場所を直して終わることがほとんどです。[計測（プロファイリング）](optimize/measure.md) と [Tracy](vs/tracy.md) を使います。

### 描画が重いときは？ {#heavy}

CPU と GPU のどちらが待っているかを、先に分けます。それから [描画最適化](rendering/index.md) の該当ページに進みます。
