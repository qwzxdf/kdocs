# K-CppUltimateAssist

メンバー関数の中で `count_ = items.size();` と書くと Visual Studio は `E0020: 識別子 "count_" が定義されていません` と赤い波線を出します。直すにはヘッダーを開いて `items.size()` の戻り値が何だったかを調べて（`size_t`）、`size_t count_;` を書き足して元のファイルに戻るという往復が要ります。Getter と Setter を作るときも同じ往復をもう一度やります。

K-CppUltimateAssist はこの往復をキー 1 つにする Visual Studio 用の拡張です。右辺の式から型を決めてクラスの宣言（`.h`）に変数を足します。ローカル変数ならその場で型を付けます。

!!! info "このページを読む前に"
    拡張機能の入れ方や C++23 の設定は [Visual Studio](../vs/index.md) にあります。K-CppUltimateAssist は右辺の型をエディターのホバー（Quick Info）から読みます。ホバーが出ない環境ではリテラルなど式だけで決まる型に限られます。

## 使い方

コマンドの多くは、キーだけで使います。拡張機能 → 「K-Cpp: 使い方...」で、この一覧を VS の中で見られます。キーは設定で変えられます。拡張機能 メニューには「K-Cpp: 設定...」「K-ErrorLog (エラーログ)を開く」と、プロジェクト全体に使うコマンド（`#include` の整理、ファイルの文字コードをそろえる、など）が出ます。設定のほうをクリックすると設定画面が開きます。

| キー | コマンド | することと例 |
|---|---|---|
| Alt+W | メンバー変数として宣言する（Write member） | クラスのヘッダー（`.h`）に `型 名前;` を足す |
| Alt+Q | ローカル変数に型を付ける（Qualify type） | その場の `count = 0;` を `int count = 0;` にする |
| Alt+G | Getter・Setter を作る（Getter） | `hp_` の `GetHp()` と `SetHp(...)` を `public:` の末尾に足す |
| Alt+N | ファイル名をまとめて変える（Name） | ヘッダーか cpp の名前を変え、相手のファイル・`#include`・CMake も同じ名前に直す。名前を変えると自動でも直す（下の「ファイル名をまとめて変える」） |
| Alt+M | 関数を ヘッダー ⇄ cpp に移す（Move） | ヘッダーに書いた関数の本体を cpp へ、cpp の `Class::Func` の本体をヘッダーへ移す |
| Alt+F | `#include` を前方宣言にする（Forward） | ヘッダーの `#include "x.h"` を `class X;` に置き換えて、`#include` を cpp に移す |
| Alt+U | 呼び出しから関数を作る（Usage） | `Foo(hp, name, 2.5f)` や `obj.Foo(x)` の行で押すと、引数の型を読んで宣言と定義の雛形を作る（下の「呼び出しから関数を作る」） |
| Alt+O | 基底クラスの仮想関数を override する（Override） | 基底クラスの仮想関数のうち、まだ宣言していないものを `override` つきで足す（純粋仮想関数が先） |
| Alt+C | コンストラクターを作る（Constructor） | データ メンバーから、初期化リストつきのコンストラクターを作る |
| Alt+S | 宣言と定義の引数を合わせる（Sync） | ヘッダーの宣言と cpp の定義の引数を、変えた側に合わせる。引数を変えるとエディターで開いている相手にも自動で写す |
| Alt+R | 宣言・定義の相手を作る（Resolve） | ヘッダーの宣言から cpp の定義の雛形を、cpp の定義からヘッダーの宣言を作る（下の「宣言と定義の相手を作る」） |
| Alt+I | `#include` を足す（Include） | カーソルの識別子（`std::vector`、`ComPtr`、`Camera`）のヘッダーを探して `#include` を足す。設定を `Auto` にすると入力中にも自動で足す |
| Alt+X | 書き換え・生成の一覧（eXplore） | `Ctrl+.` の電球と同じ項目を、一覧の窓で選ぶ（下の「書き換えと生成」） |

どのコマンドも <strong>カーソルが行のどこにあっても</strong>押せます。対象は行頭の `名前 = 右辺;` の左辺です。

```cpp
// Player.cpp
Player::Player(Weapon* weapon, int level) {
    hp_ = weapon->GetPower(level);   // この行のどこでも Alt+W
}
```

Alt+W を押すと `Player` の宣言から、ヘッダーに次の 1 行が入ります。

```cpp
 private:
  int level_;
  unsigned int hp_;
```

`Class::Func` の `Class` を宣言から探して、そのクラスの `private:` の末尾に足します。`private:` が最後でなければ末尾に `private:` を作ってから足します。ヘッダーはエディターで開いたままになり（保存はしません）、作業中のファイルへ戻ります。挿入は 1 回の編集なので Undo も 1 回です。字下げされた定義や引数が複数行に分かれた定義でも見つかります。

### 電球で、宣言のしかたを選ぶ

`hp_ = 3;` のような「名前 = 右辺;」の行で電球（`Ctrl+.` か `Alt+Enter`）を開くと、宣言のしかたが次の 5 通りで並びます。メンバー関数の中でないときは、ローカル変数だけです。

1. ローカル変数として型を付ける。その場に `int hp_ = 3;` と書きます。
2. private メンバー変数としてヘッダーに宣言する。`int hp_;` を足します（Alt+W と同じです）。
3. public メンバー変数としてヘッダーに宣言する。同じ宣言を `public:` の区画に足します。
4. private 定数としてヘッダーに宣言する。`static constexpr int hp_ = 3;` を足します。
5. public 定数としてヘッダーに宣言する。同じものを `public:` の区画に足します。

定数は、右辺の値を宣言へ移すので、cpp の `hp_ = 3;` の行は消します。`constexpr` の変数は、宣言のあとに代入できないからです。右辺が実行時に決まる値（関数の引数や、`constexpr` でない関数の結果）のときは、ヘッダーに足した宣言がコンパイルできません。そのときは Undo してから、メンバー変数を選んでください。型を決められないときは `auto` になります。

置く場所は、クラスの中の並びを守って決めます。並びは、型・`using` → 定数 → コンストラクター → デストラクター → コピー・ムーブ → 関数 → メンバー変数です。たとえば `private:` の区画に関数が並んでいれば、メンバー変数はその後ろに、定数は `using` のすぐ後ろ（なければ区画の先頭）に入ります。空行は、前後の宣言と種類が違うときだけ入れます。同じ種類が並ぶときは、空行を入れません。その指定子の区画がなければ、`public:` はクラスの先頭に、`private:` はクラスの末尾に、指定子ごと作ります。

## 型の決め方

右辺から次の順に決めます。

1. <strong>式そのもの。</strong> `0` は `int`、`1.0f` は `float`、`true` は `bool`、`"abc"` は `const char*`、`static_cast<T>(...)` は `T`、`std::make_unique<T>(...)` は `std::unique_ptr<T>`、`new T` は `T*` です。
2. <strong>Quick Info（ホバーの内容）。</strong> 関数呼び出しなら戻り値の型を取り出します。`size_t std::vector<int>::size() const` から `size_t` を取ります。変数や引数ならその型を取ります。
3. <strong>どちらでも決まらないとき。</strong> Alt+W は型の入力欄を出します。Alt+Q は `auto` を入れます。

演算子を含む式（`a + b`、`x < y`、`!flag`、`(float)n`、`&x`）は部分ごとに 1 と 2 で型を決めて、組み立てます。比較と論理演算は `bool` です。算術は C++ の通常の算術変換で、`int + float` は `float`、`float * double` は `double` になります。`UINT + UINT` や `size_t * size_t` のように綴りがそろっていれば、その綴りのままです。`char` や `short` は `int` になります。クラスの型が混じるときは最初のクラスの型（`XMFLOAT3 * float` も `float * XMFLOAT3` も `XMFLOAT3`、`std::string + "x"` は `std::string`）、ポインターに整数を足せばそのポインターの型です。シフトは左の型になります。

右辺が `cond ? A : B` の形のときは A と B を順に試して、最初に型が決まったほうを使います。`{}` と `nullptr` の枝は型を持たないので飛ばします。

`const` と参照は外して値の型にそろえます（`const UINT&` は `UINT`）。ポインターの `const` は残します。

## Getter・Setter

メンバー変数の宣言行（`UINT hp_;`）にカーソルを置くか `.cpp` の `hp_ = ...;` の行にカーソルを置いて、Alt+G を押します。名前は `hp_` から末尾の `_` を外して、先頭を大文字にします（`cpu_start_` は `GetCpuStart` / `SetCpuStart`）。

電球（Alt+Enter）には「Getter・Setter を作る」「Getter を作る」「Setter を作る」の 3 つが並びます。片方だけが要るときは、下の 2 つを使います。`const` のメンバーや `std::unique_ptr` のように Setter を作れない型で「Setter を作る」を選ぶと、作らずに理由を出します。

```cpp
 public:
  Player(Weapon* weapon, int level);

  unsigned int GetHp() const { return hp_; }

  void SetHp(unsigned int value) { hp_ = value; }
```

同じ名前がすでにあるときは足しません。`public:` がなければクラスの先頭に作ります。型によって書き方を変えます。

| 型 | Getter | Setter |
|---|---|---|
| `int`・`float`・ポインター・`UINT` のような大文字の型・ヘッダーに `enum` の定義がある型 | 値 | 値 |
| `std::string`・`std::vector`・構造体など | `const T&` | `const T&` |
| `bool`（名前が `is_` / `has_` で始まる） | `IsVisible()` / `HasXxx()` | `SetVisible(...)` / `SetHasXxx(...)` |
| `ComPtr<T>` | `T*`（`.Get()`） | 作らない |
| `std::unique_ptr<T>` | `T*`（`.get()`） | 作らない |
| `std::shared_ptr<T>` | `T*`（`.get()`） | 値で受けて `std::move` |
| `std::weak_ptr<T>` | `std::shared_ptr<T>`（`.lock()`） | `const&` |
| `std::atomic<T>` | `T`（`.load()`） | `T`（`.store()`） |
| `const` メンバー・参照メンバー | 作る | 作らない |
| `std::mutex`・`std::thread` など | 作らずに断る | 作らずに断る |

`ComPtr` の Getter が `T*` なのは、呼び出し側が毎回 `.Get()` を書かなくて済むようにするためです。Setter を作らないのは DirectX のオブジェクトは、作った側が持ち主になる使い方が多いからです。配列と `static` のメンバーは対象外です。

## #include を足す

カーソルの識別子（`std::vector`、`ComPtr`、`Camera` など）のヘッダーを探して、`#include` を 1 行足します。すでにあれば足しません。

ヘッダーは次の順に決めます。

1. 表。 標準ライブラリ（`std::vector` → `<vector>`）、Windows（`UINT` → `<Windows.h>`）、DirectX（`ID3D12Resource` → `<d3d12.h>`、`XMFLOAT3` → `<DirectXMath.h>`）の固定の対応表。
2. ソリューションの索引。 ヘッダーから集めた `class` / `struct` / `enum` / `using X =` / `typedef` の定義。関数、メソッド、変数、クラスの中の入れ子の型は入れないので、`Instance()` のような名前がヘッダーに引かれることはありません。
3. 索引で複数見つかったら、選ぶ欄を出します（自動では足しません）。

足す場所はファイルにある `#include` の並びに合わせます。空行でグループが分かれていればグループごとに（自分のヘッダー、C、C++ 標準、その他の `<>`、プロジェクトの `""` の順）、分かれていなければ 1 つの塊の中で並び順に。フォルダーは 2 つのファイルの共通の親からの相対（`"core/scene.h"`）で書きます。挿入は 1 回の Undo です。

### 書き方（`""` か `<>` か）

プロジェクトのヘッダーは `""`、標準・Windows・DirectX は `<>` です。`""` のパスはプロジェクトが実際に使っている基準に合わせます。ソリューションの既存の `#include "a/b.h"` が、どの親フォルダーから開けるかを数えて、いちばん多く使われている基準からの相対で書きます（`Engine/Source` が基準なら `"Prest/Core/GraphicsModule.h"`）。同じフォルダーかその下ならそこからの相対。基準が分からないときはこのファイルからの相対（`"../Core/x.h"`）にするので、必ず開けます。

### 入力中の自動挿入

設定の「`#include` を足すしかた」を `Auto` にすると、入力中に自動で足します。次をすべて満たすときだけです。

- 識別子を打ち終えた（`<` `::` `*` `(` 空白などの区切りを打った）あと入力が止まって約 0.9 秒たった。
- 補完リストが出ていないビルド中でない、カーソルがその識別子の上にない。
- コメント・文字列・`#` の行の中ではなく、型として使われている形（`Foo x` / `Foo*` / `Foo<` / `Foo::` / `new Foo` など）。`.名前` `->名前` `Foo::Instance()` のような呼び出しは対象外。
- その識別子に IntelliSense のエラーの波線が付いている（ほかのヘッダー経由ですでに見えているものには足さない）。
- ヘッダーが 1 つに決まる。索引から引く名前は拒否リスト（`Instance` `Get` `Data` `Type` など。設定で変えられる）にないもの。
- `.h` の中では表（標準・Windows・DirectX）のものだけ。足すと循環するヘッダーは足さない。

PCH（プリコンパイル済みヘッダー）経由でもう見えている型には、波線が出ないので自動では足しません。足したいときは型の上で Alt+F を押してください（Alt+F は波線を見ずに足します）。

足したあと 40 秒以内にその識別子を消したり書き換えたりしたら、足した `#include` も戻します（ほかの場所でまだ使っていれば戻しません）。足すたびにステータスバーに理由を出し、`vsix.log` に残します。

初期値は `Auto`（Alt+I に加えて、入力中にも自動で足す）です。`ManualOnly` にすると Alt+I だけ、`Off` にするとどちらも止まります。ヘッダーを探さないフォルダー（`third_party` `build` など）も設定で変えられます。

## 宣言と定義の引数を合わせる

ヘッダーの宣言か cpp の定義（コンストラクターを含む）の引数を変えると、相手の引数も同じに書き換えます。引数の型・数・名前の変更、並べ替え追加、削除に対応します。

```cpp
// Player.h
Player(Weapon* weapon, int level = 0);         // ← float scale = 1.0f を足す
// Player.cpp
Player::Player(Weapon* weapon, int level) {...}  // ← 自動で (Weapon* weapon, int level, float scale) になる
```

- 自動（設定の「宣言と定義の引数を合わせるしかた」が `Auto`、初期値）: 括弧の中を編集すると、すぐに（待ちは 0 ミリ秒。設定の「自動で合わせるまでの待ち」で変えられます）、相手を書き換えます。相手がエディターで開いていなければ、開いて書き換え作業中のファイルへ戻ります。
- Alt+S: カーソルの関数の引数を相手に写します。相手が開いていなければ開いて書き換えます。引数が違う相手が複数あれば選ぶ欄を出します。
- ヘッダー → cpp: 既定値（`= 0`）は cpp に付けません。残る引数は cpp の書き方（名前・`const` の位置）のまま残します。cpp の本文が引数の名前を使っているので、ヘッダーで改名しても cpp には写しません。型だけ変えたときは cpp の名前を残して、型だけ新しくします。
- cpp → ヘッダー: 残る引数の既定値と書き方は、ヘッダーのものを引き継ぎます。cpp で引数を改名したときだけヘッダーにも新しい名前を写します。新しい引数に既定値は付きません。既定値のある引数のあとに既定値のない引数ができたときは、ステータスバーで知らせます（C++ では書けない形です）。
- どの関数かは名前と `const` の有無と `namespace` とクラスの並びと変える前の引数の型で決めます。同じ名前のオーバーロード（`Add(int)` と `Add(float)`、`Get() const` と `Get()`）や別の `namespace`・別のクラスの同名の関数は、取り違えません。cpp が `using namespace` で修飾を省いていても、ほかに合うものがなければ見つかります。見つからない・複数ある・書きかけ（末尾のカンマなど）のときは、何もしません。
- 書き換えは相手側の 1 回の Undo です。相手のあとでもう一度戻されることはありません。
- 呼び出し側（`Move(1, 2.5f)` など）は、並べ替えと削除だけを直します（下の「引数を並べ替える・消すと、呼び出しも直る」）。戻り値の型の変更は対象外です。
- 別名の違いは同じ型として相手を探します。`HANDLE` と `void*`、`DWORD` と `unsigned long`、`uint32_t` と `unsigned int`、`LPCWSTR` と `const wchar_t*` などです。ヘッダーにだけ付いた SAL 注釈（`_In_`、`_Out_writes_bytes_(n)`）、`__cdecl` の有無、関数ポインタの引数の中の名前の違い（`void (*cb)(void* arg)` と `void (*cb)(void*)`）も違いとして数えません。
- 引数の途中に `#if` が入る関数は枝の選び方ごとの型の並びで相手を探します。ただし、どの枝が有効か分からないので、書き換えはしません。ステータスバーに理由を出すので、相手は手で合わせてください。

## 名前を変えると使っている場所も変わる（自動）

メンバー変数の名前を `hp_` から `life_` に変えたくなったとき、ヘッダーの宣言を直しただけではビルドが通りません。cpp の中で `hp_` を使っている行を 1 つずつ直すか、置換を使って別のクラスの `hp_` まで巻き込まないように気を付けることになります。

K-CppUltimateAssist は宣言の名前を書き換えると、その名前を使っている場所を打つそばから同じ名前にします。キーは要りません。

```cpp
// Player.h
class Player {
 private:
  int hp_ = 0;        // ← hp_ を life_ に書き換える
};
// Player.cpp（自動で変わる）
void Player::Hit(int damage) {
  life_ -= damage;    // hp_ だった
}
void Enemy::Hit(int damage) {
  hp_ -= damage;      // 別のクラスなので変わらない
}
```

書き換えている間は、一緒に変わる場所を点線の枠で囲みます。書き換えている宣言の名前は実線の枠です。C# の名前の変更と同じ見え方で、どこが変わってどこが変わらないか（上の例なら `Enemy::Hit` の `hp_` に枠がない）を、打ちながら確かめられます。枠が付くのは開いているファイルの中だけです。閉じているファイルの場所は、終わったときにディスクの上で書き換えます。カーソルが名前から離れて名前の変更が終わると、枠は消えます。

対象は次の 5 つの、宣言（か定義）の名前です。使っている側の名前を書き換えても、ほかは変わりません。

- ローカル変数。宣言から、その変数が見えるブロックの終わりまでが範囲です。内側のブロックで同じ名前を宣言し直している所は変えません。`for` や `if` の括弧の中の宣言とラムダのキャプチャも追います。
- 引数。定義（本体のある関数）の引数を変えると本体の中も変わります。コンストラクターの初期化子リストの `hp_(hp)` は、括弧の中だけが引数です。
- メンバー変数。クラスの本体、`Class::Func` の定義の中、`this->名前`、`Class::名前`（static メンバーの定義）が変わります。引数やローカル変数に同じ名前があれば、そちらは変えません。
- メンバー関数。ヘッダーの宣言と cpp の定義のどちらを変えても、相手と呼び出しが変わります。派生クラスの `override` と基底クラスの宣言も同じ名前にします。
- 関数（クラスに属さないもの）。宣言・定義・呼び出しが変わります。`SetCallback(window, OnKey)` や `&OnKey` のように `(` なしで渡している所も変わります。`static` の関数と無名の `namespace` の中の関数は、そのファイルの中だけを見ます。

### 途中の名前でほかの名前と混ざらない

使っている場所は、最初の 1 文字を打ったときに決めて、そのあとは位置で追いかけます。名前では探し直しません。`hp_` を `h` まで消して `health_` と打ち直すあいだに `h` という別の変数があっても、混ざりません。名前が空や数字始まりになっている間は、ほかの場所を前の名前のまま待たせます。

新しい名前が、同じ範囲にすでにある名前と同じになったときは、ほかの場所へ写しません。`a` を `b` に変えたとき、もとからあった `b` と区別がつかなくなるためです。小さなウィンドウに「同じ名前がすでにあるので、ほかの場所は変えていません」と出て、別の名前にすると続きが写ります。`index` と打つ途中の `i` がすでにある変数でも、打ち進めれば写ります。ローカル変数と引数は見える範囲の中の名前を、メンバーは同じクラスのメンバー変数（メンバー変数を変えるときはメンバー関数も）を調べます。

新しく宣言を打っているあいだは、名前の変更とはみなしません。`int position` と打つ途中の `pos` が、たまたま下の行で使っているメンバーの名前と同じでも、何も変えません。カーソルが名前から離れたあとで、その名前を書き換えたときに初めて働きます。行を複製して写しの名前を書き換えているとき（同じブロックに同じ名前の宣言がもう 1 つあるとき）も、何も変えません。

### `obj.name` はどこまで変えるか

`obj.hp` や `p->Update()` は、文字だけでは `obj` がどのクラスか決まりません。K-CppUltimateAssist は `obj` の宣言を読みます。関数の引数とローカル変数、その関数が属するクラスのメンバー変数の順に探して、型が同じクラス（か派生クラス）なら変えます。`std::unique_ptr<Enemy>` や `ComPtr<Enemy>` のようなスマート ポインターは、`->` のときだけ中身のクラスのメンバーとして扱います。

入れ物の要素も、入れ物の宣言から型を引きます。`std::vector<Enemy> enemies_;` があれば、`for (auto& e : enemies_) e.Update(dt);` の `e` と `enemies_[i].Update(dt)` と `auto& first = enemies_.front();` の `first` は `Enemy` です。`std::vector<std::unique_ptr<Enemy>>` なら `->` のときに `Enemy` として扱います。対象の入れ物は `vector` `array` `list` `deque` `set` `span` などで、`map` は対象外です。

型が別のクラスだと分かれば変えません。分からないもの（関数の戻り値を受けた `auto`、`using` の別名、`GetBoss()->hp`）は変えずに、出力ウィンドウの「K-Cpp」に `ファイル(行): …` の一覧を出します。行をダブルクリックするとその場所へ飛べます。private なメンバーを同じクラスの関数の中から `other.hp_` の形で触っている所は、同じクラスの物と決まるので変えます。

設定の「型が分からない obj.name も変える」を True にすると、分からないものも同じ名前なら変えます。`x` や `Update` のような名前では別のクラスのメンバーも変わるので、初期値は False です。

### ほかのファイルと、元に戻す

ローカル変数と引数は、いまのファイルの中だけで決まるのですぐ変わります。メンバーと関数はソリューションの下の C++ のファイルを調べるので、調べ終わるまで小さなウィンドウに「使っている場所を調べています…」と出ます。調べているあいだに打ち終えても、調べ終わった時点の名前を写します。

- エディターで開いているファイルは、打つそばから変わります。保存はしません。
- 閉じているファイルは、カーソルが名前から離れたときにディスクの上で書き換えて保存します。文字コード（UTF-8 の BOM の有無、シフト JIS）は保ちます。書き換えたファイルは出力ウィンドウに出ます。読み取り専用などで書けなかったファイルも、同じ所に「書き換えられませんでした」と出ます。
- タブにあるだけでまだ表示していない文書は、開いている文書として扱います（ディスクの上では書き換えません）。
- Ctrl+Z で宣言の名前を戻すと、ほかの開いているファイルと閉じているファイルも、戻したあとの名前に合わせます。

同じ名前で引数の違う関数（オーバーロード）があるときは、引数の型が同じ宣言と定義だけを変えます。呼び出しはどちらの関数か決められないので、一覧に出します。同じ名前のクラスが別のファイルにも定義されているときは、そちらのファイルの中は一覧に出すだけにします。

### 引数を並べ替える・消すと、呼び出しも直る

関数の引数を並べ替えるか消して、カーソルが括弧の外へ出ると、その関数の呼び出しの引数も同じ並びに直します。宣言と定義の相手は、上の「宣言と定義の引数を合わせる」が打つそばから直しています。

```cpp
void Move(int id, float speed);     // ← (float speed, int id) に並べ替える
// 呼び出し（カーソルが括弧の外へ出たときに変わる）
Move(1, 2.5f);                      // → Move(2.5f, 1);
```

打つそばからではなく括弧の外へ出たときに直すのは、切り取って貼る途中の形（引数が 1 つ減った形）で呼び出しを直すと、消えた実引数を取り戻せないためです。どの引数がどこへ動いたかは、まず引数の名前で、次に型で決めます。

- 足した引数に渡す値は決められません。既定値のある引数を末尾に足したときは省いたままにして、それ以外の呼び出しは直さずに一覧に出します。
- 同じ型の引数が並んでいて、名前も変えて 1 つ消したとき（`(int x, int y)` を `(int height)` にしたとき）は、どちらを消したか決められないので何もしません。名前を残して消せば直せます。
- コンストラクターの呼び出し（`Foo(…)`、`make_unique<Foo>(…)`）と、オーバーロードのある関数は対象外です。
- Ctrl+Z で引数を直す前の並びに戻すと、直した呼び出しも元の文字に戻します。やり直し（Ctrl+Y）で、もう一度直します。閉じているファイルは、こちらが書いたあとで変わっていなければ戻します。

## 宣言と定義の相手を作る

ヘッダーに宣言を足したのに cpp に定義を書くのが手間、という場面のためのコマンドです。Alt+R を押すとカーソルのある関数の相手を作ります。

- ヘッダーの宣言にカーソルがあるとき: cpp に定義の雛形を足します。戻り値の型・`const`・`noexcept`・後置の戻り値の型は宣言のままです。`virtual`・`static`・`override`・既定値・SAL 注釈・export マクロは、定義に書かないので外します。本体は `{ }` で戻り値が `bool` なら `return false;`、数なら `return 0;`、ポインターなら `return nullptr;`、それ以外の値なら `return {};` を入れます。参照を返す関数と `void` には `return` を書きません。
- cpp の `Class::Func` の定義にカーソルがあるとき: ヘッダーのクラスの `public:` の末尾に、宣言を足します。`public:` がなければ末尾に作ります（`struct` は先頭から `public` です）。
- 置き場所は定義なら「同じクラスの前の宣言の定義の直後」です。なければ同じクラスの最後の定義の直後、それもなければ同じ `namespace` の定義の直後、最後は末尾です。cpp が `namespace` の中に書かれていれば、その分の修飾は付けません。足したあとは cpp が開いて、カーソルが新しい本体に移ります。
- 相手がすでにあれば（同じ名前・同じ引数の型）、何もしません。`= 0`・`= default`・`= delete`・`friend`・`constexpr`・`template` の関数は定義を作りません。デストラクターと演算子も対象外です。

### 電球（Quick Fix）

`Ctrl+.` かカーソル横の電球から次の項目を選べます。カーソルの位置で使えるものだけが出ます。設定の「電球に出す」で消せます。

- 宣言から cpp に定義を作る / 定義からヘッダーに宣言を作る（Alt+R と同じ）。
- cpp の定義の引数を宣言に合わせる / ヘッダーの宣言の引数を定義に合わせる（Alt+S と同じ。同じ名前の関数があって引数の型だけ違うときに出ます）。
- ローカル変数として型を付ける / メンバー変数としてヘッダーに宣言する（Alt+Q・Alt+W と同じ。`名前 = 右辺;` の文のとき）。

電球に出すかどうかは保存済みの同名のファイル（`Foo.h` と `Foo.cpp`）を見て決めます。実行するときは開いているエディターの内容で処理します。

## 関数を ヘッダー ⇄ cpp に移す

クラスの中に書いた短い関数が育ってきたので cpp に出したい、逆に、cpp の小さな getter をヘッダーに戻したい、という場面のためのコマンドです（Alt+M）。

- ヘッダーの本体のある関数にカーソルを置いて押すと、本体を cpp の定義に移して、ヘッダーには宣言だけを残します。戻り値の型・`const`・`noexcept` は宣言のままで、`override`・`virtual`・`static` は定義に書きません。クラスの外の `inline` 関数は、`inline` を外して宣言だけにします。
- cpp の `Class::Func` の定義にカーソルを置いて押すと、ヘッダーの宣言の `;` を本体に置き換えて、cpp の定義を消します。引数の名前が宣言と定義で違うときは、本体が使っている cpp の名前に宣言をそろえて、既定値はヘッダーのまま残します。1 文だけの短い本体は `{ return x_; }` の 1 行にして、コンストラクターの初期化子リストも一緒に移します。
- 置き場所は Alt+R の定義と同じで、同じクラスの前の関数の定義の直後です。
- `template` のクラスの中、`template`・`constexpr`・`friend` の関数、引数の途中に `#if` がある関数、`= 0`・`= default`・`= delete` の宣言には移しません。理由はステータスバーに出ます。
- 本体が使う `#include` は、移した先に足しません。コンパイルで足りないと言われたら、Alt+I で足してください。

電球（Quick Fix）にも「実装を cpp に移す」「実装をヘッダーに移す」が出ます。実際のソース（leveldb・DirectXTK・yaml-cpp・spdlog）のヘッダー関数を cpp に移してから戻して、本体の文字が変わらないことを確かめています。

関数名にカーソルを置いて Alt+Enter を押すと出る「実装を cpp に移す」は、同じ名前の cpp がなければ作って（プロジェクトにも足します）、そこへ移します。cpp には、ヘッダーでそのクラスを囲んでいる namespace の枠（`namespace Prest { ... }`）を作り、枠の中に `Foo::Bar()` と書きます。`Prest::Foo::Bar()` のように、毎回 namespace を付けて修飾する書き方にはしません。すでに cpp に枠があれば、その中に足します。

クラス名の行で Alt+Enter を押すと、次の 2 つも選べます。

- 「コンストラクター・デストラクターを cpp に移す」: すでにヘッダーに書いてあるコンストラクター・デストラクター（`{}` の本体や `= default;`）を、宣言だけにして cpp に移します。`= default` のものは、cpp に `Foo::Foo() = default;` と書きます。
- 「struct にする」: `class` を `struct` に書き換え、デフォルトのコンストラクター・デストラクター（`Foo() = default;`、`Foo() {}`、`~Foo() = default;`、`~Foo() {}`）を消します。先頭の `public:` は要らないので消します。先頭に指定子なしで書いたメンバー（class では private）があれば、private のまま残すために `private:` を足します。ほかのコンストラクターがあるときは、引数なしのコンストラクターを消すと書けなくなるので残します。

生成するコードをクラスに足すときの並びは、コンストラクター → デストラクター → コピー → ムーブ → 関数 → メンバー変数の順に保ちます。`public:` の中にメンバー変数があっても、足した関数は変数より前に入ります。

## #include を整理する・消す

プロジェクトやソリューションを右クリックすると、次の 2 つが出ます。拡張機能 メニューにも同じ項目があります。

- <strong>#include を整理（プロジェクト全体）</strong>。プロジェクトの `.h`・`.cpp` の `#include` を、グループに分けて並べ直します。順番は、自分のヘッダー（`Foo.cpp` なら `Foo.h`）、C の標準（`<stdio.h>`）、C++ の標準（`<vector>`）、そのほかの `<>`、`"..."` の順で、グループの間に空行を入れ、グループの中は名前順にします。同じ行の重複は消します。`#if` の中の `#include` と、`#define` などをはさんで離れている `#include` のまとまりには触りません（まとまりごとに整理します）。`windows.h` のように順番に意味があるものは、`#define` や `#if` でまとまりを分けておくと、そのままです。
- <strong>使っていない #include を消す（プロジェクト全体）</strong>。ヘッダーが定義している名前（クラス・列挙型と値・`using`・`typedef`・マクロ・関数・定数）を、そのヘッダーが `#include` しているものも含めて集めて、cpp が 1 つも使っていなければ、使っていないとみなします。消す前に、一覧を見せて確認します。自分のヘッダー、行に `keep` と書いた `#include`（`// keep`）、`#if` の中の `#include`、場所を探せないヘッダー、名前を 1 つも拾えないヘッダーは、いつも残します。標準のヘッダーは、`<vector>`・`<string>`・`<map>` など、中身が決まっている一部だけを調べます。

使っていない `#include` の削除は、ヘッダーに対しては、設定の「使っていない #include を、ヘッダーからも消す」（初期値は False）を True にしたときだけ行います。ヘッダーの `#include` は、そのヘッダーを include している別のファイルが、間接に受け取っていることがあり、消すとビルドが通らなくなるからです。

整理も削除も、エディターで開いているファイルはエディターの内容を書き換えて（Undo できます）、閉じているファイルはその場で保存します。ファイルのエンコードと BOM は変えません（BOM のない UTF-8 でも読めないときは、Shift-JIS として読みます）。いまのファイルだけを整理するときは、拡張機能 メニューの「このファイルの #include を整理」を使います。

## #include を前方宣言にする

ヘッダーが別のヘッダーを `#include` しているだけで、使っているのはポインターや参照だけ、ということがよくあります。`#include` を前方宣言（`class Scene;`）に置き換えて、`#include` を cpp に移すと、ヘッダーを変えたときに再コンパイルされるファイルが減ります（Alt+D）。

- カーソルが `#include "scene.h"` の行にあれば、その 1 つだけを調べます。行になければ、ヘッダーの `"..."` の `#include` を全部調べます。
- 変えるのは、ポインター（`Scene*`）・参照（`Scene&`）・`std::shared_ptr<Scene>`・`std::weak_ptr<Scene>`・`std::unique_ptr<Scene>` でしか使っていない型だけです。値のメンバー、継承、関数の本体の中での使用が 1 つでもあれば、変えません。理由はステータスバーに出ます。
- 同じヘッダーの型以外の名前（定数・関数・`enum` など）を使っているときも変えません。
- 前方宣言は、`namespace` ごとにまとめて、残りの `#include` の最後のあとに置きます。`template` のクラスは対象にしません。
- `#include` は、同じ名前の cpp に足します（Alt+I と同じ並びのルール）。cpp がなければ、足さずに知らせます。

電球にも、ヘッダーの `#include "..."` の行で「#include を前方宣言にして、cpp に #include を移す」が出ます。

メンバー変数の行（`std::unique_ptr<TCPServer> server_;` など）でも、型がポインター・参照・スマート ポインターの中身で、その名前のヘッダーを `#include` していれば、電球に「TCPServer を前方宣言にする (#include を cpp に移す)」が出ます。その型を定義している `#include` だけを前方宣言にします（`<Prest/Network/TCPServer.h>` のような `<>` の書き方も対象です）。

<strong>unique_ptr のとき</strong>。`std::unique_ptr<Foo>` のデストラクターは、`Foo` の完全な定義を要ります。そのため、ヘッダーに `~Bar() = default;` があると、前方宣言だけではコンパイルが通りません。コンストラクターとムーブも、途中で例外が出たときや代入の前に中身を消すので、同じです。そこで前方宣言にしたとき、`unique_ptr<Foo>` を持つクラスのこれらを、ヘッダーでは宣言（`~Bar();`）だけにし、cpp に `Bar::~Bar() = default;` の形で定義を作ります。デストラクターがなければ、`~Bar();` を足します。処理を書いた本体（`{ … }` の中身があるもの）には触りません。cpp が見つからないときは、定義の置き場がないので、ヘッダーもそのままにします。

前方宣言にしたあと、その名前に自動で `#include` を足し直すことはしません。ヘッダーに `class Foo;` があれば、`Foo` の `#include` は、自動でも電球でも足しません（cpp には、これまでどおり足します）。

## コンストラクター・override・呼び出しから関数を作る

enum に値を足したのに、それを使う `switch` に `case` を足し忘れる。メンバーを足したのに、コンストラクターの初期化リストに足し忘れる。どちらも、書く内容が決まっている作業なので、キーで作ります。

### コンストラクターを作る（Alt+C）

クラスの中（または `class` / `struct` の行）にカーソルを置いて押すと、データ メンバーを全部受け取るコンストラクターを、初期化リストつきで作ります。

```cpp
class Player {
 public:
  Player(const std::string& name, int hp, float speed)
      : name_(name), hp_(hp), speed_(speed) {}
  // ...
 private:
  std::string name_;
  int hp_ = 100;
  float speed_;
};
```

- 引数の名前は、メンバー名から末尾の `_` と先頭の `m_` を取ったものです。
- 引数の型は、組み込みの型・ポインター・参照・`std::string_view` ならそのまま、それ以外は `const T&` にします。`std::unique_ptr` / `std::shared_ptr` は値で受けて `std::move` します。
- メンバーが 1 つだけなら `explicit` を付けます。
- 80 桁に収まらないときは、Google スタイルで折り返します。
- `static`・`mutable`・関数・`using`・ビットフィールド・配列は対象にしません。`int a, b;` のように 1 行に複数のメンバーを書いているときは、作りません。
- 同じ個数の引数のコンストラクターがすでにあるときは、作りません。
- `public:` があればその直後に、なければ（`struct` は先頭に、`class` は `public:` を足して）入れます。

### 基底クラスの仮想関数を override する（Alt+O）

`class Circle : public Shape` のように基底クラスを書いたクラスの中（または `class` の行）で押すと、基底クラスの仮想関数のうち、このクラスにまだないものの `override` 宣言を足します。

```cpp
class Shape {
 public:
  virtual ~Shape() = default;
  virtual void Draw(Renderer& r, int layer = 0) const = 0;
  virtual float Area() const = 0;
  virtual void Update(float dt) {}
};

class Circle : public Shape {
 public:
  void Draw(Renderer& r, int layer) const override;   // ← Alt+O で、この 2 行が入る
  float Area() const override;
  Circle(float r);
};
```

- 純粋仮想関数が残っていれば、それだけを足します（派生クラスを作るのに必須なため）。残りの `virtual`（`Update` など）は、もう一度押すと足します。
- 基底クラスの定義は、いまのファイル、`#include "..."` をたどった先（3 段まで）、ソリューションのヘッダーの索引から探します。基底クラスのさらに基底の仮想関数も対象で、近い基底の宣言を先に使います。
- 引数の既定値（`int layer = 0`）は書きません。仮想関数の既定値は静的な型で決まり、`override` 側に書くと食い違いやすいためです。
- デストラクターと演算子は対象外です。同じ名前で引数の個数が同じ関数がすでにあれば、足しません。
- 入れる位置は、コンストラクターと同じです（`public:` の直後）。cpp の定義は作りません。足したあとで Alt+R（宣言から定義を作る）を押すと、cpp に雛形が入ります。

### 呼び出しから関数を作る（Alt+U）

まだない関数を、先に呼び出しから書く。C# の「使い方から生成」と同じ流れです。呼び出しの行にカーソルを置いて押すと、その関数を作ります。

```cpp
void Player::Update(float dt) {
  int hp = 3;
  std::string name = "a";
  Heal(hp, name, 2.5f, dt);       // ← この行で Alt+U
}
```

- 呼び出しがメンバー関数の中の `Heal(...)` や `this->Heal(...)` なら、そのクラスのメンバーにします。ヘッダーのクラスの末尾に `void Heal(int hp, const std::string& name, float arg3, float dt);` を足し、cpp に `Player::Heal` の定義の雛形（Alt+R と同じ形）を足します。
- `obj.Heal(...)` / `obj->Heal(...)` なら、`obj` の宣言（引数・ローカル変数）から型を読んで、そのクラスの `public:` に足します。`std::unique_ptr<Enemy>` のようなスマート ポインターは中の型を使います。型を決められないときは、何もしません。
- クラスの外（cpp の自由関数の中）なら、いまの関数の前に、中身が `// TODO` の自由関数を足します。
- 引数の型は、リテラル（`2.5f` → `float`、`"a"` → `const char*`）と、同じ関数の中で見える変数の宣言から決めます。組み込みの型・ポインター・参照はそのまま、ほかは `const T&` にします。引数の名前は、変数ならその名前（`m_` と末尾の `_` を除く）、式なら `arg3` のようにします。
- 戻り値の型は、使われ方から決めます。`float x = Foo();` なら `float`、`if (Foo())` や `!Foo()` なら `bool`、`return Foo();` なら囲んでいる関数の戻り値の型、文として呼んでいれば `void`。決められなければ `int` にして、ステータスバーで知らせます。`auto x = Foo();` も `int` になります。
- 型を決められなかった引数（関数の戻り値や、`x + 1` のような式）は `int` にして、ステータスバーに式を出します。
- 同じ名前の関数がそのクラスにすでにあれば、作りません。クラスの外の関数が別のヘッダーにあるかどうかは見ないので、すでにある関数の行で押さないでください。
- cpp がない（ヘッダーだけの）クラスには、`{ return {}; }` の本体つきで足します。

どれも電球（`Alt+Enter`）に出ます（`class` / `struct` の行。呼び出しから関数を作るのは、キーだけです）。1 回の編集なので、Undo も 1 回です。

## switch を打ったら、case を自動で入れる

enum の値を `switch` で受けるたびに、値の名前を 1 つずつ書くのは面倒で、書き忘れもします。`switch (state) {` と打って改行すると、本体が空なら、enum の値ごとの `case` と `default:` を自動で入れます。

```cpp
enum class State { Idle, Walk, Run };

switch (state) {
	case State::Idle:
		break;
	case State::Walk:
		break;
	case State::Run:
		break;
	default:
		break;
}
```

- enum の型は、`switch` の式の変数の宣言から決めます。定義は、いまのファイルと、`#include "..."` をたどった先（2 段まで）から探します。整数の `switch` のように、enum の型が決められないときは、何もしません。
- `enum class` の値は `State::Walk`、昔の `enum` は `Walk` の形で書きます。末尾が `Count`・`Max`・`Num`・`Size` のような「個数を数えるための印」の値は、入れません。
- 字下げは、`switch` の行がタブならタブ、そうでなければファイルで多いほう（判断できなければ空白 2 つ）です。
- 入れるのは、本体が空の `switch` に、改行を打った直後だけです。入れたあとに `Ctrl+Z` を 1 回押せば、消えます。<strong>消した `switch`（本体を自分で消したときも含む）には、もう入れません。</strong>
- 設定の「switch を打ったら、case と default を自動で入れる」で、オフにできます。

## Alt+Enter の電球（ほとんどの機能）

キーを覚えなくても、カーソルを置いて `Alt+Enter`（`Ctrl+.` でも同じです）を押せば、その位置で使える機能が並びます。エディターの右クリックにも「K-Cpp: この位置の書き換え・生成の一覧...」が出ます。キーは今までどおりです。

- メンバー変数の宣言の行: Getter・Setter を作る
- 足りない `#include` のある名前の上: `#include` を足す
- `#include` の行: 前方宣言にする、このファイルの `#include` を整理する、使っていない `#include` を消す
- 宣言していない変数への代入: ローカル変数・メンバー変数として宣言する
- 関数の宣言・定義: 相手を作る、引数を合わせる、本体を移す
- `class` / `struct` の行: 下の「クラス名の上の電球」

### クラス名の上の電球

ヘッダーで `class Foo {` の行（か、クラスの中の空の行、`{` や `};` の行、`public:` などの行）にカーソルを置くと、次が出ます。

- <strong>Foo.cpp を作る</strong>: 同じ名前の cpp がなければ、`#include "Foo.h"` とクラスを囲む namespace だけの cpp を作って、プロジェクトに足します（クラス名の行だけ）。

コンストラクター・デストラクターは、書き方の違う 3 つが並びます。どれも、引数のない `Foo()` と `~Foo()` のうち、まだないほうだけを作ります（仮想関数があれば `virtual ~Foo`）。クラスにコピー・ムーブの宣言があれば、その上に置きます（コンストラクター → デストラクター → コピー → ムーブ の順になります）。

1. <strong>コンストラクター・デストラクターを作る (= default)</strong>: `Foo() = default;` と `~Foo() = default;`。中身の要らないクラスは、これがいちばん短く書けます。
2. <strong>コンストラクター・デストラクターを作る (.h に {} で書く)</strong>: `Foo() {}` と `~Foo() {}`。あとでヘッダーの中に処理を書き足すとき向きです。
3. <strong>コンストラクター・デストラクターを作る (.h に宣言、.cpp に定義)</strong>: ヘッダーに `Foo();` と `~Foo();` を書き、cpp（なければ作ります）に `Foo::Foo()` と `Foo::~Foo()` の定義を作ります。cpp に namespace の枠（`namespace Prest { }`）があれば、その中に `Foo::Foo()` と書きます（枠の外に `Prest::Foo::Foo()` とは書きません）。

- <strong>メンバーからコンストラクターを作る</strong>: データ メンバーを引数で受け取るコンストラクターを作ります（上の 3 つのすぐ下に出ます）。
- <strong>pimpl にする (実装を cpp の Impl に移す)</strong>: 次の節。

### pimpl にする {#pimpl}

クラスの private のメンバーを変えるたびに、そのヘッダーを `#include` しているファイルが全部コンパイルし直しになります。メンバーを cpp の中の構造体に移して、ヘッダーにはポインター 1 つだけを残すと、メンバーを変えても cpp 1 つのコンパイルで済みます。この形を pimpl（pointer to implementation）と呼びます。

ヘッダーのクラスの上で「pimpl にする」を選ぶと、次のように書き換えます。

1. ヘッダーの private のデータ メンバーを消し、そこに `struct Impl;` と `std::unique_ptr<Impl> impl_;` を置きます。`#include <memory>` がなければ足します。protected のメンバーは、派生クラスが使うかもしれないので残します。
2. cpp に `struct Foo::Impl { … };` を作り、消したメンバーを初期化子ごと移します。置き場所は、`Foo::` の最初の定義の前（同じ namespace の中）です。
3. cpp の `Foo::` の関数の本体で、移したメンバーを `impl_->hp_` に書き換えます（`this->hp_` も同じ）。`other.hp_` や `p->hp_` のような、ほかのオブジェクトのメンバーには触りません。
4. コンストラクターは `impl_(std::make_unique<Impl>())` で Impl を作ります。初期化子リストで決めていたメンバー（`hp_(50)`）は、本体の先頭の代入（`impl_->hp_ = 50;`）に変えます。コンストラクターがなければ、`Foo();` を宣言して cpp に定義を作ります。
5. デストラクターとムーブは、`unique_ptr<Impl>` の決まり（前の節）どおり、cpp に `= default` で定義します。

ヘッダーに本体を書いた関数（`int GetHp() const { return hp_; }`）が、移すメンバーを使っているときは、書き換えません。ヘッダーの中では `Impl` が不完全な型なので、`impl_->hp_` と書けないためです。先に「実装を cpp に移す」で cpp に移してから、もう一度選んでください。参照や `const` のメンバーを初期化子リストで決めているときも、代入に直せないので、書き換えずに知らせます。どちらのファイルも、エディターの文字を書き換えるだけで、保存はしません（ファイルごとに Ctrl+Z で戻せます）。
- <strong>コピー・ムーブを禁止する</strong>: コピー・ムーブのコンストラクターと代入演算子を `= delete` で宣言します。これと「コピー禁止・ムーブ可にする」は、クラス名の行に加えて、クラスの中の空の行、`{` や `};` の行、`public:` などの行でも出ます。メンバー変数や関数の行では、その行への操作と紛れないように、クラス全体を作り変える項目（コピー・ムーブ、`==` と `<=>`、formatter、hash、Natvis など）を出しません。

`public:` のないクラス（`class X { int a_; };` のように、指定子を書いていないもの）に宣言を足すときは、クラスの先頭に `public:` を作って宣言を置き、その下に `private:` を足します。もとからあったメンバーは、private のままです。

## 新しいファイルのひな形

プロジェクトに新しく足した<strong>空のファイル</strong>を開くと、ひな形を書きます（作ってから 2 分以内の、空のファイルだけ。昔からある空のファイルには触りません）。

ヘッダーには、次の形を書きます。クラス名は、初期値ではファイル名と同じです。初期値では namespace の中を 1 段字下げし、閉じる `}` にはコメントを付けません。コンストラクターとデストラクターは `= default` で書いておきます。

```cpp
#pragma once

namespace Prest {

    class GameObject {
    public:
        GameObject() = default;
        ~GameObject() = default;
    };

}
```

cpp には、同じ名前のヘッダーがあれば `#include "GameObject.h"` と、namespace の枠だけを書きます。

<strong>VS の「クラスの追加」</strong>（プロジェクトを右クリック → 追加 → クラス）で作ったファイルも、同じ形に書き直します。VS は `#pragma once` と `class X { };`、`#include "X.h"` と空のコンストラクター・デストラクターを書くので、空のファイルではありません。作ってから 2 分以内で、VS が書いたままの形（手で書き足していない）のときだけ書き直します。クラス名、基底クラス、`#include`、コンストラクター・デストラクターは引き継ぎ、namespace・字下げ・`{` の位置を、このページのひな形にそろえます。

プロジェクトの「強制インクルード ファイル」（`/FI`）に `pch.h` があると、VS が cpp に書く `#include "pch.h"` は要りません。設定の「強制インクルードにある pch の #include を書かない」（初期値は True）で、書き直すときに消します。

namespace と字下げは、ソリューションの既存のヘッダー（新しく作るファイルに近いフォルダーのものを先に、最大 300 個。`ThirdParty`・`external`・`vendor` など、外部ライブラリを置くフォルダーは除く）を調べて、一番多いものを使います。行頭の `namespace X {` を数えるので、`std` は数えません。字下げは、タブと空白のどちらが多いかを見て、空白なら 2 か 4 を選びます。判断できなければ、タブにします。

設定（ツール → オプション → K-CppUltimateAssist → 新規ファイル）で、次を変えられます。

- ひな形を書くかどうか。ヘッダーに `class` を書くかどうか。
- class にコンストラクター・デストラクターを `= default` で書くかどうか（初期値は書く）。VS の「クラスの追加」で作ったクラスにも書きます。VS がすでにコンストラクター・デストラクターを書いていれば、そちらを残します。
- クラス名の決めかた: ファイル名のまま（初期値）、PascalCase（`game_object` → `GameObject`）、SnakeCase（`GameObject` → `game_object`）、CamelCase（`game_object` → `gameObject`）。
- namespace: 既存のヘッダーから決める（初期値）、固定の名前、書かない。
- 字下げ（自動・タブ・空白 2・空白 4）と、namespace の中を字下げするかどうか（初期値は字下げする）。
- `#pragma once` かインクルード ガードか。
- namespace を閉じる行に `}  // namespace X` のコメントを付けるかどうか（初期値は付けない）。
- 強制インクルード（`/FI`）にある pch の `#include` を書かないかどうか（初期値は書かない）。

電球や Alt キーで作るコード（コンストラクター、Getter・Setter、`std::formatter` など）にはコメントを付けません。字下げ（タブ・空白 2・空白 4）と `public:` の位置（クラスと同じ位置か、Google スタイルの 1 字下げか）は、そのファイルの書き方から決めます。ファイルに手がかりがないときは、タブと、クラスと同じ位置の `public:`（VS の既定）にします。

## 書き換えと生成（Ctrl+.・Alt+X）

C# では `Ctrl+.` を押すと「if を反転する」「== を作る」のような小さな書き換えが並び、選ぶだけでコードが変わります。C++ の Visual Studio にも電球はありますが、出てくる項目は C# よりずっと少なめです。K-CppUltimateAssist はゲームの C++ でよく手で書く形を、電球の項目として足します。

カーソルを置いて `Ctrl+.` を押すとその位置で使えるものだけが出ます。Alt+X を押すと同じ項目を一覧の窓で選べます。どれもいまの文字で計算し直してから書き換えるので電球を出したあとに打った文字も反映されます。1 つのファイルの書き換えは 1 回の Undo で戻ります。

| 置く場所 | 出る項目 |
|---|---|
| [行の書き換え](#kca-line) | NULL → nullptr、typedef → using、C のキャスト、範囲 for、if の反転、早期 return、auto |
| [デバッグ出力](#kca-dbg) | 変数を出力する行を足す、まとめて消す |
| [クラスの中](#kca-class) | コピー禁止、== と <=>、formatter、hash、JSON、cereal、Natvis |
| [enum の上](#kca-enum) | ToString と FromString |
| [頂点・定数バッファ](#kca-d3d) | 入力レイアウト、HLSL の 16 バイト境界 |
| [ファイルをまたぐもの](#kca-files) | 定義をまとめて作る、クラスを別ファイルへ、初期化子の並べ替え |

### 行の書き換え {#kca-line}

古い書き方を今の C++ に直すものと、制御の形を変えるものです。どれもカーソルの行だけを見ます。

<strong>NULL を nullptr にする。</strong>行の中の `NULL` を `nullptr` にします。電球には「ファイル全体」の項目も並びます。`NULL` は `0` と同じ整数なので、`f(int)` と `f(int*)` のオーバーロードがあると `f(NULL)` は `int` の方を呼びます。`nullptr` はポインターにしかならないので、この取り違えが起きません。コメントと文字列の中の `NULL` は変えません。

<strong>typedef を using にする。</strong>`typedef std::map<int, Enemy> Table;` を `using Table = std::map<int, Enemy>;` にします。関数ポインターの `typedef void (*Callback)(int);` は `using Callback = void (*)(int);` になります。名前が左に来るので長い型でも何の別名かを先に読めます。`typedef struct { … } X;` のように複数行にまたがるものは対象外です。

<strong>C のキャストを static_cast にする。</strong>`(float)a / b` を `static_cast<float>(a) / b` にします。キャストは割り算より強く結び付くので、元の式でも変換されるのは `a` だけです。書き換えたあとも意味は同じで、どこまでが変換の対象かが括弧で見えるようになります。対象は数の型（`int` `float` `UINT` `size_t` など）だけです。ポインターのキャストは `static_cast` と `reinterpret_cast` のどちらが正しいかを文字だけでは決められないので変えません。`sizeof(int)` や `f(int)` の宣言はキャストではないので飛ばします。

<strong>添字の for を範囲 for にする。</strong>次の形の `for` で押します。

```cpp
for (size_t i = 0; i < enemies_.size(); ++i) {
  enemies_[i].Update(dt);
}
// ↓
for (auto& enemy : enemies_) {
  enemy.Update(dt);
}
```

要素の名前は入れ物の名前の単数形です（`enemies_` → `enemy`、`boxes` → `box`）。本体で `i` を `enemies_[i]` 以外に使っていれば断ります（番号が要る処理なので）。本体で `push_back` や `erase` をしているときも断ります。範囲 for の中で要素を足し引きすると反復子が無効になって落ちるからです。

<strong>if を反転する。</strong>`if (hp > 0) { A } else { B }` を `if (hp <= 0) { B } else { A }` にします。比較が 1 つなら演算子を裏返し（`<` → `>=`）、`!IsAlive()` は `IsAlive()` にします。`a && b` のような組み合わせは `!(a && b)` で包みます。ド・モルガンで展開すると読みにくくなることが多いためです。

<strong>早期 return にする。</strong>関数の最後の文が `if (alive_) { … }` のとき、`if (!alive_) return;` にして本体を 1 段浅くします。ループの最後の文なら `continue;` にします。戻り値のある関数では何を返すかを決められないので断ります。`else` のある `if` と、後ろに文が続く `if` も対象外です（意味が変わるため）。

<strong>型を auto にする。</strong>右辺に同じ型がそのまま書いてあるときだけ `auto` にします。`std::unique_ptr<Enemy> e = std::make_unique<Enemy>();`、`Enemy* e = new Enemy;`、`static_cast<float>(n)`、`v.begin()` を受ける反復子が対象です。`float x = 1;` は `auto` にすると `int` に変わってしまうので出しません。

### デバッグ出力 {#kca-dbg}

`hp_ -= damage;` のような行で選ぶと、次の行に値を出力ウィンドウへ書く文を足します。

```cpp
hp_ -= damage;
OutputDebugStringA(std::format("{}({}): hp_ = {}\n", __FILE__, __LINE__, hp_).c_str());  // KDBG
```

`ファイル(行): ` の形で書くので出力ウィンドウでその行をダブルクリックするとソースの行へ飛べます。`std::println` ではなく `OutputDebugStringA` を使うのは、ウィンドウのゲームにはコンソールがないからです。`<format>` がなければ足し、`<Windows.h>`（か `pch.h`）がなければそれも足します。値が `std::format` で書けない型（自作のクラスなど）だとビルドエラーになります。その型に下の「std::format で書けるようにする」を使うと通ります。

足した行には `// KDBG` の印が付きます。電球の「デバッグ出力の行をすべて消す」でファイルの中の印つきの行をまとめて消せるので、調べ終わったあとに消し忘れません。

### クラスの中 {#kca-class}

クラスか構造体の中（か `struct X {` の行）にカーソルを置くと出ます。クラスの本体を読んでデータ メンバーを集め、決まった形のコードを作ります。

<strong>コピー禁止・ムーブ可にする。</strong>テクスチャーやバッファのように資源を持つクラスをコピーすると 2 つのオブジェクトが同じ資源を解放してしまいます。この項目はコピー コンストラクターとコピー代入を `= delete` にし、ムーブの 2 つを `noexcept = default` にします。`noexcept` を付けるのは、`std::vector` が要素を移すときに `noexcept` でないムーブを使わずコピーしようとするからです。コピー コンストラクターを宣言すると暗黙の既定コンストラクターが消えるので、コンストラクターを書いていないクラスには `X() = default;` も足します。仮想関数のあるクラスには `virtual ~X() = default;` も足します。

<strong>全部 = default で書く。</strong>上と同じ場所に、コピー・ムーブ・デストラクターを `= default` で並べます。何もしないのと動きは同じですが、「わざとコピーできるようにしている」ことが読む人に伝わります。すでに宣言してあるものは足しません。

<strong>== と &lt;=&gt; を作る。</strong>`bool operator==(const X&) const = default;` と `auto operator<=>(const X&) const = default;` を足します（C++20）。`==` から `!=` が、`<=>` から `<` `<=` `>` `>=` が作られます。メンバーの中に比較のない型があると、`= default` は「削除された」扱いになり使ったときにエラーになります。

<strong>std::format で書けるようにする。</strong>`std::formatter<X>` の特殊化を、クラスを囲む `namespace` の後ろに足します。`XMFLOAT3` や `Vector3` のメンバーは成分（`x` `y` `z`）に分け、ポインターはアドレスにし、配列は `std::span` にして範囲の書式で出します。`std::println("{}", hit);` が `{pos=(1, 2, 3), damage=5, ids=[1, 2, 3]}` になります。private のメンバーは外の `formatter` から読めないので public のものだけを入れます。

<strong>std::hash を作る。</strong>`std::unordered_map` のキーにするための `std::hash<X>` を足します。メンバーごとの `std::hash` を `boost::hash_combine` と同じ式で混ぜます。キーには `==` も要るので、なければ上の「== と <=> を作る」も使ってください。

JSON・cereal・Natvis の 3 つは、設定の「… の項目を出す」を True にしたときだけ出ます（初期値は出しません）。

<strong>JSON に読み書きできるようにする。</strong>`NLOHMANN_DEFINE_TYPE_INTRUSIVE(Save, level, name)` をクラスの中に足し、`<nlohmann/json.hpp>` を足します。クラスの中に書くので private のメンバーも入ります。ポインターと参照のメンバーは保存できないので入れません。キーが足りない JSON を読むと例外になります。

<strong>cereal で保存できるようにする。</strong>`template <class Archive> void serialize(Archive& ar)` を足し、メンバーを `CEREAL_NVP` で並べます。cereal は 1 つの関数で保存と読み込みの両方を済ませます。`std::vector` などを持つときは `cereal/types/vector.hpp` の `#include` も要ります。

<strong>デバッガーの表示 (Natvis) を作る。</strong>プロジェクトのフォルダーに `プロジェクト名.natvis` を作り（あれば書き足し）、プロジェクトに足します。ウォッチやホバーでクラスが `{x=1, v={ size=3 }}` のように 1 行で見えます。メンバーは先頭から 4 つまでです。同じ型の項目がすでにあれば置き換えます。Natvis はデバッグを始め直すと効きます。

### enum の上 {#kca-enum}

`enum` か `enum class` の行で押すと、値を名前の文字にする `ToString` と、文字から値に戻す `XxxFromString` を足します。

```cpp
enum class Weapon { kSword, kBow };

constexpr std::string_view ToString(Weapon value) {
  switch (value) {
    case Weapon::kSword: return "kSword";
    case Weapon::kBow: return "kBow";
  }
  return "?";
}
constexpr std::optional<Weapon> WeaponFromString(std::string_view text) { … }
```

`switch` に `default` を書かないのは、値を足したのに `ToString` を作り直し忘れたときにコンパイラーが警告（C4062）で教えてくれるからです。`kFirst = kSword` のような別名は `case` が重なるので入れません。クラスの中の `enum` には `static constexpr` で足します。

### 頂点・定数バッファ {#kca-d3d}

<strong>入力レイアウトを作る。</strong>頂点の構造体の中で押すと、`D3D11_INPUT_ELEMENT_DESC`（ファイルに `d3d12.h` があれば `D3D12_INPUT_ELEMENT_DESC`）の配列を構造体のすぐ後ろに足します。

```cpp
struct Vertex {
  XMFLOAT3 position;
  XMFLOAT3 normal;
  XMFLOAT2 uv;
};
inline constexpr D3D11_INPUT_ELEMENT_DESC kVertexInputLayout[] = {
    {"POSITION", 0, DXGI_FORMAT_R32G32B32_FLOAT, 0, offsetof(Vertex, position), D3D11_INPUT_PER_VERTEX_DATA, 0},
    {"NORMAL", 0, DXGI_FORMAT_R32G32B32_FLOAT, 0, offsetof(Vertex, normal), D3D11_INPUT_PER_VERTEX_DATA, 0},
    {"TEXCOORD", 0, DXGI_FORMAT_R32G32_FLOAT, 0, offsetof(Vertex, uv), D3D11_INPUT_PER_VERTEX_DATA, 0},
};
```

形式はメンバーの型から（`XMFLOAT3` → `R32G32B32_FLOAT`）、意味名はメンバーの名前から（`pos` `position` → `POSITION`、`normal` → `NORMAL`、`color` → `COLOR`、それ以外 → `TEXCOORD` に番号）決めます。名前から決めた意味名が違っていたら直してください。位置は `D3D11_APPEND_ALIGNED_ELEMENT` ではなく `offsetof` で書くので構造体に詰め物が入っても C++ の並びと食い違いません。上のコメントに、頂点シェーダーの入力の構造体（`float3 position : POSITION;` …）の形も書きます。シェーダーと C++ の意味名・順番が合わないと、`CreateInputLayout` が失敗するか、頂点がでたらめな位置に描かれます。

<strong>定数バッファの並びを HLSL に合わせる。</strong>HLSL の定数バッファは 1 つのメンバーが 16 バイトの境界をまたがないように詰めます。C++ の構造体はそうしないので同じ順に書いても位置がずれることがあります。

```cpp
struct Cb {
  XMFLOAT4X4 world;   // 0〜63
  XMFLOAT3 light;     // 64〜75
  float pad0;         // ← 足す。HLSL の color は 80 から始まる
  XMFLOAT3 color;     // 80〜91（足さないと C++ では 76 から）
  float power;        // 92〜95
};
static_assert(sizeof(Cb) % 16 == 0, "定数バッファの大きさは 16 の倍数にする");
```

`light` の後ろの空きは 4 バイトで、`color` の 12 バイトは入りません。HLSL は `color` を次の 16 バイトの頭（80）に置きますが、C++ は 76 に置きます。このずれがあるとシェーダーで読む色が 4 バイトずれた値になり、画面の色や明るさがおかしくなります。この項目は HLSL の規則で各メンバーの位置を数え、足りない所に `float padN;` を足し、全体を 16 の倍数にそろえて、`static_assert` を足します。行列と配列は 16 バイトの境界から始まるとして数えます。

`bool` は C++ で 1 バイト、HLSL で 4 バイトなので断ります（`uint32_t` か `BOOL` に）。`float w[4];` のような配列も断ります。HLSL の配列は要素ごとに 16 バイトに広がるので、詰め物では並びを合わせられないからです（`XMFLOAT4` の配列に）。

### ファイルをまたぐもの {#kca-files}

<strong>定義のない関数を cpp にまとめて作る。</strong>ヘッダーのクラスの中で押すと宣言だけで cpp に定義のない関数を全部探して、cpp に雛形を作ります。Alt+R を 1 つずつ押すのと同じ形です。`= 0` `= default` `= delete`、`friend`、`constexpr`、テンプレートは対象外です。

<strong>クラスを 名前.h / .cpp に移す。</strong>C# の「型を一致するファイルへ移動」にあたります。ヘッダーに複数のクラスがあるとき、カーソルのクラスを `クラス名.h` へ移し、元のヘッダーには `#include "クラス名.h"` を足します。同じ名前の cpp に `クラス名::関数` の定義があれば、`クラス名.cpp` へ移します。新しいファイルにはどちらも元のファイルの `#include` を写し、`namespace` も同じもので囲みます。使っていない `#include` はあとで「このファイルの #include を整理」で消してください。新しいファイルはプロジェクトに足します（フィルターの中ではなく、プロジェクトの直下に入ります）。テンプレートのクラスと入れ子のクラスは移しません。新しいファイルはディスクに書きますが、元のファイルの編集は保存しないので、Undo で戻すときは新しいファイルを手で消してください。

<strong>初期化子リストを並べ替える。</strong>メンバーは初期化子リストに書いた順ではなくクラスで宣言した順に初期化されます。`A() : b_(1), a_(b_)` と書くと、`a_` が先に初期化されてまだ値の入っていない `b_` を読みます（警告 C5038）。この項目は初期化子をメンバーの宣言の順に並べ替えます。基底クラスの初期化子は先頭のままにします。cpp のコンストラクターでもヘッダーのクラスの宣言を読んで並べ替えます。

### 確かめたこと

生成するコードのうち `ToString`、`std::formatter`、`std::hash`、`==` と `<=>`、コピー禁止、入力レイアウト、定数バッファの詰め物は、MSVC（Visual Studio 2026、`/std:c++latest /W4`）でコンパイルして、警告なしで通ることと実行の結果を確かめました。JSON と cereal はライブラリを入れていないのでコンパイルしていません。

## 呼び出しの引数をビルド前にチェックする（自動）

`std::make_unique<SwapChain>(a, b, c)` のように、**引数の個数がどのコンストラクターにも合わない**呼び出しに、ビルドの前に、エディターで赤い波線を引きます。波線にカーソルを置くと、「`SwapChain` のコンストラクターに 3 個の引数を受け取るものがありません」と、候補のコンストラクターが出ます。

- **調べる呼び出し。** `std::make_unique<T>(…)`、`std::make_shared<T>(…)`、`new T(…)`。入力が止まって 0.7 秒たつと調べます（設定で変えられます）。
- **コンストラクターの探し方。** `T` がいまのファイルで定義されていればそれ、なければソリューションのヘッダーの索引で 1 つに決まるヘッダーから読みます。ヘッダーを編集中（保存前）でも、エディターの内容で調べ、ヘッダーを直すと開いている cpp の波線もやり直します。既定の引数と、`...`（可変長）は数えます。
- **波線の位置。** 引数が多いときは、余った引数から。足りないときは、`( )` 全体です。入力中の呼び出しには、「足りない」とは言いません（まだ打っている途中のため）。キャレットが外へ出ると出ます。
- **確実なものだけ出します。** 個数だけを見て、型の違い（`const`・暗黙の変換・参照）は見ません。次のクラスは、調べません: コンストラクターを書いていないクラス（集成体）、テンプレートのクラス、`using Base::Base;` で継承したコンストラクターのあるクラス、マクロが書かれているクラス、定義が 1 つに決まらないクラス、`std::` の型。1 個だけ渡していて、リテラルでなければ、コピー・ムーブかもしれないので出しません。引数の中に `...`（パック展開）があるときも出しません。
- **間違って出るとき。** 設定の「調べないクラス」に、そのクラスを書くと出なくなります。「波線の色」を Warning にすると、緑の波線（警告）になります。設定の True / False で、全体も `make_unique` / `new` も切れます。

この波線は、エディターだけのものです。エラー一覧には出ず、ビルドの結果にも影響しません。型の違いまで知りたいときは、ビルド後のエラーログ（下）が、呼び出しの行と候補のコンストラクターを並べます。

## ファイル名をまとめて変える（Alt+N・自動）

ヘッダー（`Foo.h`）か cpp（`Foo.cpp`）の名前を変えたとき、ほかに直す所を、まとめて直します。

- **相手のファイル。** `Foo.h` を `Bar.h` にすると、同じフォルダーの `Foo.cpp`（`.cc` `.cxx`）も `Bar.cpp` にします。cpp を変えたときは、`Foo.h`（`.hpp` `.hh` `.hxx`）も同じです。新しい名前がすでに使われているときは、相手には触れません。プロジェクトに入っているファイルは、プロジェクトごと名前を変えます。
- **`#include`。** ソリューションの全ファイルの `#include "Foo.h"` を、`#include "Bar.h"` に直します。別のフォルダーへ移したときは、パスも直します（`<Prest/Network/TCPServer.h>` → `<Prest/Memory/TCPServer.h>`）。`<>` の書き方の基準には、プロジェクトの「追加のインクルード ディレクトリ」も使います。フォルダーつき（`"core/Foo.h"`）も、フォルダーを保ったまま直します。指しているのが、本当に名前を変えたファイルかを確かめます。コンパイラと同じ順（そのファイルのフォルダー、プロジェクトの `#include` の基準）で探して、同じ名前の別のファイルには触れません。
- **CMake。** `CMakeLists.txt` と `.cmake` の `src/Foo.cpp` なども直します（`MyFoo.cpp` や `Foo.cpp.in` のように、名前の一部だけが同じものには触れません）。直したあとは、CMake の再構成が要ります。
- **文字コード。** エディターで開いていないファイルは、元の文字コード（UTF-8、BOM つき UTF-8、シフト JIS）のまま書き換えます。開いているファイルは、エディターの文字を書き換えます（Undo できます。保存はしません）。

**自動で動きます**（設定の「ヘッダー・cpp の名前を変えたときのしかた」が `Auto`、初期値）。Alt+N を押す必要はありません。名前を変えたことを、次の 2 つで見つけます。

- **Solution Explorer** での名前変更（F2）。
- **フォルダーの監視**。フォルダー ビュー（CMake）、エクスプローラー、`git mv`、別のツールでの名前変更も見つけます。ヘッダーと cpp どうしの名前変更だけを見て、保存の一時ファイルなどは見ません。
- **まとめて動かしたとき**。Solution Explorer で範囲選択して、いくつものファイルを一度に動かした（名前を変えた）ときは、1 つのダイアログで「全部に反映するか」を聞きます。Solution Explorer からの操作は、件数が多くても一括の操作（git）とはみなしません。
- **フォルダーの名前の変更と移動**。ディスクのフォルダー（`Render` → `Draw`）の名前を変えたり、別の場所に移したりすると、中のファイルを `#include` している所（`"Render/Mesh.h"` → `"Draw/Mesh.h"`）と CMake のパスを直すか聞きます。C++ のプロジェクトの「フィルター」は、ディスクのフォルダーではないので、名前を変えても何もしません。

次の場合は、自動では直しません。

- **一括の操作。** 3 秒の間に、設定の件数（初期値 4）より多くの名前変更が起きたときは、git のブランチ切り替えなどとみなして、何もしません（ステータスバーで知らせます）。
- **取り消された変更。** 通知のあと、元に戻された・すでに別の名前になったときは、何もしません。
- **自分で変えた名前。** K-CppUltimateAssist が名前を変えたファイル（相手のファイル、Ctrl+R, R のあとに変えたファイル名）は、変える前に覚えておき、その変更をもう一度「名前が変わった」とは見つけません。

<strong>確認のダイアログ</strong>。名前が変わると、何を何に直すかを見せて、項目ごとにチェックで選べます。見出しは、変わったものに合わせます（「ヘッダーの名前が変わりました」「cpp の名前が変わりました」「ファイルを別のフォルダーに移しました」「フォルダーの名前が変わりました」など）。

1. 「相手のファイル・`#include`・CMake も直す」。`Foo.cpp → Bar.cpp` と `#include "Foo.h" → #include "Bar.h"` を並べて見せます。
2. 「クラス名も直す」。ヘッダーのクラス（ファイル名と同じ名前のもの。なければ最初のクラス）を、新しいファイル名から決めた名前（`Foo` → `Bar`）に直します。ファイル名とクラス名が元から食い違っていたときは、そう書いて、チェックを外した状態で出します。直すのは、コード全体の同じ名前の単語です（`FooBar` や `m_Foo` には当たりません）。

ダイアログの左下の「次から確認しない」（初期値は印なし）に印を付けて「反映する」を押すと、設定の「直す前に確認する」が False になって保存されます。それからは、ダイアログを出さずに、ダイアログの初期値どおりに直します。相手のファイル・`#include`・CMake は直し、クラス名はファイル名と同じだったときだけ直します。Ctrl+R, R でクラス名を変えたときも同じで、ファイル名がクラス名と同じだったときだけ、ファイル名を直します。設定を True に戻すと、またダイアログが出ます。

逆に、VS の「名前の変更」（Ctrl+R, R）でクラス名を変えたときは、ヘッダーのクラスが 1 つだけ別の名前になったことを見つけて、「ファイル名・相手のファイル・`#include`・CMake も直しますか?」と聞きます（ファイル名がクラス名と同じだったときは、チェックを入れて出します）。

<strong>ファイル名とクラス名の書き方</strong>。新しい名前は、古いファイル名と古いクラス名の関係を見て、同じ書き方で作ります。Google スタイル（`game_object.h` に `class GameObject`）で `GameObject` を `GameEntity` にすると、ファイル名は `game_entity.h` です。ファイル名を `game_entity.h` にしたときは、クラス名を `GameEntity` にします。Unreal の `APlayerController`（`PlayerController.h`）や MFC の `CPlayer`（`Player.h`）のような、大文字 1〜2 字の接頭辞も対応とみなして、接頭辞を保ちます。

**Alt+N** は、開いているヘッダー（か cpp）の新しい名前（拡張子なし）を入力欄で決めて、同じことを行います（自動を切っているとき用です）。

Alt+N で名前を変えるのは、ファイルだけです。インクルード ガード（`FOO_H`）とファイルの中の文字は、直しません。

## ファイルの文字コードをそろえる

人から受け取ったファイルが Shift-JIS で、自分で作ったファイルは UTF-8、というプロジェクトはよくあります。混ざったままだと、日本語のコメントや文字列が、ファイルによって文字化けします（理由は [ソースファイルの文字コードと強制](../encoding/source-files.md)）。1 つずつ「名前を付けて保存」で直すのは手間なので、まとめてそろえるコマンドを用意しました。

拡張機能 メニューの「K-Cpp: ファイルの文字コードをそろえる...」を押すと、設定の画面が開きます。ソリューション エクスプローラーでプロジェクトかソリューションを右クリックしても出ます。

1. <strong>対象を選びます。</strong> 選択中のプロジェクト、ソリューションのすべてのプロジェクト、ソリューションのフォルダー全体（プロジェクトに入っていないファイルも含む。CMake のフォルダーを開いているときはこちら）の 3 つです。拡張子は `.h;.cpp;.hlsl` のように `;` で区切って変えられます。
2. <strong>文字コードと改行を選びます。</strong> 文字コードは UTF-8（BOM 付き）、UTF-8（BOM なし）、Shift-JIS の 3 つです。改行は「そのまま」「CRLF」「LF」から選びます。
3. <strong>「調べる」を押します。</strong> ファイルごとに、いまの文字コード・改行・することが一覧に出ます。ここではまだ何も書き換えません。行をダブルクリックすると、そのファイルが開きます。「一覧をコピー」で表にして貼れます。
4. <strong>「変換する」を押します。</strong> 件数を確かめる画面が出て、はいを押すと書き換えます。開いていないファイルはそのまま保存するので、Ctrl+Z では戻せません。戻すときは Git などを使います。

迷ったら UTF-8（BOM 付き）を選びます。Visual Studio も MSVC も、BOM を見て UTF-8 と分かるので、設定がいりません。BOM なしの UTF-8 は Git や他のエディターと相性がよいのですが、MSVC は BOM のないファイルを Shift-JIS として読みます。そのため、画面の「BOM なし UTF-8 のとき、プロジェクトに /source-charset:utf-8 を付ける」（初期値はオン）で、`.vcxproj` のすべての構成の「追加のオプション」に `/source-charset:utf-8` を足します。`/utf-8` ではなくこちらを使うのは、`/utf-8` が文字列リテラルの文字コードまで UTF-8 に変えて、`MessageBoxA` などに渡す日本語が化けることがあるためです。CMake のプロジェクトには足せないので、`add_compile_options(/source-charset:utf-8)` を自分で書きます。

画面のそのほかの選択肢は、次のとおりです。

- <strong>.editorconfig に書く</strong>（初期値はオン）。ソリューションのフォルダーの `.editorconfig` に、選んだ拡張子の節（`[*.{h,cpp}]`）を作り、`charset` と `end_of_line` を書きます。同じ見出しの節があれば、その 2 つのキーだけを書き換えます。Visual Studio は保存するときにこの設定を使うので、新しく作ったファイルもそろいます。Shift-JIS は `.editorconfig` の規格にないので、そのときは改行だけを書きます。
- <strong>開いている未保存のファイルを、先に全部保存する</strong>（初期値はオン）。オフにすると、未保存のファイルは「未保存なので飛ばす」になります。保存していない編集を、あとから保存で上書きしないためです。
- <strong>変換が要るファイルだけ一覧に出す</strong>（初期値はオン）。

変換しないファイルもあります。Shift-JIS にない文字（絵文字、ハングル、一部の記号）を含むファイルを Shift-JIS にするときは、その文字を一覧に出して飛ばします。中に 0 のバイトがあるファイル（バイナリ）と、8 MB を超えるファイルも飛ばします。文字コードの判定は、BOM、厳密に読める UTF-8、Shift-JIS の順です。ASCII だけのファイルは、BOM なし UTF-8 とも Shift-JIS とも同じバイト列なので、BOM 付きを選んだときだけ変換します。

開いているファイルは、変換したあと Visual Studio が読み直します。「再読み込みしますか」と聞かれたら、はいを押します。

## エラーログ（K-ErrorLog）

C++ のビルドエラーを、**色つきの専用ログ窓**に整理して出します。「出力」ウィンドウのとなりにタブで並びます。ビルドが終わると、エラーがあるときだけ前に出ます（入力の邪魔はしません）。拡張機能 メニューの「K-ErrorLog (エラーログ)を開く」から、いつでも開けます。

- **未解決の外部シンボル（LNK2019 / LNK2001）を、原因ごとにまとめる。** 同じシンボルを 1 つにして、起動関数がない・`.lib` が足りない（ビット数違いや `dllimport` の食い違いも指摘）・Windows / DirectX の `.lib`・vtable や static メンバーの定義漏れ・定義はあるのにリンクされていない、などを判定し、何をすれば直るかまで書きます。`.lib` はソリューションの下を読み（シンボルの索引だけを読むので速い）、定義の探索はソースの文字列検索です。**推測**なので、「原文」表示と見比べてください
- **そのほかのリンカー エラー。** `LNK2005`（二重定義）、`LNK2038`（`RuntimeLibrary` や `_ITERATOR_DEBUG_LEVEL` の不一致を並べて表示）、`LNK1104` / `LNK1181` など
- **テンプレートのエラーを読みやすくする。** `std::basic_string<char, …>` → `std::string`、`std::unique_ptr<T, std::default_delete<T>>` → `std::unique_ptr<T>` のように型名を短くし、渡した型と期待する型を 2 行に並べ、テンプレート引数を 1 行ずつに分けます
- **原因の場所と経路。** エラーが `<memory>` の中で出ていても、自分のコードの呼び出し行を探してリンクにします。「see reference to function template instantiation … being compiled」の連なりは、自分のコードの行を強調し、ライブラリの中の段は畳みます（「経路を全部表示」で展開）。オーバーロードの候補と落ちた理由（`C2672`、`C2784` など）も並べます
- **読みやすさのための案内。** エラーが複数あるときは、先頭に「まず一番上のエラーから直す」と出します。同じ原因から続いているエラーには「連鎖の可能性」と書き、原因の候補（上のエラー）へのリンクを出します（未定義の名前を含むエラー、同じファイルの構文エラーより後ろのエラー）。名前入りの説明（`「GraphicsModule」は、この場所から見えていません…`）と、直し方の例（修正前と修正後のコード）が付くコードもあります。ヒントがあるコードは約 220 個で、ないコードにも「公式のページで調べる」案内が出ます
- **警告がエラーになっているとき（C2220）。** `/WX` で、警告がエラー扱いになっています。原因の警告を、リンクつきで並べます
- **二重定義（LNK2005）。** 変数なら「ヘッダーに `extern` なしで書いた」、関数なら「`inline` なしで本体を書いた」と、原因を分けて説明します
- 主なエラー コードに、日本語の見出しとヒントを付けます。日本語バージョン・英語バージョンの Visual Studio の出力と、GCC / Clang の形式を読みます
- 色は Visual Studio のテーマ（ダーク / ライト）に合わせて変わります。ファイルの場所を押すとその行へ飛び、シンボルの横の「宣言を検索」で、ソリューション全体から探して「検索結果 1」に出します
- <strong>1 件を 2〜3 行で見せる。</strong> 1 行目は「エラー コード・日本語の見出し・場所」で、`C2065` のようなコードを押すと、公式のページ（検索）が開きます。続けて、メッセージ、ソースの 1 行、ヒントが 1 行だけ出ます。経路・候補・補足・例・同じ内容の別の場所は、行頭の「▸」を押すと開きます。連鎖の可能性があるエラーは、見出しの 1 行だけに畳みます。
- <strong>縮小変換の修正ボタン。</strong> `double` から `int`、`size_t` から `int` のような縮小変換の警告・エラーで、1 行で終わる「型 名前 = 式;」「名前 = 式;」「return 式;」「型 名前{式};」なら、見出しの横に「[クリックで修正]」が出ます。押すと、その行の右辺を `static_cast<型>(…)` で包みます（Ctrl+Z で戻せます）。1 行に文が 2 つある行は、どちらの右辺か決められないので出しません。
- <strong>全部を修正。</strong> 直せる行が 1 つ以上あると、上のボタンの並びに「全部を修正 (件数)」が出ます。押すと、ファイルごとの件数を確かめる画面が出て、表示している分をまとめて直します。ファイルを開いて書き換え、保存はしません。戻すときは、ファイルごとに Ctrl+Z を押します。ビルドのあとで行が変わっているものは飛ばして、その数を知らせます。警告は「警告も表示」を入れたときだけ表示されるので、そのときだけ対象になります。引数の途中や複数行の式は、場所を決められないので出しません。値が切り捨てられてよいかは、自分で確かめます。
- <strong>ファイル別の目次。</strong> エラーのあるファイルが 2 つ以上のとき、先頭に「ファイル別」の一覧（ファイル名と件数）が出ます。押すと、そのファイルの最初のエラーへ移ります。
- <strong>窓の高さ。</strong> 下のパネルが低いとき、自動で開くたびに高くします（高くしてあるときは触りません）。
- 窓の上の**警告も表示**と**原文**（整理せずに色だけ付ける）で表示を切り替えます。**コピー**は、いま見えている内容を文字にします。「…」のメニューに、**すべての詳細を開く**・**経路を全部表示**・**原文を併記**・**原文をコピー**（AI や質問に貼る用）があります

ビルド欄の文字を読むので、ビルドのあとで「出力」を消すと「再読み込み」で何も出ません。`.lib` の探索はソリューションのフォルダーの下だけです。以前に別の拡張として配布していた K-ErrorLog と K-CppErr は、この拡張に統合しました。K-ErrorLog を入れている場合は、二重に出ないように、Visual Studio の「拡張機能の管理」から外してください。

## 「よく使うプロパティ」のページ

プロジェクトのプロパティを開くと、「構成プロパティ」の先頭（「全般」の上）に、「よく使うプロパティ」のページが増えます。C++ の言語標準、警告レベル、`/utf-8`、インクルードの検索パス、プリプロセッサの定義、リンクするライブラリ、出力ディレクトリなど、プロジェクトを作るたびに触る項目だけを、1 か所に集めたページです。

困りごとは、これらの項目が「全般」「C/C++」「リンカー」「マニフェスト ツール」「ビルド イベント」に散らばっていて、探すたびにツリーを開き直すことでした。

ページの項目は、新しい設定ではありません。元のページにある設定の窓口です。ここで書き換えると、`.vcxproj` の同じ要素が書き換わるので、C/C++ のページを開いても同じ値が見えます。逆に、元のページで書き換えれば、こちらにも反映されます。値が二重になることも、`.vcxproj` に項目が増えることもありません。

入っている項目は、次のとおりです。

- 外部ライブラリ: インクルードの検索パス、追加のライブラリ ディレクトリ、追加の依存ファイル（ページの先頭に置いてあります）
- 全般: 構成の種類、プラットフォーム ツールセット、文字セット、出力ディレクトリ、中間ディレクトリ
- C/C++: C++ 言語標準、C 言語標準、準拠モード、警告レベル、SDL チェック、マルチプロセッサ コンパイル、プリプロセッサの定義、必ず使用されるインクルード ファイル、無視する警告、プリコンパイル済みヘッダー（種類とファイル）、追加のオプション
- リンカー: サブシステム、エントリ ポイント
- マニフェスト ツール: セグメント ヒープ、追加のマニフェスト ファイル
- ビルド イベント: ビルド後のコマンド ラインと説明

項目の定義は、Visual Studio の `cl.xml` などから写して作ります。そのため、説明文と選択肢は、VS の言語とバージョンのままです。

仕組みは、`%LOCALAPPDATA%\K-CppAssist\KCommonProps.xml` に規則を書き、`%LOCALAPPDATA%\Microsoft\MSBuild\v4.0\Microsoft.Cpp.x64.user.props`（`Win32`・`ARM64` も）に、目印で挟んだ数行を足して読み込ませます。ファイルのほかの部分は触りません。設定の「「よく使うプロパティ」のページを出す」を False にして VS を再起動すると、足した数行は消えます。拡張を外したときは、`Microsoft.Cpp.*.user.props` の `K-CppUltimateAssist begin` から `end` の間を消してください。

## vcpkg パッケージ（K-vcpkg）

vcpkg のライブラリを探して、`vcpkg.json` に足すところまでを、NuGet のパッケージ マネージャーのような窓でできます。コマンドを覚えなくても、名前で探して、押して、インストールまで進みます。

開くには、メニューの「拡張機能」→「K-Cpp」→「vcpkg パッケージ...」を選びます。窓は、Visual Studio の中に並ばず、独立した窓（フロート）で開きます。「K-Cpp」には、この拡張機能のコマンドがまとまっていて、マウスを重ねると右（▶）に項目が開きます。

窓には「参照」「インストール済み」「更新」の 3 つのタブがあります。

- 参照: 最初の画面には、ゲーム制作でよく使うライブラリを、おすすめ順（117 個）に並べます。上の検索欄に名前か説明の一部を入れると、vcpkg の全パッケージから絞り込みます。右に、説明・最新のバージョン・ライセンス・対応する環境・依存・ホームページが出ます
- インストール済み: `vcpkg.json` に書いてあるパッケージと、実際に入っているバージョン、最新のバージョンを並べます。削除や、「このバージョン以上」への書き換えもできます
- 更新: 新しいバージョンがあるものだけを出します。「ベースラインを更新して、インストール」で、まとめて新しくできます

右の詳細では、機能（feature）のチェックと、既定の機能（default-features）の有無、バージョンの指定（ベースラインのまま、または `version>=`）を選んで、「vcpkg.json に追加」を押します。`vcpkg.json` の書式は壊さず、「元に戻す」で直前の状態に戻せます。分かりにくい項目（ベースライン・既定の機能・トリプレットなど）の横には「?」のアイコンがあり、押すと説明が開きます。機能の一覧では、既定で入るものに「[既定]」と付きます（「既定の機能を使う」が入のとき、チェックが切でも入ります）。下の「ベースラインでバージョンをそろえる」のチェックで、`builtin-baseline` を書く・消すを切り替えられます。`vcpkg.json` がない場所を選んで追加すると、新しく作って、`builtin-baseline` も書き込みます。

上の欄で、`vcpkg.json` の置き場所（ソリューションと各プロジェクト）と、トリプレット（`x64-windows` など。プロジェクトの `triplets` フォルダーの自作トリプレットも）を選びます。「インストール」は `vcpkg install` を実行して、出力を下のログに流します。失敗したときは、ネットワーク・ベースライン・ビルド失敗・非対応のトリプレットなどの原因の見当を、ログの末尾に書きます。

vcpkg が見つからないときは、入れ方の案内が出ます。一覧は一度取得すると手元に残るので、オフラインでも検索できます（詳細の GitHub からの情報だけは取れません）。

自作のレジストリや overlay-ports の編集、ポートの公開は、この窓の対象外です。

### vcpkg を使うプロジェクトを選ぶ

ソリューションには、vcpkg を使わないプロジェクトも混ざります。そこで、窓の下の「vcpkg を使うプロジェクト」に、選んだ `vcpkg.json` の下にあるプロジェクトを、名前のチップで並べます。チップには、いまの状態（ON か OFF）が出て、ON のものは色が付きます。

- チップを押すと、そのプロジェクトの ON と OFF が切り替わります。`.vcxproj` の `VcpkgEnabled` と `VcpkgEnableManifest` を書き換えます（OFF は `VcpkgEnabled` を `false` にします。足すのは `Label="Vcpkg"` の `PropertyGroup` だけで、ほかの書式は変えません）
- 「すべて ON」「すべて OFF」で、まとめて切り替えられます
- パッケージを追加したとき、どのプロジェクトも OFF だった場合だけ、すべてを ON にします。すでに選んだ状態があれば、触りません
- Visual Studio でそのプロジェクトを開いているときは、「プロジェクトが変更されました」の確認が出るので、再読み込みを選びます

### ビルド時の自動インストールと VS との連携

ON のプロジェクトは、Visual Studio でビルドするたびに、`vcpkg.json` に書いたパッケージを、足りなければ自動で入れます。そのため、この状態（連携済みで、ON のプロジェクトがある）のときは、窓の「今すぐインストール」のボタンを隠します。連携していないときや、CMake のように自動で入らないときは、ボタンが出ます。

自動で入るには、2 つがそろう必要があります。

1. プロジェクトが ON（マニフェスト モードが有効）なこと
2. Visual Studio と vcpkg が連携していること（`vcpkg integrate install`）

連携していないときは、「VS と連携する」のボタンが出ます。連携済みかは、`%LOCALAPPDATA%\vcpkg\vcpkg.user.targets` があるかで見ています。この仕組みは `.vcxproj` が対象で、CMake のプロジェクトには使えません。

### vcpkg が入っていないとき

vcpkg が見つからないと、窓に入れ方の案内が出ます。

- この窓から入れる: フォルダー（既定は `C:\vcpkg`）を決めて「vcpkg を入れる」を押すと、`git clone`、`bootstrap-vcpkg.bat` を順に実行して、環境変数 `VCPKG_ROOT`（ユーザー）の設定と `integrate install` までします。Git が要ります。履歴が要るので、浅い clone にはしません
- Visual Studio に付いているものを使う: インストーラーの「vcpkg パッケージ マネージャー」を入れます。窓から、インストーラーを開けます。付属のものは、一覧（ports）がないので、検索にはおすすめしません

## 設定

拡張機能 メニューの「K-Cpp: 設定...」から開けます（ツール → オプション → K-CppUltimateAssist → 全般と同じ画面です）。

- <strong>表示する言語</strong>。日本語・English・中文（简体）・한국어・Español・Português・Deutsch・Français・Русский の 9 つから選びます。初期値は日本語で、初めて起動したときだけ、PC（Windows）の表示言語に合わせます（この 9 つにない言語のときは English）。訳すのは、メニュー、電球の項目、ダイアログ、この設定の画面（分類・項目名・説明文）、ステータスバーの知らせ、出力ウィンドウの行、文字コードをそろえる画面、使い方の画面、エラーログの窓のボタンと中身（エラーごとの見出し・ヒント・具体的な説明・直し方の例のコメント・リンカーの原因の解説）です。ビルドの出力そのもの（コンパイラが出す原文）は、Visual Studio の言語のままです。メニューは次に開いたときから、設定の画面の文字は Visual Studio を開き直すと変わります。

- <strong>Getter と Setter の間に空行を入れる</strong>（初期値は True）。True のときは Getter の前（直前がメンバーの行のとき）と Getter と Setter の間に空行を 1 行入れます。
- <strong>書き換えた場所に点線を出す</strong>（初期値は True）。引数を相手のファイルへ写したときと、名前を変えたときと、呼び出しの引数を直したときに、書き換えた名前の下に、点線を約 3 秒だけ出します。C# の名前の変更と同じ見せかたで、ウィンドウは出さないので、コードを隠しません。点線が出るのは、いま開いているエディターの中の場所だけです（ほかのファイルの変更は、点線では見えません）。
- <strong>宣言の名前を変えたら、使っている場所も変える</strong>。`Off`（何もしない）・`OnLeave`（カーソルが名前から離れたときにまとめて変える）・`Auto`（打つそばから変える）。初期値は `Auto`。
- <strong>一緒に変わる場所を枠で囲む</strong>（初期値は True）。名前を書き換えている間、一緒に変わる場所を点線で、書き換えている宣言を実線で囲みます。色は ツール → オプション → 環境 → フォントおよび色 の「K-Cpp: 一緒に変わる場所」「K-Cpp: 名前を変えている宣言」で変えられます。
- <strong>型が分からない obj.name も変える</strong>（初期値は False）。False のときは、`obj` の型を宣言から読めて同じクラスだと分かるものだけ変えます。
- <strong>引数の並べ替え・削除を、呼び出しにも写す</strong>（初期値は True）。
- <strong>電球（Quick Fix）に出す</strong>（初期値は True）。`Ctrl+.` の電球にこのツールの機能を出します。
- <strong>エラーログを使う</strong>。初期値は True。False にすると、ビルドが終わってもエラーログを作りません（窓も自動では開きません）。ビルドを重くしたくないときや、エラーログが要らないときに切ります。
- <strong>エラーがあるとき、窓を自動で前に出す</strong>。初期値は False（ビルドが失敗しても、窓は自動では開きません）。True にすると前に出ます。False のときは、拡張機能 メニューの「K-ErrorLog (エラーログ)を開く」から開きます。
- <strong>原因を探す (.lib とソースの検索)</strong>。初期値は True。未解決の外部シンボル（LNK2019 など）について、ソリューションの `.lib` とソースを探して、原因を言い当てます。時間がかかるときは False にします。「探す時間の上限 (秒)」（初期値 6）と「読む .lib の数の上限」（初期値 800）も変えられます。
- <strong>型名を短くする</strong>。初期値は True。`std::basic_string<char, …>` を `std::string` のようにします。False にすると、コンパイラの出した型名のまま出します。
- <strong>ヒントを出す</strong>。初期値は True。エラー コードごとの見出しの下に、対処のヒントを、表示する言語で出します。
- <strong>エラーログ（窓の初期値）</strong>。「警告も表示」「経路を全部表示」「原文を併記」「原文」の、窓を開いたときの初期値です。窓の上のチェックボックスと「…」のメニューは、開いたあとで切り替えられます。
- <strong>#include を足すしかた / 宣言と定義の引数を合わせるしかた</strong>。それぞれ `Off`（何もしない）・`ManualOnly`（キーを押したときだけ）・`Auto`（入力中に自動）。初期値は `#include` が `Auto`、引数の同期が `Auto` です。
- <strong>ヘッダー・cpp の名前を変えたときのしかた</strong>。`Off` / `ManualOnly`（Alt+N だけ）/ `Auto`（Solution Explorer での名前変更も自動）。初期値は `Auto`。
- <strong>相手のファイルも同じ名前にする</strong>。初期値は True。False にすると、`#include` と CMake だけを直します。
- <strong>CMake の書き方も直す</strong>。初期値は True。
- <strong>ステータスバーに知らせる</strong>。初期値は True。#include を足した、引数を写した、ファイル名を直した、などを 1 行出します。False でも、失敗の知らせは出ます。
- <strong>ログを残す</strong>。初期値は True。動作の記録を `%LOCALAPPDATA%\K-CppAssist\vsix.log` に書きます。
- <strong>「よく使うプロパティ」のページを出す</strong>。初期値は True。プロジェクトのプロパティの先頭にページを足します。切ったあとは、VS を再起動してください。
- <strong>標準・Windows・DirectX の表を使う / ソリューションのヘッダーの索引を使う</strong>。どちらも初期値は True。`#include` を決める 2 つの元を、別々に切れます。
- <strong>自分で決める対応 (名前=ヘッダー)</strong>。`Vec3="math/vec3.h";Json=<nlohmann/json.hpp>` のように、`;` か改行で区切って書きます。組み込みの表より先に使います。自動でも使われます。
- <strong>.h でも、ソリューションの型を自動で足す</strong>。初期値は False。ヘッダーに自動で足すのは、標準・Windows・DirectX の表と、自分で決めた対応のものだけです（循環 include を避けるため）。True にすると、ソリューションの型も足します。
- <strong>自動で足した #include を戻すまでの秒数</strong>。初期値は 40。足した直後に識別子を消したら戻す、その猶予です。0 で、戻しません。
- <strong>#include も新しい名前に直す / ファイルの名前変更を、フォルダーの監視でも見つける / 多数の名前変更を、自動では直さない件数 / 直す前に確認する</strong>。ファイル名の同期の細かい設定です。初期値は True / True / 4 / True。
- <strong>JSON (nlohmann) の項目を出す / cereal の項目を出す / Natvis の項目を出す</strong>。どれも初期値は False。使うライブラリ次第の項目なので、True にしたときだけ電球に出します。

- <strong>引数の個数をビルド前にチェックする</strong>。初期値は True。`make_unique` / `make_shared` / `new` の引数の個数が合わない呼び出しに波線を引きます。「波線の色」（Error / Warning。初期値は Error）、「入力が止まってから調べるまでの待ち」（初期値 700 ミリ秒）、「`make_unique` / `make_shared` を調べる」「`new T(…)` を調べる」（どちらも True）、「調べないクラス」（カンマ区切り）があります。

## 制限

- 対象は `名前 = 右辺;` の形の文です。`int x = 0;` のようにすでに型があるものは対象外です。右辺が何行に分かれていてもラムダの中の 1 文（`[this] { count_ = 1; }`）でもその文のどこにカーソルがあっても働きます。`;` をまだ書いていない行は続きの行がなさそうならそこまでを 1 文として読みます。
- Alt+W と Alt+G は `Class::Func(` の形の定義の中とクラスの本体に直接書いた関数（ヘッダーのインライン関数）の中で働きます。字下げされていても引数が複数行に分かれていても見つかります。ラムダの中は囲んでいる関数のクラスに足します。クラスに属さない関数の中では使えません。
- ヘッダーはいまのファイルの中にクラスの定義があればそれなければソリューションのフォルダーの下から探します。cpp と同じ名前の `.h` を先に見て、そこに 1 つだけ合えば決めます。なければ `class Class {` を含む `.h` を探します。
- クラスが入れ子（`Outer::Inner::Func`）のときは `Outer` が外側にあるクラスだけを選びます。同じ名前のクラスが別の `namespace` にもあるときは、cpp を囲む `namespace` と外側の名前が末尾から多く一致するほうに足します。決められなければ選ぶ欄を出します。cpp が `using namespace` だけで修飾を省いているときは、`namespace` が分からないので選ぶ欄になることがあります。
- 演算子を含む右辺は部分の型から組み立てます（上の「型の決め方」）。ユーザー定義の演算子が別の型を返すとき `enum` と整数の演算、型の分からない部分が混じるときは決められず入力欄（Alt+W）か `auto`（Alt+Q）になります。
- キーは「テキスト エディター」の範囲に割り当てます。エディターの外（ソリューション エクスプローラーなど）では、Alt+F でファイル メニューが開きます。0.20.1 までは範囲が「グローバル」だったので、0.21.0 を入れて初めて起動したときに 1 回だけ、テキスト エディターの範囲へ移します。エディターの中では、Alt+W・Alt+F・Alt+G・Alt+S がメニューのアクセスキーより先に効きます。メニューを開きたいときは、Alt を押して離してから文字を押すか、設定で別のキーに付け替えてください。
- 失敗したときはステータスバーに理由が出ます。詳しいログは `%LOCALAPPDATA%\K-CppAssist\vsix.log` です。
- 呼び出しのチェックは、引数の「個数」だけを見ます。型の違い（`const`・暗黙の変換）は、ビルドして初めて分かります。`T` のコンストラクターを読めないとき（マクロ・テンプレート・継承したコンストラクター・定義が複数）は、何も出しません。`emplace_back` や `T x(…)` の宣言は、まだ調べません。
