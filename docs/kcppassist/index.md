# K-CppAssist

メンバー関数の中で `count_ = items.size();` と書くと Visual Studio は `E0020: 識別子 "count_" が定義されていません` と赤い波線を出します。直すにはヘッダーを開いて `items.size()` の戻り値が何だったかを調べて（`size_t`）、`size_t count_;` を書き足して元のファイルに戻るという往復が要ります。ゲッターとセッターを作るときも同じ往復をもう一度やります。

K-CppAssist はこの往復をキー 1 つにする Visual Studio 用の拡張です。右辺の式から型を決めてクラスの宣言（`.h`）に変数を足します。ローカル変数ならその場で型を付けます。

!!! info "このページを読む前に"
    拡張機能の入れ方や C++23 の設定は [Visual Studio](../vs/index.md) にあります。K-CppAssist は右辺の型をエディターのホバー（Quick Info）から読みます。ホバーが出ない環境ではリテラルなど式だけで決まる型に限られます。

## 使い方

コマンドの多くは、キーだけで使います。拡張機能 → 「K-CppAssist の使い方...」で、この一覧を VS の中で見られます。キーは設定で変えられます。拡張機能 メニューに出るのは「K-CppAssist の設定...」と「K-ErrorLog (エラーログ)を開く」の 2 つで、設定のほうをクリックすると設定画面が開きます。

| キー | コマンド | することと例 |
|---|---|---|
| Alt+W | メンバー変数として宣言する | クラスのヘッダー（`.h`）に `型 名前;` を足す |
| Alt+Q | ローカル変数に型を付ける | その場の `count = 0;` を `int count = 0;` にする |
| Alt+E | ゲッター・セッターを作る | `stride_` の `GetStride()` と `SetStride(...)` を `public:` の末尾に足す |
| Alt+N | ファイル名をまとめて変える | ヘッダーか cpp の名前を変え、相手のファイル・`#include`・CMake も同じ名前に直す。名前を変えると自動でも直す（下の「ファイル名をまとめて変える」） |
| Alt+M | 関数を ヘッダー ⇄ cpp に移す | ヘッダーに書いた関数の本体を cpp へ、cpp の `Class::Func` の本体をヘッダーへ移す |
| Alt+D | `#include` を前方宣言にする | ヘッダーの `#include "x.h"` を `class X;` に置き換えて、`#include` を cpp に移す |
| Alt+Z | switch の足りない case を足す | enum の値のうち、まだ書いていない `case` を、`default` の前に足す（下の「switch の case とコンストラクターを作る」） |
| Alt+U | 呼び出しから関数を作る | `Foo(hp, name, 2.5f)` や `obj.Foo(x)` の行で押すと、引数の型を読んで宣言と定義の雛形を作る（下の「呼び出しから関数を作る」） |
| Alt+O | 基底クラスの仮想関数を override する | 基底クラスの仮想関数のうち、まだ宣言していないものを `override` つきで足す（純粋仮想関数が先） |
| Alt+C | コンストラクターを作る | データ メンバーから、初期化リストつきのコンストラクターを作る |
| Alt+G | 宣言と定義の引数を合わせる | ヘッダーの宣言と cpp の定義の引数を、変えた側に合わせる。引数を変えるとエディターで開いている相手にも自動で写す |
| Alt+R | 宣言・定義の相手を作る | ヘッダーの宣言から cpp の定義の雛形を、cpp の定義からヘッダーの宣言を作る（下の「宣言と定義の相手を作る」） |
| Alt+F | `#include` を足す | カーソルの識別子（`std::vector`、`ComPtr`、`Camera`）のヘッダーを探して `#include` を足す。設定を `Auto` にすると入力中にも自動で足す |

どのコマンドも <strong>カーソルが行のどこにあっても</strong>押せます。対象は行頭の `名前 = 右辺;` の左辺です。

```cpp
// Alloc.cpp
Alloc::Alloc(Dev* device, int type) {
    stride_ = device->GetStride(type);   // この行のどこでも Alt+W
}
```

Alt+W を押すと `Alloc` の宣言から、ヘッダーに次の 1 行が入ります。

```cpp
 private:
  int capacity_;
  unsigned int stride_;
```

`Class::Func` の `Class` を宣言から探して、そのクラスの `private:` の末尾に足します。`private:` が最後でなければ末尾に `private:` を作ってから足します。ヘッダーはエディターで開いたままになり（保存はしません）、作業中のファイルへ戻ります。挿入は 1 回の編集なので Undo も 1 回です。字下げされた定義や引数が複数行に分かれた定義でも見つかります。

## 型の決め方

右辺から次の順に決めます。

1. <strong>式そのもの。</strong> `0` は `int`、`1.0f` は `float`、`true` は `bool`、`"abc"` は `const char*`、`static_cast<T>(...)` は `T`、`std::make_unique<T>(...)` は `std::unique_ptr<T>`、`new T` は `T*` です。
2. <strong>Quick Info（ホバーの内容）。</strong> 関数呼び出しなら戻り値の型を取り出します。`size_t std::vector<int>::size() const` から `size_t` を取ります。変数や引数ならその型を取ります。
3. <strong>どちらでも決まらないとき。</strong> Alt+W は型の入力欄を出します。Alt+Q は `auto` を入れます。

演算子を含む式（`a + b`、`x < y`、`!flag`、`(float)n`、`&x`）は部分ごとに 1 と 2 で型を決めて、組み立てます。比較と論理演算は `bool` です。算術は C++ の通常の算術変換で、`int + float` は `float`、`float * double` は `double` になります。`UINT + UINT` や `size_t * size_t` のように綴りがそろっていれば、その綴りのままです。`char` や `short` は `int` になります。クラスの型が混じるときは最初のクラスの型（`XMFLOAT3 * float` も `float * XMFLOAT3` も `XMFLOAT3`、`std::string + "x"` は `std::string`）、ポインターに整数を足せばそのポインターの型です。シフトは左の型になります。

右辺が `cond ? A : B` の形のときは A と B を順に試して、最初に型が決まったほうを使います。`{}` と `nullptr` の枝は型を持たないので飛ばします。

`const` と参照は外して値の型にそろえます（`const UINT&` は `UINT`）。ポインターの `const` は残します。

## ゲッター・セッター

メンバー変数の宣言行（`UINT stride_;`）にカーソルを置くか `.cpp` の `stride_ = ...;` の行にカーソルを置いて、Alt+E を押します。名前は `stride_` から末尾の `_` を外して、先頭を大文字にします（`cpu_start_` は `GetCpuStart` / `SetCpuStart`）。

```cpp
 public:
  Alloc(Dev* device, int type);

  unsigned int GetStride() const { return stride_; }

  void SetStride(unsigned int value) { stride_ = value; }
```

同じ名前がすでにあるときは足しません。`public:` がなければクラスの先頭に作ります。型によって書き方を変えます。

| 型 | ゲッター | セッター |
|---|---|---|
| `int`・`float`・ポインター・`UINT` のような大文字の型・ヘッダーに `enum` の定義がある型 | 値 | 値 |
| `std::string`・`std::vector`・構造体など | `const T&` | `const T&` |
| `bool`（名前が `is_` / `has_` で始まる） | `IsVisible()` / `HasXxx()` | `SetVisible(...)` / `SetHasXxx(...)` |
| `ComPtr<T>` | `T*`（`.Get()`） | 作らない |
| `std::unique_ptr<T>` | `T*`（`.get()`） | 作らない |
| `std::shared_ptr<T>` | `T*`（`.get()`） | 値で受けて `std::move` |
| `std::weak_ptr<T>` | `std::shared_ptr<T>`（`.lock()`） | `const&` |
| `std::atomic<T>` | `T`（`.load()`） | `T`（`.store()`） |
| `const` メンバー・参照メンバー | 作る | 作らない |
| `std::mutex`・`std::thread` など | 作らずに断る | 作らずに断る |

`ComPtr` のゲッターが `T*` なのは、呼び出し側が毎回 `.Get()` を書かなくて済むようにするためです。セッターを作らないのは DirectX のオブジェクトは、作った側が持ち主になる使い方が多いからです。配列と `static` のメンバーは対象外です。

## #include を足す

カーソルの識別子（`std::vector`、`ComPtr`、`Camera` など）のヘッダーを探して、`#include` を 1 行足します。すでにあれば足しません。

ヘッダーは次の順に決めます。

1. 表。 標準ライブラリ（`std::vector` → `<vector>`）、Windows（`UINT` → `<Windows.h>`）、DirectX（`ID3D12Device` → `<d3d12.h>`、`XMFLOAT3` → `<DirectXMath.h>`）の固定の対応表。
2. ソリューションの索引。 ヘッダーから集めた `class` / `struct` / `enum` / `using X =` / `typedef` の定義。関数、メソッド、変数、クラスの中の入れ子の型は入れないので、`Instance()` のような名前がヘッダーに引かれることはありません。
3. 索引で複数見つかったら、選ぶ欄を出します（自動では足しません）。

足す場所はファイルにある `#include` の並びに合わせます。空行でグループが分かれていればグループごとに（自分のヘッダー、C、C++ 標準、その他の `<>`、プロジェクトの `""` の順）、分かれていなければ 1 つの塊の中で並び順に。フォルダーは 2 つのファイルの共通の親からの相対（`"core/scene.h"`）で書きます。挿入は 1 回の Undo です。

### 書き方（`""` か `<>` か）

プロジェクトのヘッダーは `""`、標準・Windows・DirectX は `<>` です。`""` のパスはプロジェクトが実際に使っている基準に合わせます。ソリューションの既存の `#include "a/b.h"` が、どの親フォルダーから開けるかを数えて、いちばん多く使われている基準からの相対で書きます（`Engine/Source` が基準なら `"Prest/Core/GraphicsModule.h"`）。同じフォルダーかその下ならそこからの相対。基準が分からないときはこのファイルからの相対（`"../Core/x.h"`）にするので、必ず開けます。

### 入力中の自動挿入

設定の「`#include` を足すしかた」を `Auto` にすると、入力中に自動で足します。次をすべて満たすときだけです。

- 識別子を打ち終えた（`<` `::` `*` `(` 空白などの区切りを打った）あと入力が止まって約 0.9 秒たった。
- 補完リストが出ていないビルド中でない、カーソルがその識別子の上にない。
- コメント・文字列・`#` の行の中ではなく、型として使われている形（`Foo x` / `Foo*` / `Foo<` / `Foo::` / `new Foo` など）。`.名前` `->名前` `Foo::Instance()` のような呼び出しは対象外。
- その識別子に IntelliSense のエラーの波線が付いている（ほかのヘッダー経由ですでに見えているものには足さない）。
- ヘッダーが 1 つに決まる。索引から引く名前は拒否リスト（`Instance` `Get` `Data` `Type` など。設定で変えられる）にないもの。
- `.h` の中では表（標準・Windows・DirectX）のものだけ。足すと循環するヘッダーは足さない。

PCH（プリコンパイル済みヘッダー）経由でもう見えている型には、波線が出ないので自動では足しません。足したいときは型の上で Alt+F を押してください（Alt+F は波線を見ずに足します）。

足したあと 40 秒以内にその識別子を消したり書き換えたりしたら、足した `#include` も戻します（ほかの場所でまだ使っていれば戻しません）。足すたびにステータスバーに理由を出し、`vsix.log` に残します。

初期値は `ManualOnly`（Alt+F だけ）です。`Auto` にすると入力中の自動も動きます。`Off` にするとどちらも止まります。ヘッダーを探さないフォルダー（`third_party` `build` など）も設定で変えられます。

## 宣言と定義の引数を合わせる

ヘッダーの宣言か cpp の定義（コンストラクターを含む）の引数を変えると、相手の引数も同じに書き換えます。引数の型・数・名前の変更、並べ替え追加、削除に対応します。

```cpp
// Alloc.h
Alloc(Dev* device, int type = 0);          // ← float scale = 1.0f を足す
// Alloc.cpp
Alloc::Alloc(Dev* device, int type) {...}  // ← 自動で (Dev* device, int type, float scale) になる
```

- 自動（設定の「宣言と定義の引数を合わせるしかた」が `Auto`、初期値）: 括弧の中を編集すると、すぐに（待ちは 0 ミリ秒。設定の「自動で合わせるまでの待ち」で変えられます）、相手を書き換えます。相手がエディターで開いていなければ、開いて書き換え作業中のファイルへ戻ります。
- Alt+G: カーソルの関数の引数を相手に写します。相手が開いていなければ開いて書き換えます。引数が違う相手が複数あれば選ぶ欄を出します。
- ヘッダー → cpp: 既定値（`= 0`）は cpp に付けません。残る引数は cpp の書き方（名前・`const` の位置）のまま残します。cpp の本文が引数の名前を使っているので、ヘッダーで改名しても cpp には写しません。型だけ変えたときは cpp の名前を残して、型だけ新しくします。
- cpp → ヘッダー: 残る引数の既定値と書き方は、ヘッダーのものを引き継ぎます。cpp で引数を改名したときだけヘッダーにも新しい名前を写します。新しい引数に既定値は付きません。既定値のある引数のあとに既定値のない引数ができたときは、ステータスバーで知らせます（C++ では書けない形です）。
- どの関数かは名前と `const` の有無と `namespace` とクラスの並びと変える前の引数の型で決めます。同じ名前のオーバーロード（`Add(int)` と `Add(float)`、`Get() const` と `Get()`）や別の `namespace`・別のクラスの同名の関数は、取り違えません。cpp が `using namespace` で修飾を省いていても、ほかに合うものがなければ見つかります。見つからない・複数ある・書きかけ（末尾のカンマなど）のときは、何もしません。
- 書き換えは相手側の 1 回の Undo です。相手のあとでもう一度戻されることはありません。
- 呼び出し側（`Move(1, 2.5f)` など）は、並べ替えと削除だけを直します（下の「引数を並べ替える・消すと、呼び出しも直る」）。戻り値の型の変更は対象外です。
- 別名の違いは同じ型として相手を探します。`HANDLE` と `void*`、`DWORD` と `unsigned long`、`uint32_t` と `unsigned int`、`LPCWSTR` と `const wchar_t*` などです。ヘッダーにだけ付いた SAL 注釈（`_In_`、`_Out_writes_bytes_(n)`）、`__cdecl` の有無、関数ポインタの引数の中の名前の違い（`void (*cb)(void* arg)` と `void (*cb)(void*)`）も違いとして数えません。
- 引数の途中に `#if` が入る関数は枝の選び方ごとの型の並びで相手を探します。ただし、どの枝が有効か分からないので、書き換えはしません。ステータスバーに理由を出すので、相手は手で合わせてください。

## 名前を変えると使っている場所も変わる（自動）

メンバー変数の名前を `hp_` から `life_` に変えたくなったとき、ヘッダーの宣言を直しただけではビルドが通りません。cpp の中で `hp_` を使っている行を 1 つずつ直すか、置換を使って別のクラスの `hp_` まで巻き込まないように気を付けることになります。

K-CppAssist は宣言の名前を書き換えると、その名前を使っている場所を打つそばから同じ名前にします。キーは要りません。

```cpp
// Player.h
class Player {
 private:
  int hp_ = 0;        // ← hp_ を life_ に書き換える
};
// Player.cpp（自動で変わる）
void Player::Hit(int damage) {
  life_ -= damage;    // hp_ だった
}
void Enemy::Hit(int damage) {
  hp_ -= damage;      // 別のクラスなので変わらない
}
```

対象は次の 5 つの、宣言（か定義）の名前です。使っている側の名前を書き換えても、ほかは変わりません。

- ローカル変数。宣言から、その変数が見えるブロックの終わりまでが範囲です。内側のブロックで同じ名前を宣言し直している所は変えません。`for` や `if` の括弧の中の宣言とラムダのキャプチャも追います。
- 引数。定義（本体のある関数）の引数を変えると本体の中も変わります。コンストラクターの初期化子リストの `hp_(hp)` は、括弧の中だけが引数です。
- メンバー変数。クラスの本体、`Class::Func` の定義の中、`this->名前`、`Class::名前`（static メンバーの定義）が変わります。引数やローカル変数に同じ名前があれば、そちらは変えません。
- メンバー関数。ヘッダーの宣言と cpp の定義のどちらを変えても、相手と呼び出しが変わります。派生クラスの `override` と基底クラスの宣言も同じ名前にします。
- 関数（クラスに属さないもの）。宣言・定義・呼び出しが変わります。`SetCallback(window, OnKey)` や `&OnKey` のように `(` なしで渡している所も変わります。`static` の関数と無名の `namespace` の中の関数は、そのファイルの中だけを見ます。

### 途中の名前でほかの名前と混ざらない

使っている場所は、最初の 1 文字を打ったときに決めて、そのあとは位置で追いかけます。名前では探し直しません。`hp_` を `h` まで消して `health_` と打ち直すあいだに `h` という別の変数があっても、混ざりません。名前が空や数字始まりになっている間は、ほかの場所を前の名前のまま待たせます。

新しい名前が、同じ範囲にすでにある名前と同じになったときは、ほかの場所へ写しません。`a` を `b` に変えたとき、もとからあった `b` と区別がつかなくなるためです。小さなウィンドウに「同じ名前がすでにあるので、ほかの場所は変えていません」と出て、別の名前にすると続きが写ります。`index` と打つ途中の `i` がすでにある変数でも、打ち進めれば写ります。ローカル変数と引数は見える範囲の中の名前を、メンバーは同じクラスのメンバー変数（メンバー変数を変えるときはメンバー関数も）を調べます。

新しく宣言を打っているあいだは、名前の変更とはみなしません。`int position` と打つ途中の `pos` が、たまたま下の行で使っているメンバーの名前と同じでも、何も変えません。カーソルが名前から離れたあとで、その名前を書き換えたときに初めて働きます。行を複製して写しの名前を書き換えているとき（同じブロックに同じ名前の宣言がもう 1 つあるとき）も、何も変えません。

### `obj.name` はどこまで変えるか

`obj.hp` や `p->Update()` は、文字だけでは `obj` がどのクラスか決まりません。K-CppAssist は `obj` の宣言を読みます。関数の引数とローカル変数、その関数が属するクラスのメンバー変数の順に探して、型が同じクラス（か派生クラス）なら変えます。`std::unique_ptr<Enemy>` や `ComPtr<Enemy>` のようなスマート ポインターは、`->` のときだけ中身のクラスのメンバーとして扱います。

入れ物の要素も、入れ物の宣言から型を引きます。`std::vector<Enemy> enemies_;` があれば、`for (auto& e : enemies_) e.Update(dt);` の `e` と `enemies_[i].Update(dt)` と `auto& first = enemies_.front();` の `first` は `Enemy` です。`std::vector<std::unique_ptr<Enemy>>` なら `->` のときに `Enemy` として扱います。対象の入れ物は `vector` `array` `list` `deque` `set` `span` などで、`map` は対象外です。

型が別のクラスだと分かれば変えません。分からないもの（関数の戻り値を受けた `auto`、`using` の別名、`GetBoss()->hp`）は変えずに、出力ウィンドウの「K-CppAssist」に `ファイル(行): …` の一覧を出します。行をダブルクリックするとその場所へ飛べます。private なメンバーを同じクラスの関数の中から `other.hp_` の形で触っている所は、同じクラスの物と決まるので変えます。

設定の「型が分からない obj.name も変える」を True にすると、分からないものも同じ名前なら変えます。`x` や `Update` のような名前では別のクラスのメンバーも変わるので、初期値は False です。

### ほかのファイルと、元に戻す

ローカル変数と引数は、いまのファイルの中だけで決まるのですぐ変わります。メンバーと関数はソリューションの下の C++ のファイルを調べるので、調べ終わるまで小さなウィンドウに「使っている場所を調べています…」と出ます。調べているあいだに打ち終えても、調べ終わった時点の名前を写します。

- エディターで開いているファイルは、打つそばから変わります。保存はしません。
- 閉じているファイルは、カーソルが名前から離れたときにディスクの上で書き換えて保存します。文字コード（UTF-8 の BOM の有無、シフト JIS）は保ちます。書き換えたファイルは出力ウィンドウに出ます。読み取り専用などで書けなかったファイルも、同じ所に「書き換えられませんでした」と出ます。
- タブにあるだけでまだ表示していない文書は、開いている文書として扱います（ディスクの上では書き換えません）。
- Ctrl+Z で宣言の名前を戻すと、ほかの開いているファイルと閉じているファイルも、戻したあとの名前に合わせます。

同じ名前で引数の違う関数（オーバーロード）があるときは、引数の型が同じ宣言と定義だけを変えます。呼び出しはどちらの関数か決められないので、一覧に出します。同じ名前のクラスが別のファイルにも定義されているときは、そちらのファイルの中は一覧に出すだけにします。

### 引数を並べ替える・消すと、呼び出しも直る

関数の引数を並べ替えるか消して、カーソルが括弧の外へ出ると、その関数の呼び出しの引数も同じ並びに直します。宣言と定義の相手は、上の「宣言と定義の引数を合わせる」が打つそばから直しています。

```cpp
void Move(int id, float speed);     // ← (float speed, int id) に並べ替える
// 呼び出し（カーソルが括弧の外へ出たときに変わる）
Move(1, 2.5f);                      // → Move(2.5f, 1);
```

打つそばからではなく括弧の外へ出たときに直すのは、切り取って貼る途中の形（引数が 1 つ減った形）で呼び出しを直すと、消えた実引数を取り戻せないためです。どの引数がどこへ動いたかは、まず引数の名前で、次に型で決めます。

- 足した引数に渡す値は決められません。既定値のある引数を末尾に足したときは省いたままにして、それ以外の呼び出しは直さずに一覧に出します。
- 同じ型の引数が並んでいて、名前も変えて 1 つ消したとき（`(int x, int y)` を `(int height)` にしたとき）は、どちらを消したか決められないので何もしません。名前を残して消せば直せます。
- コンストラクターの呼び出し（`Foo(…)`、`make_unique<Foo>(…)`）と、オーバーロードのある関数は対象外です。
- Ctrl+Z で引数を直す前の並びに戻すと、直した呼び出しも元の文字に戻します。やり直し（Ctrl+Y）で、もう一度直します。閉じているファイルは、こちらが書いたあとで変わっていなければ戻します。

## 宣言と定義の相手を作る

ヘッダーに宣言を足したのに cpp に定義を書くのが手間、という場面のためのコマンドです。Alt+R を押すとカーソルのある関数の相手を作ります。

- ヘッダーの宣言にカーソルがあるとき: cpp に定義の雛形を足します。戻り値の型・`const`・`noexcept`・後置の戻り値の型は宣言のままです。`virtual`・`static`・`override`・既定値・SAL 注釈・export マクロは、定義に書かないので外します。本体は `{ }` で戻り値が `bool` なら `return false;`、数なら `return 0;`、ポインターなら `return nullptr;`、それ以外の値なら `return {};` を入れます。参照を返す関数と `void` には `return` を書きません。
- cpp の `Class::Func` の定義にカーソルがあるとき: ヘッダーのクラスの `public:` の末尾に、宣言を足します。`public:` がなければ末尾に作ります（`struct` は先頭から `public` です）。
- 置き場所は定義なら「同じクラスの前の宣言の定義の直後」です。なければ同じクラスの最後の定義の直後、それもなければ同じ `namespace` の定義の直後、最後は末尾です。cpp が `namespace` の中に書かれていれば、その分の修飾は付けません。足したあとは cpp が開いて、カーソルが新しい本体に移ります。
- 相手がすでにあれば（同じ名前・同じ引数の型）、何もしません。`= 0`・`= default`・`= delete`・`friend`・`constexpr`・`template` の関数は定義を作りません。デストラクターと演算子も対象外です。

### 電球（Quick Fix）

`Ctrl+.` かカーソル横の電球から次の項目を選べます。カーソルの位置で使えるものだけが出ます。設定の「電球に出す」で消せます。

- 宣言から cpp に定義を作る / 定義からヘッダーに宣言を作る（Alt+R と同じ）。
- cpp の定義の引数を宣言に合わせる / ヘッダーの宣言の引数を定義に合わせる（Alt+G と同じ。同じ名前の関数があって引数の型だけ違うときに出ます）。
- ローカル変数として型を付ける / メンバー変数としてヘッダーに宣言する（Alt+Q・Alt+W と同じ。`名前 = 右辺;` の文のとき）。

電球に出すかどうかは保存済みの同名のファイル（`Foo.h` と `Foo.cpp`）を見て決めます。実行するときは開いているエディターの内容で処理します。

## 関数を ヘッダー ⇄ cpp に移す

クラスの中に書いた短い関数が育ってきたので cpp に出したい、逆に、cpp の小さな getter をヘッダーに戻したい、という場面のためのコマンドです（Alt+M）。

- ヘッダーの本体のある関数にカーソルを置いて押すと、本体を cpp の定義に移して、ヘッダーには宣言だけを残します。戻り値の型・`const`・`noexcept` は宣言のままで、`override`・`virtual`・`static` は定義に書きません。クラスの外の `inline` 関数は、`inline` を外して宣言だけにします。
- cpp の `Class::Func` の定義にカーソルを置いて押すと、ヘッダーの宣言の `;` を本体に置き換えて、cpp の定義を消します。引数の名前が宣言と定義で違うときは、本体が使っている cpp の名前に宣言をそろえて、既定値はヘッダーのまま残します。1 文だけの短い本体は `{ return x_; }` の 1 行にして、コンストラクターの初期化子リストも一緒に移します。
- 置き場所は Alt+R の定義と同じで、同じクラスの前の関数の定義の直後です。
- `template` のクラスの中、`template`・`constexpr`・`friend` の関数、引数の途中に `#if` がある関数、`= 0`・`= default`・`= delete` の宣言には移しません。理由はステータスバーに出ます。
- 本体が使う `#include` は、移した先に足しません。コンパイルで足りないと言われたら、Alt+F で足してください。

電球（Quick Fix）にも「関数の本体を cpp に移す」「関数の本体をヘッダーに移す」が出ます。実際のソース（leveldb・DirectXTK・yaml-cpp・spdlog）のヘッダー関数を cpp に移してから戻して、本体の文字が変わらないことを確かめています。

## #include を整理する・消す

プロジェクトやソリューションを右クリックすると、次の 2 つが出ます。拡張機能 メニューにも同じ項目があります。

- <strong>#include を整理（プロジェクト全体）</strong>。プロジェクトの `.h`・`.cpp` の `#include` を、グループに分けて並べ直します。順番は、自分のヘッダー（`Foo.cpp` なら `Foo.h`）、C の標準（`<stdio.h>`）、C++ の標準（`<vector>`）、そのほかの `<>`、`"..."` の順で、グループの間に空行を入れ、グループの中は名前順にします。同じ行の重複は消します。`#if` の中の `#include` と、`#define` などをはさんで離れている `#include` のまとまりには触りません（まとまりごとに整理します）。`windows.h` のように順番に意味があるものは、`#define` や `#if` でまとまりを分けておくと、そのままです。
- <strong>使っていない #include を消す（プロジェクト全体）</strong>。ヘッダーが定義している名前（クラス・列挙型と値・`using`・`typedef`・マクロ・関数・定数）を、そのヘッダーが `#include` しているものも含めて集めて、cpp が 1 つも使っていなければ、使っていないとみなします。消す前に、一覧を見せて確認します。自分のヘッダー、行に `keep` と書いた `#include`（`// keep`）、`#if` の中の `#include`、場所を探せないヘッダー、名前を 1 つも拾えないヘッダーは、いつも残します。標準のヘッダーは、`<vector>`・`<string>`・`<map>` など、中身が決まっている一部だけを調べます。

使っていない `#include` の削除は、ヘッダーに対しては、設定の「使っていない #include を、ヘッダーからも消す」（初期値は False）を True にしたときだけ行います。ヘッダーの `#include` は、そのヘッダーを include している別のファイルが、間接に受け取っていることがあり、消すとビルドが通らなくなるからです。

整理も削除も、エディターで開いているファイルはエディターの内容を書き換えて（Undo できます）、閉じているファイルはその場で保存します。ファイルのエンコードと BOM は変えません（BOM のない UTF-8 でも読めないときは、Shift-JIS として読みます）。いまのファイルだけを整理するときは、拡張機能 メニューの「このファイルの #include を整理」を使います。

## #include を前方宣言にする

ヘッダーが別のヘッダーを `#include` しているだけで、使っているのはポインターや参照だけ、ということがよくあります。`#include` を前方宣言（`class Scene;`）に置き換えて、`#include` を cpp に移すと、ヘッダーを変えたときに再コンパイルされるファイルが減ります（Alt+D）。

- カーソルが `#include "scene.h"` の行にあれば、その 1 つだけを調べます。行になければ、ヘッダーの `"..."` の `#include` を全部調べます。
- 変えるのは、ポインター（`Scene*`）・参照（`Scene&`）・`std::shared_ptr<Scene>`・`std::weak_ptr<Scene>` でしか使っていない型だけです。値のメンバー、継承、`std::unique_ptr<Scene>`（破棄に完全な型が要るため）、関数の本体の中での使用が 1 つでもあれば、変えません。理由はステータスバーに出ます。
- 同じヘッダーの型以外の名前（定数・関数・`enum` など）を使っているときも変えません。
- 前方宣言は、`namespace` ごとにまとめて、残りの `#include` の最後のあとに置きます。`template` のクラスは対象にしません。
- `#include` は、同じ名前の cpp に足します（Alt+F と同じ並びのルール）。cpp がなければ、足さずに知らせます。

電球にも、ヘッダーの `#include "..."` の行で「#include を前方宣言にして、cpp に #include を移す」が出ます。

## switch の case・コンストラクター・override・呼び出しから関数を作る

enum に値を足したのに、それを使う `switch` に `case` を足し忘れる。メンバーを足したのに、コンストラクターの初期化リストに足し忘れる。どちらも、書く内容が決まっている作業なので、キーで作ります。

### 足りない case を足す（Alt+Z）

`switch` の中（または `switch (...)` の行）にカーソルを置いて押すと、enum の値のうち、まだ `case` にない値を足します。

```cpp
enum class State { Idle, Walk, Run };

switch (state) {
  case State::Idle:
    break;
  // ← Alt+Z で、Walk と Run が入る
}
```

- enum は、すでにある `case` の名前から決めます。まだ 1 つもなければ、`switch` の式の変数（`state`）の宣言から探します。宣言が見えない（別のファイルの変数など）ときは決められないので、`case` を 1 つ書いてから押してください。
- enum の定義は、いまのファイルと、`#include "..."` をたどった先（2 段まで）から探します。
- 末尾が `Count`・`Max`・`Num`・`Size` のような「個数を数えるための印」の値は、足しません。
- `enum class` の値は `State::Walk` の形で、昔の `enum` は `Walk` の形で書きます。すでにある `case` の書き方があれば、それに合わせます。
- 足した `case` は `break;` で終わります。`default:` があれば、その前に入れます。

### コンストラクターを作る（Alt+C）

クラスの中（または `class` / `struct` の行）にカーソルを置いて押すと、データ メンバーを全部受け取るコンストラクターを、初期化リストつきで作ります。

```cpp
class Player {
 public:
  Player(const std::string& name, int hp, float speed)
      : name_(name), hp_(hp), speed_(speed) {}
  // ...
 private:
  std::string name_;
  int hp_ = 100;
  float speed_;
};
```

- 引数の名前は、メンバー名から末尾の `_` と先頭の `m_` を取ったものです。
- 引数の型は、組み込みの型・ポインター・参照・`std::string_view` ならそのまま、それ以外は `const T&` にします。`std::unique_ptr` / `std::shared_ptr` は値で受けて `std::move` します。
- メンバーが 1 つだけなら `explicit` を付けます。
- 80 桁に収まらないときは、Google スタイルで折り返します。
- `static`・`mutable`・関数・`using`・ビットフィールド・配列は対象にしません。`int a, b;` のように 1 行に複数のメンバーを書いているときは、作りません。
- 同じ個数の引数のコンストラクターがすでにあるときは、作りません。
- `public:` があればその直後に、なければ（`struct` は先頭に、`class` は `public:` を足して）入れます。

### 基底クラスの仮想関数を override する（Alt+O）

`class Circle : public Shape` のように基底クラスを書いたクラスの中（または `class` の行）で押すと、基底クラスの仮想関数のうち、このクラスにまだないものの `override` 宣言を足します。

```cpp
class Shape {
 public:
  virtual ~Shape() = default;
  virtual void Draw(Renderer& r, int layer = 0) const = 0;
  virtual float Area() const = 0;
  virtual void Update(float dt) {}
};

class Circle : public Shape {
 public:
  void Draw(Renderer& r, int layer) const override;   // ← Alt+O で、この 2 行が入る
  float Area() const override;
  Circle(float r);
};
```

- 純粋仮想関数が残っていれば、それだけを足します（派生クラスを作るのに必須なため）。残りの `virtual`（`Update` など）は、もう一度押すと足します。
- 基底クラスの定義は、いまのファイル、`#include "..."` をたどった先（3 段まで）、ソリューションのヘッダーの索引から探します。基底クラスのさらに基底の仮想関数も対象で、近い基底の宣言を先に使います。
- 引数の既定値（`int layer = 0`）は書きません。仮想関数の既定値は静的な型で決まり、`override` 側に書くと食い違いやすいためです。
- デストラクターと演算子は対象外です。同じ名前で引数の個数が同じ関数がすでにあれば、足しません。
- 入れる位置は、コンストラクターと同じです（`public:` の直後）。cpp の定義は作りません。足したあとで Alt+R（宣言から定義を作る）を押すと、cpp に雛形が入ります。

### 呼び出しから関数を作る（Alt+U）

まだない関数を、先に呼び出しから書く。C# の「使い方から生成」と同じ流れです。呼び出しの行にカーソルを置いて押すと、その関数を作ります。

```cpp
void Player::Update(float dt) {
  int hp = 3;
  std::string name = "a";
  Heal(hp, name, 2.5f, dt);       // ← この行で Alt+U
}
```

- 呼び出しがメンバー関数の中の `Heal(...)` や `this->Heal(...)` なら、そのクラスのメンバーにします。ヘッダーのクラスの末尾に `void Heal(int hp, const std::string& name, float arg3, float dt);` を足し、cpp に `Player::Heal` の定義の雛形（Alt+R と同じ形）を足します。
- `obj.Heal(...)` / `obj->Heal(...)` なら、`obj` の宣言（引数・ローカル変数）から型を読んで、そのクラスの `public:` に足します。`std::unique_ptr<Enemy>` のようなスマート ポインターは中の型を使います。型を決められないときは、何もしません。
- クラスの外（cpp の自由関数の中）なら、いまの関数の前に、中身が `// TODO` の自由関数を足します。
- 引数の型は、リテラル（`2.5f` → `float`、`"a"` → `const char*`）と、同じ関数の中で見える変数の宣言から決めます。組み込みの型・ポインター・参照はそのまま、ほかは `const T&` にします。引数の名前は、変数ならその名前（`m_` と末尾の `_` を除く）、式なら `arg3` のようにします。
- 戻り値の型は、使われ方から決めます。`float x = Foo();` なら `float`、`if (Foo())` や `!Foo()` なら `bool`、`return Foo();` なら囲んでいる関数の戻り値の型、文として呼んでいれば `void`。決められなければ `int` にして、ステータスバーで知らせます。`auto x = Foo();` も `int` になります。
- 型を決められなかった引数（関数の戻り値や、`x + 1` のような式）は `int` にして、ステータスバーに式を出します。
- 同じ名前の関数がそのクラスにすでにあれば、作りません。クラスの外の関数が別のヘッダーにあるかどうかは見ないので、すでにある関数の行で押さないでください。
- cpp がない（ヘッダーだけの）クラスには、`{ return {}; }` の本体つきで足します。

どれも電球（`Ctrl+.`）に出ます（`switch` の行、`class` / `struct` の行。呼び出しから関数を作るのは、キーだけです）。1 回の編集なので、Undo も 1 回です。

## 呼び出しの引数をビルド前にチェックする（自動）

`std::make_unique<SwapChain>(a, b, c)` のように、**引数の個数がどのコンストラクターにも合わない**呼び出しに、ビルドの前に、エディターで赤い波線を引きます。波線にカーソルを置くと、「`SwapChain` のコンストラクターに 3 個の引数を受け取るものがありません」と、候補のコンストラクターが出ます。

- **調べる呼び出し。** `std::make_unique<T>(…)`、`std::make_shared<T>(…)`、`new T(…)`。入力が止まって 0.7 秒たつと調べます（設定で変えられます）。
- **コンストラクターの探し方。** `T` がいまのファイルで定義されていればそれ、なければソリューションのヘッダーの索引で 1 つに決まるヘッダーから読みます。ヘッダーを編集中（保存前）でも、エディターの内容で調べ、ヘッダーを直すと開いている cpp の波線もやり直します。既定の引数と、`...`（可変長）は数えます。
- **波線の位置。** 引数が多いときは、余った引数から。足りないときは、`( )` 全体です。入力中の呼び出しには、「足りない」とは言いません（まだ打っている途中のため）。キャレットが外へ出ると出ます。
- **確実なものだけ出します。** 個数だけを見て、型の違い（`const`・暗黙の変換・参照）は見ません。次のクラスは、調べません: コンストラクターを書いていないクラス（集成体）、テンプレートのクラス、`using Base::Base;` で継承したコンストラクターのあるクラス、マクロが書かれているクラス、定義が 1 つに決まらないクラス、`std::` の型。1 個だけ渡していて、リテラルでなければ、コピー・ムーブかもしれないので出しません。引数の中に `...`（パック展開）があるときも出しません。
- **間違って出るとき。** 設定の「調べないクラス」に、そのクラスを書くと出なくなります。「波線の色」を Warning にすると、緑の波線（警告）になります。設定の True / False で、全体も `make_unique` / `new` も切れます。

この波線は、エディターだけのものです。エラー一覧には出ず、ビルドの結果にも影響しません。型の違いまで知りたいときは、ビルド後のエラーログ（下）が、呼び出しの行と候補のコンストラクターを並べます。

## ファイル名をまとめて変える（Alt+N・自動）

ヘッダー（`Foo.h`）か cpp（`Foo.cpp`）の名前を変えたとき、ほかに直す所を、まとめて直します。

- **相手のファイル。** `Foo.h` を `Bar.h` にすると、同じフォルダーの `Foo.cpp`（`.cc` `.cxx`）も `Bar.cpp` にします。cpp を変えたときは、`Foo.h`（`.hpp` `.hh` `.hxx`）も同じです。新しい名前がすでに使われているときは、相手には触れません。プロジェクトに入っているファイルは、プロジェクトごと名前を変えます。
- **`#include`。** ソリューションの全ファイルの `#include "Foo.h"` を、`#include "Bar.h"` に直します。フォルダーつき（`"core/Foo.h"`）も、フォルダーを保ったまま直します。指しているのが、本当に名前を変えたファイルかを確かめます。コンパイラと同じ順（そのファイルのフォルダー、プロジェクトの `#include` の基準）で探して、同じ名前の別のファイルには触れません。
- **CMake。** `CMakeLists.txt` と `.cmake` の `src/Foo.cpp` なども直します（`MyFoo.cpp` や `Foo.cpp.in` のように、名前の一部だけが同じものには触れません）。直したあとは、CMake の再構成が要ります。
- **文字コード。** エディターで開いていないファイルは、元の文字コード（UTF-8、BOM つき UTF-8、シフト JIS）のまま書き換えます。開いているファイルは、エディターの文字を書き換えます（Undo できます。保存はしません）。

**自動で動きます**（設定の「ヘッダー・cpp の名前を変えたときのしかた」が `Auto`、初期値）。Alt+N を押す必要はありません。名前を変えたことを、次の 2 つで見つけます。

- **Solution Explorer** での名前変更（F2）。
- **フォルダーの監視**。フォルダー ビュー（CMake）、エクスプローラー、`git mv`、別のツールでの名前変更も見つけます。ヘッダーと cpp どうしの名前変更だけを見て、保存の一時ファイルなどは見ません。

次の場合は、自動では直しません。

- **一括の操作。** 3 秒の間に、設定の件数（初期値 4）より多くの名前変更が起きたときは、git のブランチ切り替えなどとみなして、何もしません（ステータスバーで知らせます）。
- **取り消された変更。** 通知のあと、元に戻された・すでに別の名前になったときは、何もしません。
- **設定で止めたとき。** 「直す前に確認する」を True にすると、ダイアログで確認してから直します。

**Alt+N** は、開いているヘッダー（か cpp）の新しい名前（拡張子なし）を入力欄で決めて、同じことを行います（自動を切っているとき用です）。

名前を変えるのは、ファイルだけです。クラス名、インクルード ガード（`FOO_H`）、ファイルの中の文字は、直しません。フォルダーを動かす操作や、別のフォルダーへの移動も、対象外です。

## エラーログ（K-ErrorLog）

C++ のビルドエラーを、**色つきの専用ログ窓**に整理して出します。「出力」ウィンドウのとなりにタブで並びます。ビルドが終わると、エラーがあるときだけ前に出ます（入力の邪魔はしません）。拡張機能 メニューの「K-ErrorLog (エラーログ)を開く」から、いつでも開けます。

- **未解決の外部シンボル（LNK2019 / LNK2001）を、原因ごとにまとめる。** 同じシンボルを 1 つにして、起動関数がない・`.lib` が足りない（ビット数違いや `dllimport` の食い違いも指摘）・Windows / DirectX の `.lib`・vtable や static メンバーの定義漏れ・定義はあるのにリンクされていない、などを判定し、何をすれば直るかまで書きます。`.lib` はソリューションの下を読み（シンボルの索引だけを読むので速い）、定義の探索はソースの文字列検索です。**推測**なので、「原文」表示と見比べてください
- **そのほかのリンカー エラー。** `LNK2005`（二重定義）、`LNK2038`（`RuntimeLibrary` や `_ITERATOR_DEBUG_LEVEL` の不一致を並べて表示）、`LNK1104` / `LNK1181` など
- **テンプレートのエラーを読みやすくする。** `std::basic_string<char, …>` → `std::string`、`std::unique_ptr<T, std::default_delete<T>>` → `std::unique_ptr<T>` のように型名を短くし、渡した型と期待する型を 2 行に並べ、テンプレート引数を 1 行ずつに分けます
- **原因の場所と経路。** エラーが `<memory>` の中で出ていても、自分のコードの呼び出し行を探してリンクにします。「see reference to function template instantiation … being compiled」の連なりは、自分のコードの行を強調し、ライブラリの中の段は畳みます（「経路を全部表示」で展開）。オーバーロードの候補と落ちた理由（`C2672`、`C2784` など）も並べます
- **読みやすさのための案内。** エラーが複数あるときは、先頭に「まず一番上のエラーから直す」と出します。同じ原因から続いているエラーには「連鎖の可能性」と書き、原因の候補（上のエラー）へのリンクを出します（未定義の名前を含むエラー、同じファイルの構文エラーより後ろのエラー）。名前入りの説明（`「GraphicsModule」は、この場所から見えていません…`）と、直し方の例（修正前と修正後のコード）が付くコードもあります。ヒントがあるコードは約 220 個で、ないコードにも「公式のページで調べる」案内が出ます
- **警告がエラーになっているとき（C2220）。** `/WX` で、警告がエラー扱いになっています。原因の警告を、リンクつきで並べます
- **二重定義（LNK2005）。** 変数なら「ヘッダーに `extern` なしで書いた」、関数なら「`inline` なしで本体を書いた」と、原因を分けて説明します
- 主なエラー コードに、日本語の見出しとヒントを付けます。日本語版・英語版の Visual Studio の出力と、GCC / Clang の形式を読みます
- 色は Visual Studio のテーマ（ダーク / ライト）に合わせて変わります。ファイルの場所を押すとその行へ飛び、シンボルの横の「宣言を検索」で、ソリューション全体から探して「検索結果 1」に出します
- <strong>1 件を 2〜3 行で見せる。</strong> 1 行目は「エラー コード・日本語の見出し・場所」で、`C2065` のようなコードを押すと、公式のページ（検索）が開きます。続けて、メッセージ、ソースの 1 行、ヒントが 1 行だけ出ます。経路・候補・補足・例・同じ内容の別の場所は、行頭の「▸」を押すと開きます。連鎖の可能性があるエラーは、見出しの 1 行だけに畳みます。
- <strong>縮小変換の修正ボタン。</strong> `double` から `int`、`size_t` から `int` のような縮小変換の警告・エラーで、1 行で終わる「型 名前 = 式;」「名前 = 式;」「return 式;」「型 名前{式};」なら、「右辺を static_cast<型>(…) にする」を押すと、その行を書き換えます（Ctrl+Z で戻せます）。引数の途中や複数行の式は、場所を決められないので出しません。値が切り捨てられてよいかは、自分で確かめます。
- <strong>ファイル別の目次。</strong> エラーのあるファイルが 2 つ以上のとき、先頭に「ファイル別」の一覧（ファイル名と件数）が出ます。押すと、そのファイルの最初のエラーへ移ります。
- <strong>窓の高さ。</strong> 下のパネルが低いとき、自動で開くたびに高くします（高くしてあるときは触りません）。
- 窓の上の**警告も表示**と**原文**（整理せずに色だけ付ける）で表示を切り替えます。**コピー**は、いま見えている内容を文字にします。「…」のメニューに、**すべての詳細を開く**・**経路を全部表示**・**原文を併記**・**原文をコピー**（AI や質問に貼る用）があります

ビルド欄の文字を読むので、ビルドのあとで「出力」を消すと「再読み込み」で何も出ません。`.lib` の探索はソリューションのフォルダーの下だけです。以前に別の拡張として配布していた K-ErrorLog と K-CppErr は、この拡張に統合しました。K-ErrorLog を入れている場合は、二重に出ないように、Visual Studio の「拡張機能の管理」から外してください。

## 設定

拡張機能 メニューの「K-CppAssist の設定...」から開けます（ツール → オプション → K-CppAssist → 全般と同じ画面です）。

- <strong>ゲッターとセッターの間に空行を入れる</strong>（初期値は True）。True のときはゲッターの前（直前がメンバーの行のとき）とゲッターとセッターの間に空行を 1 行入れます。
- <strong>書き換えた場所を小さなウィンドウで見せる</strong>（初期値は True）。引数を相手のファイルへ写したときと名前を変えたときに、変えた内容（前の行と書き換えたあとの行）を約 3 秒だけ見せます。ウィンドウは変えた関数や変数の名前の 1 文字目に左端をそろえて、その行のすぐ上に出ます。上に収まらなければ行のすぐ下に出ます。どちらでも名前には重なりません。フォーカスは奪いません。
- <strong>宣言の名前を変えたら、使っている場所も変える</strong>。`Off`（何もしない）・`OnLeave`（カーソルが名前から離れたときにまとめて変える）・`Auto`（打つそばから変える）。初期値は `Auto`。
- <strong>型が分からない obj.name も変える</strong>（初期値は False）。False のときは、`obj` の型を宣言から読めて同じクラスだと分かるものだけ変えます。
- <strong>引数の並べ替え・削除を、呼び出しにも写す</strong>（初期値は True）。
- <strong>電球（Quick Fix）に出す</strong>（初期値は True）。`Ctrl+.` の電球にこのツールの機能を出します。
- <strong>エラーログを使う</strong>。初期値は True。False にすると、ビルドが終わってもエラーログを作りません（窓も自動では開きません）。ビルドを重くしたくないときや、エラーログが要らないときに切ります。
- <strong>エラーがあるとき、窓を自動で前に出す</strong>。初期値は True。False のときは、拡張機能 メニューの「K-ErrorLog (エラーログ)を開く」から開きます。
- <strong>原因を探す (.lib とソースの検索)</strong>。初期値は True。未解決の外部シンボル（LNK2019 など）について、ソリューションの `.lib` とソースを探して、原因を言い当てます。時間がかかるときは False にします。「探す時間の上限 (秒)」（初期値 6）と「読む .lib の数の上限」（初期値 800）も変えられます。
- <strong>型名を短くする</strong>。初期値は True。`std::basic_string<char, …>` を `std::string` のようにします。False にすると、コンパイラの出した型名のまま出します。
- <strong>日本語のヒントを出す</strong>。初期値は True。エラー コードごとの見出しの下に、対処のヒントを出します。
- <strong>エラーログ（窓の初期値）</strong>。「警告も表示」「経路を全部表示」「原文を併記」「原文」の、窓を開いたときの初期値です。窓の上のチェックボックスと「…」のメニューは、開いたあとで切り替えられます。
- <strong>#include を足すしかた / 宣言と定義の引数を合わせるしかた</strong>。それぞれ `Off`（何もしない）・`ManualOnly`（キーを押したときだけ）・`Auto`（入力中に自動）。初期値は `#include` が `ManualOnly`、引数の同期が `Auto` です。
- <strong>ヘッダー・cpp の名前を変えたときのしかた</strong>。`Off` / `ManualOnly`（Alt+N だけ）/ `Auto`（Solution Explorer での名前変更も自動）。初期値は `Auto`。
- <strong>相手のファイルも同じ名前にする</strong>。初期値は True。False にすると、`#include` と CMake だけを直します。
- <strong>CMake の書き方も直す</strong>。初期値は True。
- <strong>ステータスバーに知らせる</strong>。初期値は True。#include を足した、引数を写した、ファイル名を直した、などを 1 行出します。False でも、失敗の知らせは出ます。
- <strong>ログを残す</strong>。初期値は True。動作の記録を `%LOCALAPPDATA%\K-CppAssist\vsix.log` に書きます。
- <strong>標準・Windows・DirectX の表を使う / ソリューションのヘッダーの索引を使う</strong>。どちらも初期値は True。`#include` を決める 2 つの元を、別々に切れます。
- <strong>自分で決める対応 (名前=ヘッダー)</strong>。`Vec3="math/vec3.h";Json=<nlohmann/json.hpp>` のように、`;` か改行で区切って書きます。組み込みの表より先に使います。自動でも使われます。
- <strong>.h でも、ソリューションの型を自動で足す</strong>。初期値は False。ヘッダーに自動で足すのは、標準・Windows・DirectX の表と、自分で決めた対応のものだけです（循環 include を避けるため）。True にすると、ソリューションの型も足します。
- <strong>自動で足した #include を戻すまでの秒数</strong>。初期値は 40。足した直後に識別子を消したら戻す、その猶予です。0 で、戻しません。
- <strong>#include も新しい名前に直す / ファイルの名前変更を、フォルダーの監視でも見つける / 多数の名前変更を、自動では直さない件数 / 直す前に確認する</strong>。ファイル名の同期の細かい設定です。初期値は True / True / 4 / False。
- <strong>先頭に「まず一番上から」の案内を出す / 連鎖の可能性を示す / 直し方の例を出す / 一度に出すエラーの数の上限</strong>。エラーログの表示の設定です。初期値は True / True / True / 400。
- <strong>引数の個数をビルド前にチェックする</strong>。初期値は True。`make_unique` / `make_shared` / `new` の引数の個数が合わない呼び出しに波線を引きます。「波線の色」（Error / Warning。初期値は Error）、「入力が止まってから調べるまでの待ち」（初期値 700 ミリ秒）、「`make_unique` / `make_shared` を調べる」「`new T(…)` を調べる」（どちらも True）、「調べないクラス」（カンマ区切り）があります。
- <strong>キー。</strong> コマンドのキーをここで変えられます。「Alt+Q」「Ctrl+Alt+M」のように書き OK を押すと Visual Studio のキー割り当てに反映されます。空にするとキーを外します。開いたときは今の割り当てが表示されます。

## 制限

- 対象は `名前 = 右辺;` の形の文です。`int x = 0;` のようにすでに型があるものは対象外です。右辺が何行に分かれていてもラムダの中の 1 文（`[this] { count_ = 1; }`）でもその文のどこにカーソルがあっても働きます。`;` をまだ書いていない行は続きの行がなさそうならそこまでを 1 文として読みます。
- Alt+W と Alt+E は `Class::Func(` の形の定義の中とクラスの本体に直接書いた関数（ヘッダーのインライン関数）の中で働きます。字下げされていても引数が複数行に分かれていても見つかります。ラムダの中は囲んでいる関数のクラスに足します。クラスに属さない関数の中では使えません。
- ヘッダーはいまのファイルの中にクラスの定義があればそれなければソリューションのフォルダーの下から探します。cpp と同じ名前の `.h` を先に見て、そこに 1 つだけ合えば決めます。なければ `class Class {` を含む `.h` を探します。
- クラスが入れ子（`Outer::Inner::Func`）のときは `Outer` が外側にあるクラスだけを選びます。同じ名前のクラスが別の `namespace` にもあるときは、cpp を囲む `namespace` と外側の名前が末尾から多く一致するほうに足します。決められなければ選ぶ欄を出します。cpp が `using namespace` だけで修飾を省いているときは、`namespace` が分からないので選ぶ欄になることがあります。
- 演算子を含む右辺は部分の型から組み立てます（上の「型の決め方」）。ユーザー定義の演算子が別の型を返すとき `enum` と整数の演算、型の分からない部分が混じるときは決められず入力欄（Alt+W）か `auto`（Alt+Q）になります。
- Alt+W は Visual Studio の「ウィンドウ」メニューのアクセスキーと重なります。効かないときは設定のキーで別のキーに付け替えてください。
- 失敗したときはステータスバーに理由が出ます。詳しいログは `%LOCALAPPDATA%\K-CppAssist\vsix.log` です。
- 呼び出しのチェックは、引数の「個数」だけを見ます。型の違い（`const`・暗黙の変換）は、ビルドして初めて分かります。`T` のコンストラクターを読めないとき（マクロ・テンプレート・継承したコンストラクター・定義が複数）は、何も出しません。`emplace_back` や `T x(…)` の宣言は、まだ調べません。
