# 学習ロードマップ

このサイトは、ページ数が多く、どこから読めばいいか迷います。とくに C++ を覚えたてのころは、STL の関数を片っ端から読んでも、ゲームは作れるようになりません。ゲームが動くまでに必要なものは、言語、道具、数学、描画、設計と、分野をまたぐからです。

ここでは、「何を作りたいか」から逆に、読む順番を示します。全部を順に読む必要はありません。自分の段階に合う列を選び、詰まったときだけ別の列に寄り道してください。

!!! info "このページを読む前に"
    - [このサイトの読み方](how-to-read.md)（ランクや速さのバッジの意味）

## 段階 1：C++ のコードを動かす {#step1}

まず、書いて、ビルドして、動かせる状態を作ります。

1. [インストールとプロジェクトの作成](vs/setup.md)
2. [C++23 を使えるようにする設定](vs/settings.md)
3. [文字コードを UTF-8 にしよう](vs/utf8.md)
4. [デバッグのやり方](vs/debugging.md)
5. [Git の基礎](vs/git.md)（早いうちに覚えると、壊したときに戻れる）

ここで詰まったら、[よくあるエラー](vs/errors.md) を見ます。

## 段階 2：言語の基礎を固める {#step2}

ゲームのコードを読み書きするのに必要な、C++ の仕組みです。

1. [基礎](basics/index.md) の、ポインタ、参照、ムーブ、所有権
2. [STL](stl/index.md) の `vector`、`string`、`unordered_map`、`unique_ptr` から。全部を読まず、よく使う（`rank-must` / `rank-often`）ものだけでよい
3. [最適化](optimize/index.md) の「計測」だけ。速さの話は、測れるようになってから

## 段階 3：2D か 3D かを決めて、ゲームを作る {#step3}

ここから、作りたいものによって分かれます。

| 作りたいもの | 読む順番 |
| --- | --- |
| まず 2D のミニゲーム | [ゲームエンジン](engine/index.md)（ゲームループ、シーン、リソース）、[外部ライブラリ](libs/index.md)（描画・音のライブラリ） |
| 3D のゲーム | [ゲーム数学](gamemath/index.md) → [3D ゲーム](3d/index.md) → [DirectX](directx/index.md) |
| 設計をきれいにしたい | [設計](design/index.md) の、ステートマシン、イベント、オブジェクトプール |
| Unity と組み合わせたい | [C# 連携](csharp/index.md) |

3D を作るなら、数学を飛ばさないでください。ベクトル、行列、クォータニオンは、見た目に直結します。分かった気にならず、実際に動かして確かめます。

## 段階 4：見た目を良くする {#step4}

動くようになったら、見た目と速さを磨きます。

1. [シェーダー](graphics/index.md)：ライティング、影、ポストプロセスの原理
2. [描画最適化](rendering/index.md)：それを軽くする方法
3. [RenderDoc と PIX](vs/renderdoc-pix.md)、[GPU デバッグの流れ](vs/gpu-debug.md)：描画が壊れたときの調べ方

「シェーダー」と「描画最適化」は、同じ話題を、原理と軽量化に分けた対になっています。

## 段階 5：チームで作る {#step5}

複数人で作り始めたら、道具を整えます。

1. [チーム開発の進め方](vs/team.md)
2. [Git LFS とゲームのリポジトリ](vs/git-lfs.md)
3. [GitHub Actions で自動ビルド](vs/github-actions.md)
4. [単体テスト](vs/unit-test.md) と [clang-tidy](vs/clang-tidy.md)

## これだけ覚える {#summary}

- 順に全部を読まず、作りたいものから逆に選ぶ

- 詰まったら寄り道して、また戻る
