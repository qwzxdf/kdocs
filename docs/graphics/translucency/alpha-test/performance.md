# Performance and Shadow Passes

<strong>アルファ テストを使うシェーダーは、Early-Z（早期の深度テスト）が効かず、重くなります</strong>。影や深度のパスでもアルファ テストが必要です。このページではパフォーマンスへの影響と、影・深度パスでの扱いを説明します。

!!! tip "ポイント"
    - clip を使うと、Early-Z が無効（または、効きが悪い）。
    - 対策：深度プリパスで、アルファ テストを先に済ませる。
    - 葉などはポリゴンで形に切り抜くと、clip を減らせる。
    - 影のパスでもアルファ テストが必要（葉の影が板状にならない）。

## パフォーマンス：Early-Z が効かない
<strong>`clip` を含むシェーダーは「深度を書くかどうか」がシェーダー実行後でないと決まらない</strong>ため、Early-Z（シェーダーの前に深度テスト）が使えません。

Early-Z が効かない理由です。Early-Z はピクセル シェーダーの前に深度テストを行い、隠れた画素のシェーダーを省く仕組みです。`clip` があるとハードウェアはシェーダーの後でないと、深度を書くか分かりません。その影響で隠れた葉でもシェーダーが走り、オーバードローが重くなります。

### 対策

| 方法 | 内容 |
| --- | --- |
| 深度プリパスでアルファ テスト物も描く | 深度だけを軽いシェーダー（テクスチャ 1 回と `clip`）で先に描き、本描画は深度 `EQUAL`。本描画の重いシェーダーが見える葉にだけ走る |
| 不透明物を先に描く | アルファ テスト物の前に不透明物を描いて深度を埋める（Early-Z が、アルファ テスト物を隠す） |
| ジオメトリで形を作る | 葉をアルファの形に近い多角形で作り、無駄な透明部分を減らす（オーバードローを減らす） |
| `[earlydepthstencil]` | 強制的に Early-Z（`clip` の結果が深度に影響しない場合のみ。通常は使えない） |

不透明 → アルファ テスト → 半透明の順で描くのが、一般的な構成です。

## 影・深度パスでのアルファ テスト
<strong>影（シャドウ マップ）や深度プリパス</strong>でも、葉の形で影を落とすにはアルファ テストが必要です。これらのパスにも同じ `clip` を入れます（[特殊な影](../../shadows/special-cases/index.md)）。

## アルファ テストが GPU にとって、高い理由

アルファ テスト（`clip` / `discard`）を使うと、GPU の <strong>高速化の機能</strong>の一部が使えなくなります。

### ① Early-Z が、効かなくなる

GPU はふつう ピクセル シェーダーを実行する前に 深度テストを行い（Early-Z）、手前に別の物があって見えない画素は、シェーダーを実行せずに捨てます。ところが、ピクセル シェーダーの中で `clip` する場合、その画素が残るかどうかはシェーダーを実行しないと分かりません。そのため、深度の書き込みはシェーダーの後でなければできず、Early-Z が制限されます。

| | 通常の描画 | `clip` を使う描画 |
| --- | --- | --- |
| 深度テスト | シェーダーの前（Early-Z） | シェーダーの後（Late-Z）、または制限付きの Early-Z |
| 隠れた画素 | シェーダーを実行しない | シェーダーを実行してから、捨てる |
| 深度の書き込み | シェーダーの前でも、可能 | シェーダーの後 |

葉や草のように画面を何重にも、覆う物を `clip` で描くと 奥の葉まで、すべてのピクセル シェーダーが実行されます（オーバードローがそのままコストに）。

### ② HiZ（階層的な、深度）の更新

GPU は 階層化された深度（HiZ）を持ち、タイル（数十画素）ごとにまとめて、深度テストして、隠れたタイルを一気に捨てます。`clip` を使うとそのタイルが完全に塗りつぶされるか分からないので、HiZ の更新が制限されます（実装は、GPU ごとに異なる）。

## 影響を減らす 5 つの方法

### 方法 1：不透明な部分を分ける（ジオメトリで切り抜く）

葉を <strong>四角い板に絵を貼る</strong>のではなく、葉の形にジオメトリを切り抜くと `clip` が、不要な部分が増えます。

| 部分 | 描き方 |
| --- | --- |
| 葉の中の完全に不透明な部分 | `clip` なしの、メッシュ（Early-Z が、効く） |
| 葉の縁（アルファのある部分） | `clip` ありの、メッシュ |

メッシュを 2 つに分けて、描きます。不透明な部分で先に深度を書き、縁の部分はあとで描くと Early-Z が、効いた状態で縁の描画ができます。

### 方法 2：Z プリパス（深度だけを先に描く）

画面全体の深度を 先に軽いシェーダーで、描いて、本描画では深度が一致する画素だけを実行します。

```text
パス 1（Z プリパス）: 深度だけを描く。色は計算しない。clip は必要（アルファ テストする物は、clip する）。
パス 2（本描画）  : 深度テストを「等しい」にして描く。Early-Z が効き、隠れた画素は、重いシェーダーを実行しない。
```

| パス | 内容 |
| --- | --- |
| 1. 深度プリパス | 軽いピクセル シェーダー（テクスチャを読んで、`clip` するだけ）で深度を書く |
| 2. 本描画 | 重いライティングを行う。深度テストは `EQUAL`（または `LESS_EQUAL`）。深度が一致した画素だけ実行される |

```cpp
// 本描画: 深度の書き込みを無効にし、テストを「等しい」にする。
D3D11_DEPTH_STENCIL_DESC ds = {};
ds.DepthEnable = TRUE;
ds.DepthWriteMask = D3D11_DEPTH_WRITE_MASK_ZERO;          // 書き込まない（プリパスで、書いた）
ds.DepthFunc = D3D11_COMPARISON_EQUAL;                    // プリパスの深度と、一致する画素だけ
device->CreateDepthStencilState(&ds, &depth_equal_state);
```

プリパスでアルファ テストした結果が深度に入るので 本描画では `clip` が、不要になります。重いシェーダーが実行される画素は、最終的に見える画素だけです。

!!! warning "プリパスと、本描画の深度を完全に同じにする"
    プリパスと本描画で頂点シェーダーの、計算が 1 ビットでも違うと深度が一致せず 画素が欠けます（`EQUAL` の、落とし穴）。同じ頂点シェーダーを共有し `invariant` な計算を保つ。DirectX 11 では同じ頂点シェーダーを使えば、同じ結果になることが一般的ですが別の、シェーダーを使うとずれる可能性があります。

### 方法 3：アルファの範囲を狭める

葉の板（カード）に 透明部分が多すぎると透明な画素のシェーダーが無駄です。板の形を葉の輪郭に合わせて切る（タイトなメッシュ）と、透明な画素が減りオーバードロー（重なり）も、減ります。

| 板の形 | 透明な部分 | 無駄なシェーダー実行 |
| --- | --- | --- |
| 正方形 | 約 60% | 多い |
| 葉の輪郭に合わせて 8〜12 頂点で、切る | 約 15% | 少ない |

頂点数を少し増やしてピクセルを大きく減らすのは よい取引です。

### 方法 4：ミップ レベルをコントロール

アルファのミップが薄くなる問題（[Foliage Translucency](../../terrain/vegetation/translucency.md)）を補正したミップを使えば 遠くで葉がスカスカになりません。結果、カード（板）を増やして補う必要がなくなりオーバードローが減ります。

### 方法 5：遠景はアルファを使わない

遠くの木は インポスター（板 1 枚）、または アルファを使わないメッシュ（LOD で葉を塊の、不透明な形にする）に置き換えます（[Trees](../../terrain/vegetation/trees.md)）。

## 影のパスでのアルファ テスト

シャドウ マップを描くときも <strong>葉をアルファで切り抜く</strong>必要があります。影のパスは深度だけを書くので、軽いピクセル シェーダー（テクスチャを読んで、`clip` するだけ）を使います。

| 工夫 | 内容 |
| --- | --- |
| 影用の軽いシェーダー | アルファの、テクスチャだけを読む。ライティングはしない |
| 影用のアルファ テクスチャ | 低解像度の、ミップを読む（影は細かい形が不要） |
| 遠くの葉は影を落とさない | 影に描く距離を限る |
| 影用の LOD | 描画より、粗い LOD を使う |

## 計測する

| 項目 | 方法 |
| --- | --- |
| オーバードロー | 色で、可視化する（描かれた回数を加算ブレンドで、数える） |
| ピクセル シェーダーの実行回数 | PIX、RenderDoc、GPU プロファイラーのカウンター |
| `clip` の影響 | `clip` を一時的に無効にしてフレーム時間を比べる |

```hlsl
// オーバードロー可視化: 描かれるたびに、少しずつ加算する（加算ブレンド）。
return float4(0.1, 0.05, 0.02, 1.0);
// 結果の、明るい所ほど、重なって描かれた画素が多い
```

草原や森の場面では <strong>オーバードローが 10 倍を超える</strong>こともあります。測らずに最適化しないことが、大切です（[パフォーマンス プロファイラー](../../../vs/profiler.md)）。

## よくあるミス
