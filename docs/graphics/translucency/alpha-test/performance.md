# Performance and Shadow Passes

<strong>アルファ テストを使うシェーダーは、Early-Z（早期の深度テスト）が効かず、重くなります</strong>。<strong>影や深度のパスでも、アルファ テストが必要</strong>です。このページでは、パフォーマンスへの影響と、影・深度パスでの扱いを説明します。

!!! tip "ポイント"
    - clip を使うと、Early-Z が無効（または、効きが悪い）。
    - 対策：深度プリパスで、アルファ テストを先に済ませる。
    - 葉などは、ポリゴンで形に切り抜くと、clip を減らせる。
    - 影のパスでも、アルファ テストが必要（葉の影が板状にならない）。

## パフォーマンス：Early-Z が効かない
<strong>`clip` を含むシェーダーは、「深度を書くかどうか」が、シェーダー実行後でないと決まらない</strong>ため、<strong>Early-Z（シェーダーの前に深度テスト）が、使えません</strong>。

Early-Z が効かない理由です。Early-Z は、ピクセル シェーダーの前に深度テストを行い、隠れた画素のシェーダーを省く仕組みです。`clip` があると、ハードウェアはシェーダーの後でないと、深度を書くか分かりません。その影響で、隠れた葉でもシェーダーが走り、オーバードローが重くなります。

### 対策

| 方法 | 内容 |
| --- | --- |
| 深度プリパスで、アルファ テスト物も描く | 深度だけを、<strong>軽いシェーダー（テクスチャ 1 回と `clip`）</strong>で先に描き、本描画は深度 `EQUAL`。本描画の重いシェーダーが、見える葉にだけ走る |
| 不透明物を先に描く | アルファ テスト物の前に、不透明物を描いて、深度を埋める（Early-Z が、アルファ テスト物を隠す） |
| ジオメトリで形を作る | 葉を、アルファの形に近い多角形で作り、無駄な透明部分を減らす（オーバードローを減らす） |
| `[earlydepthstencil]` | 強制的に Early-Z（`clip` の結果が深度に影響しない場合のみ。通常は使えない） |

<strong>不透明 → アルファ テスト → 半透明</strong>の<strong>順で描く</strong>のが、一般的な構成です。

## 影・深度パスでのアルファ テスト
<strong>影（シャドウ マップ）や深度プリパス</strong>でも、<strong>葉の形で影を落とす</strong>には、アルファ テストが必要です。これらのパスにも、同じ `clip` を入れます（[特殊な影](../../shadows/special-cases/index.md)）。

## アルファ テストが、GPU にとって、高い理由

アルファ テスト（`clip` / `discard`）を、使うと、GPU の、<strong>高速化の機能</strong>の、一部が、<strong>使えなくなります</strong>。

### ① Early-Z が、効かなくなる

GPU は、ふつう、<strong>ピクセル シェーダーを、実行する前</strong>に、<strong>深度テスト</strong>を行い（Early-Z）、手前に、別の物があって、見えない画素は、シェーダーを、実行せずに、捨てます。ところが、ピクセル シェーダーの中で、`clip` する場合、その画素が、残るかどうかは、シェーダーを、実行しないと、分かりません。そのため、深度の書き込みは、シェーダーの後でなければ、できず、Early-Z が、制限されます。

| | 通常の描画 | `clip` を使う描画 |
| --- | --- | --- |
| 深度テスト | シェーダーの前（Early-Z） | シェーダーの後（Late-Z）、または、制限付きの、Early-Z |
| 隠れた画素 | シェーダーを、実行しない | シェーダーを実行してから、捨てる |
| 深度の書き込み | シェーダーの前でも、可能 | シェーダーの後 |

<strong>葉や、草のように、画面を、何重にも、覆う物</strong>を、`clip` で描くと、<strong>奥の葉まで、すべての、ピクセル シェーダーが、実行</strong>されます（オーバードローが、そのままコストに）。

### ② HiZ（階層的な、深度）の、更新

GPU は、<strong>階層化された深度</strong>（HiZ）を、持ち、<strong>タイル（数十画素）ごとに、まとめて、深度テストして</strong>、隠れた、タイルを、一気に、捨てます。`clip` を使うと、そのタイルが、完全に、塗りつぶされるか、分からないので、HiZ の、更新が、制限されます（実装は、GPU ごとに、異なる）。

## 影響を、減らす 5 つの方法

### 方法 1：不透明な、部分を、分ける（ジオメトリで、切り抜く）

葉を、<strong>四角い板に、絵を貼る</strong>のではなく、<strong>葉の形に、ジオメトリを、切り抜く</strong>と、`clip` が、不要な部分が、増えます。

| 部分 | 描き方 |
| --- | --- |
| 葉の、中の、完全に、不透明な部分 | `clip` なしの、メッシュ（Early-Z が、効く） |
| 葉の、縁（アルファの、ある部分） | `clip` ありの、メッシュ |

メッシュを、<strong>2 つに、分けて</strong>、描きます。<strong>不透明な部分</strong>で、先に、深度を書き、縁の部分は、あとで、描くと、Early-Z が、効いた状態で、縁の描画が、できます。

### 方法 2：Z プリパス（深度だけを、先に描く）

<strong>画面全体の、深度</strong>を、<strong>先に、軽いシェーダーで、描いて</strong>、本描画では、深度が、一致する画素だけを、実行します。

```text
パス 1（Z プリパス）: 深度だけを描く。色は計算しない。clip は必要（アルファ テストする物は、clip する）。
パス 2（本描画）  : 深度テストを「等しい」にして描く。Early-Z が効き、隠れた画素は、重いシェーダーを実行しない。
```

| パス | 内容 |
| --- | --- |
| 1. 深度プリパス | 軽いピクセル シェーダー（テクスチャを、読んで、`clip` するだけ）で、深度を書く |
| 2. 本描画 | 重いライティングを、行う。深度テストは、`EQUAL`（または `LESS_EQUAL`）。深度が、一致した画素だけ、実行される |

```cpp
// 本描画: 深度の書き込みを、無効にし、テストを「等しい」にする。
D3D11_DEPTH_STENCIL_DESC ds = {};
ds.DepthEnable = TRUE;
ds.DepthWriteMask = D3D11_DEPTH_WRITE_MASK_ZERO;          // 書き込まない（プリパスで、書いた）
ds.DepthFunc = D3D11_COMPARISON_EQUAL;                    // プリパスの深度と、一致する画素だけ
device->CreateDepthStencilState(&ds, &depth_equal_state);
```

<strong>プリパスで、アルファ テストした結果</strong>が、深度に入るので、<strong>本描画では、`clip` が、不要</strong>になります。重いシェーダーが、実行される画素は、最終的に、見える画素だけです。

!!! warning "プリパスと、本描画の、深度を、完全に、同じにする"
    プリパスと、本描画で、頂点シェーダーの、<strong>計算が、1 ビットでも違う</strong>と、深度が、一致せず、<strong>画素が、欠けます</strong>（`EQUAL` の、落とし穴）。同じ、頂点シェーダーを、共有し、`invariant` な計算を、保つ。DirectX 11 では、同じ頂点シェーダーを使えば、同じ結果になることが、一般的ですが、別の、シェーダーを使うと、ずれる可能性があります。

### 方法 3：アルファの、範囲を、狭める

葉の板（カード）に、<strong>透明部分</strong>が、<strong>多すぎる</strong>と、透明な、画素の、シェーダーが、無駄です。板の形を、葉の輪郭に、合わせて、切る（タイトなメッシュ）と、透明な画素が、減り、オーバードロー（重なり）も、減ります。

| 板の形 | 透明な部分 | 無駄なシェーダー実行 |
| --- | --- | --- |
| 正方形 | 約 60% | 多い |
| 葉の輪郭に、合わせて、8〜12 頂点で、切る | 約 15% | 少ない |

<strong>頂点数を、少し増やして、ピクセルを、大きく減らす</strong>のは、<strong>よい取引</strong>です。

### 方法 4：ミップ レベルを、コントロール

アルファの、ミップが、薄くなる問題（[Foliage Translucency](../../terrain/vegetation/translucency.md)）を、<strong>補正した</strong>ミップを、使えば、<strong>遠くで、葉が、スカスカになりません</strong>。結果、カード（板）を、増やして、補う必要が、なくなり、オーバードローが、減ります。

### 方法 5：遠景は、アルファを、使わない

遠くの木は、<strong>インポスター</strong>（板 1 枚）、または、<strong>アルファを使わない、メッシュ</strong>（LOD で、葉を、塊の、不透明な、形にする）に、置き換えます（[Trees](../../terrain/vegetation/trees.md)）。

## 影のパスでの、アルファ テスト

シャドウ マップを、描くときも、<strong>葉を、アルファで、切り抜く</strong>必要があります。<strong>影のパスは、深度だけ</strong>を、書くので、軽いピクセル シェーダー（テクスチャを読んで、`clip` するだけ）を、使います。

| 工夫 | 内容 |
| --- | --- |
| 影用の、軽い、シェーダー | アルファの、テクスチャだけを、読む。ライティングは、しない |
| 影用の、アルファ テクスチャ | 低解像度の、ミップを、読む（影は、細かい形が、不要） |
| 遠くの、葉は、影を落とさない | 影に、描く、距離を、限る |
| 影用の LOD | 描画より、粗い LOD を、使う |

## 計測する

| 項目 | 方法 |
| --- | --- |
| オーバードロー | 色で、可視化する（描かれた回数を、加算ブレンドで、数える） |
| ピクセル シェーダーの、実行回数 | PIX、RenderDoc、GPU プロファイラーの、カウンター |
| `clip` の、影響 | `clip` を、一時的に、無効にして、フレーム時間を、比べる |

```hlsl
// オーバードロー可視化: 描かれるたびに、少しずつ加算する（加算ブレンド）。
return float4(0.1, 0.05, 0.02, 1.0);
// 結果の、明るい所ほど、重なって描かれた画素が、多い
```

草原や、森の、場面では、<strong>オーバードローが、10 倍を超える</strong>ことも、あります。<strong>測らずに、最適化しない</strong>ことが、大切です（[パフォーマンス プロファイラー](../../../vs/profiler.md)）。

## よくあるミス
