# XeSS

NVIDIA と AMD は、それぞれ自社の GPU を中心にアップスケーラを作りました。Intel の XeSS（Xe Super Sampling）は、<strong>自社の Arc GPU の専用ユニットで高画質に動き、他社の GPU でも動く</strong>、という両取りの設計です。ニューラル ネットワークを使う点は DLSS と同じです。

!!! tip "ポイント"
    - Arc の XMX（行列演算ユニット）では、専用のモデルで動く。高画質
    - それ以外の GPU では、DP4a（整数のドット積命令）で動く、軽めのモデルになる
    - 入力は、低解像度のカラー、深度、動きベクトル、ジッター。FSR や DLSS と共通
    - SDK は DX11 / DX12 / Vulkan に対応

!!! info "このページを読む前に"
    - [Upscaling](index.md)（入力と品質モード）

## 2 つの動き方 {#paths}

XeSS は、動かす GPU によって、使うモデルが変わります。

Intel Arc では、XMX という行列演算ユニットで、大きなモデルを動かします。画質が最も高い経路です。

他社の GPU では、DP4a 命令（4 つの 8 ビット整数の積和を 1 命令で行う）を使う、軽い経路で動きます。モデルが小さく、画質は XMX の経路より落ち、実行時間も長くなる傾向があります。ただし、新しめの GPU ならほぼ動くので、対応範囲が広いのが強みです。

ゲームの側は、どの経路になるかを意識せずに SDK を呼びます。SDK が GPU を見て切り替えます。

## 組み込みの流れ {#integrate}

1. XeSS の SDK を取り込み、描画 API（DX11 / DX12 / Vulkan）のコンテキストを作る
2. 品質モードを選ぶ（Ultra Quality Plus から Ultra Performance までの複数がある）
3. 毎フレーム、ジッターを加えて低解像度で描き、カラー、深度、動きベクトルを渡す
4. 出力の高解像度の画像にポストプロセスと UI を行う

ジッターの並び（Halton 列など）や、動きベクトルの単位の合わせ方は、他のアップスケーラと同様です。SDK が、推奨のジッター量を返す関数を持っています。

## 品質モード {#modes}

XeSS は、他より細かく品質モードを持っています。倍率は 1.3 倍から 3 倍まで、複数の段階があります。比率は版で調整されることがあるので、SDK の定数を使い、自分で決め打ちしません。

## よくあるミス {#mistakes}

??? failure "DP4a の経路で、期待より重い"
    他社 GPU の経路は、Arc より重くなります。ゲーム内の設定で、アップスケールの有無と品質を選べるようにします。

??? failure "動きベクトルの単位が違って、画面が滲む"
    SDK に渡す動きベクトルのスケールが描画側と合っていません。設定の項目で合わせます。

## これだけ覚える {#summary}

- XeSS は、Arc の専用ユニットでは高画質、他社 GPU でも DP4a で動く
- 入力は他のアップスケーラと共通
- 経路の切り替えは SDK がやる。性能は経路で違うので、設定で選べるようにする
