# FSR

アップスケーラを入れたいが、特定のメーカーの GPU でしか動かないのは困る、という場面があります。FSR（FidelityFX Super Resolution）は AMD が作った技術で、<strong>特別な GPU が要らず、ソースが公開されていて、どのメーカーの GPU でも動く</strong>のが特徴です。PC だけでなく、コンソールにも使われます。

!!! tip "ポイント"
    - FSR 1（2021）は空間方式。EASU（拡大）と RCAS（輪郭の強調）の 2 パス
    - FSR 2（2022）は時間方式で、手作りの規則で履歴を使う。動きベクトルとジッターが要る
    - FSR 3 はフレーム生成を足し、3.1 でアップスケーラとフレーム生成が分かれた
    - FSR 4 は機械学習を使う版で、対応する GPU が限られる
    - ライブラリは FidelityFX SDK。DX12 と Vulkan に対応

## 版の違い {#versions}

### FSR 1 {#fsr1}

空間方式です。EASU（Edge Adaptive Spatial Upsampling）がエッジの向きを見ながら拡大し、RCAS（Robust Contrast Adaptive Sharpening）が輪郭を強調します。動きベクトルが要らないので、組み込みが楽ですが、細部の復元には限界があり、低解像度から拡大すると、ぼやけが目立ちます。

### FSR 2 {#fsr2}

時間方式への移行です。DLSS のようなニューラル ネットワークを使わず、決め打ちの規則（深度や色の差から、履歴を捨てるか決める）で動きます。専用ユニットが要らず、どの GPU でも動きます。入力は、カラー、深度、動きベクトル、ジッター、露出です。

### FSR 3 と 3.1 {#fsr3}

FSR 3 は、アップスケーラにフレーム生成（Frame Generation）を足したものです。2 つのレンダリングしたフレームの間に動きの情報から補間したフレームを入れて、見かけのフレーム数を増やします。ただし入力の反応は、補間されたフレームの分は変わらないので、元のフレームレートが低すぎると、操作の重さが気になります。

FSR 3.1 で、アップスケーラとフレーム生成が独立し、別々に差し替えられるようになりました。

### FSR 4 {#fsr4}

機械学習を使う版です。画質が上がる代わりに、対応する GPU が限られます。

## 組み込みの流れ {#integrate}

1. FidelityFX SDK を取り込み、アップスケーラのコンテキストを作る（描画の解像度と出力の解像度を渡す）
2. 毎フレーム、投影行列にジッターを加えて描く（SDK がジッターの並びを計算する関数を持つ）
3. 低解像度のカラー、深度、動きベクトルをアップスケーラに渡して Dispatch する
4. 出力の高解像度の画像にトーンマッピングと UI を適用する

動きベクトルの単位（画面の割合かピクセルか）と向き、深度の向き（逆 Z かどうか）をコンテキストを作るときの設定で合わせます。ここを間違えると、画面が滲むか、揺れます。

## テクスチャのミップ バイアス {#tips}

低解像度で描くと、テクスチャが粗く見えます。テクスチャのサンプリングで、ミップ レベルを少し細かい側にずらす（負のミップ バイアス）と、拡大後のテクスチャが締まります。SDK は、描画の解像度と出力の解像度から、推奨のバイアスを計算する関数を持っています。

## よくあるミス {#mistakes}

??? failure "動く物体の後ろに残像が出る"
    動きベクトルが動く物体の分（スキンメッシュ、粒子）で抜けています。

??? failure "画面全体が揺れる"
    渡したジッター量と、投影行列に加えた量が違います。

## これだけ覚える {#summary}

- FSR は GPU を選ばず、ソースが公開されている
- 1 は空間方式、2 は時間方式、3 でフレーム生成、4 は機械学習
- 動きベクトルとジッターの正確さが、画質を決める
