# Hair Geometry

髪の形をどう作るか。これが、髪の描画の設計の出発点で、後の透明・影・シェーディングのすべてに影響します。大きく 2 つの方法があります。髪の束を**板（カード）**で近似する方法と、**1 本ずつ（ストランド）**描く方法です。このページでは、それぞれの作り方、長所と短所、使い分けを説明します。

!!! tip "ポイント"
    - **カード** ＝ 髪の束の絵を貼った**板ポリ**。**軽く、アーティストが形を制御しやすい**。ゲームの大半。
    - **ストランド** ＝ 髪を**1 本ずつ線**で描く。**10 万本規模**で**最高品質**だが**重い**。
    - カードは<strong>層状に重ねて</strong>、厚みと奥行きを出す。**テクスチャのアルファで切り抜く**。
    - ストランドは<strong>線分の列</strong>。**GPU で、カメラに向いた細い帯に展開**して描く。
    - 髪の動きは、**ボーン**（カード）か**物理シミュレーション**（ストランド）で与える。

## カード（ヘア カード）

カード方式は、髪の束を<strong>細長い板ポリゴン</strong>で表し、そこに**髪の絵（アルベド・アルファ・法線など）**を貼ります。1 枚の板が、数十本から数百本の髪の毛の束を表します。

### 作り方

1. **髪の束の絵を用意する**。髪の毛が束になって流れる様子を描いたテクスチャで、背景は透明（アルファ）です。1 枚のテクスチャ アトラスに、いろいろな形・太さの束を並べておきます。
2. **板を髪の流れに沿って配置する**。頭に沿ってカードを重ね、前髪、側面、後ろ髪を作ります。各カードの向きは、髪が流れる向きに揃えます。
3. **層状に重ねる**。1 層だけだと平坦なので、内側から外側へ、**何層にも**重ねます。内側のカードは暗く、外側は明るくして、奥行きを出します。
4. **毛先を細くする**。カードの端は、細く尖らせ、毛先がバラける様子を、アルファで表現します。

### 長所と短所

長所は、軽いことです。1 キャラクターで数千ポリゴンに収まります。アーティストが形を直接コントロールできるので、髪型の作り込みが容易です。アルファ テストで描けるので、Z バッファをそのまま使えます。

短所は、**近づくと板だと分かる**ことです。カードの輪郭が硬く、髪が「紙のように」見えます。髪の動きも、カード全体が硬く動くため、細かな毛先の動きは表せません。髪型の細かさ（束の細かさ）が、テクスチャの解像度で決まります。

### カードのシェーディングで気をつけること

カードを使うときは、**法線の向き**が重要です。カードの法線は、板の面の法線です。髪のシェーディングは、法線でなく**髪の流れの方向（接線）**を基準にします（[Kajiya-Kay](kajiya-kay.md)）。そこで、カードの UV の V 方向（またはU方向）を、髪の流れの方向に揃えて作り、接線として使います。

もう 1 つ、**法線を頭の中心から外へ向けて**調整する方法がよく使われます。カードの法線を、頭の中心から外向きに（球面に近く）設定すると、髪全体が、1 つの球のように滑らかに照らされ、のっぺりしたカードの境目が目立たなくなります。さらに、髪の毛先に向かうほど暗くなる AO を、頂点カラーに焼いておくと、立体感が増します。

## ストランド

ストランド方式は、髪の毛を<strong>1 本ずつ、線分の列</strong>として表します。1 本のストランドは、根元から毛先まで、数個から十数個の制御点（頂点）で表されます。ストランドの本数は、見た目の品質に直結します。

### データの持ち方

髪の本数は、1 キャラクターで、数万〜十万本を扱います。全部を描画するのは重いので、**ガイド ヘア**と呼ばれる少数の代表的なストランドだけを、物理シミュレーションします。残りのストランドは、ガイド ヘアの周りに**補間して**生成します。たとえば、1 本のガイドにつき 10 本の追従するストランドを生成します。

頂点の情報は、各制御点の位置、太さ、接線方向などです。10 万本のストランドで、1 本あたり 16 点なら、160 万点で、メモリは数十 MB 程度です。

### 描画の流れ

ストランドは、線として描かれますが、GPU は線を細い（1 画素）幅でしか描けません。そこで、ストランドの各線分を、**カメラに向いた細い帯（ビルボード）**に展開して描きます。ジオメトリ シェーダーやメッシュ シェーダー、または、頂点シェーダーで、線分を 2 つの三角形に展開します。

```hlsl
float3 tangent = normalize(p1 - p0);
float3 to_camera = normalize(camera_pos - p0);
float3 side = normalize(cross(tangent, to_camera));
float3 left = p0 - side * (width * 0.5);
float3 right = p0 + side * (width * 0.5);
```

帯の幅は、ストランドの実際の太さ（0.05〜0.1 mm）を使うと、画面上で 1 画素に満たないことが多く、ちらつきが出ます。そのため、**画面上で 1 画素以上になる**ように幅を補正し、足りない分をアルファで薄めます（[Hair Anti-Aliasing](anti-aliasing.md)）。

### 長所と短所

長所は、品質です。1 本 1 本の髪が見えるので、近づいたときのリアルさが圧倒的です。物理シミュレーションで動かせば、風になびく様子、毛先の動き、髪どうしの絡みが自然に表せます。

短所は、重さです。描画するプリミティブが多く、ほとんどが画素より細いため、ラスタライザの効率が悪くなります。半透明の扱い（透明、影、自己影）も、カードより難しく、専用の処理が必要です。メモリと GPU 時間のコストが大きく、描画できるキャラクター数が限られます。

## LOD：カードとストランドの併用

実際のゲームでは、カードとストランドを**距離で切り替える**設計が現実的です。近距離では、ストランドで高品質に描き、中距離では、本数を減らしたストランドや、カードに切り替え、遠距離では、簡易なカードやメッシュにします。切り替えの境で、見た目が急に変わらないよう、シェーディングを共通にし、カードのテクスチャを、ストランドの見た目から**ベイク**して作るのが一般的です。

Unreal Engine の Groom は、同じヘア アセットから、ストランド、カード、メッシュを自動生成する LOD の仕組みを持ちます。

## 髪の動き

髪が動かない（頭に固定された）ゲームでは、髪の形は静的です。髪を動かす場合、方法は、データの持ち方によって違います。

カード方式では、カードに**ボーン**を付けて、物理シミュレーション（バネ・ダンパーや、位置ベース動力学）で動かします。ボーンの数は少ない（髪の束ごとに数本）ので、軽く済みます。ただし、硬い板が動くので、柔らかい髪の動きにはなりません。

ストランド方式では、ガイド ヘアを物理シミュレーションします。各ストランドを、質点とバネ（または位置ベース動力学の拘束）の列としてモデル化し、重力・風・頭の動き・衝突（頭や肩との接触）を解きます。シミュレーションは GPU のコンピュート シェーダーで並列に実行されます（AMD の TressFX、NVIDIA の HairWorks）。計算は重いため、シミュレーションを行うのは、ガイド ヘアの数千本程度に絞ります。

## よくあるミス

??? failure "カードが 1 層で、髪が薄っぺらい"
    **内側から外側へ、何層も重ねる**。内側を暗く、外側を明るくして、奥行きを出す。

??? failure "カードの境目が、はっきり見える"
    カードの**法線を頭の中心から外向き**に調整する。**毛先を細く、アルファで消す**。

??? failure "ストランドが、細すぎてちらつく"
    **画面上で 1 画素以上**になるよう幅を補正し、**足りない分をアルファで薄める**。

??? failure "ストランドの本数が多すぎて、フレーム時間が足りない"
    **ガイド ヘアだけをシミュレーション**し、残りは補間。**距離で本数を減らす（LOD）**。
