# Diffusion Profiles

前のページで、SSS が**拡散プロファイル R_d(r)** という 1 本の曲線で表せることを見ました。この曲線は、**光が入った点から、距離 r だけ離れた場所に、どれだけ光が出てくるか**を表します。このページでは、リアルタイムで使える形にするための**ガウスの和による近似**と、それを使った、最も高品質な実装（d'Eon と Luebke の方法）を説明します。

!!! tip "ポイント"
    - 拡散プロファイルは<strong>RGB ごとに別の曲線</strong>。**赤が広く、青が狭い**。
    - 曲線を<strong>数個のガウスの和</strong>で近似する。**ガウスは、ぼかしが速く、段階的に重ねられる**。
    - d'Eon の方法は、**6 つのガウス**。顔の **UV 空間**にライティングを書き、**段階的にぼかして**足す。
    - **UV の歪み**（伸び縮み）を補正する<strong>ストレッチ マップ</strong>が要る。
    - 最も高品質だが、**キャラごとに UV パスが必要**で重い。

## なぜガウスなのか

拡散プロファイルは、中心が鋭く、裾が長い曲線です。これを、そのままの形でぼかしのカーネルにしようとすると、2 つの問題があります。1 つは、カーネルが大きく、サンプルが多く必要なことです（裾が長いため）。もう 1 つは、2 次元のぼかしを、縦横の 2 回の 1 次元のぼかしに分解できないことです。

ガウス関数には、この問題を解く性質が 2 つあります。

1 つ目は<strong>分離可能</strong>なことです。2 次元のガウスは、横方向の 1 次元ガウスと縦方向の 1 次元ガウスの積に分解できます。そのため、2 次元のぼかしを、横にぼかしてから縦にぼかす 2 回の処理で済ませられます。サンプル数は、N×N から 2N に減ります。

2 つ目は<strong>畳み込みが閉じている</strong>ことです。分散 v₁ のガウスと、分散 v₂ のガウスを畳み込むと、分散 v₁ + v₂ のガウスになります。この性質により、小さいガウスでぼかした結果を、さらにぼかして、大きなガウスの結果を作れます。大きなカーネルを直接使う代わりに、小さなぼかしを何度も重ねられるわけです。

ガウスの 2 次元の式は、次のとおりです。

<div class="formula">G(v, r) = (1 / 2πv) · exp(−r² / 2v)　　（v：分散、r：中心からの距離）</div>

## ガウスの和による近似

拡散プロファイル R(r) を、重み w_i と分散 v_i を持つ複数のガウスの和で近似します。

<div class="formula">R(r) ≈ Σᵢ wᵢ · G(vᵢ, r)</div>

重み w_i は RGB の 3 つの値を持ち、色ごとに別の曲線を表します。d'Eon と Luebke（GPU Gems 3、2007）は、Donner と Jensen の 3 層の肌のモデル（2005）で計算したプロファイルに、**6 つのガウス**をあてはめました。その値は、次のとおりです。分散の単位は mm² で、重みは（R, G, B）の順です。

* 分散 0.0064：(0.233, 0.455, 0.649)
* 分散 0.0484：(0.100, 0.336, 0.344)
* 分散 0.187：(0.118, 0.198, 0.0)
* 分散 0.567：(0.113, 0.007, 0.007)
* 分散 1.99：(0.358, 0.004, 0.0)
* 分散 7.41：(0.078, 0.0, 0.0)

この表の読み方を説明します。分散が小さい（0.0064 や 0.0484）ガウスは、狭い範囲のぼかしで、RGB のすべてに大きな重みがあります。これが「鋭い中心」です。分散が大きくなるにつれて、緑と青の重みが 0 に近づき、**赤だけが残ります**。分散 7.41 のガウスは、赤だけに 0.078 の重みを持ち、これが赤の「長い裾」を作ります。表の数値に、赤が遠くまで広がる性質が、そのまま入っています。

## 実装の流れ（テクスチャ空間のぼかし）

d'Eon の方法は、顔の **UV 空間**でぼかします。流れは次のとおりです。

1. **ライティングの結果を UV 空間に書き出す**。キャラクターの顔を、UV 展開の座標でレンダリングして、各 UV の位置に、その点の拡散光（アルベドを掛ける前の、放射照度）を書き込みます。画面の見た目ではなく、モデルの表面の座標でテクスチャに保存するので、**カメラの向きに依らない**ぼかしができます。
2. **ガウスで段階的にぼかす**。6 つのガウスのぼかしを、順番に行います。分散 v₁ のガウスでぼかした結果を、次に分散 v₂ − v₁ のガウスでぼかすと、分散 v₂ のガウスでぼかした結果になります。この積み重ねで、6 枚のぼかした画像を得ます。ぼかしは、横と縦の 2 パスで、7 タップ程度のカーネルを使います。
3. **重み付きで足し合わせる**。6 枚の画像を、表の重み（RGB ごと）で足します。
4. **アルベドを掛けて、最終的な色にする**。足した結果に、肌のアルベド（色）を掛けます。

```hlsl
float3 sss = 0;
sss += irradiance_blur[0] * float3(0.233, 0.455, 0.649);
sss += irradiance_blur[1] * float3(0.100, 0.336, 0.344);
sss += irradiance_blur[2] * float3(0.118, 0.198, 0.000);
sss += irradiance_blur[3] * float3(0.113, 0.007, 0.007);
sss += irradiance_blur[4] * float3(0.358, 0.004, 0.000);
sss += irradiance_blur[5] * float3(0.078, 0.000, 0.000);
float3 diffuse = sss * albedo;
```

## UV の歪みを補正する

UV 空間でぼかすときの問題は、**UV の距離が、実際の表面の距離と違う**ことです。顔の UV 展開は、場所によって引き伸ばされたり縮められたりしています。たとえば、鼻の側面は、UV では細く圧縮されているかもしれません。UV の距離のままぼかすと、そこでは、実際より広くぼけてしまいます。

この歪みを補正するのが、**ストレッチ マップ**（stretch map）です。UV の各位置で、「UV 上の 1 単位が、実際の表面の何 mm にあたるか」を、u 方向と v 方向のそれぞれについて記録した画像です。ぼかすときに、サンプル間隔をこの値で調整して、実際の長さで一定のぼけ幅にします。ストレッチ マップは、ピクセル シェーダーの `ddx` と `ddy` で UV の変化量とワールド位置の変化量を比べて、毎フレーム作れます。

## 画面空間のぼかしとの違い

この方法は、品質が非常に高い反面、いくつかの欠点があります。

顔の UV 展開を使うので、**キャラクターごとに UV 空間のレンダリングが必要**です。キャラクターが複数いれば、その数だけ UV 空間のパスが増えます。UV 空間のテクスチャの解像度（たとえば 2048²）に比例するコストがかかり、遠くの小さなキャラクターに対しても、一定のコストがかかります。逆に、画面上で見えない部分（背中側）も計算してしまう無駄があります。

これに対して、[画面空間の分離ぼかし](screen-space-sss.md)は、画面に映っている肌の画素だけを処理するため、見えているキャラクターの大きさに比例したコストで済み、実装も単純です。そのため、d'Eon の方法は、映画やハイエンドな表現で使われ、ゲームでは画面空間の方法が主流になりました。

## 肌以外への応用

ガウスの和の方法は、肌専用ではありません。プロファイルの形を変えるだけで、他の半透明の物体にも使えます。大理石は、肌より広く、色の差が小さい曲線を持ちます。ろうそくは、さらに広く、黄色から橙に偏った曲線になります。牛乳は、広く均一な白です。葉は、緑が広がります。

## よくあるミス

??? failure "アルベドを、ぼかしの前に掛けている"
    **テクスチャの模様（毛穴・そばかす）まで、ぼけてしまう**。**ぼかすのは、アルベドを掛ける前の放射照度**。アルベドは、ぼかした後に掛ける（または、半分ずつ掛ける）。

??? failure "ガウスの重みの合計が 1 でない"
    重みの合計は、**RGB ごとに 1**。1 を超えると肌が明るくなりすぎ、下回ると暗くなる。

??? failure "UV の歪みを補正せず、鼻や耳で、ぼけ方が変わる"
    **ストレッチ マップ**を使って、サンプル間隔を調整する。
