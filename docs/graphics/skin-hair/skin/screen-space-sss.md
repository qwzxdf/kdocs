# Separable SSS

**画面空間の SSS**は、ライティングが終わった画像を、肌の画素だけ**ぼかして**、SSS を表現する方法です。UV 空間を使わず、画面に映っている画素だけを処理するので、**軽く、実装も単純**です。Jimenez らの "Separable Subsurface Scattering"（2015）は、**ぼかしを縦横の 2 回の 1 次元処理に分け**、実用的なコストで高品質な SSS を実現しました。現代のゲームの標準的な方法です。このページでは、考え方、カーネルの作り方、実装の注意点を説明します。

!!! tip "ポイント"
    - **拡散反射の画像**を、**肌の画素だけ**、**深度を考慮して**ぼかす。
    - ぼかしを<strong>横 → 縦の 2 パス</strong>に分ける（**分離可能**）。サンプルは 11〜25 個。
    - カーネルは、**拡散プロファイルを、1 次元に積分した形**。**RGB ごとに別の重み**。
    - **ぼかしの幅は、画面上の距離でなく、実際の長さ**。**深度で補正**する。
    - **鏡面反射はぼかさない**。**アルベドは、ぼかしの前に外す**。

## 考え方

拡散近似の下では、肌の表面のある点の SSS の光は、周りの点のライティング結果に、距離に応じた重み R(r) を掛けて足したもの、つまり**ぼかし**でした。これを画面の画像に対して行います。

手順は、次のとおりです。

1. 通常どおり、シーンのライティングを行います。肌の画素に対しては、**拡散反射と鏡面反射を、別々の画像に**（またはアルファチャンネルに）書き出します。
2. **拡散反射の画像**に、横方向のぼかしを、続いて縦方向のぼかしを掛けます。ぼかしを掛けるのは、**ステンシルで印を付けた肌の画素だけ**です。
3. ぼかした拡散反射に、**鏡面反射を足して**、最終的な色にします。

分離可能であることは、この方法の鍵です。拡散プロファイルは、本来は 2 次元の円対称な関数なので、厳密には縦横に分解できません。しかし、Jimenez らは、**プロファイルを 1 次元のカーネルに近似して、縦と横に 2 回掛ける**ことで、見た目がほぼ変わらないことを示しました。サンプル数が N×N から 2N に減り、1080p でも 0.5〜1 ms ほどで収まります。

## カーネルの作り方

1 次元のカーネルは、次のように作ります。まず、拡散プロファイル R(r)（2 次元の円対称）を、ある方向の 1 次元の断面へ**積分**して、1 次元の関数にします。プロファイルは RGB で別々なので、カーネルも RGB ごとに別の重みを持ちます。次に、カーネルを離散化します。中心を含めて N 個のサンプル（典型的には 11 個から 25 個）を、中心から外へ向かって、**間隔を不均一に**取ります。中心付近は細かく、外側は粗くします。プロファイルは中心が尖っているので、そこを細かく取るためです。各サンプルに、オフセット（中心からの距離）と、RGB の重みを割り当てます。最後に、重みの合計が、RGB ごとに 1 になるよう**正規化**します。

このカーネルは、あらかじめ（起動時に）計算しておき、定数バッファに入れて、シェーダーから使います。

```hlsl
struct KernelSample {
  float3 weight;
  float offset;
};
StructuredBuffer<KernelSample> kernel;

float4 SssBlur(float2 uv, float2 direction, float sss_width) {
  float4 center = diffuse_tex.SampleLevel(point_clamp, uv, 0);
  float depth = linear_depth_tex.SampleLevel(point_clamp, uv, 0);

  float2 step = direction * sss_width / depth;
  float3 sum = center.rgb * kernel[0].weight;
  for (int i = 1; i < kSampleCount; ++i) {
    float2 sample_uv = uv + kernel[i].offset * step;
    float3 color = diffuse_tex.SampleLevel(linear_clamp, sample_uv, 0).rgb;
    float sample_depth = linear_depth_tex.SampleLevel(point_clamp, sample_uv, 0);

    float s = saturate(300.0 * sss_width * abs(depth - sample_depth) / depth);
    color = lerp(color, center.rgb, s);
    sum += kernel[i].weight * color;
  }
  return float4(sum, center.a);
}
```

## 画面上の幅を、実際の長さに合わせる

SSS のぼけ幅は、**物体の表面上の実際の長さ**（mm）で決まります。画面上では、カメラから遠いほど、同じ長さが小さく映ります。そこで、ぼかしの画面上の幅を、**深度で割って**調整します。コードの `step = direction * sss_width / depth` がそれです。`sss_width` は、世界での広がり（人間の肌なら 1 cm 以下）を、射影の係数を含めて画面上の長さに変換した値で、近くの顔は大きく、遠くの顔は小さくなります。この補正を忘れると、カメラが引いたときに顔のぼけが大きくなりすぎます。

## 輪郭をまたがないための工夫

ぼかしは、**別の面の画素まで混ぜてしまう**と、不自然になります。たとえば、顔の輪郭の外側の背景や、髪、服の色が、肌に混ざってしまいます。コードの `s` の項は、中心の画素とサンプル点の**深度の差が大きいとき、サンプルの色を中心の色に置き換える**工夫です。深度が離れた（別の面の）サンプルは、使われなくなるので、輪郭をまたいだにじみが防げます。

さらに、ステンシルで肌の画素だけに印を付けておくと、肌以外の画素に対して、ぼかしのシェーダーが走りません。画面の大半が肌でないシーンでは、大きく節約できます。

## アルベドの扱い

もう 1 つの重要な注意が、**アルベド（テクスチャの色）**です。ライティングの結果にアルベドを掛けてからぼかすと、**毛穴・そばかす・ほくろなどのテクスチャの細かい模様まで、ぼけてしまいます**。実際の肌では、模様は、肌の表面にある（表皮の色素）ので、内部で散乱する光でぼけません。

そのため、アルベドは、ぼかしの**前に外し**（ライティングの結果をアルベドで割るか、そもそも掛けずに放射照度を保存する）、ぼかしの**後に掛け直す**のが正しい方法です。ただし、アルベドを完全に後だけで掛けると、肌の色が、散乱によって「色を変えながら」広がる効果（赤が広がる）を表せません。そこで、Jimenez らは、**アルベドの平方根を、ぼかしの前後に半分ずつ掛ける**折衷案を示しています。この方法は、毛穴などの詳細を残しながら、色の広がりも出せます。

## 品質の調整

いくつかのパラメータで、見た目を調整できます。

`sss_width` は、ぼかしの全体の広がりで、肌の SSS の強さを決めます。大きいほど、肌が柔らかく見えますが、大きすぎると顔がのっぺりします。`sss_strength` は、ぼかした結果と元の画像を混ぜる割合で、0 なら SSS なし、1 なら完全にぼかします。顔の部位ごとに強さを変えたいとき（頬は強く、鼻の頭は弱くなど）は、**SSS の強度マスク**のテクスチャを使います。耳や鼻、唇は強め、額や頬骨は弱めにすると、現実に近くなります。

## 軽量化

品質を保ちながらコストを減らす方法があります。サンプル数を減らす（25 個を 11 個や 7 個に）。ぼかしを半解像度で行う（顔が小さいキャラクターなど）。画面上で小さいキャラクターは、SSS を省略するか、サンプル数を減らす（LOD）。これらを使い分けると、1080p で 0.5 ms 程度に収まります。

## よくあるミス

??? failure "鏡面反射まで、一緒にぼけて、つやが消える"
    **拡散反射と鏡面反射を、別の画像に書く**。ぼかすのは拡散だけで、**鏡面は後で足す**。

??? failure "顔の輪郭で、背景の色が肌ににじむ"
    **深度の差が大きいサンプルを、中心の色に置き換える**（深度を考慮したぼかし）。

??? failure "カメラが引くと、顔のぼけが大きくなる"
    ぼかしの画面上の幅を**深度で割って**、実際の長さを一定にする。

??? failure "毛穴やそばかすまで、ぼけてしまう"
    **アルベドを、ぼかしの前に外す**（または、√アルベドを前後に掛ける）。

??? failure "横方向と縦方向で、ぼけ方が違って見える"
    **画面のアスペクト比を考慮して**、横と縦のステップ幅を揃える。
