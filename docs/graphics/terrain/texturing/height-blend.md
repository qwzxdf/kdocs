# Height-Based Blending

<strong>重みだけで混ぜると境目がぼやけて、のっぺりします</strong>。<strong>各テクスチャの「高さ（凹凸）」を使って混ぜる</strong>と、土の隙間から草が生えるような、自然な境目になります。このページでは高さブレンドを説明します。

!!! tip "ポイント"
    - 各テクスチャに高さ情報を持たせる。
    - 重み ＋ 高さの大きい方が勝つように、混ぜる。
    - 境目に凹凸に沿った模様が出る。
    - コストは少し増える。

## 高さによるブレンド
<strong>重みの線形ブレンドは境目がぼんやり混ざって不自然</strong>です。<strong>実際の地面は「石の隙間に土が入り込む」ように凹凸に沿って境ができます</strong>。各テクスチャの高さ（ハイトマップ）を足し込んでから、一番高い層を優先すると自然な境目になります。

```hlsl
float4 heights = float4(
  height_array.Sample(linear_wrap, float3(tile_uv, 0)).r,
  height_array.Sample(linear_wrap, float3(tile_uv, 1)).r,
  height_array.Sample(linear_wrap, float3(tile_uv, 2)).r,
  height_array.Sample(linear_wrap, float3(tile_uv, 3)).r);

float4 blended = weights + heights * height_strength;
float max_value = max(max(blended.r, blended.g), max(blended.b, blended.a)) - blend_depth;
float4 final_weights = max(blended - max_value, 0.0);
final_weights /= (final_weights.r + final_weights.g + final_weights.b + final_weights.a);
```

高さブレンドのコードの要点です。`blend_depth` は境目の幅（0.1 程度）で、小さいと鋭く大きいとぼやけます。高い層が勝つので凸な所が先に現れ、凹んだ所に他の層が残ります。テクスチャごとに高さのチャンネルが必要で、法線マップのアルファなどに詰めます。

## なぜ線形ブレンドは不自然なのか

重みで色を線形に混ぜると境目は、「2 枚の写真が半透明で重なった」ように見えます。実際の地面では境目はそうなりません。

| 現実の地面 | 線形ブレンド |
| --- | --- |
| 石の高い所は石のまま。土は石の隙間に溜まる | どこでも、石と土が同じ割合で混ざる |
| 境目が凹凸に沿ってギザギザになる | 境目が、ぼんやりとなだらかに混ざる |
| 草の根元に土が見える | 草と土が一面に、均等に混ざる |

ここで欲しいのは <strong>「重みが 0.5 でも、石の出っ張りは石、窪みは土」と高さで勝敗を決める</strong>ことです。各テクスチャに <strong>高さ情報（出っ張り・窪み）</strong>を持たせて、<strong>重みに高さを足した値が最も大きい層だけが、見える</strong>ようにします。

## 基本の式

層 i の重みを `w_i`、高さを `h_i` とします。

```text
v_i = w_i + h_i                    重みと高さの合計（その層の勢い）
m   = max(v_i) − depth             一番勢いのある層から、depth だけ引いた線
b_i = max(v_i − m, 0)              その線より上に出ている分だけが、見える
最終の重み = b_i / Σ b_j
```

| 値 | 意味 |
| --- | --- |
| `depth` | 境目の幅。0 に近いと勝った層だけが残る（切り替え）。大きいと線形ブレンドに近づく |
| `max(...)` | 一番高い層を基準にする |
| `/ Σ b_j` | 重みの合計を 1 に戻す |

`depth` が小さいほど境目が鋭く凹凸に沿った形になります。`0.05〜0.2` の間で見た目に合わせます。

## シェーダーでの書き方

```hlsl
// 4 層分の、高さを読む。高さは、アルベドのアルファ チャンネルに入れておくと、
// 色と同時に 1 回で読める。
float4 SampleHeights(float2 uv) {
  return float4(
      g_albedo_height.Sample(g_linear_wrap, float3(uv, 0)).a,
      g_albedo_height.Sample(g_linear_wrap, float3(uv, 1)).a,
      g_albedo_height.Sample(g_linear_wrap, float3(uv, 2)).a,
      g_albedo_height.Sample(g_linear_wrap, float3(uv, 3)).a);
}
```

4 層の高さを読みます。高さをアルベドのアルファ チャンネルに、入れておくと色と同時に読めます。

```hlsl
float4 HeightBlendWeights(float4 weights, float4 heights, float depth) {
  float4 v = weights + heights;
  float m = max(max(v.x, v.y), max(v.z, v.w)) - depth;
  float4 b = max(v - m, 0.0);
  return b / max(dot(b, 1.0), 1e-4);
}
```

ブレンドの重みを高さで調整します。普通の重み（スプラット マップ）に高さを足し、最大値から `depth`（なじませる幅）を引いた基準を、下回る層は 0 にします。高い層ほど残りやすいので境目で、石の隙間に土がたまるように見えます。残った分を合計 1 にそろえます。

```hlsl
float4 main(PSInput input) : SV_Target {
  float4 w = LoadWeights(input.splat_uv);
  float4 h = SampleHeights(input.tile_uv);
  float4 fw = HeightBlendWeights(w, h, 0.15);

  float3 color = 0;
  [unroll] for (int i = 0; i < 4; ++i) {
    color += g_albedo_height.Sample(g_linear_wrap, float3(input.tile_uv, i)).rgb * fw[i];
  }
  return float4(color, 1.0);
}
```

最後のループで `Sample` をもう一度呼んでいます。コンパイラが同じ読み込みをまとめてくれることが多いですが、<strong>高さの読み込みと色の読み込みを、1 回にまとめた</strong>ほうが確実です。

## よく起きる問題と対策

### ① 重みが 0 の層が、顔を出す

`v_i = w_i + h_i` なので <strong>重みが 0 でも、高さが高い層は `v_i` が大きくなります</strong>。`depth` を大きくすると重みが 0 の層が、現れてしまいます。

| 対策 | 内容 |
| --- | --- |
| 高さに重みを掛ける | `v_i = w_i + h_i * w_i`（`w_i = 0` なら、必ず 0） |
| 重みを高さの影響範囲に収める | `v_i = w_i * (1 + k * h_i)` のような形 |
| 重みが 0 なら除外する | `b_i *= step(0.001, w_i)` |

```hlsl
// 重みが 0 の層は、高さがどれだけ高くても、現れない形にする。
float4 HeightBlendWeights2(float4 weights, float4 heights, float depth) {
  float4 v = weights * (1.0 + heights);              // 重みが 0 なら 0
  float m = max(max(v.x, v.y), max(v.z, v.w)) - depth;
  float4 b = max(v - m, 0.0) * step(0.001, weights);
  return b / max(dot(b, 1.0), 1e-4);
}
```

### ② 境目の画素がちらつく

スプラット マップの重みはバイリニアで、補間されます。高さブレンドは <strong>重みの小さな変化を、急な変化に変える</strong>ので境目が、ギザギザにちらつきます。

- スプラット マップの解像度を上げる
- `depth` を少し大きくして境目に、幅を持たせる
- ノイズで重みを揺らして規則的なギザギザを消す

### ③ 高さをどこから取るか

| 方法 | 内容 |
| --- | --- |
| アルベドの A に入れる（BC7） | 色と同時に読める。高さの精度は 8 ビット。標準的 |
| 法線マップの A に入れる | 同上。法線マップが BC5 で A が使えない場合は、別のテクスチャが必要 |
| 専用の高さマップ（`R8_UNORM`） | 精度は自由。読み込みが 1 回増える |
| ORM テクスチャに入れる | Occlusion・Roughness・Metallic に加えて高さを、1 枚にまとめる |

高さの値は 0〜1 に正規化して、<strong>平均が 0.5 になるよう</strong>に、作ります。平均が偏っていると層ごとに勝ちやすさが違ってしまいます。

## 実装のバリエーション

| 方式 | 特徴 |
| --- | --- |
| 上の式（`weights + heights`） | 最も単純。多くの実装で基本形になっている |
| `weights * heights` をべき乗する | 重みが 0 の層が、出ない。境目がややなめらか |
| Mishkinis（2013）の方式 | 層ごとの高さに、コントラストを足してブレンドの鋭さを、素材ごとに調整できる |

層ごとに `depth` や高さのコントラストを変えると、<strong>「砂は石の隙間に入り込む」「草は、土の上に乗る」</strong>のような素材ごとの性格を、出せます。
