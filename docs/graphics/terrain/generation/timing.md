# When to Generate

<strong>地形の生成は事前に行うか実行時に行うか、選べます</strong>。<strong>事前なら重い処理ができ実行時なら無限に広い地形が作れます</strong>。このページでは生成のタイミングの選び方を説明します。

!!! tip "ポイント"
    - 事前生成：高品質（侵食も）。データが大きい。
    - 実行時生成：無限の地形。軽いノイズだけ。
    - ハイブリッド：事前の骨格 ＋ 実行時の細部。
    - シード値で同じ地形を再現できる。

!!! info "このページを読む前に"
    - [Terrain Generation](index.md)（このセクション全体の地図と、読む順番）

## 生成のタイミング
生成のタイミングは 3 つの方式があります。事前に作って焼く方式（オフライン）は、地形ツール（World Machine・Gaea・Houdini）や自作ツールで高さマップを生成し、ゲームにはテクスチャとして持ち込みます。ランタイム生成はゲーム中にシードから生成する方式で、ノイズ関数は軽いのでチャンクごとに GPU や CPU で生成できます。無限の世界やランダム ステージに向きます。ハイブリッドは大きな形は手で描き、細かい起伏だけノイズで足します。

<strong>ランタイム生成</strong>では <strong>チャンクの境界で値が連続する</strong>こと（ワールド座標でノイズを引く）、侵食は隣のチャンクにも影響するため難しいことに注意します。

## 地形はいつ作るか

地形の生成（ノイズ、侵食、配置）を <strong>いつ実行するか</strong>は設計の、最初の分かれ道です。

| タイミング | 内容 | 向くもの |
| --- | --- | --- |
| オフライン（ツール） | 制作時に地形を生成して結果をファイルに保存する。ゲームは読み込むだけ | 手作りの、ステージ。侵食など重い処理を使う地形 |
| ロード時 | 起動、またはステージ開始時に生成する。数秒〜数十秒、待つ | 毎回違うランダム生成のステージ（シード値から） |
| ストリーミング（実行時） | プレイヤーが近づいた範囲だけをその場で生成する | 巨大な、あるいは無限の世界（マインクラフト型、ノーマンズ スカイ型） |
| 毎フレーム | 毎フレーム、GPU で計算する | 動く地形（水面、砂漠の風紋）、軽いノイズだけ |

## 選ぶときの基準

| 観点 | オフライン | ロード時 | ストリーミング |
| --- | --- | --- | --- |
| 生成の重さの許容 | いくらでも重くできる | 数秒〜数十秒 | 1 タイルあたり、数ミリ秒（フレームを止めない） |
| 侵食の使用 | 使える（数千ステップ） | 軽い侵食のみ | 難しい（タイル間の、整合性） |
| 結果の再現性 | 保存したデータなので、完全に同じ | シードから同じ（環境によって、浮動小数点の差に注意） | 同じ（決定的な式で、組む必要がある） |
| ディスク容量 | 大きい（地形データを持つ） | 小さい（シードだけ） | 小さい |
| 編集 | アーティストが手で、直せる | 生成後に直せない | 直せない（ルールを直す） |
| 世界の広さ | ディスクの容量に比例 | メモリに収まる範囲 | 事実上、無限 |

## オフライン生成の流れ

ほとんどの手作りのゲームはこの方式です。

```text
ツール:  ノイズ → 高さの変換 → 侵食 → 川 → 手で修正 → 配置のルール適用
              ↓
          保存: 高さマップ、スプラット マップ、配置データ（バイナリ）
              ↓
ゲーム:  読み込んで、描画する
```

| 利点 | 内容 |
| --- | --- |
| 品質 | 重い処理が使える。アーティストが何度でも調整して、気に入った形で確定できる |
| 起動の速さ | 読み込むだけ |
| 安定性 | 環境が違っても結果が変わらない |

## 実行時の生成：落とし穴

### ① 継ぎ目をなくす

地形をチャンクに分けて生成すると、<strong>隣のチャンクとの境目</strong>で形が食い違いやすくなります。

| 方法 | 内容 |
| --- | --- |
| ワールド座標でノイズを計算する | チャンクごとに座標がずれても同じ式で同じ値になる（[fBm](fbm.md)） |
| 侵食には余白を付ける | 侵食は、周りの画素に影響される。チャンクの周りに数十画素の余白を足して計算し余白は、捨てる |
| 境界の高さを共有する | 隣り合うチャンクが同じ境界の画素を同じ値で持つ |

### ② フレームを止めない

1 つのチャンクの生成が数十ミリ秒かかると、<strong>画面がカクつきます</strong>。

| 対策 | 内容 |
| --- | --- |
| 非同期で生成する | ワーカー スレッド（CPU）、または非同期コンピュート（GPU）で、裏で作る |
| 予算を決める | 1 フレームに生成に使う時間を制限する（例：2 ms まで） |
| 細かく分割する | 1 つのチャンクを数フレームに分けて少しずつ作る |
| 先読みする | プレイヤーが近づく前に方向を予測して作り始める |
| 低解像度から作る | まず、粗い地形を出して後から細かくする（LOD と、組み合わせる） |

### ③ 決定性を守る

実行時に同じ場所が同じ地形でないと、<strong>ゲームが成り立ちません</strong>（セーブしても、地形が違うマルチプレイで人によって地形が違う）。

| 注意点 | 内容 |
| --- | --- |
| 乱数 | グローバルな乱数列を使わず、座標から種を作る（[Placement Generation](placement.md)） |
| 浮動小数点 | GPU が違うと `sin`、`cos`、`pow` の結果がわずかに違う。整数のハッシュと基本的な演算だけを使う。重要な値は CPU で計算する |
| 生成の順序 | 生成の順序が変わっても、同じ結果になること（チャンクがほかのチャンクに依存しないこと） |
| 変更の保存 | プレイヤーが地形を変えたら元の地形からの差分を保存する |

## キャッシュ

実行時に生成した地形を <strong>ディスクにキャッシュ</strong>しておくと 2 回目以降は生成が省けます。

| 項目 | 内容 |
| --- | --- |
| キャッシュのキー | シード、チャンクの座標、生成アルゴリズムのバージョン |
| バージョン管理 | アルゴリズムを変えたら古いキャッシュを無効にする（バージョンをキーに含める） |
| 容量の上限 | 古いものから、削除する（LRU） |

## 実際の組み合わせ

多くのゲームは <strong>1 つの方式だけでなく、組み合わせて</strong>います。

| 組み合わせ | 例 |
| --- | --- |
| オフライン ＋ 実行時の配置 | 地形は、手作りで焼いて保存。草・木の配置は実行時に GPU で生成（Horizon Zero Dawn のような構成） |
| ロード時の生成 ＋ 手作りの特別な場所 | 全体は、シードから生成。拠点などの重要な場所だけ手作りの地形で、上書きする |
| ストリーミング ＋ 低解像度の、事前計算 | 遠景は事前に作った、粗い地形。近景だけ実行時に細かくする |

## よくあるミス
