# Trees

<strong>木は近くは詳細なメッシュ、遠くは簡易なメッシュやビルボード</strong>にして、LOD で負荷を下げます。このページでは木の描画を説明します。

!!! tip "ポイント"
    - 近く：幹と枝のメッシュ ＋ 葉のカード。
    - 中距離：簡易メッシュ。
    - 遠く：ビルボード（板に木の絵）。
    - LOD の切り替えは、ディザでなめらかに。

## 木
<strong>木はポリゴンが多く（数万）、枚数も多い</strong>ので LOD が重要です。

| LOD | 内容 |
| --- | --- |
| LOD 0（近景） | 幹・枝の 3D モデル ＋ 葉のカード（板に葉の絵） |
| LOD 1〜2 | 枝を減らす・葉のカードを統合 |
| インポスター（遠景） | 木を数方向から撮った絵（板ポリ）に置き換え。カメラの向きに応じて絵を切り替える／混ぜる |
| ビルボード（最遠） | 1 枚の板 |

インポスターは 事前に木を複数の視点（例：8×8 = 64 方向）から撮影し、アトラスに並べます。描画時はカメラに最も近い方向の絵を選び、板に貼ります。法線・深度もアトラスに持つと、ライティングも正しくなります。

| 点 | 説明 |
| --- | --- |
| LOD の切り替え | ディザリング（市松のフェード）で、ポップを隠す（[Alpha Testing](../../translucency/alpha-test/index.md)） |
| 葉のカード | 1 枚に複数の葉を描いた板。アルファ テスト |
| 幹と葉でマテリアルを分ける | 幹は不透明、葉はアルファ テスト |
| 影 | 影の LOD は、描画より粗くする（[Shadows](../../shadows/index.md)） |

## 木はどう作られるか

木の 3D モデルは <strong>手で作る</strong>場合と、ルールから自動生成する場合があります。

| 方法 | 内容 |
| --- | --- |
| 手作り（DCC ツール） | アーティストが幹、枝、葉をモデリングする。品質は高いが手間がかかる |
| 木の専用ツール | 樹種ごとの、パラメーターから木を生成する。パラメーターを変えて同じ種類の、別の木をたくさん作れる |
| 手続き的な生成（L システムなど） | ルール（枝分かれの規則）を繰り返し適用して枝を生やす |

自動生成の基礎は L システム（Prusinkiewicz と Lindenmayer、1990）と Weber と Penn の、パラメトリックな木（1995）です。

### Weber と Penn の考え方

1 本の木を 少数のパラメーターで記述します。

| パラメーター | 内容 |
| --- | --- |
| 枝の分かれる数 | 幹から、何本の枝が出るか |
| 枝の長さ・太さの減り方 | 先へ行くほど短く、細く |
| 枝の曲がり・ねじれ | 枝がどのくらいまっすぐでないか |
| 枝の角度 | 幹からどの角度で分かれるか |
| ランダムさ | 個体ごとの、ばらつき |

パラメーターを変えると 松、オーク、柳など違う樹種が生成できます。1 本の定義から ランダムなバリエーションをいくつも作れるので同じ木が並ぶ問題が軽減されます。

## 木を構成する部品

| 部品 | 形 | 素材 |
| --- | --- | --- |
| 幹・太い枝 | メッシュ（円柱を曲げたもの） | 不透明（木の皮のテクスチャ） |
| 細い枝 | メッシュ、または板 | アルファ テスト |
| 葉 | カード（板に葉の房の絵） | アルファ テスト、透過（[Foliage Translucency](translucency.md)） |

葉を 1 枚ずつ 3D モデルにすると、<strong>数十万ポリゴン</strong>になります。葉の房を 1 枚の板に描いて、並べる（カード）ことで数千ポリゴンに収めます。

## LOD

木は 1 本が <strong>数万ポリゴン</strong>で森では、数万本です。LOD が 必須です。

| LOD | 距離 | 内容 | 三角形（目安） |
| --- | --- | --- | --- |
| 0 | 〜30 m | 幹・枝の、完全なメッシュ ＋ 葉のカード | 20,000〜50,000 |
| 1 | 30〜80 m | 細い枝を減らす。葉のカードを統合 | 5,000〜10,000 |
| 2 | 80〜200 m | 幹と、主な枝だけ。葉は大きなカードに | 1,000〜3,000 |
| インポスター | 200 m〜 | 数方向から撮った絵を板に貼る | 2（板 1 枚） |
| ビルボード | 最遠 | 1 枚の絵（常に、カメラを向く） | 2 |

### LOD の切り替えを隠す

LOD が切り替わる瞬間に ポップが起きます。隠すには ディザ フェードを使います。

```hlsl
// ディザ フェード: 2 つの LOD を市松状のパターンで、混ぜて切り替える。
// fade が 0 → 1 に動くと、LOD A が、少しずつ、消えて、LOD B が現れる。
void ApplyDitherFade(float4 screen_pos, float fade) {
  // 4×4 のベイヤー行列（0〜15）から、しきい値を作る
  static const float bayer[16] = {
     0, 8, 2,10,  12, 4,14, 6,  3,11, 1, 9,  15, 7,13, 5};
  uint2 p = uint2(screen_pos.xy) & 3;
  float threshold = (bayer[p.y * 4 + p.x] + 0.5) / 16.0;
  clip(fade - threshold);        // fade が threshold 未満の画素は、捨てる（LOD A の側）
}
// LOD B には、逆（1 - fade）を渡す。
```

2 つの LOD を 同時に、描く期間が必要です。コストは増えますが切り替えの、見た目が大きく改善します（[Dithered Transparency](../../translucency/alpha-test/dither.md)）。

## インポスター

<strong>インポスター（imposter）</strong>は、3D の木を事前に複数の方向から撮影した絵を板に貼って木の代わりに描く手法です。

### 作り方

| 手順 | 内容 |
| --- | --- |
| ① 撮影 | 木を周りの、決まった方向（例：8×8 = 64 方向）から、撮影する。色、法線、深度をそれぞれ記録する |
| ② アトラス | 撮影した絵を 1 枚の大きなテクスチャ（アトラス）に並べる |
| ③ 実行時 | カメラの向きに、最も近い撮影方向の絵を板に貼って描く |

### 方向の決め方（8 面体マッピング）

撮影する方向を 球面上に均等に並べたいとき 8 面体（正八面体）マッピングが使われます。球面を正方形に展開する方法で、格子状に均等な方向を取れます（Brucks、2018）。

```text
方向 (x, y, z) → 正方形上の座標 (u, v)      ← 8 面体マッピング（球面 ↔ 正方形）
 u, v を、N×N の格子に、離散化          → 撮影する方向の、番号
```

### 実行時：3 枚の絵を混ぜる

カメラが 撮影方向の間を向いているとき、1 枚の絵だけだと ポップが起きます（絵が切り替わる瞬間）。そこで、近い 3 つの方向の絵を重みつきで、混ぜます。

```hlsl
// インポスターの、ピクセル シェーダー（概略）。
float4 ImposterPS(float2 uv : TEXCOORD0, float3 view_dir_local : TEXCOORD1) : SV_Target {
  // ① カメラの向きを 8 面体マッピングの、座標に変える
  float2 grid = OctEncode(normalize(view_dir_local)) * (kGridSize - 1);
  float2 cell = floor(grid);
  float2 f = frac(grid);

  // ② 近い 3 つの方向（格子の三角形）を選ぶ。重みは、重心座標
  float2 c0 = cell, c1 = cell + float2(1, 0), c2 = cell + float2(0, 1), c3 = cell + float2(1, 1);
  bool upper = (f.x + f.y) > 1.0;
  float3 w = upper ? float3(1.0 - f.y, 1.0 - f.x, f.x + f.y - 1.0)
                   : float3(1.0 - f.x - f.y, f.x, f.y);
  float2 a = upper ? c3 : c0, b = upper ? c2 : c1, c = upper ? c1 : c2;

  // ③ 3 枚の、アトラスの絵を読んで、混ぜる
  float4 col = SampleAtlas(a, uv) * w.x + SampleAtlas(b, uv) * w.y + SampleAtlas(c, uv) * w.z;
  clip(col.a - 0.5);
  return col;
}
```

| 項目 | 内容 |
| --- | --- |
| 方向の数 | 8×8（64 枚）が一般的。多いほど滑らかだがアトラスが大きい（例：2048×2048 に 64 枚 ＝ 1 枚 256×256） |
| 深度・法線 | 色だけでなく、法線と深度も撮影しておくとライティングと、地面との接点（深度のオフセット）が正しくなる |
| 距離の切り替え | LOD 2 から、インポスターへディザ フェードで、切り替える |
| 向き | 地面に垂直な軸で、回転する（木は地面に立っているため）。真上から見る場合を除いて縦の軸だけで回す、簡易版もある |

簡易版は 横方向の数方向（8 方向）だけを撮影します。真上や真下から見ない地上のゲームでは、十分です。

## ビルボード（最遠）

最も遠い木は <strong>カメラを常に向いた、板 1 枚</strong>にします。1 方向の絵だけで回転で、形が崩れないようほぼシルエットだけが、分かる程度です。

| 距離 | 見え方 |
| --- | --- |
| 500 m〜 | 数画素の、緑のかたまり。詳細は不要 |
| 1 km〜 | 木を 1 本ずつ描かず森の、色の塊として地形のテクスチャに含める |

## 影

| LOD | 影への扱い |
| --- | --- |
| 近い木 | 完全なメッシュで、影を落とす。葉はアルファ テストで切り抜く |
| 中くらい | 影用の簡略な LOD（描画より、粗い）を使う |
| 遠い木 | 影を落とさない。または、インポスターで影も近似する |

影の描画は <strong>カメラの描画と別の距離で、LOD を決めて</strong>かまいません（影は、粗くても気づかれにくい）。
