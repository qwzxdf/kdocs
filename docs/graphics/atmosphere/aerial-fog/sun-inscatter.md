# Sun Inscatter

霧のかかった朝に太陽の方を向くと霞がまぶしく白く光ります。反対を向くと同じ霧が青灰色に沈んでいます。霧の色が視線の向きで変わっているのですが、霧の色を 1 色で決めていると、この見え方は出ません。

<strong>視線が太陽に近いほど霧の色を太陽の色へ寄せます</strong>。霧の粒子（ミー散乱）が光を進んできた向きのまま（前方に）強く散らすためです。このページでは位相関数による式、数字で見る前方散乱の強さ夕方の色づけ霧の式への組み込み影を無視する限界を説明します。

!!! tip "ポイント"
    - 視線と太陽方向の内積（`dot(view_dir, sun_dir)`）で、霧の色に太陽の項を足します。
    - 太陽側は明るく暖色で、反対側は空の青のままです。
    - 前方散乱の強さは Henyey-Greenstein の位相関数で表します。`g = 0.76` なら正面は真後ろの約 390 倍です。
    - 影を無視するので、光の筋は出ません。軽さと引き換えです。
    - 物理ベースの大気（LUT）を使うならこの項は最初から含まれています。

## なぜ太陽の方向が明るいのか {#why}

空気中の粒子（エアロゾル、水滴）による散乱をミー散乱と呼びます。ミー散乱の特徴は強い前方散乱です。光が進んできた向きのまま散らされやすく、横や後ろへは散らされにくいのです。太陽の方向を見ているとき視線は光が進んでくる向きと逆なので、散乱光が最も強く目に入ります。

この角度による強さの変化を表す関数が、位相関数です。ゲームでは Henyey-Greenstein（HG）関数がよく使われます。

<div class="formula">HG(cosθ, g) = (1 − g²) / (4π · (1 + g² − 2 g cosθ)^(3/2))</div>

`g` は非対称パラメータ（−1〜1）で、0 なら等方（どの向きにも均等）、1 に近づくほど前方散乱が強くなります。`θ` は光の進む向きと粒子からカメラへ戻る向きのなす角です。太陽の向き `sun_dir`（太陽へ向かう向き）と視線 `view_dir`（カメラから画素へ向かう向き）で書くと、`cosθ = dot(view_dir, sun_dir)` になります。太陽を見ているとき `cosθ = 1`（`θ = 0`）で、前方散乱の最大です。

数字で確かめます。`g = 0.76` では `θ = 0°`（正面）で 2.43、`30°` で 0.25、`90°` で 0.017、`180°`（真後ろ）で 0.0062 です。等方（`g = 0`）はどの向きでも `1 / 4π ≒ 0.0796` です。正面は等方の約 30 倍で真後ろの約 390 倍です。太陽の周りの 30° ほどが急に明るくなって、そこから離れると急速に暗くなります。大気中のミー散乱では `g` が 0.76 前後の値がよく使われます。

簡単な近似に `pow(saturate(dot(view_dir, sun_dir)), 8)` があります。`pow` の指数が大きいほど太陽のすぐ周りだけが効きます。HG 関数はこの近似を物理的な形にしたものです。

## 霧の色に太陽を足す {#add}

位相関数の値を太陽の色に掛けて、霧の色に足します。

```hlsl
cbuffer FogConstants : register(b0) {
  float3 g_fog_color;            // 太陽を含まない霧の色（空の青い環境光）。例: (0.45, 0.55, 0.7)
  float g_fog_density;           // 霧の濃さ（1/メートル）。例: 0.01
  float3 g_sun_color;            // 太陽の色（1 に近い白〜黄色）。例: (1.0, 0.95, 0.85)
  float g_sun_inscatter;         // 太陽の項の強さ。例: 0.3
  float3 g_sun_dir;              // 太陽へ向かう単位ベクトル
  float g_phase_g;               // HG の g。例: 0.76
};

// Henyey-Greenstein の位相関数。cos_theta = dot(view_dir, sun_dir)
float HenyeyGreenstein(float cos_theta, float g) {
  float g2 = g * g;
  float denom = 1.0 + g2 - 2.0 * g * cos_theta;
  return (1.0 - g2) / (4.0 * 3.14159265 * pow(max(denom, 1e-4), 1.5));   // 足した: 0 割りの防止
}

float3 FogColorWithSun(float3 view_dir) {
  float cos_theta = dot(view_dir, g_sun_dir);
  float phase = HenyeyGreenstein(cos_theta, g_phase_g);
  // 空の青（環境光）に、太陽の項を足す。足すことで、太陽側だけが明るく暖色になり、
  // 反対側は青いままになる
  return g_fog_color + g_sun_color * phase * g_sun_inscatter;
}
```

`g_sun_inscatter` は太陽の項全体の強さです。`phase` が正面で 2.43 になるので、`g_sun_inscatter = 0.3` だと正面で約 0.73 が足されます。色が白飛びしないようにこの値は霧の色の明るさと見比べて決めます。

## 霧の式に組み込む {#apply}

霧の標準的な式は `シーンの色 × 透過率 + 霧の色 × (1 − 透過率)` です。霧の色が視線で変わるだけで式の形は変わりません。

```hlsl
Texture2D<float4> g_scene : register(t0);
SamplerState g_linear_clamp : register(s0);

cbuffer CameraConstants : register(b1) {
  float3 g_camera_position;
  float _pad1;
  float4x4 g_inv_view_proj;
  float2 g_screen_size;
  float2 _pad2;
};

float3 ApplyFogWithSun(float3 scene_color, float3 view_dir, float distance_to_pixel) {
  float3 fog_color = FogColorWithSun(view_dir);
  float transmittance = exp(-g_fog_density * distance_to_pixel);   // ベールの法則
  return scene_color * transmittance + fog_color * (1.0 - transmittance);
}

float4 SunFogPS(float4 pos : SV_Position, float2 uv : TEXCOORD0) : SV_Target {
  float3 scene = g_scene.SampleLevel(g_linear_clamp, uv, 0).rgb;
  // 深度から、ワールド位置を復元する代わりに、ここでは距離を固定値にした例（足した簡略）
  float4 far_pos = mul(float4(uv.x * 2.0 - 1.0, 1.0 - uv.y * 2.0, 1.0, 1.0), g_inv_view_proj);
  float3 view_dir = normalize(far_pos.xyz / far_pos.w - g_camera_position);
  return float4(ApplyFogWithSun(scene, view_dir, 200.0), 1.0);
}
```

霧の色が視線で変わるので同じ霧でも太陽の方向と反対側で色が違う立体的な霧になります。実際の描画では `200.0` を深度から復元した距離に置き換えます。

## 夕方の色づけ {#sunset}

夕方は太陽が低くなって光が大気の厚い層を通るので、青い光が散らされて失われ太陽側が赤橙に染まります。太陽の高さから太陽の色を決める簡単な近似を足すとこの変化が出ます。

```hlsl
// 太陽の高さ（水平線からの角度の正弦）から、太陽の色を赤くする近似（足した処理。物理計算ではない）
float3 SunColorAtElevation(float sin_elevation) {
  float airmass = 1.0 / max(sin_elevation, 0.05);           // 大気を通る道のりの目安。低いほど大きい
  float3 extinction = float3(0.03, 0.07, 0.15);              // 色ごとの減衰の強さ。青が最も強い（一例）
  return exp(-extinction * airmass);
}

float3 FogColorWithSunset(float3 view_dir) {
  float3 sun_color = SunColorAtElevation(g_sun_dir.y) * g_sun_color;
  float phase = HenyeyGreenstein(dot(view_dir, g_sun_dir), g_phase_g);
  return g_fog_color + sun_color * phase * g_sun_inscatter;
}
```

`g_sun_dir.y` は太陽の高さの正弦です（y が上向きのとき）。太陽が高い（正弦が 1）と `airmass` が 1 で、色はほぼ白です。太陽が低い（正弦 0.1）と `airmass` が 10 になって、青が強く減って赤橙になります。数字は一例で見た目に合わせて調整します。

反対側（太陽の逆）は `phase` が小さいので、`g_fog_color`（空の青）がそのまま見えます。この色も夕方は赤紫や暗い青に変える必要があります。空の色のマップを霧の色に使うと自動的に変わります。

!!! note "確かめた範囲"
    HLSL は `fxc`（`ps_5_0`）で、`SunFogPS` と夕方の色の関数をコンパイルして、エラーが出ないことを確かめました。HG の値は Python で `g = 0`、`0.3`、`0.6`、`0.76` と 4 つの角度で計算しました。GPU での描画は確認していません。

## 影を考えない限界 {#shadow}

この方式は霧の色に太陽を足すだけなので、影を無視します。建物や木の影の中でも霧は一様に明るくなります。そのため、光の筋（ゴッド レイ）は出ません。

- この方式は霧の色に太陽を足します。影は無視して全体が一様です。
- ボリューム フォグはシャドウ マップを引いて、影の中を暗くします（[Volumetric Fog](../volumetric-fog/index.md)）。
- ゴッド レイは放射状ブラーやレイマーチで、影の有無から筋を作ります（[God Rays](../god-rays/index.md)）。

影を無視する代わりにこの方式は軽いので、遠景の霞に向いています。近景の影つきの霧はボリュームで作ります。

物理ベースの大気（[Physically Based Aerial Perspective](physical.md)）の LUT は、太陽の方向による内向き散乱を最初から含んでいます。ミー散乱の位相関数を積分に含めているからです。LUT を使うならこの項を手で足す必要はありません。

## よくあるミス {#mistakes}

??? failure "太陽の方向でも霧が青いままで、まぶしくない"
    原因は太陽の項を霧の色に足していないことです。`g_fog_color` に `g_sun_color * phase` を足します。`phase` が小さすぎるなら `g_sun_inscatter` を上げるか `g` を下げて、広い範囲を明るくします。

??? failure "太陽と反対側が明るくなる"
    原因は `cos_theta` の符号を逆にしていることです。`view_dir` はカメラから画素へ向かう向き `sun_dir` は太陽へ向かう向きで `dot(view_dir, sun_dir)` が、太陽を見るとき 1 になるようにそろえます。`view_dir` を逆向き（画素からカメラ）にしていると、符号が反転します。

??? failure "太陽の周りが白飛びして、霧の色が消える"
    原因は `phase` が正面で 2.43 になるのに、`g_sun_inscatter` が大きいことです。値を 0.3 程度から始めて、トーンマッピング後の見た目で調整します。

## これだけ覚える {#summary}

!!! abstract "まとめ"
    - [x] 霧の色に太陽の色 × 位相関数（HG）を足します。
    - [x] `cosθ = dot(view_dir, sun_dir)` で太陽を見るとき 1 です。
    - [x] `g = 0.76` なら正面は等方の約 30 倍、真後ろの約 390 倍です。
    - [x] 影は無視します。影が必要ならボリューム フォグを使います。
