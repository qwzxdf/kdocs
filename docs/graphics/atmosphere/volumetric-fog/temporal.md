# Temporal Accumulation

<strong>froxel の解像度は低いので、ノイズや段が出ます</strong>。毎フレーム、サンプルの位置をずらして前フレームと混ぜると、実質の解像度が上がりなめらかになります。このページでは時間蓄積を説明します。

!!! tip "ポイント"
    - 毎フレーム、サンプル位置を少しずらす（ジッタ）。
    - 前フレームの結果を再投影して混ぜる。
    - 動く物体の周りで、ゴーストに注意。
    - TAA と同じ考え方。

## 時間蓄積（TAA 風）
<strong>froxel の解像度が低く、サンプルが少ない</strong>のでそのままだとノイズや縞が出ます。前フレームの結果を再利用して、時間方向に平均します。

| 工夫 | 内容 |
| --- | --- |
| ジッター | 毎フレーム、froxel 内のサンプル位置を少しずらす（ブルー ノイズなど） |
| 履歴の再投影 | 前フレームの froxel の位置をカメラの動きで求めてその値を混ぜる |
| ブレンド率 | 新 5〜10 %、履歴 90〜95 % |
| 履歴の拒否 | ライトが動いたとき／急な変化は、履歴を弱める |

```hlsl
float3 previous_uvw = ReprojectFroxel(world_position, previous_view_projection);
float4 history = history_volume.SampleLevel(linear_clamp, previous_uvw, 0);
float4 current = float4(scattering, extinction);
float blend = IsValidHistory(previous_uvw) ? 0.05 : 1.0;
float4 result = lerp(history, current, blend);
```

### 効果とその仕組み

ジッターを入れて時間蓄積すると、実質的な解像度が上がります。毎フレーム、セル内のサンプル位置（セルの中心でなく、少しずれた位置）を変えて計算し、その結果を平均するとセルの内側の構造が時間をかけて少しずつ埋まっていくからです。TAA が画素の中のサブピクセル位置をずらして平均し、エッジを滑らかにするのと同じ原理です。

注意点はライトや霧の密度が急に変わった場合です。履歴をそのまま混ぜると変化に対する追従が遅れて、残像として見えます。ライトの強さや位置が大きく変わったフレームでは、ブレンド率を一時的に上げて（履歴を軽視する）、新しい値へ素早く切り替えます。また、動く物体（キャラクター）が通ったとき、その通り道の霧が乱される表現を入れる場合は、動く物体の周りの履歴を捨てる処理も必要です。

再投影した位置が froxel の範囲外（画面の外から入ってきたセル）の場合、履歴は存在しないのでブレンド率を 1（新しい値だけ）にします。コードの `IsValidHistory` がその判定です。

## 時間方向の平均で品質を上げる

<strong>froxel</strong> は 低解像度（160×90×64）なので、そのまま使うと縞（バンディング）や、ちらつきが出ます。フレームごとにサンプル位置をわずかにずらし（ジッター）、前のフレームの結果と混ぜる（時間方向の、平均）と多くのフレームの情報が集まり、なめらかで高品質になります（Wronski、2014、Hillaire、2015）。

## ジッター：サンプル位置をずらす

<strong>各フレームで</strong>、セルの中のどの位置で密度や影をサンプルするかを少しずつ変えます。

```hlsl
// フレームごとに、違うジッター（0〜1）を返す。ハルトン数列などの、低食い違い量列を使う。
float3 JitterOffset() {
  return float3(Halton(g_frame_index, 2), Halton(g_frame_index, 3), Halton(g_frame_index, 5)) - 0.5;
}

// セルの、ワールド位置を求めるとき、ジッターを足す（Step 1、Step 2 の、FroxelToWorld の、引数に足す）。
float3 world = FroxelToWorld(float3(id) + 0.5 + JitterOffset());
```

セルの中心ではなく セルの中の、ランダムな位置でサンプルします。フレームごとに違う位置をサンプルするので、複数フレームを平均するとセル全体の平均に近づきます。ハルトン数列は一様にかたよりなく点を並べる（低食い違い量列）ので、ランダムより少ないフレームで、収束します。

## 再投影：前のフレームを探す

<strong>カメラが動く</strong>と 前のフレームの、froxelの同じセルは今のフレームの、別の位置に対応します。前のフレームのビュー・射影行列で、今のセルのワールド位置を前の froxel の座標へ変換します。

```hlsl
// 今のセルのワールド位置から、前のフレームの froxel の、uvw を求める。
float3 ReprojectToPrevFroxel(float3 world) {
  float4 prev_clip = mul(float4(world, 1.0), g_prev_view_proj);
  float2 prev_uv = prev_clip.xy / prev_clip.w * float2(0.5, -0.5) + 0.5;
  float prev_depth = prev_clip.w;                                           // 前のフレームでの、ビュー深度
  float prev_slice = ViewDepthToSlice(prev_depth);
  return float3(prev_uv, prev_slice);
}
```

ワールド位置は同じ（霧の、その場所）ですが前のフレームでは画面の、別の位置でした。前の行列で前の画面座標とスライスを求めます。

## 履歴と混ぜる

```hlsl
// 注入後の、散乱光（今フレーム）を前フレームの、履歴と、混ぜる。
float3 uvw = ReprojectToPrevFroxel(world);
bool valid = all(uvw >= 0.0) && all(uvw <= 1.0);                           // 前の froxel の、範囲内か
float4 history = valid ? g_froxel_history.SampleLevel(g_linear_clamp, uvw, 0) : current;

float blend = valid ? 0.05 : 1.0;                                          // 履歴が有効なら、今フレームは 5%、無効なら 100%
float4 result = lerp(history, current, blend);
g_froxel_lighting_out[id] = result;
```

<strong>履歴を 95%</strong> 残し 今フレームを 5% だけ混ぜます。約 20 フレームの指数移動平均に相当し、ノイズ・縞が大きく減ります。履歴が範囲の外（カメラが動いて新しく、見える領域）なら今フレームの値を 100% 使います。

| 混ぜる割合（今フレーム） | 効果 |
| --- | --- |
| 0.02〜0.05（履歴を強く） | なめらか。ゴースト（動いたものの残像）が出やすい |
| 0.1〜0.2 | ほどほど。ゴーストが少ないノイズが残る |
| 1.0 | 時間方向の平均なし（縞がそのまま） |

## ゴーストを抑える

<strong>ライトが動く</strong>、霧が動く、物が動くと前のフレームの結果が古く、残像（ゴースト）が出ます。

| 対策 | 内容 |
| --- | --- |
| 履歴のクランプ | 今フレームの周囲のセルの、最小・最大に履歴を押し込む（[Cloud Temporal Reprojection](../clouds/temporal.md) と、同じ） |
| 動きの速さで割合を変える | カメラ・ライトが速く動くほど今フレームの割合を大きく |
| ライトが動いたらリセット | 動く、ライトの周囲のセルだけ履歴を捨てる |
| ライトの強さが急に変わる | 履歴を捨てる（フラッシュなど） |

```hlsl
// 動いているライトの、影響範囲では、履歴を弱める。
float light_motion = g_moving_light_influence(world);                       // 0（静止）〜 1（動いている）
float blend = lerp(0.05, 0.5, light_motion);
```

## 描画への影響

<strong>時間方向の平均</strong>は ボリューム フォグの、品質に大きく貢献します。ほぼ必須です。

| 設定 | 効果 |
| --- | --- |
| 時間方向の平均なし | 縞、ちらつき。高解像度（重い）が必要 |
| ジッター + 履歴（95%） | なめらか。低解像度（160×90×64）で、十分 |

カメラが止まっていると 履歴が収束してなめらかになります。カメラが急に動くと一時的に品質が落ちます。
