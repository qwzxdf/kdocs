# Irradiance

<strong>拡散の間接光は「その点の周りの全方向から来る光を法線に合わせて足し合わせた量」</strong>で、これを放射照度と呼びます。法線ごとに 1 つの値なので、環境マップ全体を法線ごとの放射照度マップに「畳み込んで」おくと、実行時は読むだけになります。このページでは放射照度の意味と、畳み込みの考え方を説明します。

!!! tip "ポイント"
    - 放射照度 ＝ 法線の半球に入る光の、余弦重み付き平均。
    - 法線の向きごとに 1 つの値で、とてもなめらか。
    - 環境マップを事前に畳み込んで、放射照度マップを作る。
    - 実行時は法線で 1 回読むだけ。

!!! info "このページを読む前に"
    - [GI Theory](index.md)（このセクション全体の地図と、読む順番）

## 放射照度：拡散の間接光を畳み込む

ランバート面（理想的な拡散面）では、出ていく光の量は視線方向に依存せず、<strong>入ってくる光を余弦で重みづけて足し合わせた量</strong>だけで決まります。この量を放射照度 E と呼びます。

<div class="formula">E(n) = ∫ L_i(ω) · max(0, n·ω) dω　、　L_o = (albedo / π) · E(n)</div>

式の意味を言葉でほどきます。ある点に立って周りの全方向から来る光を想像してください。真上から来る光（法線 n と同じ向き）は、面に垂直に当たるので最大限に効きます。斜めから来る光は面に斜めに当たって薄まります（n·ω が小さい）。真横から来る光は面をかすめるだけで、ほとんど効きません。半球の外側（裏側）から来る光は、面に当たらないので 0 です（`max(0, …)` の意味）。この「効き具合」を余弦という重みで表し、全方向で足したものが E です。

E を π で割って albedo を掛けるのは、エネルギー保存のためです。完全な白（albedo = 1）の面に放射照度 E を当てたとき、出ていく光の総量が入ってくる総量を超えないようにする正規化です。

### なぜ「なめらか」なのか

E は法線 n だけの関数です（位置 p を固定すれば）。入ってくる光 L_i が空の青や周りの壁の色のように、方向によって激しく変化していても、それに余弦のなだらかなカーネルを畳み込むので、結果の E(n) はなめらかに変わります。法線が 10 度回転しても E はほとんど変わりません。画像のぼかしと同じで大きなぼかしの後には細かい情報が残らないのです。

この性質のおかげで拡散の間接光は粗い情報で保存できます。環境マップ（解像度が数百 × 数百のキューブマップ）をそのまま持たなくても、数十個の数値で E(n) をほぼ表せます。

### 事前の畳み込み

実行時に毎回半球の積分をするのは重いので、あらかじめ積分しておきます。環境マップ（キューブマップ）から、法線ごとの放射照度を計算して、小さなキューブマップ（たとえば 32×32 × 6 面）に保存します。これを放射照度マップと呼びます。実行時は法線で 1 回読むだけで済みます。

作り方は放射照度マップの各テクセル（法線 n に対応）について、元の環境マップの全テクセルを余弦重み付きで足し合わせます。ブルート フォースだと重いので、元のキューブマップのミップの高い（小さい）レベルを使ったり、ランダム サンプルで近似したりして作るのが普通です。

### より良いやり方：球面調和関数で持つ

放射照度マップよりもさらに小さく持つ方法が[球面調和関数（SH）](spherical-harmonics.md)です。Ramamoorthi と Hanrahan（2001）は、拡散の放射照度がわずか 9 個の SH 係数（3 バンド）で、平均誤差 1 % 程度まで表せることを示しました。余弦のカーネルが強い低域通過フィルタとして働くため、高周波の情報がほぼ残らないからです。9 個の係数を RGB で 27 個の数値として持てば、法線から E を計算できます。ライトプローブはこの考え方で作られています（[Storing SH](../probes/sh-storage.md)）。

## 放射照度を式で書く

<strong>放射照度</strong>（irradiance、`E`）は ある点のある向きの面に入ってくる光の総量です。半球の全方向から来る光を面の法線との、角度の余弦で重みづけして足し合わせます。

```text
E(n) = ∫ L_i(ω) × max(n · ω, 0) dω           半球 Ω（法線 n の側）の、全方向について積分
```

`L_i(ω)` は 方向 `ω` から入ってくる光（放射輝度）、`n · ω` は 法線と入射方向の内積（斜めから来る光ほど、薄まる）です。`max(…, 0)` は面の裏側から来る光（負の内積）を 0 にするためです。

## 拡散反射の出ていく光

ランバート面（完全に拡散する面）では、<strong>入ってきた光が全方向へ均等に散ります</strong>。出ていく光は放射照度から、1 行で求まります。

```text
L_o = albedo / π × E(n)
```

`albedo`（反射率）は 入った光の何割が反射するか（0〜1）です。`π` で割るのは半球の全方向へ均等に散らすときエネルギーが保存されるためです。確かめます。放射照度 `E` の光が当たる面から、全方向に出る光の総量は `L_o × π`（余弦で重みづけした、半球の積分が `π`）でこれが `albedo × E` に、等しくなるという計算です。

## 放射照度は法線だけの関数

<strong>点の位置を固定</strong>すれば 放射照度は、法線 `n` だけの関数です。法線の向きごとに 1 つの値（RGB）を持てば、足ります。これが環境光を小さなデータで、保存できる根拠です。

また、放射照度は法線の向きに対して、なめらかに変わります。入ってくる光（空の青、壁の赤）の細かい模様は余弦で重みづけして半球を積分する間にほぼ平均されて消えるためです。

```text
L_i の細かい模様（雲、窓の格子） ──→ 余弦重みで、半球を、平均 ──→ E(n) は、なめらかな、ゆるやかな分布
```

## 環境マップから放射照度マップを作る

<strong>周りの景色</strong>（環境マップ、キューブマップ）から 全方向の `L_i` が、得られます。各法線 `n` について積分して、放射照度マップ（畳み込み済みの、キューブマップ）を事前に作ります。

### キューブマップの 1 テクセルの立体角

環境マップの 各テクセルが球面上でどれだけの広さ（立体角）を占めるかが積分の重みに必要です。面の中心は広く角は狭い（キューブマップを球に投影するため）。

```hlsl
// キューブマップの、1 テクセルの立体角。(u, v) は、面上の座標（-1〜1）、size は、1 辺のテクセル数。
float TexelSolidAngle(float u, float v, float size) {
  float texel = 2.0 / size;                                         // 1 テクセルの、面上での、大きさ
  return texel * texel / pow(1.0 + u * u + v * v, 1.5);              // 面上の面積を球面上の、立体角へ
}
```

面の中心（`u = v = 0`）では `texel²` で、最も広く、角（`u = v = 1`）では `/ 3^1.5 ≈ /5.2`、狭くなります。6 面の全テクセルの立体角を足すと、球全体の立体角 `4π`になります（検算に使えます）。

### 計算シェーダーで畳み込む

```hlsl
TextureCube<float3> g_env : register(t0);                           // 元の、環境マップ
RWTexture2DArray<float3> g_irradiance : register(u0);               // 出力: 32×32×6 の、放射照度マップ

[numthreads(8, 8, 1)]
void ConvolveCS(uint3 id : SV_DispatchThreadID) {
  // 出力のテクセルが表す法線 n（キューブマップの、面と、座標から）。
  float3 n = CubeFaceTexelToDirection(id.z, (id.xy + 0.5) / 32.0);
```

出力のテクセルは 1 つの、法線 `n` に対応します。面の番号と面上の座標から方向を求めます。

```hlsl
  float3 sum = 0.0;
  const int kSrcSize = 64;                                          // 元の環境マップの、1 辺（小さくてよい。放射照度は、なめらか）
  for (int face = 0; face < 6; ++face) {
    for (int y = 0; y < kSrcSize; ++y) {
      for (int x = 0; x < kSrcSize; ++x) {
        float2 uv = (float2(x, y) + 0.5) / kSrcSize * 2.0 - 1.0;    // 面上の座標（-1〜1）
        float3 dir = normalize(CubeFaceTexelToDirection(face, (float2(x, y) + 0.5) / kSrcSize));
        float cos_term = max(dot(n, dir), 0.0);                      // 余弦重み（裏側は 0）
        float solid_angle = TexelSolidAngle(uv.x, uv.y, kSrcSize);
        sum += g_env.SampleLevel(g_linear_clamp, dir, 0) * cos_term * solid_angle;
      }
    }
  }
  g_irradiance[id] = sum;                                           // E(n)。albedo / π は、描画のときに掛ける
}
```

元の環境マップの全テクセルについて、その方向の光 × 余弦 × 立体角を足します。放射照度はなめらかなので元の環境マップは、64×64 程度の小さな解像度で、十分です（計算量が減ります）。出力も 32×32 で十分です。出力に `albedo / π` は掛けません。物体ごとにアルベドが違うので、描画のときに掛けます。

## 描画での使い方

```hlsl
TextureCube<float3> g_irradiance_map : register(t6);

float3 DiffuseIndirect(float3 normal, float3 albedo) {
  float3 irradiance = g_irradiance_map.SampleLevel(g_linear_clamp, normal, 0);   // 法線で、1 回読む
  return albedo / 3.14159265 * irradiance;                                        // 拡散の、間接光
}
```

<strong>法線でキューブマップを 1 回読んで</strong>、`albedo / π` を掛ける。これで拡散の環境光が完成です（重い積分は事前に、終わっている）。

## SH でさらに小さく

<strong>放射照度マップ</strong>（32×32×6 = 6,144 テクセル × RGB）は 十分、小さいですがさらに小さく（27 個の数）できます。球面調和関数（[Spherical Harmonics (SH)](spherical-harmonics.md)）が放射照度のなめらかさを利用した、圧縮です（Ramamoorthi と Hanrahan、2001）。数十個のプローブ（[Probe GI](../probes/index.md)）を空間に置くとき 1 つが 27 個の数で、済むのでメモリが大幅に減ります。
