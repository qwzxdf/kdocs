# Lightmaps and Dynamic Lights

**ライトマップは静的な光を含みますが、動的なライトは、別に足し合わせます**。**静的な光は焼き込み、動くライトはリアルタイムで計算する**のが、**一般的な組み合わせ**です。このページでは、**静的と動的の組み合わせ方と、長所・短所**を説明します。

!!! tip "ポイント"
    - **静的ライト ＝ ベイク**。**動的ライト ＝ リアルタイム**。
    - **同じライトを、二重に足さない**（ベイク済みは、リアルタイムで切る）。
    - **影の整合性（ベイクの影とリアルタイムの影）に注意**。
    - **長所：軽い・高品質。短所：静的限定・ベイクの時間**。

## 動的なライトとの関係
**ライトマップに焼いた光は、固定**です。**時間で動く太陽**（昼夜サイクル）には**対応できません**。

対策はいくつかあります。1 つ目は、朝・昼・夕のライトマップを複数持ち、時間で切り替えたり補間したりする方法です。メモリが倍々に増えるのが難点です。2 つ目は、<strong>間接光だけをベイクして、直接光（太陽など）は動的に計算する</strong>ミックス ライティングです。太陽が動いても、直接光は正しく動きます。間接光は動かないので、昼と夕方の間接光の色の違いは再現できませんが、見た目の破綻は小さく済みます。3 つ目は、静的な影だけを別のチャンネルに焼く、シャドウマスクです。静的な影は焼いておき、動く物体の影だけをリアルタイムで描いて、最後に合成します。4 つ目は、昼夜サイクルが必須なら、プローブ・DDGI・レイトレのような動的な GI を選ぶことです。

## 長所と短所
ライトマップの長所は、実行時のコストがほぼゼロであること、オフラインの正確な計算による高品質、モバイルでも使えること、ノイズがなくソフト シャドウがきれいなこと、シェーダーが簡単なことです。短所は、静的なものしか反映できないこと、ライトマップ アトラスのメモリ、変更のたびに再ベイクが要るベイク時間、UV2 の準備（歪み・マージン・密度の管理）、そしてライトを動かしてもすぐ確認できないイテレーションの遅さです。

実際の現場では、**イテレーションの遅さ**が最大の問題になります。ライトの位置を少し動かすたびに、数十分から数時間のベイクが必要では、アーティストの作業が止まります。最近のエンジンは、GPU ベイクや、低解像度のプレビュー ベイクで、この待ち時間を縮めています。

## よくあるミス

    **ベイク済みのライトは、リアルタイムの計算から外す**。
