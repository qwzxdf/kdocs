# Lightmaps and Dynamic Lights

<strong>ライトマップは静的な光を含みますが、動的なライトは別に足し合わせます</strong>。静的な光は焼き込み動くライトはリアルタイムで計算するのが、一般的な組み合わせです。このページでは静的と動的の組み合わせ方と、長所・短所を説明します。

!!! tip "ポイント"
    - 静的ライト ＝ ベイク。動的ライト ＝ リアルタイム。
    - 同じライトを二重に足さない（ベイク済みは、リアルタイムで切る）。
    - 影の整合性（ベイクの影とリアルタイムの影）に注意。
    - 長所：軽い・高品質。短所：静的限定・ベイクの時間。

## 動的なライトとの関係
<strong>ライトマップに焼いた光は固定</strong>です。時間で動く太陽（昼夜サイクル）には対応できません。

| 対策 | 内容 |
| --- | --- |
| 複数のライトマップを切り替え・補間 | 朝・昼・夕のライトマップを複数持ち、時間で補間（メモリが倍々） |
| 直接光は動的、間接光のみベイク | 間接光だけをベイクし、直接光（太陽）は動的に。ミックス ライティング |
| 影だけ別に（シャドウマスク） | 静的な影を別のチャンネルに焼く |
| 動的な GI（プローブ・DDGI・RT） | 昼夜サイクルが必須なら、動的な方式 |

## 長所と短所
| 長所 | 短所 |
| --- | --- |
| 実行時のコストがほぼゼロ | 静的なものだけ（動く物・動くライトを反映できない） |
| 高品質（オフラインの正確な計算） | メモリ（ライトマップ アトラス） |
| モバイルでも使える | ベイク時間（変更のたびに再ベイク） |
| ノイズなし（きれいなソフト シャドウも） | UV2 の準備（歪み・マージン・密度の管理） |
| シェーダーが簡単 | イテレーションが遅い（ライトを動かして、すぐ確認できない） |


実際の現場では <strong>イテレーションの遅さ</strong>が最大の問題になります。ライトの位置を少し動かすたびに、数十分から数時間のベイクが必要では、アーティストの作業が止まります。最近のエンジンは GPU ベイクや、低解像度のプレビュー ベイクで、この待ち時間を縮めています。

## ライトマップ（静的）と、動的なライトを組み合わせる

<strong>ライトマップ</strong>は 静的な光を、焼き込みます。ゲームには動くライト（懐中電灯、爆発、点滅するライト）もあります。静的な光はライトマップ、動的な光は実行時に計算し足し合わせるのが、基本です。

## ライトの 3 つのモード

エンジンでは <strong>ライトごとにモードを、選び</strong>ます。

| モード | ライトマップに、焼く | 実行時に計算 | 用途 |
| --- | --- | --- | --- |
| ベイク（静的） | 直接光 + 間接光 | しない | 動かない、ライト（部屋の照明、街灯） |
| 動的（リアルタイム） | しない | 直接光（影も、実行時） | 動くライト（懐中電灯、爆発）、プレイヤーが触れるライト |
| ミックス（混合） | 間接光のみ | 直接光（影も、実行時） | 太陽など動かないが影は、動く物と連動したい |

### ミックスの詳細

ミックスは 間接光だけを、ベイクし直接光は実行時に計算します。動く物が影を落とせる（実行時の、シャドウ マップ）、間接光は焼き込み済みで安い両方の、いいとこ取りです。

```text
ベイク:   間接光のみ（ライトマップ）
実行時:   直接光（影つき）+ ライトマップの間接光
```

| ミックスの方式 | 内容 |
| --- | --- |
| 間接光のみ（Indirect） | 間接光を、ライトマップに。直接光 + 影は実行時（動く物の影が、出る） |
| 影マスク（Shadowmask） | 静的な物の影を別の、テクスチャに焼く。遠くの影は安く近くは実行時 |
| 減算（Subtractive） | 直接光 + 影を、ライトマップに焼く。動く物の影は実行時に減算で足す |

## 描画の組み合わせ

```hlsl
float4 main(PSInput input) : SV_Target {
  float3 albedo = g_albedo.Sample(g_linear_wrap, input.uv).rgb;
  float3 N = normalize(input.world_normal);

  // ① ライトマップ（焼き込み済みの、間接光、または、直接光 + 間接光）。
  float3 baked = g_lightmap.Sample(g_linear_clamp, input.lightmap_uv);

  // ② 動的な、ライト（実行時に、計算）。
  float3 dynamic_light = 0;
  for (uint i = 0; i < g_dynamic_light_count; ++i) {
    dynamic_light += ComputeLight(g_dynamic_lights[i], input.world_position, N);    // 距離減衰 + ランバート + 影（あれば）
  }

  // ③ 合算: アルベド × (焼き込み + 動的)。
  return float4(albedo * (baked + dynamic_light), 1.0);
}
```

<strong>焼き込み済みの光</strong>（ライトマップ）と、動的な光を足し合わせアルベドを、掛けます。どちらも、「光の量」なので足し算で合成できます。

## 動的なライトの問題

| 問題 | 内容 | 対策 |
| --- | --- | --- |
| 動的な光の間接光が無い | 動くライトの、反射光（光が壁で反射して周りを、照らす）はライトマップに含まれない | プローブ GI の、動的更新（[Dynamic Updates](../probes/dynamic-update.md)）、DDGI、簡易なアンビエントを動くライトの周りに、足す |
| ライトマップと動的な光の、二重になる | ライトをベイクにも、動的にも設定すると二重に照らされる | ライトの、モードを 1 つにする |
| 静的なライトのオン・オフが、できない | ベイクした光は、消せない（照明のスイッチが押せない） | スイッチする、ライトは動的にする。または、ライトマップを 2 セット（オン用、オフ用）焼いて切り替える |

### 照明のオン・オフ

<strong>部屋の照明を消す</strong>ような ゲームの、仕掛けには動的な光を使います。ライトマップの光は消せません。

| 方法 | 内容 |
| --- | --- |
| 動的なライトにする | オン・オフ可能。間接光は出ない（直接光だけ）。簡易なアンビエントを足すと自然 |
| ライトマップを 2 セット | オン用とオフ用を焼き、切り替え（または補間）。メモリが 2 倍 |
| ライトマップにライトごとの寄与を、焼く（ライトごとのライトマップ） | ライトごとに、別のライトマップを焼き実行時に、オン・オフに応じて足し合わせる。メモリがライト数に比例 |

## 太陽（動かない場合）

<strong>太陽が固定</strong>（時間が止まっている）なら、太陽の光もライトマップに焼けます。昼夜が変わるなら太陽は動的です（[Day-Night Cycle](../../atmosphere/sky-models/day-night.md)）。ライトマップは時間帯ごとに複数セットを焼き、補間するまたはプローブ GI の、動的更新を使います。
