# Lightmap UVs (UV2)

<strong>ライトマップはモデルの面ごとに「専用の場所」が必要</strong>で、通常のテクスチャの UV は、同じ場所を使い回す（重なる）ので、使えません。重ならない専用の UV（UV2）を用意します。このページでは UV2 の条件と、作り方を説明します。

!!! tip "ポイント"
    - UV2 ＝ 面が重ならない、ライトマップ専用の UV。
    - 面と面の間に余白（パディング）を取る（にじみ防止）。
    - 面積を実際の大きさに比例させる（解像度を揃える）。
    - 自動生成のツールがある。

## なぜ専用の UV が必要か

通常のテクスチャはタイリング（同じ絵の繰り返し）や、同じパーツの使い回しをします。たとえば、同じ形の柱を 10 本並べるとき、10 本とも同じ UV を使い、同じテクスチャを貼ればメモリを節約できます。ライトマップではこれができません。10 本の柱は窓からの距離が違えば当たる光が違うので、<strong>10 本それぞれが固有の場所を持たなければならない</strong>からです。そこで、メッシュに 2 番目の UV セット（UV2）を持たせ、ライトマップはこちらで引きます。

### UV2 が満たすべき条件

* 重ならない。別の面の光が混ざってしまうのを防ぎます。
* 0〜1 の範囲に収める。1 枚のテクスチャに入るためです。
* 歪みが少ない。テクセルあたりの面積が均一になれば、ライトの解像度が場所で変わりません。UV が引き伸ばされた所では、影の輪郭がぼやけます。
* 面ごとに分離する（アイランド）。面の境目で光が不連続でもにじまないようにします。
* アイランドの外側にマージン（パディング）を取る。バイリニア補間で隣のアイランドの色が滲み込むのを防ぎます。ライトマップをバイリニアで読むと、テクセル中心から 0.5 テクセル離れた所まで隣の値を拾うので、少なくとも 1〜2 テクセルの余白が要ります。ミップマップや圧縮を使うなら、さらに広く取ります。
* 面積に比例した割り当て。大きい面には多くのテクセルを小さい面には少なく割り当てます。

### 自動生成とパッキング

UV2 は DCC ツールやエンジン（Unity の Generate Lightmap UVs、Unreal Engine の Generate Lightmap UVs、オープンソースの xatlas など）で自動生成するのが普通です。処理は 2 段階です。まず、メッシュを歪みが小さくなる単位（チャート）に切り分けます（平らに近い面ごとに分割する）。次に、切り分けたチャートを 1 枚の正方形に隙間なく詰めます（パッキング）。パッキングの効率はライトマップの無駄を左右します。

自動生成の落とし穴は 切れ目が増えすぎることです。切れ目（シーム）が増えるとそこで光がわずかに不連続になり、継ぎ目が見えてしまいます。また、チャートの数が多いとマージンが占める割合が増えて、実質のテクセル数が減ります。形がシンプルなメッシュは自動生成に任せるより、手で UV2 を作ったほうが、きれいな結果になります。

### テクセル密度

ライトマップの 1 テクセルがワールドで何 cm にあたるか（テクセル密度）が影の細かさを決めます。大きな床や遠景なら 1 テクセル = 1 m 程度の粗さでも十分です。屋内の主要な面なら 10〜20 cm、影の細部が重要な重要オブジェクトなら数 cm まで上げます。細かくするほどメモリとベイク時間が増えるので、見る距離と重要度で使い分けます。エンジンの多くはオブジェクトごとに密度のスケールを設定でき、画面に近い物ほど高くします。

## なぜ専用の UV が要るのか

<strong>普通のテクスチャ</strong>（アルベドなど）は、同じ絵を複数の面で使い回します（タイル、ミラー、重なった UV）。ライトマップは面ごとに違う明るさを持つので各面に専用の場所が必要です。1 つのメッシュの全ての面を重ならないようにライトマップ上に並べた UV（UV2、第 2 UV）を使います。

| | 通常の UV（UV0） | ライトマップの UV（UV2） |
| --- | --- | --- |
| 面の重なり | あってよい（同じ絵を複数の面で使い回す） | あってはいけない（面ごとに違う、明るさ） |
| 0〜1 の範囲 | はみ出して、タイルしてよい | 0〜1 の中にすべて、収める |
| 向き・伸縮 | 自由（デザインで、決める） | 歪みを少なく（光が均一に焼ける） |
| 用途 | 色、模様 | 光 |

## UV2 の条件

| 条件 | 理由 |
| --- | --- |
| 面が重ならない | 重なった所は、同じ画素に別の面の光を書き込んで、衝突する |
| 0〜1 の範囲に収まる | ライトマップは、1 枚の画像。範囲の外は無い |
| 歪みが少ない | 歪んだ UV（引き伸ばし）は、画素ごとの面積が不均一になり、ある所は細かく別の所は粗い |
| 面の間に余白（パディング） | 隣の面の光がにじむ（バイリニア補間で隣の画素を読む）のを防ぐ |
| 面積に比例した大きさ | 広い面に大きな領域を与える（画素密度が一定） |

## UV2 の作り方

### ① DCC ツールで手動

<strong>3D ツール</strong>（Blender、Maya、3ds Max）で メッシュを展開（UV アンラップ）し、第 2 UVとしてライトマップ用の配置を作ります。手間ですが制御が効きます。

### ② 自動生成

自動で UV を作る、ライブラリやツールがあります。

| ツール | 内容 |
| --- | --- |
| UVAtlas（DirectX） | Microsoft の、UV アトラス生成ライブラリ。DirectX Tool Kit 周りで、使える |
| xatlas | オープンソースの、UV アトラス生成。C++ で組み込みやすい |
| エンジンの自動 UV（Unity、Unreal） | インポート時に自動で、UV2 を生成 |

自動生成の考え方は メッシュを小さな、パッチ（チャート）に分割し、各チャートを平らに展開（歪みを最小に。最小二乗等角写像、Lévy ら 2002）、チャートを 1 枚の画像に詰める（パッキング）、という流れです。

```cpp
// xatlas で、ライトマップ UV を自動生成する（概略）。
xatlas::Atlas* atlas = xatlas::Create();
xatlas::MeshDecl decl;
decl.vertexPositionData = positions;  decl.vertexPositionStride = sizeof(float) * 3;
decl.indexData = indices;  decl.indexCount = index_count;  decl.indexFormat = xatlas::IndexFormat::UInt32;
xatlas::AddMesh(atlas, decl);

xatlas::ChartOptions chart_options;                         // チャートの分割の、設定（歪みの、許容など）
xatlas::PackOptions pack_options;
pack_options.resolution = 1024;                              // ライトマップの、解像度
pack_options.padding = 2;                                    // 面の間の、余白（画素）
pack_options.texelsPerUnit = 8.0f;                           // 1 メートルあたりの、画素数（密度をそろえる）
xatlas::Generate(atlas, chart_options, pack_options);
// atlas->meshes[0] から、新しい頂点（UV2 つき）と、インデックスを取り出す。
```

`texelsPerUnit` は 画素密度（1 m あたりの、画素数）で ライトマップの細かさを決めます。8（12.5 cm ごとに 1 画素）が一般的です。密度をそろえるとどの面も同じ、細かさで光が焼けます。

## 頂点の分割

<strong>UV2 は UV0 と別の展開</strong>なので、1 つの頂点が UV0 と UV2 で、別の位置を持つ必要があります。展開の境目（チャートの継ぎ目）では、同じ位置の頂点が別の UV2 を持つため頂点が複製（分割）されます。頂点数が増えます。

```cpp
struct Vertex {
  float3 position;
  float3 normal;
  float2 uv0;            // 通常のテクスチャ（アルベドなど）
  float2 uv2;            // ライトマップ
};
```

## パディング（余白）の重要性

<strong>バイリニア補間</strong>でライトマップを読むと画素の境目では隣の画素の色も、混ざります。隣の面の画素が隣り合っていると、別の面の光がにじんで継ぎ目に線（ライト リーク）が出ます。

| 対策 | 内容 |
| --- | --- |
| 余白（2〜4 画素）を空ける | 面の間に何も、書かない領域を作る |
| 余白を面の色で塗りつぶす（ブリード） | 余白に隣の面の端の色を延ばして塗る。補間のにじみが自分の面の色に近くなる |

```text
面 A のチャート       余白       面 B のチャート
┌─────────────┐ ░░ ┌─────────────┐
│    A         │ ░░ │    B         │      ░░ = 余白（A の端の色を、延ばして塗る = ブリード）
└─────────────┘ ░░ └─────────────┘
```

## ライトマップの解像度の決め方

| 場所 | 密度（画素 / m） |
| --- | --- |
| 近くで見える重要な面（床、壁） | 8〜16 |
| 普通の面 | 4〜8 |
| 遠くの面、見えない面 | 1〜2、または焼かない |
| 屋外の地形 | 0.5〜2 |

<strong>画素密度を高く</strong>すると 影の境目が鋭くなりますがメモリが増えます（密度を 2 倍で、メモリは 4 倍）。メッシュごとに重要度に応じて密度を変えます。

## よくあるミス

??? failure "面の境目に暗い線やにじみが出る"
    <strong>余白を増やす</strong>・ベイク後に端の色を広げる。
