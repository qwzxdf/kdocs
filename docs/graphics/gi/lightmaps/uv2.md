# Lightmap UVs (UV2)

<strong>ライトマップは、モデルの面ごとに「専用の場所」が必要</strong>で、<strong>通常のテクスチャの UV は、同じ場所を使い回す（重なる）ので、使えません</strong>。重ならない、専用の UV（UV2）を用意します。このページでは、UV2 の条件と、作り方を説明します。

!!! tip "ポイント"
    - UV2 ＝ 面が重ならない、ライトマップ専用の UV。
    - 面と面の間に、余白（パディング）を取る（にじみ防止）。
    - 面積を、実際の大きさに比例させる（解像度を揃える）。
    - 自動生成のツールがある。

## なぜ専用の UV が必要か

通常のテクスチャは、タイリング（同じ絵の繰り返し）や、同じパーツの使い回しをします。たとえば、同じ形の柱を 10 本並べるとき、10 本とも同じ UV を使い、同じテクスチャを貼れば、メモリを節約できます。ライトマップでは、これができません。10 本の柱は、窓からの距離が違えば当たる光が違うので、<strong>10 本それぞれが固有の場所を持たなければならない</strong>からです。そこで、メッシュに 2 番目の UV セット（<strong>UV2</strong>）を持たせ、ライトマップはこちらで引きます。

### UV2 が満たすべき条件

* <strong>重ならない</strong>。別の面の光が混ざってしまうのを防ぎます。
* <strong>0〜1 の範囲に収める</strong>。1 枚のテクスチャに入るためです。
* <strong>歪みが少ない</strong>。テクセルあたりの面積が均一になれば、ライトの解像度が場所で変わりません。UV が引き伸ばされた所では、影の輪郭がぼやけます。
* <strong>面ごとに分離する</strong>（アイランド）。面の境目で光が不連続でも、にじまないようにします。
* <strong>アイランドの外側にマージン（パディング）を取る</strong>。バイリニア補間で、隣のアイランドの色が滲み込むのを防ぎます。ライトマップをバイリニアで読むと、テクセル中心から 0.5 テクセル離れた所まで隣の値を拾うので、少なくとも 1〜2 テクセルの余白が要ります。ミップマップや圧縮を使うなら、さらに広く取ります。
* <strong>面積に比例した割り当て</strong>。大きい面には多くのテクセルを、小さい面には少なく割り当てます。

### 自動生成とパッキング

UV2 は、DCC ツールやエンジン（Unity の Generate Lightmap UVs、Unreal Engine の Generate Lightmap UVs、オープンソースの xatlas など）で自動生成するのが普通です。処理は 2 段階です。まず、メッシュを、歪みが小さくなる単位（チャート）に切り分けます（平らに近い面ごとに分割する）。次に、切り分けたチャートを 1 枚の正方形に隙間なく詰めます（パッキング）。パッキングの効率は、ライトマップの無駄を左右します。

自動生成の落とし穴は、<strong>切れ目が増えすぎる</strong>ことです。切れ目（シーム）が増えると、そこで光がわずかに不連続になり、継ぎ目が見えてしまいます。また、チャートの数が多いと、マージンが占める割合が増えて、実質のテクセル数が減ります。形がシンプルなメッシュは、自動生成に任せるより、手で UV2 を作ったほうが、きれいな結果になります。

### テクセル密度

ライトマップの 1 テクセルが、ワールドで何 cm にあたるか（テクセル密度）が、影の細かさを決めます。大きな床や遠景なら 1 テクセル = 1 m 程度の粗さでも十分です。屋内の主要な面なら 10〜20 cm、影の細部が重要な重要オブジェクトなら数 cm まで上げます。細かくするほど、メモリとベイク時間が増えるので、見る距離と重要度で使い分けます。エンジンの多くは、オブジェクトごとに密度のスケールを設定でき、画面に近い物ほど高くします。

## よくあるミス

    <strong>余白を増やす</strong>・<strong>ベイク後に端の色を広げる</strong>。
