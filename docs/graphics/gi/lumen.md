# Lumen and Nanite

Unreal Engine 5 の看板機能である Lumen と Nanite は、名前だけが先に広まり、「何をしているのか」が見えにくい技術です。ゲームを作る側から見ると、これらは<strong>「ライトマップを焼く手間」と「LOD を作る手間」を実行時の処理に置き換えた</strong>ものです。ここでは、自分の描画に取り入れられる考え方に絞って説明します。

!!! tip "ポイント"
    - Lumen は動的なグローバル イルミネーション。複数の表現（スクリーン空間、メッシュ距離場、ハードウェア レイトレース）を組み合わせ、光を集める
    - 表面の見た目をキャッシュ（Surface Cache）に貯め、レイが当たった所で、そこから光を読む
    - Nanite は仮想化ジオメトリ。メッシュを小さなクラスターに分け、画面に必要な細かさのクラスターだけを GPU が選んで描く
    - どちらも、事前の焼き込みや手作りの LOD を減らす。代わりに、GPU 側の仕組みが複雑

## Lumen：動的 GI を 1 つにまとめる {#lumen}

動的 GI の手法には、それぞれ得意不得意があります。スクリーン空間の方式（[SSGI](ssgi.md)）は、画面に映っていない物からの光を拾えません。プローブ方式は、細かい陰影が出ません。ボクセルは、メモリを食います。

Lumen は、これらを<strong>近くは細かく、遠くは粗く</strong>という形で組み合わせます。

1. まず、画面に映っている範囲は、スクリーン空間でレイを飛ばして、当たりを探す
2. 当たらなかったレイは、シーンの簡略版（メッシュ距離場、または低解像度のメッシュ）に対して飛ばす
3. 当たった場所の明るさは、そこを直接再計算せず、「Surface Cache」から読む

### Surface Cache {#surface-cache}

メッシュの表面を小さなカード（四角い領域）に分けて、各カードの明るさや色（直接光を当てた結果）をアトラスに貯めます。レイが当たったときは、当たった点を含むカードから、貯めてある光を読むだけです。当たった場所で、毎回ライティングを計算せずに済みます。

カードは、フレームを通して少しずつ更新します。ライトが動くと、数フレームかけて反映されます。動的な GI の反映に数フレームの遅れが出るのは、この仕組みのためです。

### 最終的に集める {#gather}

画面のピクセルごとに全部レイを飛ばすと重すぎるので、スクリーン プローブ（画面上に格子状に置いた、光を集める点）で光を集めます。プローブは、その周りの半球方向にレイを飛ばして光を受け取ります。そこから、周りの画素に補間します。時間方向の蓄積とフィルタで、ノイズを消します。

## Nanite：仮想化ジオメトリ {#nanite}

ゲームのモデルは、距離に応じて、頂点数の違う LOD を切り替えます。LOD を作るのは手間ですし、切り替わる瞬間が目立ちます。

Nanite は、メッシュを約 128 個程度の三角形からなる小さなクラスターに分け、階層構造にします。粗い階層のクラスターは、細かいクラスターを統合・簡略化したものです。

描画のとき、GPU 側で、画面での大きさが約 1 ピクセルになるように、階層から適切なクラスターを選びます。画面に映る三角形は、常に 1 ピクセルほどの大きさになるので、距離にかかわらず、見た目の細かさが一定になり、LOD の切り替えも目立ちません。

### 小さい三角形を描く工夫 {#small-triangles}

三角形が 1 ピクセル程度に小さいと、ハードウェアのラスタライザーは、効率が悪くなります（1 ピクセルのために、2×2 のクアッドを処理する）。そこで、Nanite は、小さい三角形をコンピュート シェーダー（ソフトウェアのラスタライザー）で描き、大きい三角形だけをハードウェアで描き分けます。

描画した結果は、ビジビリティ バッファ（各ピクセルがどの三角形か、の ID）に書きます。その後、ID から材質を引いて、ライティングします。[Visibility Buffer](../../rendering/visibility-buffer.md) の考え方です。

## 自分の描画に取り入れるなら {#apply}

Lumen と Nanite をそのまま自作するのは、大規模な作業です。ただし、考え方は部分的に取り入れられます。

| 考え方 | 取り入れ方 |
| --- | --- |
| 簡略版のシーンでレイを飛ばす | 距離場や低ポリのメッシュに対して、レイを飛ばす |
| 光の結果をキャッシュして使い回す | ライトマップや、プローブに貯める。更新を何フレームかに分ける |
| スクリーン プローブで集める | 画面の格子点だけで光を集め、周りは補間する |
| クラスターごとの可視判定 | メッシュ シェーダーで、クラスター単位にカリングする |
| ビジビリティ バッファ | 三角形 ID を書き、あとで材質を引く |

## これだけ覚える {#summary}

- Lumen は、複数の手法を組み合わせた動的 GI。光を Surface Cache に貯めて使い回す
- Nanite は、メッシュをクラスターに分け、必要な細かさだけを GPU が選ぶ
- 小さい三角形はソフトウェアで、結果はビジビリティ バッファに書く
