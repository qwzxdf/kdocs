# Global Illumination (GI)

光源から出た光は、<strong>面に当たって反射し、別の面を照らします</strong>。この<strong>跳ね返った光（間接光）</strong>まで含めて計算することを、<strong>グローバル イルミネーション</strong>（GI、大域照明）と呼びます。赤い壁の隣の白い床がほんのり赤くなる（カラー ブリーディング）、日陰でも真っ暗にならないといった現実感は、間接光が作ります。しかし、<strong>直接光（光源 → 面 → 目）</strong>と違い、間接光はシーン全体が互いに影響し合うため、リアルタイムで正確に解くのは非常に難しい問題です。このセクションでは、<strong>「何を解いているのか」</strong>から、ライトマップ・プローブ・SSGI・ボクセル・DDGI・レイトレまで方式ごとの発想とトレードオフを説明します。

## GI をどう学ぶか

GI は、方式がとても多い分野です。ライトマップ、プローブ、SSGI、ボクセル、DDGI、レイトレ。名前を並べると別々の技術に見えますが、すべて<strong>「他の面から来る光を、どこに・いつ・どれだけの精度で持つか」</strong>という同じ問題に対する、別々の答えです。このセクションでは、まず問題の形をはっきりさせてから（[GI Theory](theory/index.md)）、答えを古い順に追います。

最初の答えは、<strong>事前に計算して焼く</strong>ことでした。光が動かない前提なら、時間をかけて正確に計算した結果を、テクスチャ（ライトマップ）や空間の点（プローブ）に保存しておけば、実行時は読むだけで済みます。ゲームの GI は長い間これでした。次に、「光が動いても使いたい」という要求が出ました。そこで登場するのが、画面の情報だけで近似する SSGI、シーンをボクセルにして円錐でトレースするボクセル GI、そしてレイトレーシングで空間のプローブを毎フレーム更新する DDGI です。さらに最近は、ハードウェアのレイトレーシングや、Lumen のような統合的な仕組みで、「動的な光とジオメトリ」の両方を扱う方向へ進んでいます。

読むときは、「この方式は、どの時点で計算していて、何を犠牲にしているのか」という視点で比べてみてください。犠牲にしているものは、必ずあります。ライトマップなら動的な光、SSGI なら画面外の情報、ボクセル GI ならメモリと解像度、レイトレ GI ならノイズと対応ハードウェアです。
