# ライトマップ

**静的なシーン**の間接光は、**毎フレーム計算する必要がありません**。**事前（オフライン）に、時間をかけて正確に計算**し、**結果をテクスチャに焼いて**おけば、**実行時はテクスチャを 1 回引くだけ**で、**高品質な GI**が**ほぼ無料**で手に入ります。これが**ライトマップ**（Lightmap）です。**最も古く、今でも最も広く使われる GI**の一つです。

!!! tip "ポイント"
    - <strong>静的なメッシュ</strong>の<strong>表面の明るさ</strong>を、<strong>専用の UV（UV2）</strong>上に<strong>テクスチャとして保存</strong>。
    - 実行時のコストは<strong>テクスチャ 1 回</strong>（＋乗算）。<strong>品質はベイクの質で決まる</strong>。
    - <strong>ライトマップ UV</strong>は<strong>重ならない・ゆがみが少ない・マージンあり</strong>が必須。
    - <strong>方向情報</strong>（Directional / SH ライトマップ）を足すと<strong>法線マップ</strong>が効く。
    - 欠点：<strong>動く物・動くライトは反映されない</strong>。<strong>メモリ・ベイク時間</strong>。
    - <strong>動く物体には、プローブ</strong>を併用する（[ライト プローブ](probes.md)）。

## 原理

**オフライン**で**パス トレーシング**などの、**重いが正確な計算**を行い、<strong>各表面点に届く光（放射照度）</strong>を求めます。それを**メッシュ専用の UV 座標**に沿って、<strong>テクスチャ（ライトマップ）</strong>に書き込みます。

実行時、**ピクセル シェーダー**は、**ライトマップ UV で、ライトマップを引き**、**アルベド（色）に掛け**るだけです。

```hlsl
float3 irradiance = lightmap.Sample(linear_sampler, input.lightmap_uv).rgb;
float3 indirect_diffuse = albedo * irradiance;
```

| 項目 | 内容 |
| --- | --- |
| **保存するもの** | **放射照度**（またはアルベドを掛けた後の**出射光**） |
| **実行時のコスト** | **テクスチャ 1 回** |
| **品質** | **ベイクの設定で決まる**（バウンス数・サンプル数・解像度） |
| **対象** | **静的なメッシュ・静的なライト**（動かないもの） |

## ライトマップ UV（UV2）

**通常のテクスチャ UV**は、**タイリング（繰り返し）や、同じパーツの使い回し**をします。**ライトマップは、各表面点が固有の場所**を持たなければならないので、**専用の UV**（**UV2**、2 番目の UV セット）が必要です。

| 要件 | 理由 |
| --- | --- |
| **重ならない** | **別の面の光**が**混ざる**のを防ぐ |
| **0〜1 の範囲に収める** | **1 枚のテクスチャ**に入る |
| **歪みが少ない** | **テクセルあたりの面積**が**均一**になる（**ライトの解像度が場所で変わらない**） |
| <strong>面ごとの分離（アイランド）</strong> | **面の境目で光が不連続**でもにじまない |
| <strong>マージン（パディング）</strong> | **アイランドの外側**に**余白**を持たせ、**バイリニア補間で隣のアイランドの色**が**にじまない**ようにする |
| **面積に比例した割り当て** | **大きい面は多くのテクセル** |

**UV2 はツール（DCC・エンジン）で自動生成**されることが多く、<strong>パッキング（アイランドの敷き詰め）</strong>は、**ライトマップの効率**を左右します。

### テクセル密度

**ライトマップの 1 テクセルが、ワールドで何 cm か**（**テクセル密度**）が、**影の細かさ**を決めます。

| 密度の目安 | 用途 |
| --- | --- |
| <strong>粗い（例：1 テクセル = 1 m）</strong> | **遠景・床・大きな面** |
| <strong>標準（例：10〜20 cm）</strong> | **屋内・主要な面** |
| <strong>細かい（例：数 cm）</strong> | **影の細部が重要な、重要なオブジェクト** |

**細かくするほど**、**メモリ・ベイク時間**が増えます。

## ベイクの流れ

| 手順 | 内容 |
| --- | --- |
| **① UV2 の生成・パッキング** | 全メッシュの UV2 を、**ライトマップ アトラス**に配置 |
| **② ベイク** | **各テクセルのワールド位置・法線**から、**パス トレース**で放射照度を計算 |
| **③ デノイズ** | **少ないサンプルで速く**計算し、**デノイザ**でノイズを除去 |
| **④ 圧縮・出力** | <strong>BC6H（HDR）</strong>などに**圧縮** |
| **⑤ 実行時に読み込む** | **シーンと一緒にライトマップ**をストリーミング |

**ベイクには数分〜数時間**かかります。**GPU ベイク**（GPU レイトレース）で、**大幅に短縮**できます。

## 方向情報（法線マップとの併用）

<strong>通常のライトマップは、「その点に届く光の総量（スカラー）」</strong>しか持ちません。**法線マップで細かい凹凸を付けてもライトマップの明るさは、法線に応じて変わらない**ので、**平坦に見えます**。

| 方式 | 内容 |
| --- | --- |
| **スカラーのみ** | **放射照度のみ**。**法線マップが効かない** |
| **Directional ライトマップ** | **主な光の方向**を**もう 1 枚のテクスチャ**に保存。**方向と法線**から、**明るさを補正** |
| **SH ライトマップ** | <strong>L1 SH（4 係数）</strong>を保存。**法線**で、**SH を評価** |
| <strong>Radiosity Normal Mapping（Half-Life 2）</strong> | **3 つの基底方向**（正三角形に配した 3 方向）の、**それぞれの放射照度**を保存し、**法線マップの法線**で**3 方向を補間** |

```hlsl
float3 basis0 = lightmap0.Sample(linear_sampler, uv).rgb;
float3 basis1 = lightmap1.Sample(linear_sampler, uv).rgb;
float3 basis2 = lightmap2.Sample(linear_sampler, uv).rgb;
float3 w = saturate(float3(dot(n_ts, kBasis0), dot(n_ts, kBasis1), dot(n_ts, kBasis2)));
w *= w;
w /= (w.x + w.y + w.z);
float3 irradiance = basis0 * w.x + basis1 * w.y + basis2 * w.z;
```

**方向情報**を持つことで**法線マップの凹凸に応じた、陰影**が**間接光にも**加わります。**テクスチャが 3 枚**に増える（**メモリ**）のが代償です。

## 鏡面は別

**ライトマップは、拡散の間接光のみ**です。**鏡面反射**は**反射プローブ**（[反射プローブ](../reflections/probes.md)）が**担当**します。

## 動く物体との併用

**ライトマップは、メッシュの表面**に焼くので、**動く物体・キャラクターには、使えません**。**動く物体**は**ライト プローブ**（[ライト プローブ](probes.md)）から、**周囲の間接光**を受け取ります。**静的な背景はライトマップ、動く物はプローブ**が**標準的な組み合わせ**です。

| 対象 | GI の方式 |
| --- | --- |
| **静的な背景** | ライトマップ |
| <strong>動的な物体（キャラ・乗り物）</strong> | ライト プローブ（ライトマップと**同じ見た目に、そろえる**） |
| **動く物が背景に落とす間接光** | **反映されない**（限界） |

## 動的なライトとの関係

**ライトマップに焼いた光は、固定**です。**時間で動く太陽**（昼夜サイクル）には**対応できません**。

| 対策 | 内容 |
| --- | --- |
| **複数のライトマップを切り替え・補間** | **朝・昼・夕**の**ライトマップを複数**持ち、**時間で補間**（**メモリが倍々**） |
| **直接光は動的、間接光のみベイク** | **間接光だけ**を**ベイク**し、<strong>直接光（太陽）</strong>は**動的に**。**ミックス ライティング** |
| <strong>影だけ別に（シャドウマスク）</strong> | **静的な影**を**別のチャンネル**に焼く |
| <strong>動的な GI（プローブ・DDGI・RT）</strong> | **昼夜サイクルが必須**なら、**動的な方式** |

## 長所と短所

| 長所 | 短所 |
| --- | --- |
| **実行時のコストがほぼゼロ** | **静的なものだけ**（動く物・動くライトを反映できない） |
| **高品質**（オフラインの正確な計算） | **メモリ**（ライトマップ アトラス） |
| **モバイルでも使える** | **ベイク時間**（変更のたびに再ベイク） |
| **ノイズなし**（きれいなソフト シャドウも） | **UV2 の準備**（歪み・マージン・密度の管理） |
| **シェーダーが簡単** | **イテレーションが遅い**（ライトを動かして、すぐ確認できない） |

## よくあるミス

??? failure "ライトマップ UV が重なって、他の面の光が混ざる"
    **重ならない UV2** を作ります。

??? failure "アイランドの縁に、にじみ（ライト リーク）が出る"
    **十分なマージン**を取り、**パディングの処理**をします。

??? failure "テクセル密度がバラバラで、場所によって影の解像度が違う"
    **面積に比例**した、**均一な密度**に揃えます。

??? failure "法線マップが、ライトマップ上で効いていない"
    **方向情報付き**のライトマップを使います。

??? failure "動く物体が、背景より暗く（明るく）浮く"
    **プローブ**を**ライトマップと同じ、ベイク結果**から作ります。
