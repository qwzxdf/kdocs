# ライト プローブ

[ライトマップ](lightmaps.md)は、**メッシュの表面**に焼くので、**動く物体には使えません**。**ライト プローブ**（Light Probe）は、<strong>空間の「点」</strong>に、<strong>その場所での周囲の光（放射照度）</strong>を**保存**します。**動く物体は自分の位置の近くのプローブを補間して引けば**、**周囲の間接光**を受けられます。**拡散の間接光は低周波**なので、**プローブはまばらに置いても**、**十分**です。**ライトマップと対になる、標準的な動的物体の GI**です。

!!! tip "ポイント"
    - プローブ ＝ <strong>空間の 1 点での、全方向の入射光（放射照度）</strong>を<strong>SH などの少数の数値</strong>で保存。
    - 引くときは<strong>位置に応じて、近くのプローブを補間</strong>し、<strong>法線で SH を評価</strong>。
    - <strong>四面体分割</strong>や<strong>3D 格子</strong>で、<strong>補間する相手</strong>を決める。
    - <strong>動く物体</strong>は<strong>自分の位置</strong>、<strong>静的な背景</strong>は<strong>ライトマップ</strong>。
    - <strong>置き方</strong>（密度・壁の両側・光の境目）が<strong>品質</strong>を決める。<strong>壁越しの漏れ</strong>が最大の問題。
    - 保存形式は<strong>SH L2（9 係数）・L1・アンビエント キューブ</strong>。<strong>軽さと精度</strong>で選ぶ。

## 原理

**プローブの位置 `p_i`** で、**全方向の入射光**を**キャプチャ**（ベイク・または動的に計算）し、<strong>放射照度 E_i(n)</strong>を**SH に投影**して、**係数**として**保存**します。

| 手順 | 内容 |
| --- | --- |
| **① 配置** | **シーンの空間にプローブを置く**（手動・自動・格子） |
| <strong>② 計算（ベイク）</strong> | **各プローブ**で**全方向のレイ**（またはキューブマップのレンダリング）から、**放射照度を SH に** |
| **③ 実行時の補間** | **物体の位置**に応じ、**近くのプローブの SH を、重み付けして補間** |
| **④ 評価** | **補間した SH を物体の法線で評価**して、**間接拡散光** |

```hlsl
float3 sh[9] = InterpolateProbes(world_pos);
float3 irradiance = EvaluateSH9(world_normal, sh);
float3 indirect_diffuse = albedo * irradiance;
```

## 補間の方式

### 四面体分割（Delaunay）

**プローブを不規則に置いて**、**その点群を四面体に分割**します。**物体がどの四面体の中にいるか**を調べ、**その 4 つの頂点のプローブ**を、**重心座標の重み**で**補間**します。

| 項目 | 内容 |
| --- | --- |
| **利点** | **自由な配置**（**重要な場所は密に他は疎に**） |
| **欠点** | **四面体の検索**が必要（CPU で物体ごとに）。**四面体が壁を貫通**して、**光が漏れる**ことがある |
| **採用例** | **Unity の Light Probe Group** |

### 3D 格子

**プローブを規則的な 3D 格子**に並べ、**格子上でトライリニア補間**します。

| 項目 | 内容 |
| --- | --- |
| **利点** | **補間が安い**（GPU で、3D テクスチャとして引ける）。**画素ごとに引ける** |
| **欠点** | **密度が一様**（疎な所で無駄）。**メモリが体積に比例** |
| **採用例** | <strong>ボリューム（Light Probe Volume）</strong>・**DDGI**・**モバイル向け** |

### 画素ごとの引き

<strong>物体ごと（1 点）</strong>でなく、**画素ごと**に**プローブを引く**（**GPU で、3D テクスチャ**から）と、**大きな物体・地形の場所による変化**が**反映**されます。**1 つの物体を 1 点で代表**すると、**大きな物体**で**不自然**です。

## SH をどう持つか

| 形式 | 係数 | 内容 |
| --- | --- | --- |
| <strong>SH L2（9 係数 × RGB）</strong> | 27 | **最も精度が高い**。**重い** |
| <strong>SH L1（4 係数 × RGB）</strong> | 12 | **軽い**。**やや粗い向き依存** |
| <strong>アンビエント キューブ（6 方向）</strong> | 18 | **6 方向（±X, ±Y, ±Z）の色**。**法線で、3 方向を混ぜる**。**非常に安い**（Source エンジンなど） |
| <strong>八面体マップ（小さなテクスチャ）</strong> | 可変 | **各プローブに小さな方向テクスチャ**。**DDGI などで採用**（[DDGI](ddgi.md)） |

<strong>SH のリンギング（符号が負になる）</strong>に**注意**：**SH で表すと負の値が出る**ことがあり、<strong>ウィンドウ関数（ハンニング窓）</strong>で**抑える**・**クランプ**する対策があります。

## 置き方

**プローブの配置**は、**品質**に直結します。

| 指針 | 内容 |
| --- | --- |
| **光が変化する場所に密に** | **明暗の境目・窓の近く・照明の近く** |
| **動く物体が通る場所に置く** | **通路・部屋・キャラが歩く範囲** |
| **壁の両側に置く** | **壁の内側にプローブがあると、反対側の光**が**混ざる**（**ライト リーク**） |
| **家具の中・壁の中は避ける** | **幾何の内部**のプローブは、<strong>黒（または不正な値）</strong>に |
| **高さ方向にも** | **床・腰・頭**の**数段** |
| **自動配置** | **格子を自動生成**し、**幾何の内側のプローブを、除外・補完** |

### ライト リーク（壁越しの漏れ）

**プローブ間の補間**は、**壁の存在を知らない**ので、**壁の向こう側のプローブの光**が、**こちら側に漏れる**ことがあります。

| 対策 | 内容 |
| --- | --- |
| **プローブの配置の工夫** | **壁の近くを密に**・**壁の両側にそれぞれ**置く |
| **可視性の重み付け** | **物体から、プローブが見えるか**を**判定**し、**見えないプローブの重みを下げる**（[DDGI](ddgi.md)の方式） |
| <strong>ボリュームの分割（ゾーン）</strong> | **部屋ごと**に**プローブ グループを分ける** |
| **法線バイアス** | **物体の位置を法線方向に少しずらして**、**補間** |

## 動的な更新

**ベイクしたプローブ**は、**静的な光**に対する**固定**の値です。

| 方式 | 内容 |
| --- | --- |
| **ベイクのみ** | **固定**。**最も安い** |
| **ライトの強さ・色を実行時に掛ける** | **ライトごとにプローブを別々にベイク**し、**実行時に強さ・色で合成**（**複数ライト分のメモリ**） |
| **実行時に再ライティング** | **プローブごとにレイ・キューブマップ**で**毎フレーム更新**（[DDGI](ddgi.md)・[レイトレ GI](rt-gi.md)） |
| **時間帯の切り替え** | <strong>複数セット（朝・昼・夕）</strong>を、**補間** |

## 反射プローブとの違い

| 項目 | ライト プローブ | 反射プローブ |
| --- | --- | --- |
| **保存するもの** | **放射照度**（拡散の間接光） | **放射輝度**（周囲の画像） |
| **周波数** | **低い** | **高い** |
| **保存形式** | **SH・少数の数値** | **キューブマップ** |
| **用途** | **拡散反射** | **鏡面反射** |
| **密度** | **やや密** | <strong>疎（部屋ごと）</strong> |

**反射プローブ**は、[反射プローブ](../reflections/probes/index.md)で説明しています。**両方を置いて**、**拡散と鏡面の間接光**をそれぞれ賄います。

## コストと利点

| 項目 | 内容 |
| --- | --- |
| **実行時のコスト** | **補間 ＋ SH の評価**。**非常に安い** |
| **メモリ** | **プローブ数 × 係数**。**ライトマップより、はるかに小さい** |
| **動く物体への適用** | **自然に対応** |
| **品質の限界** | **低周波のみ**。<strong>細かい間接光の影（接触部）</strong>は出ない（**AO で補う**） |

## 長所と短所

| 長所 | 短所 |
| --- | --- |
| **動く物体に間接光を与えられる** | **低周波のみ**（細かい間接影が出ない） |
| **安い・小さい** | **ライト リーク**（壁越しの漏れ） |
| **ライトマップと併用しやすい** | **配置の手間**（品質が置き方次第） |
| **動的な更新に拡張できる** | **ベイクのままでは、光の変化に追従できない** |

## よくあるミス

??? failure "壁の向こう側の光が漏れて、部屋の中が明るくなる"
    **壁の両側にプローブを置く**・**可視性の重み付け**・**法線バイアス**。

??? failure "プローブが、幾何の内側にあり、黒い値になる"
    **内側のプローブを除外**し、**周囲の値で補完**します。

??? failure "SH のリンギングで、負の値・色のにじみが出る"
    **ウィンドウ関数**・**クランプ**で抑えます。

??? failure "大きな物体を 1 点で代表して、場所による変化が出ない"
    **画素ごとにプローブを引く**。
