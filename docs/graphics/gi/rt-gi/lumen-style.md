# Lumen-Style Approaches

<strong>Lumen のような方式は、シーンを簡略化した表現（距離場やサーフェス キャッシュ）でレイを飛ばし、結果をキャッシュして再利用します</strong>。ハードウェアのレイトレが無くても動くのが特徴です。このページではこの方式の構成と、利点・欠点を説明します。

!!! tip "ポイント"
    - シーンを簡略化して持つ（距離場・サーフェス キャッシュ）。
    - 画面のプローブから、簡略化したシーンへトレース。
    - 結果をキャッシュして、時間的に再利用。
    - ハードウェア RT が無い環境でも動く。
    - 細部の精度はハードウェア RT に劣る。

## Lumen 的な方式
<strong>Unreal Engine 5 の Lumen</strong>は、ハードウェア レイトレースが無くても動くGIです。複数の手法を階層的に組み合わせています。

| 要素 | 内容 |
| --- | --- |
| サーフェス キャッシュ | メッシュの表面を小さな「カード」にキャプチャし、各カードに直接光・間接光を保存（ヒット点の光を安く得るため） |
| 距離場によるトレース | メッシュごとの SDFとグローバル SDFで、ソフトウェア レイトレース（[Distance Field Shadows](../../shadows/sdf-shadows.md)） |
| 画面空間トレース（最初の手段） | 近距離は画面の深度バッファで精密にトレース（[SSGI](../ssgi.md)） |
| スクリーン プローブ | 画面上に間引いて置いたプローブから、レイを飛ばし画素へ補間（画素ごとにレイを飛ばさない） |
| ワールド プローブ（遠距離） | 遠くの光は世界空間の粗いプローブから |
| HW RT モード | 対応 GPUでは、距離場の代わりにハードウェア レイトレース |


サーフェス キャッシュは、メッシュの表面を小さな「カード」としてキャプチャし、各カードに直接光と間接光を保存します。レイが当たった点の光を安く得るための仕組みです。三角形から毎回ライティングを計算する代わりに、カードの上のテクスチャを読めば済みます。距離場によるトレースはメッシュごとの SDF とグローバル SDF を使ったソフトウェアのレイトレースです（[Distance Field Shadows](../../shadows/sdf-shadows.md)）。画面空間トレースは近距離を画面の深度バッファで精密に追う、最初の手段です（[SSGI](../ssgi.md)）。画面で見つからなければ距離場に移ります。

スクリーン プローブがコストを下げる鍵です。画面を 16×16 画素程度のタイルに区切り、タイルごとに 1 個のプローブを置いて、プローブからだけレイを飛ばします。各プローブは八面体マップに方向ごとの放射輝度を持ちます。画素は周りのプローブから補間して間接光を得ます。画素ごとにレイを飛ばさないので、レイの数を 1/100 以下に減らせます。ワールド プローブ（遠距離）は、遠くの光を世界空間の粗いプローブから読みます。そして、対応 GPU では距離場の代わりにハードウェア レイトレースのモードも使えます。

「画素ごと」ではなく「間引いたプローブ」からレイを飛ばすことで、コストを大幅に下げています。

## 考え方のまとめ

Lumen の設計思想は <strong>「正確さを段階ごとに捨てて、コストを下げる」</strong>ことです。近距離は画面の深度で精密に中距離は距離場で粗く、遠距離はワールド プローブでさらに粗く追います。見た目への影響は近いほど大きく、遠いほど小さいのでこの配分が理にかなっています。レイは画素ごとでなく間引いたプローブから飛ばし、結果はキャッシュとして時間方向に再利用します。

トレードオフは簡略化したシーンを使うことで、細部の精度が落ちることです。薄い壁、小さな隙間、細かい模様の物体では距離場の解像度が足りず、光漏れや暗すぎる箇所が出ます。ハードウェアのレイトレースを併用すれば、これらは大きく改善されます。

## 1 つの手法では足りない

Unreal Engine 5 の <strong>Lumen</strong>（Wright ら、2022）は 1 つの手法ではなく複数の手法を、組み合わせたハイブリッドです。それぞれの手法の長所を生かし短所を、補い合います。ハードウェア レイトレーシングが、無くても動き有ると品質が上がります。

| 手法 | 得意 | 苦手 |
| --- | --- | --- |
| 画面空間のトレース（SSGI、SSR） | 近距離で最高精度（画面の実際の、ジオメトリ）。安い | 画面の外・隠れた面が、無い |
| 距離場（ソフトウェア、メッシュ SDF） | 世界全体。安い遠くまでレイを飛ばせる | 細かい形状は、粗い（距離場の解像度） |
| ハードウェア レイトレーシング | 本物の、三角形に対して正確 | 重い、GPU が必要 |
| サーフェス キャッシュ（面ごとの、ライティングのキャッシュ） | 当たった面の、ライティングを高速に引ける（毎回、計算しない） | キャッシュの更新が、必要 |

## 全体の構造（概要）

```text
各画素から、レイを、飛ばす
   ① まず、画面空間で、トレース（近距離。最も、正確）
        ↓ 当たらなければ
   ② 距離場（またはハードウェア RT）で、世界全体を、トレース（遠距離）
        ↓ 当たった点の、ライティングは
   ③ サーフェス キャッシュ（面ごとの、ライティングの、キャッシュ）から、引く（再計算しない）
        ↓ それでも、ノイジーなので
   ④ プローブ（スクリーン空間、ワールド空間）に、集めて、空間・時間で、フィルタ
```

### ① 近くは画面空間

<strong>画面に映っている</strong>、近距離のジオメトリに当たるレイは、画面空間のレイマーチ（[SSGI](../ssgi.md)）で、高精度かつ安くトレースできます。深度バッファがそのままジオメトリです。

### ② 遠くは距離場

画面空間で当たらなかったレイ（画面の外・隠れた面）は、メッシュの距離場（各メッシュを、距離場に変換したデータ。[Distance Field AO](../../ao/world-space/dfao.md)）で、トレースします。距離場はスフィア トレーシング（距離が、分かるので大きく進める）で速く、世界全体を辿れます。

```hlsl
// 距離場の、スフィア トレーシング: 各点での、最も近い面までの、距離だけ、安全に、進める。
float3 p = origin;
for (int i = 0; i < kMaxSteps; ++i) {
  float d = SampleGlobalDistanceField(p);                                // 最も近い面までの距離（グローバル距離場）
  if (d < kHitThreshold) break;                                          // 面に、十分、近づいた → 当たり
  p += dir * d;                                                          // 距離だけ、安全に進む（面を、越えない）
}
```

ソフトウェアで 動くので、ハードウェア レイトレーシングが無い、GPU でも使えます（精度は、距離場の解像度で決まる）。

### ③ サーフェス キャッシュ

レイが当たった点のライティングを 毎回、計算すると重い（直接光、影、間接光）。メッシュの各面にライティングの、キャッシュ（サーフェス キャッシュ、カード）を持ち当たった点のライティングは、キャッシュから読むだけにします。

| 項目 | 内容 |
| --- | --- |
| カード | メッシュを 6 方向（上下左右前後）から見た小さな平面の、画像（アルベド、法線、深度、ライティング）のアトラス |
| 更新 | 毎フレーム、一部（優先度の高いカード）だけ、ライティングを再計算してキャッシュを、更新 |
| 使い方 | レイが当たった点を、カードに投影しそこのライティングを、読む |

### ④ 集めてフィルタする

画素ごとのレイは ノイジーなので、プローブ（スクリーン空間に並べた、プローブ）に集め時間・空間で、フィルタします（[Fighting Noise](noise.md)）。プローブに集めることで 1 画素あたりの、コストを減らしプローブの補間で、全画素の間接光を得ます。

## 長所と短所

| | 内容 |
| --- | --- |
| 長所 | 動的（光・物の変化に、追従）。世界全体の間接光 |
| 長所 | ハードウェア RT が、無くても動く（距離場） |
| 長所 | GI と反射（粗い鏡面）を同じ、仕組みで扱える |
| 短所 | 実装が非常に複雑（距離場、サーフェス キャッシュ、プローブ、フィルタ）。自作は大変 |
| 短所 | 距離場の解像度による、細かい形状の欠落、光漏れ（薄い壁） |
| 短所 | メモリ（距離場、カード アトラス、プローブ） |
| 短所 | ハードウェア RT 版では、GPU の世代に依存 |

## 自作する場合の現実的な構成

<strong>フル機能の Lumen を自作</strong>するのは、現実的ではありません。小規模には必要な機能を絞った構成が、現実的です。

| 目的 | 構成 |
| --- | --- |
| 動的な環境光（まずこれ） | SSGI + ライト プローブ（ベイク、または空の SH） |
| 動的な間接光を広く（RT 対応の GPU） | DDGI（[DDGI](../ddgi.md)） |
| ソフトウェアで世界全体の、間接光 | ボクセル GI（[Voxel GI](../voxel-gi.md)）、距離場 |
| 高品質（RT 対応の GPU） | ReSTIR GI（[ReSTIR GI](restir.md)）+ デノイザー |
