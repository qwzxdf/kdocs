# Wakes and Collisions

水に浮かべた船の後ろに何も残らないと、船は水面の上をすべっているように見えます。船が水に触れていることを一番安く伝えるのは、後ろに伸びる白い泡の筋と V 字に広がる波の模様です。このページでは、V 字の角度がどこから来るのかを式で確かめてから、泡を「履歴バッファ」に書き込む方法と、V 字の帯（リボン）を置く方法の 2 つを、動くコードで組みます。最後に、物が水に落ちたときの波紋・泡・しぶきを時間の長さの違いとして整理します。

!!! tip "ポイント"
    - 航跡の V 字の半角は深い水の理論では約 19.47°（`asin(1/3)`）で、tan の値は約 0.354 です。このページではこの値を C++ で数え直して確かめました。
    - 泡は船が通った位置を履歴バッファに書き込み毎フレーム指数で薄くすることで作ります。後ろへ流れる筋が残るのは薄くなる速さが一定だからです。
    - 書き込みを円だけで行うと船が速いときに、跡が点々に途切れます。前フレームの位置から今の位置までの線分で書くと途切れません。
    - 履歴の更新は読み取りと書き込みを別のテクスチャにします。同じテクスチャを読みながら書くことはできません。

## 航跡の 3 つの部品 {#parts}

船の後ろに見える模様は性質の違う 3 つの部品に分けて考えると作りやすくなります。

1. **V 字の波**。ケルビン波と呼ばれる水面の波の模様です。形は幾何で決まり船が速くなっても大きく変わりません（次の節で確かめます）。
2. **船尾の泡の帯**。船体やスクリューが水をかき混ぜて、空気を巻き込んだ所です。形は決まっておらず船の動きに合わせて広がって消えます。
3. **船首波としぶき**。船首が水を押しのけてできる盛り上がりと飛び散る水です。

3 つとも一度に物理で解く必要はありません。V 字は帯のメッシュやテクスチャで描き泡は履歴バッファに書き込みしぶきはパーティクルで足す、という分担が考えやすいと思います。このページが主に扱うのは 1 と 2 です。

## ケルビン波の形 {#kelvin}

### くさびの角度を導く {#kelvin-derivation}

進む船の後ろには V 字の縁（くさび）ができます。この V 字の半角は船の速さによらず約 19.47° になると説明されることが多い値です。ここでは、深い水の理論からこの値が出てくる様子を追います。以下の導出は教科書的な手順を私が書き直したもので、す。原典（Thomson 1887）は読んでいません。

使う関係は 2 つです。1 つは深い水の波の分散関係 `ω² = g·k` です。ここから位相速度は `c = √(g / k)` になり波のエネルギーが進む速さ（群速度）は、位相速度のちょうど半分の `c / 2` になります。もう 1 つは船と一緒に止まって見える波の条件です。船は速さ `v` で進み船から見て波の形が動かないためには、波の山の並びが船の進行方向に `v·cosθ` で進む必要があります。`θ` は波の進む向きと船の進路の間の角です。したがって `c = v·cosθ` が成り立ちます。

船の位置を時刻 `t` で `(v·t, 0)` とします。時刻 0 に出た波の成分のエネルギーは、群速度 `c/2 = ½·v·cosθ` で向き `θ` に進みます。時刻 `t` にはそれが `(½·v·t·cosθ·cosθ, ½·v·t·cosθ·sinθ)` にあります。船はもう `(v·t, 0)` まで進んでいるので、船から見た位置は次のとおりです。

- 進路方向（後ろ向きを正とする）の距離は `v·t·(1 − ½·cos²θ)`
- 進路と直角な方向の距離は `½·v·t·cosθ·sinθ`

この 2 つの比が船の後ろ側から見たその成分の角度 `α` の tan です。

```text
tan α = (½ cosθ sinθ) / (1 − ½ cos²θ)
      = cosθ sinθ / (2 − cos²θ)
      = tanθ / (1 + 2 tan²θ)        ← 分母と分子を cos²θ で割った
```

`θ` を 0° から 90° まで振ると、`α` は 0 から増えてあるところで最大になりまた 0 に戻ります。最大になるのは `tanθ = 1/√2`（`θ ≈ 35.26°`）のときで、そのとき `tan α = 1/(2√2) ≈ 0.354`、つまり `α ≈ 19.47°` です。どの `θ` の成分もこの角度の内側にしか現れません。この最大の角度がくさびの縁になります。

### C++ で確かめる {#kelvin-check}

導出の式を `θ` を 0.01° 刻みで振って数え直します。コードの全行にコメントを付けました。`g++ -std=c++23 -Wall -Wextra` でコンパイルして実行した結果を直後に載せます。

```cpp
#include <cmath>
#include <cstdio>
#include <initializer_list>
#include <numbers>

// 波の進行方向が船の進路と成す角 theta から、その波が作るくさびの半角 alpha を返す。
// 深い水では位相速度 c = v cos(theta)、群速度は c の半分になる（分散関係 omega^2 = g k）。
// 導出は本文。結果は tan(alpha) = tan(theta) / (1 + 2 tan^2(theta))。
double WedgeAngle(double theta) {
  const double t = std::tan(theta);                  // 進行方向の傾き
  return std::atan(t / (1.0 + 2.0 * t * t));         // くさびの半角（ラジアン）
}

int main() {
  const double kPi = std::numbers::pi;               // 円周率
  const double kDeg = 180.0 / kPi;                   // ラジアン -> 度
  const double kGravity = 9.81;                      // 重力加速度（m/s^2）

  // theta を 0.01 度刻みで振って、alpha が最大になる所を探す。
  double best = 0.0;                                 // これまでの最大の alpha
  double best_theta = 0.0;                           // そのときの theta（度）
  for (double deg = 0.01; deg < 89.99; deg += 0.01) {
    const double a = WedgeAngle(deg / kDeg);         // この theta でのくさびの半角
    if (a > best) {                                  // 最大を更新
      best = a;
      best_theta = deg;
    }
  }
  std::printf("max alpha = %.3f deg at theta = %.2f deg\n", best * kDeg, best_theta);
  std::printf("asin(1/3) = %.3f deg, tan = %.5f\n", std::asin(1.0 / 3.0) * kDeg,
              std::tan(std::asin(1.0 / 3.0)));       // 本文の 19.47 度と tan = 1/(2 sqrt 2)

  // 横波の波長。船と同じ速さで進む波なので、c = v から lambda = 2 pi v^2 / g。
  for (double v : {5.0, 10.0, 20.0}) {               // 船の速さ（m/s）
    std::printf("v=%.0f m/s: transverse wavelength = %.1f m\n", v, 2.0 * kPi * v * v / kGravity);
  }

  // 円で押す跡は、1 フレームの移動量が直径 2R を超えると途切れる。
  for (double r : {0.3, 0.5, 2.0}) {                 // 押す円の半径（m）
    for (double fps : {60.0, 30.0}) {                // 描画の頻度（フレーム/秒）
      std::printf("R=%.1f m, %.0f fps: gap-free up to %.0f m/s\n", r, fps, 2.0 * r * fps);
    }
  }

  // 泡の減衰。毎フレーム exp(-dt / tau) を掛けると、泡は時定数 tau の指数で消える。
  for (double tau : {1.0, 3.0, 8.0}) {               // 時定数（秒）
    const double t = tau * std::log(1.0 / 0.05);     // 0.05 まで下がる時間（秒）
    std::printf("tau %.0f s: 0.05 after %.1f s; trail at 10 m/s = %.0f m\n", tau, t, 10.0 * t);
  }
  std::printf("decay per frame (60 fps, tau 3 s) = %.5f\n", std::exp(-1.0 / 60.0 / 3.0));

  // リボンの半幅。進路の後ろ d m の位置で、くさびの縁は d tan(alpha) だけ横に離れる。
  for (double d : {10.0, 50.0, 100.0}) {             // 船尾からの距離（m）
    std::printf("ribbon half width at %.0f m = %.2f m\n", d, d * std::tan(std::asin(1.0 / 3.0)));
  }
}
```

### 波長と船の速さ {#kelvin-wavelength}

横波の波長は `c = v` と `c = √(g/k)`、`λ = 2π/k` から `λ = 2π·v² / g` です。10 m/s（約 36 km/h）で 64.0 m、20 m/s で 256.2 m、5 m/s なら 16.0 m になります。速さが 2 倍になると波長は 4 倍に伸びます。ゲームの船が 10 m/s で走るとき船尾から 64 m の間隔で横波の山が並ぶことになります。画面にそれが何本見えるかは船の大きさとカメラの距離で決まります。

### この角度が当てはまる範囲 {#kelvin-limit}

19.47° は深い水で船が遅い（波が船の長さに比べてずっと小さい）ときの値です。Wikipedia の抜粋は 19.47° を「十分遅い動き」の場合と書き、フルード数 0.5・1・2 のシミュレーション図では、形が変わることを示しています。抜粋には速いときに、どう変わるかの式は書かれていません。ゲームでは船を遅い側の設定で描く限り固定の角度で十分に見えます。速いボートや水上バイクで V 字がより細く見える設計にしたい場合は、角度を速さに応じて狭める調整を自分で入れることになります。この調整の式は資料にありません。

浅い水（岸の近く）や船の下に深さの変化がある場所でも形は変わります。このページでは扱いません。

### リボンの幅に使う {#kelvin-ribbon}

くさびの縁は船尾から距離 `d` の位置で、進路から横に `d·tan(α) = 0.354·d` だけ離れます。船尾から 10 m で 3.54 m、50 m で 17.68 m、100 m で 35.36 m です。この関係は方法 2（リボン）で帯の広がりを決めるときに、使います。

## 作り方 4 つの違い {#methods}

航跡を作る方法は大きく 4 つあります。

- **泡の履歴バッファに書く**。船の位置を泡のバッファに毎フレーム書き込み薄くして残します。どんな船でも使える基本の方法で、[Persistent Foam](foam-history.md) の仕組みをそのまま使います。
- **リボンのメッシュを置く**。船の後ろに V 字の帯を置いて、テクスチャで波と泡を描きます。大きな船の決まった形の航跡に向きます。
- **波のシミュレーションに押し込む**。船が水面の高さマップを押し波が自然に V 字になるのを待ちます。静かな水面の小さな船、泳ぐキャラクターに向きます（[Applying a Height Map to the Surface](../interaction/apply-height.md)）。
- **パーティクル**。船首のしぶきと船尾の泡を補助として併用します。

以降は最初の 2 つをコードで組みます。

## 方法 1：泡の履歴バッファ {#history}

### 毎フレーム何を書くか {#history-flow}

履歴バッファは船のまわりのワールドを一定の間隔で区切った 2 次元のテクスチャです。1 テクセルを 0.25 m、一辺を 512 テクセルとすると、一辺が 128 m の範囲を覆います（一例です）。毎フレームの処理は 3 つです。

1. **薄くする**。前フレームの値に `exp(-dt / τ)` を掛けます。`τ` は時定数で秒の単位です。
2. **書き込む**。船が今フレームに動いた区間のまわりに泡の強さを書きます。
3. **入れ替える**。更新した結果を次のフレームの「前フレーム」にします。

3 の入れ替えが必要なのはピクセル シェーダーが同じテクスチャを読みながら書けないからです。2 枚のテクスチャを用意し読み取り用と書き込み用を毎フレーム入れ替えます（ピンポン）。

### 薄くする速さ {#history-decay}

毎フレーム `exp(-dt / τ)` を掛けるのは、泡の強さが時間 `t` に対して `exp(-t / τ)` で減ることを意味します。フレームの長さ `dt` を式に入れてあるので、30 fps でも 60 fps でも同じ時間で同じだけ薄くなります。60 fps で `τ = 3 s` なら 1 フレームの係数は 0.99446 です。

泡が「見えなくなる」基準を 0.05 とすると、そこまで下がるのに `τ·ln(20) ≈ 3τ` かかります。`τ = 1 s` なら 3.0 秒、`τ = 3 s` なら 9.0 秒、`τ = 8 s` なら 24.0 秒です。船が 10 m/s で走っていると、泡の筋の長さはそれぞれ 30 m、90 m、240 m になります。筋の長さは船の速さと `τ` の積でほぼ決まります。

### 円だけで押すと途切れる {#history-gap}

船の位置に円を 1 つ書く方法は実装が一番簡単です。ところが、船の 1 フレームの移動量が円の直径より大きくなると、円と円の間に押されない所ができて、跡が点々になります。直径が `2R` の円で途切れないのは、移動量が `2R` 以下のときです。移動量は `速さ / fps` なので、途切れない最大の速さは `2R × fps` です。

- 船の半幅 `R = 2.0 m` なら 60 fps で 240 m/s まで、30 fps で 120 m/s までは途切れません。大きな船ならほぼ問題にならない値です。
- 水上バイクや小さなボートで `R = 0.5 m` なら 60 fps で 60 m/s、30 fps で 30 m/s です。
- 泳ぐキャラクターのように `R = 0.3 m` だと 60 fps で 36 m/s、30 fps で 18 m/s で途切れます。ダッシュで水面をなぞる表現などでは 30 fps の環境で起きます。

対策は前フレームの位置から今フレームの位置までの線分を書くことです。点から線分までの最短距離を使うと区間のどこでも同じ太さの帯になります。

### HLSL で組む {#history-hlsl}

シェーダーは次の順に組みます。このコードは `fxc`（Windows SDK 10.0.26100.0、`-T ps_5_0` と `-T vs_5_0`）でコンパイルが通ることを確かめました。実行はしていません。

まず、定数バッファと入力です。

```hlsl
// ---- 航跡の泡: 履歴バッファの更新（スタンプ + 減衰）と、水面での読み出し ----

cbuffer WakeStampCB : register(b0) {
  float2 gSegA;           // 今フレームの区間の始点（ワールドの XZ、m）。前フレームの船の位置
  float2 gSegB;           // 区間の終点（ワールドの XZ、m）。今フレームの船の位置
  float2 gOrigin;         // 履歴バッファの左上の角のワールド XZ（m）
  float  gMetersPerTexel; // 1 テクセルが何 m か（例: 0.25）
  float  gRadius;         // 船体の半幅（m）。この半径の中が泡の濃い所
  float  gStrength;       // 0〜1。船の速さから決めた泡の強さ（止まっていれば 0）
  float  gDecay;          // 1 フレームで掛ける係数 exp(-dt / tau)。1 に近いほど長く残る
  float2 gPad;            // 16 バイトの境界にそろえる詰め物
};

Texture2D<float> gPrevFoam : register(t0);   // 前フレームの履歴（読み取り専用。同じ物には書けない）
```

`gSegA` と `gSegB` が今フレームの区間、`gOrigin` と `gMetersPerTexel` がテクセルの座標をワールドの座標に直すための値です。`gDecay` を C++ 側で `exp(-dt / τ)` として計算して渡すのは、シェーダーで毎ピクセル `exp` を呼ぶのを避けるためです。`gPad` は定数バッファの 16 バイトの境界にそろえる詰め物です。

次に、点から線分までの距離です。

```hlsl
// 点 p から線分 ab までの最短距離（m）。
// 点を円で押すだけだと、1 フレームの移動量が直径を超えたときに跡が途切れる。
float DistanceToSegment(float2 p, float2 a, float2 b) {
  float2 ab = b - a;                              // 区間の向きと長さ
  float len2 = dot(ab, ab);                       // 長さの 2 乗。0 なら船が止まっている
  // 足した: 長さが 0 のときの 0 割りを避けて、始点との距離だけを返す
  float t = (len2 > 1e-8) ? dot(p - a, ab) / len2 : 0.0;
  t = saturate(t);                                // 0 より前・1 より後ろは端点に丸める
  return length(p - (a + ab * t));                // 線分上の最も近い点との距離
}
```

`t` は点 `p` を線分に落とした影の位置を 0〜1 で表した値です。`saturate` で 0〜1 に切ると線分の外側の点は端点との距離になります。船が止まっている（`a` と `b` が同じ）と `len2` が 0 になって、割り算が壊れます。そこで、長さが十分あるときだけ割り算をして、そうでなければ `t = 0`（始点との距離）にします。この分岐は資料にない処理で私が足しました。

履歴を更新するピクセル シェーダーです。

```hlsl
// 履歴を更新するピクセル シェーダー。履歴と同じ大きさのレンダー ターゲットに描く。
float WakeStampPS(float4 sv_position : SV_Position) : SV_Target {
  // SV_Position はピクセルの中心（x.5）の座標。そのまま整数に落とせば自分のテクセルを読める。
  int2 texel = int2(sv_position.xy);
  float2 world = gOrigin + sv_position.xy * gMetersPerTexel;   // このテクセルの中心のワールド XZ

  // 1. 前フレームの泡を、指数で薄くして引き継ぐ。
  float prev = gPrevFoam.Load(int3(texel, 0)) * gDecay;

  // 2. 区間からの距離で、今フレームの泡を作る。中心は gStrength、縁は 0 に向けてなめらかに。
  float d = DistanceToSegment(world, gSegA, gSegB);
  float stamp = gStrength * (1.0 - smoothstep(gRadius * 0.5, gRadius, d));

  // 3. 足し算ではなく max にする。足すと、止まっている船の下で泡が 1 を超えて溜まり続ける。
  return max(prev, stamp);
}
```

`SV_Position` はレンダー ターゲットの中のピクセルの中心（x.5、y.5）の座標です。整数に落とすと自分のテクセルの位置になり `Load` でそのまま前フレームの値が読めます。ワールドの座標はこれに `gMetersPerTexel` を掛けて `gOrigin` に足したもので、す。

泡の強さは区間からの距離 `d` で決まります。`smoothstep(R/2, R, d)` を 1 から引くので、距離が `R/2` までは `gStrength` のまま `R` で 0 になり、その間はなめらかにつながります。

最後の `max(prev, stamp)` を足し算にすると、止まっている船の下で泡が毎フレーム足されて、1 を超えて溜まり続けます。`max` なら強さの上限が `gStrength` で止まります。

水面を描くピクセル シェーダーでの読み出しです。

```hlsl
// ---- 水面のピクセル シェーダー側: 履歴を読んで泡の強さにする ----
Texture2D<float> gFoamHistory : register(t1);   // 更新済みの履歴
SamplerState     gLinearClamp : register(s0);   // 双線形。範囲の外は 0 にしたいので、下で自分で切る

float SampleWakeFoam(float2 world_xz) {
  float2 uv = (world_xz - gOrigin) / (gMetersPerTexel * 512.0);   // 512 は履歴の一辺のテクセル数（一例）
  // 足した: バッファの外は泡なしにする（Clamp の端の値を引き延ばさない）
  if (any(uv < 0.0) || any(uv > 1.0)) return 0.0;
  return gFoamHistory.SampleLevel(gLinearClamp, uv, 0);
}
```

履歴の範囲の外は 0 にします。サンプラーを `Clamp` にしたまま範囲の外を読むとバッファの端の値が引き延ばされて、遠くの水面に泡の筋がにじみます。範囲を外れたかどうかの判定は資料にない処理で、私が足しました。`512.0` は履歴の一辺のテクセル数で、一例です。

### C++ 側の毎フレーム {#history-cpp}

C++ 側は前フレームと今フレームの位置から、シェーダーに渡す値を作ります。このコードは `g++ -std=c++23 -Wall -Wextra` でコンパイルして実行しました。

```cpp
#include <algorithm>
#include <cmath>
#include <cstdio>
#include <vector>

struct Float2 {
  float x = 0.0f;
  float z = 0.0f;  // ワールドの XZ 平面（Y が上）。2 つ目の成分を z と呼ぶ
};

// 船の設定。数値は一例で、ゲームの縮尺に合わせて決める。
struct WakeParams {
  float max_speed = 15.0f;       // この速さ（m/s）で泡の強さが 1 になる
  float strength_scale = 1.0f;   // 全体の濃さ（0〜1）
  float tau = 3.0f;              // 泡が消える時定数（秒）。0.05 まで下がるのに約 3 tau かかる
  float hull_half_width = 2.0f;  // 船体の半幅（m）。泡の濃い所の半径になる
};

// 履歴を更新するシェーダーに渡す値（WakeStampCB と対応する）。
struct WakeFrame {
  Float2 seg_a;      // 区間の始点（前フレームの船の位置）
  Float2 seg_b;      // 区間の終点（今フレームの船の位置）
  float strength;    // 0〜1
  float decay;       // exp(-dt / tau)
  float radius;      // 船体の半幅
};

// 前フレームと今フレームの位置から、シェーダーに渡す値を作る。
WakeFrame MakeWakeFrame(Float2 prev, Float2 cur, float dt, const WakeParams& p) {
  WakeFrame f;
  f.seg_a = prev;                                      // 区間の始点
  f.seg_b = cur;                                       // 区間の終点
  const float dx = cur.x - prev.x;                     // 1 フレームの移動量（m）
  const float dz = cur.z - prev.z;
  // 足した: dt が 0 のフレーム（ポーズ明けなど）で 0 割りにならないようにする
  const float speed = dt > 1e-6f ? std::sqrt(dx * dx + dz * dz) / dt : 0.0f;  // 速さ（m/s）
  f.strength = std::clamp(speed / p.max_speed, 0.0f, 1.0f) * p.strength_scale;  // 速いほど濃い
  f.decay = std::exp(-dt / p.tau);                     // 1 フレームで掛ける減衰
  f.radius = p.hull_half_width;                        // 船体の半幅
  return f;
}
```

`strength` は速さを `max_speed` で割って 0〜1 に切ったもので、す。船が止まっていれば 0 になり泡は書き込まれずに薄くなる一方、です。`dt` が 0 のときは、速さが 0 になるようにしてあります。ポーズから戻ったフレームなどで、0 割りを避けるためです。

```text title="実行結果（抜粋）"
v=10 dt=0.0167: segment=0.167 m strength=0.67 decay=0.99446
v=20 dt=0.0167: segment=0.333 m strength=1.00 decay=0.99446
v=20 dt=0.0333: segment=0.667 m strength=1.00 decay=0.98895
```

10 m/s・60 fps では区間の長さが 0.167 m（0.25 m のテクセルの 0.67 個分）、20 m/s・60 fps では 0.333 m、20 m/s・30 fps では 0.667 m です。後ろの 2 つはテクセルより大きいので、点のスタンプだと途切れます。線分で書く理由が数字でも確かめられます。

## 方法 2：リボンのメッシュ {#ribbon}

### 軌跡を記録する {#ribbon-trail}

リボンは船が通った位置を結んだ帯です。まっすぐな航跡だけなら船尾から後ろに 1 枚の台形を置けば足ります。船が曲がると帯も軌跡に沿って曲がらなければなりません。そこで、船の過去の位置を一定の間隔で記録しておきます。

```cpp
// 航跡のリボン用の軌跡。船が通った位置を一定の間隔で記録する。
class WakeTrail {
 public:
  struct Point {
    Float2 pos;     // 位置（m）
    Float2 dir;     // その点での進行方向（長さ 1）
    float born;     // 記録した時刻（秒）
  };

  WakeTrail(float spacing, float lifetime) : spacing_(spacing), lifetime_(lifetime) {}

  // 毎フレーム呼ぶ。前の点から spacing 以上離れたときだけ、新しい点を足す。
  void Push(Float2 pos, float now) {
    if (!points_.empty()) {
      const Point& last = points_.back();                // 最後に記録した点
      const float dx = pos.x - last.pos.x;
      const float dz = pos.z - last.pos.z;
      const float d = std::sqrt(dx * dx + dz * dz);      // 最後の点からの距離（m）
      if (d < spacing_) return;                          // 近すぎる点は足さない（頂点を増やしすぎない）
      points_.push_back({pos, {dx / d, dz / d}, now});   // 向きは最後の点から今の点への単位ベクトル
    } else {
      points_.push_back({pos, {1.0f, 0.0f}, now});       // 最初の点。向きはまだ分からないので仮に +X
    }
    // 寿命を過ぎた古い点を先頭から捨てる。
    auto old_end = std::find_if(points_.begin(), points_.end(),
                                [&](const Point& p) { return now - p.born <= lifetime_; });
    points_.erase(points_.begin(), old_end);
  }

  // 点 i の古さ 0（今）〜 1（寿命）。頂点シェーダーの age01 になる。
  float Age01(size_t i, float now) const {
    return std::clamp((now - points_[i].born) / lifetime_, 0.0f, 1.0f);
  }

  size_t size() const { return points_.size(); }
  const Point& at(size_t i) const { return points_[i]; }

 private:
  float spacing_;
  float lifetime_;
  std::vector<Point> points_;
};
```

`Push` は最後に記録した点から `spacing` 以上離れたときだけ点を足します。近すぎる点を足すと頂点が増えすぎ向きの計算も近い 2 点の差から求めるので、細かい揺れを拾います。寿命（`lifetime`）を過ぎた点は先頭から捨てます。最初の点には向きの手がかりがないので、仮に +X の向きを入れました。この仮の向きは 2 点目が入ると使われなくなります。

10 m/s で 12 秒走らせ間隔 1 m、寿命 9 秒（`τ = 3 s` の 3 倍）で記録した結果です。

```text title="実行結果（抜粋）"
points=84 oldest age01=1.00 newest age01=0.01
```

残っている点は 84 個です。9 秒 × 10 m/s で 90 m 分ありフレームごとの移動量が 0.167 m なので、記録の間隔は 1 m を少し超える値（平均約 1.07 m）になります。古い端の `age01` は 1.00、新しい端は 0.01 です。この `age01` が頂点シェーダーでの広がりと薄れの基準になります。

### 頂点シェーダーとピクセル シェーダー {#ribbon-shader}

リボンの頂点は軌跡の点ごとに左右の 2 つずつ作ります。左は `side = -1`、右は `side = +1` です。

```hlsl
// ---- 航跡のリボン（V 字の帯）----
cbuffer RibbonCB : register(b1) {
  float4x4 gViewProj;     // ワールド -> クリップ（行ベクトル。v * M）
  float    gShipWidth;    // 船幅の半分（m）
  float    gSpreadRatio;  // 末端の幅 / 船幅。tan(19.47°) の幅の開きに合わせて決める
  float    gTime;         // 秒。泡の模様を流す
  float    gStrength2;    // 泡の強さ
  float3   gShipPos;      // 船の位置（ワールド、m）
  float    gWaterY;       // 水面の高さ（m）
};

struct RibbonVertex {
  float3 trail_pos : POSITION;   // 軌跡の点（ワールド、m）。船が通った位置を並べたもの
  float2 trail_dir : TEXCOORD0;  // その点での進行方向の XZ（長さ 1）
  float  age01     : TEXCOORD1;  // 0（船尾）〜 1（軌跡の端）。軌跡の古さ
  float  side      : TEXCOORD2;  // -1（左の縁）〜 +1（右の縁）
};

struct RibbonV2P {
  float4 position : SV_Position;
  float2 uv       : TEXCOORD0;   // x: 横方向 0〜1、y: 進行方向（繰り返し）
  float  fade     : TEXCOORD1;
};
```

頂点シェーダーでは軌跡の向き `(x, z)` を 90 度回した `(-z, x)` を左右の方向にして、船幅から広げた半幅の分だけ押し出します。

```hlsl
RibbonV2P RibbonVS(RibbonVertex v) {
  RibbonV2P o;
  // 軌跡の向きに垂直な方向（左右）。進行方向 (x, z) を 90 度回して (-z, x)。
  float2 side_dir = float2(-v.trail_dir.y, v.trail_dir.x);
  // 古い点ほど幅を広げる。船幅から船幅 × gSpreadRatio まで。
  float half_width = lerp(gShipWidth, gShipWidth * gSpreadRatio, v.age01);
  float3 world = v.trail_pos;
  world.xz += side_dir * (v.side * half_width);   // 左右に押し出す
  world.y = gWaterY;                              // 水面に置く（波の高さの追従は足していない）
  o.position = mul(float4(world, 1.0), gViewProj);
  o.uv = float2(v.side * 0.5 + 0.5, v.age01 * 8.0 - gTime * 0.5);   // 8 は模様の繰り返し回数（一例）
  o.fade = 1.0 - smoothstep(0.0, 1.0, v.age01);   // 古いほど薄い
  return o;
}
```

古い点ほど幅を広げるのは V 字の縁が `0.354·d` で開くことに合わせるためです。たとえば 90 m 先（9 秒前の位置）まで記録するなら半幅の比 `gSpreadRatio` は、`0.354 × 90 / 船幅の半分` を目安にします。船幅の半分が 2 m なら約 16 倍です。ただし、泡の帯は V 字の縁ではなく、船尾の乱れの帯なので V 字の幅まで広げる必要はありません。見た目で決めます。

水面の高さには `gWaterY` の 1 つの値を使いました。波で上下する水面に帯を貼るには各頂点で波の高さを引く処理が要ります。それはこのコードには足していません。

```hlsl
Texture2D<float> gWakeTex   : register(t2);   // 泡の模様（白いほど泡）
SamplerState     gLinearWrap : register(s1);

float4 RibbonPS(RibbonV2P i) : SV_Target {
  float pattern = gWakeTex.Sample(gLinearWrap, i.uv);   // 模様の濃さ 0〜1
  // 縁（side が ±1 付近）で薄くして、帯の境目をぼかす。
  float edge = 1.0 - abs(i.uv.x * 2.0 - 1.0);
  float a = pattern * i.fade * edge * gStrength2;
  return float4(1.0, 1.0, 1.0, saturate(a));            // 白い泡。αブレンドで水面に重ねる
}
```

ピクセル シェーダーはテクスチャの模様に古さの薄れと縁の薄れを掛けます。`edge` は帯の幅の中央で 1、縁で 0 になる値で帯の輪郭をぼかします。出力は白でアルファに泡の濃さを入れます。

### 2 つの方法の使い分け {#ribbon-vs-history}

履歴バッファは泡が広がって消える変化をバッファの更新で自動的に作れます。形を直接決められないのが弱点で、船の周囲の解像度（0.25 m/テクセルなど）より細かい模様は出せません。リボンは形と模様をアーティストが決められます。そのかわり、軌跡の管理（記録、寿命、向き）と曲がったときの頂点の並びを自分で組む必要があります。大きな船にはリボン、小さな物や数の多い物には履歴バッファ、と使い分けるのが現実的です。

## 船首波としぶき {#bow}

船首の波は水面の高さマップに押し込みを足して作ります（[Applying a Height Map to the Surface](../interaction/apply-height.md)）。しぶきは船首の位置から速さに応じた数のパーティクルを出します。泡は船首から船体の側面に沿って、方法 1 と同じ書き込みで足せます。

船と水の力学を扱う資料として、Jacques Kerner の "Water interaction model for boats in video games"（2015）があります。この記事は船の浮力（水中の三角形に働く静水圧の力）を 1 隻あたり 1 ms 以下で求める方法を書いたもので、航跡や泡の作り方は扱っていません。記事の中で水線（水と船体の交線）が、しぶきや泡を出す位置に使えると触れているだけです。このページの航跡の作り方の根拠はこの記事ではありません。

## 衝突と水しぶき {#impact}

物が水に落ちたりぶつかったりしたときは、波紋・泡・しぶきの 3 つが出ます。この 3 つは時間の長さが違います。

波紋は高さマップのシミュレーションが広げて、数秒で薄れます。泡は履歴バッファに書き込んだ分が、`τ` の時間で消えます。しぶきはパーティクルとして空中を飛び落ちてもう一度小さな波紋と泡を作ります。この 3 つの時間のずれが「水に落ちた感じ」を作るというのが私の設計上の見方です。資料の数字ではありません。

```cpp
// 水に入った瞬間に、3 つを同時に起こす。関数名は例で、実在する API ではない。
void OnEnterWater(const Float2& pos, float speed) {
  AddImpulse(pos, radius, -speed * 0.02f);          // 波紋: 高さマップを下へ押す
  AddFoam(pos, radius * 1.5f, std::clamp(speed / 10.0f, 0.0f, 1.0f));  // 泡: 履歴に 1 点書く
  SpawnSplash(pos, speed);                          // しぶき: 速さに応じた数のパーティクル
}
```

`AddImpulse`、`AddFoam`、`SpawnSplash` はこのページでは定義していません。係数 `0.02` と速さの基準 `10` は見た目を見ながら決める値です。このコードはコンパイルしていません。

スクリューが回ると水中に泡の柱ができます。水面から水中へ向けて泡のパーティクルを出すと水中から見た航跡になります（[Underwater Rendering](../underwater/index.md)）。

## よくあるミス {#mistakes}

??? failure "船が速いと泡の筋が点々になる"
    円だけを書いていると、1 フレームの移動量が直径を超えたとき円の間に隙間ができます。船の速さと fps から移動量が `2R` を超えていないかを確かめます。直すには前フレームの位置から今の位置までの線分を書きます。

??? failure "止まっている船の下に泡が溜まり続ける"
    書き込みを足し算にすると、止まっていても毎フレーム泡が足されます。`max` にするか足し算のあとで `saturate` します。あわせて止まっているときの強さを 0 にします。

??? failure "フレームレートで航跡の長さが変わる"
    毎フレーム「0.99 を掛ける」のようにフレームごとの固定の係数を使っていると、30 fps と 60 fps で消える時間が変わります。`exp(-dt / τ)` のように `dt` を式に入れた係数を使います。

??? failure "履歴バッファの端で泡が引き延ばされる"
    サンプラーの端の処理を `Clamp` にしたままバッファの外を読むと端のテクセルの値が引き延ばされます。範囲の外を自分で判定して 0 を返すかサンプラーの境界色を 0 にします。

??? failure "船が曲がるとリボンがちぎれる"
    軌跡の点の間隔が広すぎる（急に曲がっているのに点が少ない）と向きが急に変わって帯がよじれます。間隔を狭めるか向きを前後の点の差で求めます。
