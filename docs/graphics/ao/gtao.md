# GTAO

**GTAO**（Ground Truth Ambient Occlusion）は、2016 年に Jimenez らが発表した方式です。「**正解（グラウンド トゥルース）に近い AO をリアルタイムで**」を目指し、これまでの SSAO が**省略していた、コサイン重み**を**正しく積分**しました。HBAO と同じ「**地平線を探す**」考え方ですが**積分の内側を解析的に解く式**を導き、**少ない方向数でレイトレース AO に近い**結果を出します。さらに**マルチ バウンスの近似**・**ベント法線**・**スペキュラ遮蔽**も同じ枠組みで扱います。

!!! tip "ポイント"
    - 画素ごとに<strong>1〜数本の「スライス」</strong>（視線を含む平面）を取り、<strong>各スライスで両側の地平線 h1・h2</strong>を探す。
    - <strong>コサイン重み付きの積分を、閉じた式</strong>で解く：<strong>`â(h1, h2, γ)`</strong>。<strong>γ はスライスに投影した法線の角度</strong>。
    - <strong>面の表側（法線を中心とした半円）に、地平線を丸める</strong>（クランプ）。
    - <strong>投影した法線の長さ</strong>が、スライスの重み（外側の積分）。
    - <strong>時間方向</strong>にスライスの向きを回して、<strong>少ない方向数でも</strong>収束させる。
    - <strong>マルチ バウンス</strong>（間接光の回り込み）の近似、<strong>ベント法線</strong>、<strong>スペキュラ遮蔽</strong>が付く。

## HBAO からの改良

| 項目 | HBAO | GTAO |
| --- | --- | --- |
| **積分** | **立体角**の割合（コサインなし） | **コサイン重み付き**（正しい AO） |
| **スライスの扱い** | 方向ごとに法線の傾き t で近似 | **スライス平面に法線を投影**し、**投影の長さを重みに** |
| **内側の積分** | `sin h − sin t` | **閉じた式** `â(h1, h2, γ)`（コサイン重みを含む） |
| **地平線の探し方** | 一方向に歩く（片側） | <strong>両側（±）</strong>に歩く |
| **拡張** | なし | **マルチ バウンス・ベント法線・スペキュラ遮蔽** |
| **薄い物の対策** | なし | **簡単なヒューリスティック**（地平線の弱め） |

## 理論：スライスに分けた積分

[理論](theory/index.md)の AO は次の積分でした。

<div class="formula">AO = (1/π) ∫_{Ω} V(ω) (n·ω) dω</div>

GTAO は<strong>視線ベクトル v を含む平面（スライス）</strong>に半球を分けます。スライスの向きを φ（0〜π）で表します。**各スライスの中で仰角の積分を解析的に**行い、**φ について積分**します。

<div class="formula">AO(x) = (1/π) ∫₀^π ∫_{−π/2}^{π/2} V(φ, θ) · |sin θ| · cos(…)  dθ dφ　→　(1/π) ∫₀^π ‖n_p‖ · â(h₁(φ), h₂(φ), γ(φ)) dφ</div>

| 記号 | 意味 |
| --- | --- |
| **v** | 視線ベクトル（画素から、カメラへ向かう単位ベクトル） |
| **φ** | スライスの向き（画面上の方向の角度） |
| **n_p** | 法線 n を**スライスの平面に投影**したベクトル。**‖n_p‖ はその長さ** |
| **γ** | **視線 v と投影した法線 n_p の間の角度** |
| **h₁, h₂** | スライスの中での**両側の地平線の角度**（**v を基準**に測る。h₁ は負側、h₂ は正側） |
| <strong>â(h₁, h₂, γ)</strong> | **スライス内のコサイン重み付き可視性**（閉じた式） |

**ポイント**：`‖n_p‖ â(…)` は、**1 つのスライスが、AO に寄与する量**です。法線がスライス平面から外を向いている（`‖n_p‖` が小さい）スライスは**寄与が小さく**なります。この重みが**コサイン重みを正しく反映**しています。

### 内側の積分の式

地平線 h₁・h₂ が**法線を中心にした、cos の半円**にクランプされたあとの、スライス内の可視性は、次の式です。

<div class="formula">â(h₁, h₂, γ) = ¼ ( −cos(2h₁ − γ) + cos γ + 2 h₁ sin γ ) + ¼ ( −cos(2h₂ − γ) + cos γ + 2 h₂ sin γ )</div>

| 項 | 意味 |
| --- | --- |
| **h₁・h₂** | 地平線の角度（v からの角度） |
| **γ** | 法線の方向（v からの角度） |
| <strong>cos(2h − γ)</strong> | **コサイン重みを角度で積分した結果**に現れる項 |

この式は、「**h から法線の方向まで、`cos(角度 − γ)` を積分する**」ことを`∫ cos x · …` として解いたものです。**サンプルで数える代わりに、地平線 2 つの角度を入れるだけで、積分が出る**のが、GTAO の核心です。

### 地平線のクランプ

**法線から ±90 度**より外は、**コサイン重みが 0**（面の裏側）です。**地平線が法線の半円の外に出ないよう**に、丸めます。

<div class="formula">h₁ ← γ + max(h₁ − γ, −π/2)、　h₂ ← γ + min(h₂ − γ, +π/2)</div>

## 地平線の探し方

各スライスで**両側（＋方向と −方向）に、深度バッファを歩き**ます。**角度はそのまま測らず、「コサイン」で扱う**と計算が安く済みます。

| 手順 | 内容 |
| --- | --- |
| **① スライスの方向** | 画面上の方向 `dir`（φ から決める）。ビュー空間では `(dir, 0)` |
| **② 歩く** | `+dir` と `−dir` の両側に、**数ステップ**（8〜12）。**ステップ幅は半径を画面に直したもの ÷ ステップ数**。**遠いほど幅を広げる**（べき乗） |
| **③ サンプルの位置** | `S`（ビュー空間）。**視線ベクトル v との角度**の、cos を求める：`cos = dot(normalize(S − P), v)` |
| **④ 地平線の cos を更新** | **最大**（= 角度が最小、遮蔽が最も高い）で更新。**距離の減衰**で遠い遮蔽を、**cos = −1**（遮蔽なし）の方へ補間 |
| **⑤ 角度に戻す** | `h₁ = −acos(cos₁)`、`h₂ = acos(cos₂)` |

**距離の減衰**は**地平線の cos を遠いほど −1（遮蔽なし）に近づける**形で入れます。

```hlsl
float falloff = saturate((radius_dist - dist) * falloff_mul + falloff_add);
horizon_cos = max(horizon_cos, lerp(low_horizon_cos, shc, falloff));
```

## 1 つのスライスの計算

```hlsl
float SliceVisibility(float3 p, float3 v, float3 n, float2 dir, float2 h_cos) {
  float3 dir3 = float3(dir.x, -dir.y, 0.0);
  float3 axis = normalize(cross(dir3, v));
  float3 ortho_dir = dir3 - dot(dir3, v) * v;

  float3 proj_n = n - axis * dot(n, axis);
  float proj_n_len = length(proj_n);
  float cos_n = saturate(dot(proj_n, v) / max(proj_n_len, 1e-5));
  float n_angle = -sign(dot(proj_n, ortho_dir)) * acos(cos_n);

  float h1 = -acos(clamp(h_cos.x, -1.0, 1.0));
  float h2 = acos(clamp(h_cos.y, -1.0, 1.0));

  h1 = n_angle + max(h1 - n_angle, -1.5707963);
  h2 = n_angle + min(h2 - n_angle, 1.5707963);

  float sin_n = sin(n_angle);
  float v1 = (cos_n + 2.0 * h1 * sin_n - cos(2.0 * h1 - n_angle));
  float v2 = (cos_n + 2.0 * h2 * sin_n - cos(2.0 * h2 - n_angle));
  return proj_n_len * (v1 + v2) * 0.25;
}
```

| 点 | 説明 |
| --- | --- |
| **`axis`** | スライス平面の**法線**（`dir` と `v` の外積） |
| **`proj_n`** | 法線を**スライス平面に投影**（`axis` 成分を引く） |
| **`n_angle`** | **`v` と `proj_n` の間の角度**（符号つき） |
| **クランプ** | 地平線を法線の ±90 度に丸める |
| **戻り値** | `‖proj_n‖ · â(h₁, h₂, n_angle)`。**スライスごとの可視性** |

**最終的な AO は、スライスの可視性の平均**です。

<div class="formula">visibility = (1 / スライス数) · Σ SliceVisibility</div>

!!! note "実装の参考"
    Intel の **XeGTAO**（GameTechDev/XeGTAO）は、GTAO の実装を、**HLSL の完全なコード**として公開しています。**パラメータの意味・ノイズ・時間蓄積・ベント法線**まで含んでおり、**自分で実装する際の最もよい参考資料**です。

## スライスの数とノイズ

**画素あたりのスライス数**は、**1〜2 本**（リアルタイムでは、これが限界）です。**少ない本数**でどう収束させるのでしょうか。

| 工夫 | 内容 |
| --- | --- |
| **画素ごとにスライスの向きを変える** | 空間的に**ノイズ**に変える（4×4 や、IGN など。[フィルタ](filtering/index.md)） |
| **フレームごとに向きを回す** | **時間的に**別の向きを見る |
| **空間・時間の両方で積分する** | **バイラテラル ブラー ＋ 時間蓄積**で、ノイズを平均する（実質、毎画素 数十本のスライス相当） |
| **ステップ位置のジッター** | ステップの位置にもノイズ |

**時間蓄積**が、GTAO を実用的な速さにしています（**1 フレームは、非常に粗い結果**。数フレーム重ねて、きれいに）。

## 薄い物体への対策

スクリーン空間では、**手前の物体の「厚み」が分かりません**。深度バッファが示すのは、**面の手前側だけ**です。**薄い柱の後ろ**にある面は、**柱が無限に厚い**とみなされて、**必要以上に暗く**なります。

| 対策 | 内容 |
| --- | --- |
| **地平線を遠ざかるほど弱める** | 距離の減衰を強めに掛ける |
| **簡易な厚みのヒューリスティック** | 「**手前の面から、奥へ一定の厚み**しかない」と仮定して、**地平線の更新を弱める**。**薄い物の後ろが暗くなりすぎない** |
| <strong>（高コスト）二層の深度</strong> | 手前とその裏の面の、2 枚の深度を持つ |

GTAO の論文は、**簡単な厚みの近似**を提案しています（実装は XeGTAO などを参照）。

## マルチ バウンス：回り込みの近似

AO は、「**遮蔽された方向は、真っ暗**」と考えます。しかし、現実には**遮蔽物の表面で光が反射して、そこそこ明るい**です（間接光の、2 回目以降の反射＝**マルチ バウンス**）。**明るい色の部屋の隅**が真っ黒になるのは、不自然です。

GTAO は**アルベドに応じて、AO の値を明るく戻す**、**簡単な近似式**を提案しています。

<div class="formula">A_mb = max( A , ((A · a + b) · A + c) · A )　、　a = 2.0404·ρ − 0.3324、　b = −4.7951·ρ + 0.6417、　c = 2.7552·ρ + 0.6903</div>

| 記号 | 意味 |
| --- | --- |
| **A** | もとの AO（0〜1） |
| **ρ** | **表面のアルベド**（0〜1、通常はグレースケール化したもの） |
| **A_mb** | マルチ バウンスを考慮した AO |

```hlsl
float3 MultiBounce(float ao, float3 albedo) {
  float3 a = 2.0404 * albedo - 0.3324;
  float3 b = -4.7951 * albedo + 0.6417;
  float3 c = 2.7552 * albedo + 0.6903;
  return max(ao, ((ao * a + b) * ao + c) * ao);
}
```

**明るい色**（ρ が大きい）ほど、**AO が持ち上がり**、**暗い色**ではほぼそのままです。**色ごと（RGB）に**計算すると**赤い壁の隅が赤く照らされる**効果も出ます。

## ベント法線とスペキュラ遮蔽

### ベント法線

**可視な範囲の平均の方向**を**ベント法線**（bent normal）と呼びます。普通の法線は**面が向いている方向**ですが、ベント法線は**空が見えている方向**を向きます。

| 用途 | 内容 |
| --- | --- |
| <strong>拡散の環境光（IBL）</strong> | 法線の代わりに**ベント法線で環境マップを引く**と**遮られた方向の光を拾わない** |
| **スペキュラ遮蔽** | **可視円錐の向き**として使う |

GTAO では、**スライスごとの可視な範囲の中心**から、ベント法線を作れます。

### スペキュラ遮蔽

AO は**拡散**（ざらっとした反射）に掛けるものです。**鏡面反射**にも**遮蔽**があります（隅の反射が見えないはずの所に、環境マップの反射が見える、という破綻）。これを**スペキュラ遮蔽**で弱めます。

| 方法 | 内容 |
| --- | --- |
| **円錐の交差** | **可視円錐**（AO の大きさ、ベント法線の向き）と、**反射の円錐**（粗さ、反射方向）が、**どれだけ重なるか** |
| **簡易近似** | AO・粗さ・`n·v` から、**直接求める式**（下） |

```hlsl
float SpecularOcclusion(float n_dot_v, float ao, float roughness) {
  return saturate(pow(n_dot_v + ao, exp2(-16.0 * roughness - 1.0)) - 1.0 + ao);
}
```

**粗さが低い（鏡面に近い）ほど**、AO の影響を**弱く**し、**粗いほど**、AO に近づけます。**Lagarde による、広く使われている近似**です。

## GTAO の位置づけ

| 項目 | 内容 |
| --- | --- |
| **精度** | **レイトレース AO に近い**（コサイン重みが正確、積分が解析的） |
| **コスト** | スライス 1〜2 本 × 両側 ステップ 8〜12。**時間蓄積前提** |
| **必要な入力** | 深度・（法線）。深度から復元も可能 |
| **付加機能** | マルチ バウンス・ベント法線・スペキュラ遮蔽 |
| **実装** | XeGTAO（公開）。主要なエンジンが、GTAO 系を採用または提供している |

## 弱点

| 弱点 | 説明 |
| --- | --- |
| **スクリーン空間の限界** | 画面外・隠れた物・薄い物（ヒューリスティックで軽減） |
| **ノイズ ＋ 時間蓄積に依存** | 動きの速い場面で<strong>ゴースト（残像）</strong>や、**ちらつき** |
| **実装が複雑** | 角度・クランプ・符号の管理が細かい |
| **ステップのコスト** | 画素 × スライス × 両側ステップ |

## よくあるミス

??? failure "地平線のクランプを忘れて、面の裏側の遮蔽が効く"
    `h₁, h₂` を法線の ±90 度に丸めます。

??? failure "法線をスライスに投影せず、重みを掛けない"
    `‖n_p‖`（投影した法線の長さ）が、スライスの重みです。

??? failure "1 フレームの結果をそのまま使って、ノイズだらけ"
    **ブラーと時間蓄積**が前提です（[フィルタ](filtering/index.md)）。

??? failure "マルチ バウンスを、グレーのアルベドで色付きの壁に掛けて、色味が失われる"
    <strong>色ごと（RGB）</strong>に計算すると色の回り込みが出ます。

??? failure "スペキュラ遮蔽を入れず、隅に環境マップの反射が、まぶしく映る"
    スペキュラ遮蔽を足します。
