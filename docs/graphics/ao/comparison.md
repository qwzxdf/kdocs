# AO の方式比較

これまでの各方式を**原理・必要な入力・コスト・弱点**で並べて比べます。**どの方式を選ぶか**は、**対象プラットフォーム・必要な品質・使える入力・開発の手間**で決まります。このページでは、**比較表**と**選び方の目安**、**実装の骨組み**をまとめます。

!!! tip "ポイント"
    - 方式の違いは、<strong>積分の近似法</strong>（サンプル・地平線・式）と、<strong>コサイン重みの扱い</strong>、<strong>メモリ アクセスの工夫</strong>。
    - <strong>精度の高さ</strong>：<strong>RTAO ＞ GTAO ＞ HBAO ＞ SSAO 系</strong>。
    - <strong>実装の簡単さ</strong>：<strong>半球 SSAO ＞ Alchemy・SAO ＞ HBAO ＞ GTAO</strong>。
    - <strong>新規に実装するなら</strong>：<strong>GTAO</strong>（品質・速さ・機能のバランス）または<strong>HBAO+ ライブラリ</strong>。
    - <strong>どれもブラーと時間蓄積が必要</strong>。

| **入力** | 深度 | 深度＋法線 | 深度＋法線 | **深度のみ**（法線を復元） | 深度＋法線 | 深度（＋法線） | 深度＋法線 |

## 原理による分類

| 分類 | 方式 | 考え方 |
| --- | --- | --- |
| **サンプルを数える**（モンテカルロ） | Crytek SSAO・半球 SSAO | 近くのランダムな点が面の奥にあるか。**0/1 の割合** |
| **式を足す** | Alchemy・SAO | 近くの面の点ごとに**連続的な式**を足す |
| **地平線を積分** | HBAO・HBAO+・GTAO | 方向ごとに**遮蔽が始まる角度**を探し、**角度で積分** |
| **世界を調べる** | RTAO・DFAO・VXAO | **シーン全体のデータ**で、V を求める |

## 見た目の違い

| 状況 | 起きること |
| --- | --- |
| **平らな面** | Crytek SSAO は灰色。他は問題なし |
| <strong>接地（物の下）</strong> | どれも暗くなる。**半径と強さの調整**で見た目が変わる |
| **凹んだ角** | GTAO・HBAO は**滑らか**。サンプル方式は、ノイズが出やすい |
| <strong>凸の角（外側）</strong> | 法線を使う方式は、**暗くならない**（正しい）。Crytek SSAO は、暗い輪が出やすい |
| **細い柱の周り** | どれも**ハロー**が出る（スクリーン空間の限界） |
| **斜め方向の遮蔽** | **コサイン重み**の扱いで強さが変わる（HBAO は強めに出る） |
| **明るい色の部屋** | **マルチ バウンス**（GTAO）がないと隅が**黒く**沈む |

## コストの目安

**画素数 × サンプル数**に比例します。**フル HD**での目安の読み込み回数です（概算。実装・GPU で変わる）。

| 方式 | 1 画素あたりの深度の読み込み | 備考 |
| --- | --- | --- |
| <strong>半球 SSAO（16 サンプル）</strong> | 16 ＋ 法線 | ノイズ テクスチャ ＋ ブラー |
| <strong>Alchemy / SAO（9〜13 サンプル）</strong> | 9〜13 | SAO はミップで読み込みが軽い |
| <strong>HBAO（8 方向 × 6 ステップ）</strong> | 48 | 方向を減らせば軽い |
| <strong>HBAO+</strong> | HBAO 相当（キャッシュ効率が良い） | ライブラリ |
| <strong>GTAO（1〜2 スライス × 両側 8〜12 ステップ）</strong> | 16〜48 | 時間蓄積で実質的な精度を上げる |
| <strong>RTAO（1〜2 レイ）</strong> | レイトレ | BVH の更新・デノイズ |

**実際の速さはキャッシュ効率・ブラー・解像度**で大きく変わります。**実機で測る**ことが大切です（[調査ツール](../../rendering/tools.md)）。

## 選び方

| 状況 | おすすめ |
| --- | --- |
| **とにかく簡単に、AO を入れたい** | **半球 SSAO**（[実装が簡単](ssao-hemisphere.md)）。まずここから |
| **品質・速さ・機能のバランス** | **GTAO**（コサイン重み・バウンス・スペキュラ遮蔽）。公開実装（XeGTAO）がある |
| <strong>ライブラリで済ませたい（特に PC）</strong> | <strong>HBAO+</strong> |
| **広い範囲・大きな半径を安く** | **SAO**（ミップで半径に依存しない） |
| **モバイル** | 半球 SSAO の軽量版（サンプル 4〜8）か、AO を焼いておく |
| **最高品質・レイトレ対応環境** | **RTAO** ＋ デノイザー（または GTAO と併用） |
| **静的な広い屋外** | **DFAO**、または**ベイクした AO** |
| **画面外の遮蔽が必須** | **世界空間の方式**（[RTAO・DFAO・VXAO](world-space/index.md)） |

## AO を使わない選択肢

AO が**不要**な、または**別の手段で済む**場面もあります。

| 手段 | 内容 |
| --- | --- |
| **AO テクスチャのベイク** | **静的なメッシュ**に、AO を焼いて、テクスチャに入れる（**ランタイム コストゼロ**）。動かない背景に最適 |
| **ライトマップ・プローブ** | **間接光そのもの**を事前計算（AO も含む）。[GI](../index.md) |
| **接地用のブロブ影** | キャラクターの足元に**丸い影**の簡易な AO |
| **頂点カラーに焼く** | 頂点に AO を焼いて、シェーダーで使う |

**静的なものは焼き、動くものとの接触は、スクリーン空間 AO**、という**併用**が現実的です。

## 実装の骨組み

どの方式でも**パスの構成はほぼ同じ**です。

| パス | 内容 |
| --- | --- |
| **① 深度（と法線）の準備** | **G-Buffer** または、**深度プリパス**。必要なら、**線形深度とミップ** |
| **② AO の計算** | 方式ごと。**フル解像度か、半分** |
| **③ 空間フィルタ** | バイラテラル ブラー（[フィルタ](filtering/index.md)） |
| **④ 時間蓄積** | 動きベクトル・深度で再投影（任意） |
| **⑤ （半分なら）アップサンプル** | ジョイント バイラテラル |
| **⑥ ライティングに適用** | **間接光（環境光）に乗算**。スペキュラ遮蔽も |

## 実装チェックリスト

| 確認項目 | 内容 |
| --- | --- |
| **深度の線形化** | 射影行列（標準 Z か reverse-Z か）に合った式 |
| **座標系** | ビュー空間の向き（左手系・+Z が前）と、y の符号（画面は下向き） |
| **ポイント サンプリング** | 深度・法線は補間せずに読む |
| **空と無限遠** | 深度が far のピクセル（空）は、**AO = 1**（遮蔽なし） |
| **適用先** | **間接光だけ**。直接光には掛けない |
| **リニア空間** | AO は**線形の光の量**として掛ける |
| **半径の単位** | ビュー空間（メートル）で指定 |

## よくあるミス

??? failure "どの方式を選ぶか迷い続けて、実装が進まない"
    まず**半球 SSAO**で動かして、**不満が出たら GTAO**に進みます。パスの構成は同じです。

??? failure "AO のコストを、方式だけで比較する"
    **キャッシュ・ブラー・解像度**で実測値は大きく変わります。**自分の環境で測ります**。

??? failure "ベイクした AO と、スクリーン空間 AO を、両方フルで掛けて、二重に暗くなる"
    **役割を分け**（ベイクは細部、SSAO は接触）、強さを調整します。
