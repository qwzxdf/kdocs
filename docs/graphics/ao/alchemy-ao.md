# Alchemy AO

**Alchemy AO**（Alchemy Screen-Space Ambient Obscurance）は、2011 年に McGuire らが発表した方式です。それまでの SSAO が、**経験的な式**（「面の奥にあれば 1、手前なら 0」を数える）だったのに対し、**AO の積分から導いた式**を、**遮蔽物の表面の点ごとに足すだけ**の形にしました。**比較（if）がなく、連続的な式**なので**ノイズが少なく、サンプル数を減らせます**。後の SAO（[Scalable AO](sao.md)）や、多くのエンジンの SSAO の基になった式です。

!!! tip "ポイント"
    - 入力は<strong>ビュー空間の位置と法線</strong>。<strong>各サンプルについて、p から遮蔽物の点 q へのベクトル v を使う</strong>。
    - 式は<strong>`max(0, v·n + z·β) / (v·v + ε)` を足し合わせる</strong>だけ。<strong>0/1 の判定がなく、連続</strong>。
    - 項の意味は<strong>「法線に近い向き（v·n）ほど大きく、距離（v·v）が大きいほど小さい」</strong>。
    - <strong>バイアス β</strong>が平らな面の自己遮蔽を打ち消す。<strong>ε</strong>は 0 除算を防ぐ。
    - サンプルは<strong>画面上の螺旋</strong>に置き、<strong>画素ごとに回転</strong>する。
    - 最後に<strong>強度 σ と、コントラスト k（べき乗）</strong>で、見た目を調整。

## 半球 SSAO との違い

[半球 SSAO](ssao-hemisphere.md) と Alchemy AO は、見た目は似ていますが、考え方がかなり違います。

半球 SSAO は、p の周りの半球の中に <strong>3D のサンプル点 s</strong> を置き、「その点が面の奥にあるか」を 0 または 1 で数えます。Alchemy AO は、サンプル点を<strong>画面上</strong>に螺旋状に置き、その画素に映っている面の位置 q を読んで、ベクトル v = q − p を式に入れます。判定が 0/1 でなく連続値になるため、少ないサンプルでも結果が滑らかで、ノイズが少なくなります。

範囲チェックの扱いも違います。半球 SSAO では `smoothstep` による範囲チェックを別に書く必要がありました。Alchemy AO では、式の分母に距離の 2 乗（v·v）が入っているので、遠い遮蔽物の寄与は<strong>式の中で自然に弱まります</strong>。自己遮蔽の対策も、半球 SSAO では経験的な bias ですが、Alchemy AO では「法線方向の成分から、深度に比例した値 β を引く」形で式に含まれています。そして、最大の違いは導出です。半球 SSAO は経験的なヒューリスティックでしたが、Alchemy AO は AO の積分から<strong>導いた</strong>式なので、パラメータの意味がはっきりしています。

## 式

画素の位置 C（ビュー空間）、法線 n、サンプル i で読んだ、**遮蔽物の面の位置** C_i とします。**ベクトル v_i = C_i − C** です。

<div class="formula">A(C) = max( 0, 1 − (2σ / s) · Σᵢ  max(0, vᵢ·n + z_C · β) / (vᵢ·vᵢ + ε) )ᵏ</div>

| 記号 | 意味 |
| --- | --- |
| **s** | サンプル数（9〜13 程度） |
| **v_i · n** | **ベクトル v_i の法線方向の成分**（正なら、サンプルは面の**上側**にある ＝ 遮蔽物になりうる） |
| **v_i · v_i** | **距離の 2 乗**。遠い遮蔽物の寄与を距離の 2 乗に反比例して弱める |
| **z_C · β** | **バイアス**。`z_C` は、C の深度（カメラからの距離）。**遠いほど大きく**、深度の精度の悪化に対応 |
| **ε** | 0 除算を防ぐ小さな値（0.0001 など） |
| **σ** | 強度（intensity）。大きいほど暗い |
| **k** | コントラスト（べき乗）。大きいほど、暗い所が濃くなる |

### 各項の意味

遮蔽物の点 q が点 p を遮る強さを、`max(0, v·n + zβ) / (v·v + ε)` と近似しています。これを分解して眺めます。

分子の `v·n` は、`|v| cosθ` と同じです。q の方向が法線に近い（cosθ が大きい）ほど、q は p の「真上」に近い位置にあり、強く遮ります。これが[理論](theory/index.md)に出てきたコサイン重みに相当します。分母の `v·v` は距離の 2 乗なので、遠い遮蔽物ほど急激に弱まります。分子と分母を合わせると、おおよそ `cosθ / |v|` になり、<strong>近く、かつ法線方向にある遮蔽物ほど強く寄与する</strong>という、直感に合った重みが得られます。`max(0, …)` は、面の下側（`v·n < 0`）にある点は遮蔽物でないとして 0 にします。

つまり、<strong>「遮蔽物の表面の点 1 つ 1 つが、p をどれだけ暗くするか」を、近い・正面ほど大きくなる式で足し合わせている</strong>わけです。

!!! note "導出について"
    論文では、AO の積分を**方向についての積分から、面の点についての和**に書き換え、いくつかの近似（遮蔽物の面が p を向いていると仮定する、距離の逆数で近似するなど）を重ねて、この式を導いています。**途中の近似を受け入れれば、実装は簡単な式 1 つ**です。**式の詳しい導出は、論文**（参考を参照）を見てください。

### バイアス β の役割

**平らな面**では面上の別の点 q の `v` は、**面と平行**です。**`v·n` は 0 に近い**はずですが、**深度の誤差**でわずかに**正**になり、**自己遮蔽**（平らな面が暗くなる）を起こします。

`v·n + z·β` の **β を**、`v·n` の誤差より大きくすると、**平らな面では全体が 0 以下**になり、`max(0, …)` で切り捨てられます。`z` を掛けるのは、**遠いほど深度の誤差が大きい**ためです。

## サンプルの配置：画面上の螺旋

**画面上**で画素の周りに**螺旋状**にサンプルを置きます。

<div class="formula">αᵢ = (i + 0.5) / s、　θᵢ = 2π · αᵢ · τ + φ、　位置 = u + (R′ · αᵢ) · (cos θᵢ, sin θᵢ)</div>

| 記号 | 意味 |
| --- | --- |
| **R′** | <strong>画面上の半径（ピクセル）</strong>。ビュー空間の半径 R を、**距離で割って**画面の大きさにする：`R′ = R · (画面の大きさの係数) / z` |
| **αᵢ** | 0〜1 の一様な値。**中心から外へ**サンプルを並べる |
| **τ** | 螺旋の**巻き数**（論文の例ではサンプル 9 個に対し 7 回転）。**サンプルが方向もばらつくように**する |
| **φ** | **画素ごとのランダムな回転角**（ハッシュ等で作る）。**ノイズ**として、後で消す |

**画面上で一定の大きさ**ではなく、**ビュー空間の半径 R が一定**になるように、**近い所は画面上で大きく、遠い所は小さく**サンプルを広げます。

```hlsl
float AlchemyAO(float2 uv, float3 c, float3 n) {
  float screen_radius = radius * projection_scale / c.z;
  float angle0 = Hash(uv) * 6.2831853;

  float sum = 0.0;
  for (int i = 0; i < kSamples; ++i) {
    float alpha = (i + 0.5) / kSamples;
    float angle = alpha * kTurns * 6.2831853 + angle0;
    float2 offset = float2(cos(angle), sin(angle)) * (screen_radius * alpha);

    float2 suv = uv + offset * texel_size;
    float3 q = ViewPositionFromDepth(suv);
    float3 v = q - c;

    sum += max(0.0, dot(v, n) + c.z * beta) / (dot(v, v) + epsilon);
  }

  float a = max(0.0, 1.0 - 2.0 * sigma * sum / kSamples);
  return pow(a, contrast);
}
```

| 点 | 説明 |
| --- | --- |
| **`Hash(uv)`** | 画素ごとのランダム値。**ハッシュの出来**でノイズの質が変わる（[AO Filtering](filtering/index.md)） |
| **`ViewPositionFromDepth`** | 深度から位置を復元（[Crytek SSAO](ssao-crytek.md)）。**ポイント サンプリング** |
| **`pow(a, contrast)`** | `k` 乗でコントラストを調整 |
| **`2σ/s`** | 式の係数をまとめたもの。`σ` で全体の強さを決める |

## 後処理

Alchemy AO は、<strong>サンプルが少ない（9 個前後）</strong>ので**ノイズが残ります**。**分離可能なバイラテラル ブラー**（横 → 縦）で、深度を考慮して滑らかにします（[フィルタ](filtering/index.md)）。

## 長所と短所

Alchemy AO の長所は、判定に if がなく連続なので、少ないサンプルでもきれいに仕上がることです。自己遮蔽の対策（β）と、遠い遮蔽物の弱めが式に入っているため、別に範囲チェックを書く必要がありません。導出が公開されているのでパラメータの意味が明確で、実装も短く済みます。

短所は、半径が大きいときに、サンプルが画面の遠くに散ってキャッシュが効かず、遅くなることです。ハローは完全には消えません。法線が必要で（深度からの復元もできます）、コサイン重みや可視性の扱いは近似です。

## 次の方式

半径が大きいときの遅さは、深度のミップで遠いサンプルを粗く読む [SAO](sao.md) で解決されます。地平線を直接扱いたいなら、[HBAO](hbao.md) と [GTAO](gtao.md) に進みます。

## よくあるミス

??? failure "`β` を小さくしすぎて、平らな面が縞状に暗くなる"
    β を大きくします（0.001〜0.01 程度から調整）。

??? failure "`v·n` を、正規化した v で計算して、距離の効きが失われる"
    式は**正規化していない v** で計算します（`v·v` の項が距離の弱めになる）。

??? failure "螺旋の半径を、画面上で固定して、遠い物の AO が大きすぎる"
    **ビュー空間の半径 R** を、距離で割って、画面の半径に変換します。

??? failure "`ε` を入れず、サンプルが p と同じ位置で NaN"
    `v·v + ε` にします。

    - [x] 式は<strong>`max(0, v·n + zβ) / (v·v + ε)` の和</strong>。<strong>if がなく、連続</strong>
    - [x] <strong>近く、法線方向にある遮蔽物ほど強く効く</strong>（cosθ / 距離）
    - [x] サンプルは<strong>画面上の螺旋</strong>。半径は<strong>ビュー空間で一定</strong>になるよう距離で割る
    - [x] 弱点は<strong>半径が大きいときの遅さ</strong>（→ SAO）
