# Screen Edges and Thin Objects

<strong>スクリーン空間の AO には構造的な弱点</strong>が2 つあります。画面の端では画面外の情報がないため AO が欠け薄い物体（柵・葉）は、厚みが分からず後ろの面を誤って遮蔽することです。このページでは画面端の対策（保守的な扱い・拡張）・薄い物体の対策（厚みの仮定）を説明します。

!!! tip "ポイント"
    - 画面端 ＝ 画面外の深度が無く、AO が欠ける。
    - 対策：範囲外のサンプルは、遮蔽なしとして扱う画面を少し広く描く（オーバースキャン）。
    - 薄い物体 ＝ 厚みが分からず後ろを遮る。
    - 対策：厚みを仮定する（深度の厚み）・世界空間 AO と併用。

## 画面端
### 症状

<strong>画面の端に近いほど</strong>、AO が消える、暗くなりすぎる縞が出るといった不整合が出ます。

### 原因：画面の外は誰も知らない

スクリーン空間の AO は 画面に映っている深度だけで計算します。画面の端に近い画素 p ではサンプル点の一部が画面の外に出ます。外側の深度はバッファのどこにも存在しません。

このときの動作はサンプラーの設定（アドレス モード）で決まります。

* クランプ：端の画素の値が繰り返されます。端の画素が壁なら外側にも同じ壁が続いているように見えます。偶然の一致でまあまあ見える場合も多いのですが、端に床と壁の継ぎ目があると継ぎ目の AO が不自然に伸びます。
* ラップ：反対側の端の値が読まれます。画面の右端で左端の物体に遮蔽されるという意味のない結果になります。
* ボーダー：決めた固定値（たとえば最も遠い深度）が読まれます。遮蔽なしとして扱うか遮蔽ありとして扱うかを自分で選べます。

どれを選んでも「本当は何があるか」は分からないままです。選択の違いは 分からない部分を明るくするか暗くするかの違いにすぎません。

### 対策 1：外側は「遮蔽なし」として扱う

最も安全なのはボーダーを遠い深度にして、画面の外のサンプルは遮蔽しないことにする方法です。AO が足りなくなる（少し明るくなる）方向にずれるだけなので、目立つ不具合にはなりません。サンプルを無視して残ったサンプル数で割り直す方法もありますが、サンプルが少ない画素ではノイズが増えます。

### 対策 2：端でフェードする

画面の端に近いほど AO の強さを弱めれば、「端だけ急に変わる」違和感を消せます。端から数十画素の幅で強さを 1 から 0 へ滑らかに落とします。端は視線の周辺で目立ちにくいので、通常はこれで十分です。

### より良いやり方：ガード バンド

根本の解決は 画面より少し広い範囲を描くことです。G-Buffer と深度をたとえば上下左右に 5〜10 % 広く作れば（ガード バンド、オーバースキャン）、画面の端の画素のサンプルも広げた領域の中で深度を得られます。メモリと G-Buffer の描画コストが増えるため、ほとんどの用途ではフェードで済ませ画質を最優先する場合にだけ採用します。

## 薄い物体
### 症状

<strong>細い柱・フェンス・葉</strong>の後ろにある面が必要以上に暗くなります。

### 原因：深度は「厚み」を知らない

深度バッファは各画素でカメラに最も近い面の距離だけを持ちます。その物体が 1 cm の薄い板なのか 10 m 奥まで詰まった壁なのかは、バッファからは区別できません。

柵の後ろの床の点 p を考えます。p の周りのサンプルが柵の画素に重なると、深度バッファは「ここは p より手前」と答えます。AO はそれを「厚みが無限にある壁が、p の前に立っている」と受け取って、遮蔽として数えます。実際には、柵は細い棒の集まりで棒の間から光はたくさん入ってきます。

結果として、柵・格子・葉の後ろが実際より暗くなります。[Halo](halo.md) と原因は似ていますが、こちらは「遠い」ことでなく「薄い」ことが問題です。

### 対策 1：厚みを仮定する

GTAO（[GTAO](../gtao.md)）が採った考え方は、「物体の厚みはあるところで終わる」と仮定することです。地平線を探すときに手前の面を見つけたら、その背後を無限に遮るのではなく、サンプルが離れるにつれて遮蔽の効きを弱めます。柵は「手前の薄い物」として扱われ背後の床をほとんど暗くしません。

欠点は本当に厚い物（巨大な壁の端など）の背後でも遮蔽が少し甘くなることです。薄い物に甘くするか厚い物に甘くするかの取引で、ゲームでは薄い物に誤判定されるほうが目立つため、厚みを仮定するのが普通です。

### 対策 2：半径を小さくする

半径を小さくすればサンプルが柵の画素に重なる範囲が狭くなり誤判定が減ります。AO は元々「近くの遮蔽」を見る近似なので、小さい半径はほぼ副作用がありません。

### より良いやり方：世界空間の手法を併用する

画面に映らない裏側の情報を使うには世界空間の手法を使います。レイトレース AOはシーンの実際のジオメトリにレイを当てるので、柵の棒の隙間を通るレイは遮蔽されず正しく明るくなります（[RTAO](../world-space/rtao.md)）。距離場 AO も物体の形を距離で持つので、薄い物でも扱えます（[DFAO](../world-space/dfao.md)）。ただし、距離場は薄い物を苦手とするため、それぞれ得手不得手があります（[比較](../world-space/comparison.md)）。

最後の手段として 背面を別に描いて厚みを測る方法もあります。表の面の深度と裏の面の深度の差が、その画素の厚みです。精度は高いですが描画が 2 倍になるので、一般的ではありません。

## 対策のコード

### 画面の外を遮蔽なしにして、端でフェードする

```hlsl
// サンプル位置が、画面の外なら、深度が分からない。遮蔽なし（0）として、数えない。
float2 sample_uv = center_uv + offset_uv;
if (any(sample_uv < 0.0) || any(sample_uv > 1.0)) continue;        // ループの次のサンプルへ

// 画面の端に近い画素ほど、AO を弱める（外側の情報が、足りなくなるため）。
float2 edge = saturate((0.5 - abs(center_uv - 0.5)) * 12.0);        // 端から約 8% の幅で、0 → 1
float edge_fade = min(edge.x, edge.y);
ao = lerp(1.0, ao, edge_fade);                                       // 端では、AO なし（1.0）へ
```

画面の外は誰も知らないので「遮蔽されていない」として扱いさらに端の画素では、AO 自体を弱めて急に暗さが変わる境目を隠します。ガード バンド（画面より少し広く描く）を使えば端でも外側の深度を読めます。

### 厚みを仮定して薄い物をまたげるようにする

```hlsl
// サンプルが、中心より手前でも、その差が、厚みより大きければ、薄い物の「向こう側」とみなして、遮蔽に数えない。
float dz = z_center - z_sample;                                      // 正なら、サンプルのほうが、手前
float occluded = (dz > kBias && dz < kThickness) ? 1.0 : 0.0;
```

`kThickness`（たとえば半径の 2 倍）より手前の物は、「その後ろにもまだ空間がある」とみなし、遮蔽に数えません。薄い板（フェンス、葉）が後ろの面を全部、暗くするのを防ぎます。ただし、本当に厚い物が遮るときも弱くなるので値は、見ながら決めます。

## よくあるミス

??? failure "画面端だけ AO が薄い・暗い"
    <strong>範囲外のサンプルの扱いを統一</strong>（遮蔽なし）。
