# HBAO+

<strong>HBAO+</strong>（Horizon-Based Ambient Occlusion Plus）は、NVIDIA が、HBAO を**高速化・高品質化**して、**ライブラリとして提供**している実装です（GameWorks / ShadowWorks のライブラリ）。HBAO の「地平線を探す」考え方を土台にしつつ、<strong>「GPU のキャッシュに優しく計算する」</strong>ことに力を入れました。NVIDIA の説明では、元の HBAO より、**約 3 倍速く、細部の精度は約 2 倍**とされています。このページでは、**HBAO+ が何を変えたのか**を、公式資料の説明をもとに、整理します。

!!! tip "ポイント"
    - HBAO の<strong>地平線の発想</strong>はそのまま。<strong>変えたのはメモリ アクセスと計算の組み立て</strong>。
    - <strong>ランダムなノイズ テクスチャを使わない</strong>（キャッシュを荒らすため）。代わりに<strong>画素ごとに決まった向きのジッター</strong>を使う。
    - <strong>インターリーブ（デインターリーブ）</strong>：<strong>画面を 4×4 = 16 の層に分け</strong>、<strong>各層で同じ向きの組を計算</strong>。<strong>隣り合う画素が同じ向きで歩く</strong>ので<strong>キャッシュが効く</strong>。
    - <strong>常にフル解像度</strong>で深度から直接計算（ちらつき防止）。
    - AO の式を<strong>簡略化</strong>（SAO と似た、過剰な遮蔽を避ける近似）。
    - <strong>ライブラリ（GFSDK_SSAO）</strong>として、深度（と法線）を渡せば使える。

!!! warning "ここの説明は、公式資料の概要に基づく"
    HBAO+ の内部実装（シェーダーの詳細）は、**公開されている範囲が限られています**。このページは、NVIDIA の公開ドキュメントの説明を、**考え方として整理**したものです。**正確な API・パラメータ**は公式ドキュメントとヘッダを確認してください。

## 何が遅かったのか

元の HBAO の**重さの原因**は、**メモリ アクセス**でした。

| 原因 | 説明 |
| --- | --- |
| **ランダムなノイズ** | **画素ごとに方向を回す**ために**ノイズ テクスチャ**を使う。隣り合う画素が**バラバラの方向**に歩くので、**深度を読む位置が散らばり**、**テクスチャ キャッシュが効かない** |
| **ステップ数が多い** | N 方向 × M ステップ。深度の読み込みが数十回 |

GPU は**隣り合う画素（実際には 2×2 などの塊）が、近いメモリを読む**ときに、速くなります。ランダムに方向を回すと、**この条件が崩れます**。

## 改良 1：ランダムをやめて、インターリーブ

**ランダムなノイズ テクスチャを使わず**、<strong>画面を 4×4 の画素ごとに、あらかじめ決めた 16 通りの「向きの組」</strong>に割り当てます。

| 手順 | 内容 |
| --- | --- |
| **① デインターリーブ** | **深度バッファを、4×4 ごとに分解**して、**16 枚の縮小深度**（各 1/4 × 1/4）を作る |
| **② 各層で AO を計算** | **1 枚の中の全画素が同じ向きの組**で歩く（その層に決まった向き） |
| **③ インターリーブ** | 16 枚の結果を**元の画面の位置に戻す** |
| **④ ブラー** | 最後に**深度を考慮したぼかし**（バイラテラル）で、層の境目の模様を消す |

**1 枚の層の中では、全画素が同じ向きで歩く**ので、**隣り合う画素がほぼ同じ形で深度を読み**、**キャッシュの効きが大幅に上がります**。**ランダム ノイズと同等のばらつき**（16 通りの向き）を、**メモリに優しい形で**得ているわけです。

## 改良 2：常にフル解像度

HBAO+ は、**フル解像度の深度**から、AO を計算します（縮小した深度から計算して、アップサンプルする方式は、取りません）。

| 理由 | 説明 |
| --- | --- |
| **ちらつきの防止** | 低解像度から作ると**動きで縁がちらつく** |
| **細部の保持** | 細いくぼみ・小さな物体の AO を、**取りこぼさない** |

フル解像度でも**インターリーブ**でキャッシュが効くので、速さを保てます。

## 改良 3：AO の式を簡略化

HBAO の「sin h − sin t を積分する」式を、**SAO と似た、過剰な遮蔽を避ける近似**に置き換えています。**遮蔽が強く出すぎない**ので、**見た目が自然**になります。

## パラメータ

HBAO+ のライブラリには、次のような調整項目があります（名前・範囲はバージョンで異なるので、ヘッダを確認）。

| パラメータ | 意味 |
| --- | --- |
| **Radius** | 影響半径（ビュー空間の単位） |
| **Bias** | 自己遮蔽を防ぐ（面の傾きに対する余裕） |
| **PowerExponent** | コントラスト（`pow`） |
| **SmallScaleAO / LargeScaleAO** | 小さな遮蔽と大きな遮蔽の強さの比 |
| **DepthThreshold** | **薄い物体**による、過剰な暗さを抑える（手前の物の裏を遮蔽にしない） |
| **ForegroundAO / BackgroundAO** | **手前と奥で、AO の強さを変える**（遠景を薄く） |
| **Blur** | バイラテラル ブラーの有無と、鋭さ（Sharpness） |
| <strong>Resolution（Coarse AO）</strong> | 半分の解像度で低品質・高速に |

## 使い方の概要（ライブラリ）

HBAO+ は、<strong>ライブラリ（GFSDK_SSAO）</strong>です。<strong>深度（と、あれば法線）</strong>を渡し、**AO を書く先のレンダー ターゲット**を指定します。

| 手順 | 内容 |
| --- | --- |
| **① 初期化** | デバイスを渡して、コンテキストを作る（DX11・DX12・OpenGL・Vulkan 版がある） |
| **② 入力データの設定** | **深度バッファ**（SRV）、**射影行列**（ライブラリが位置の復元に使う）、**メートル単位の変換値**（シーンの単位から、メートルへ） |
| **③ パラメータの設定** | 半径・バイアス・ブラーなど |
| **④ 出力先の指定** | AO を**乗算**するか、**別のレンダー ターゲット**に書くか |
| **⑤ 描画** | 毎フレーム、ライブラリの関数を呼ぶ |

!!! note "ライセンスと対応"
    HBAO+ は **NVIDIA のライブラリ**です。**ライセンス条件・対応 API・バージョン**は、**NVIDIA の公式ページと同梱の資料**で確認してください。**GPU ベンダーに依存せず動く**実装ですが、最適化は NVIDIA 向けに行われています。

## HBAO・SAO との関係

| 項目 | HBAO | SAO | HBAO+ |
| --- | --- | --- | --- |
| **土台** | 地平線 | Alchemy の式 | **HBAO の地平線 ＋ SAO 風の簡略化** |
| **ランダム化** | ノイズ テクスチャ | ハッシュ | <strong>決まった 16 通りの向き（デインターリーブ）</strong> |
| **キャッシュへの配慮** | なし | **深度ミップ** | **デインターリーブ** |
| **解像度** | 縮小もよくある | フルまたは縮小 | **フル解像度** |
| **提供形態** | 論文・サンプル | 論文・サンプル | **ライブラリ** |

## 長所と短所

| 長所 | 短所 |
| --- | --- |
| **速い**（キャッシュ効率） | **ライブラリとして使うので、内部の改造が難しい** |
| **フル解像度でちらつきが少ない** | スクリーン空間の限界（画面外・薄い物・隠れた物）は、同じ |
| **ライブラリで導入が簡単** | **コサイン重みやバウンスは扱わない**（[GTAO](gtao.md)） |
| **細部の精度が高い** | 実装の詳細が非公開の部分もある |

## 自分で実装するなら

HBAO+ の発想を自前の実装に取り入れるなら、次の 3 点です。

| 発想 | 実装のしかた |
| --- | --- |
| **ノイズ テクスチャを使わない** | 画素の座標（`x % 4`, `y % 4`）から、**16 通りの向きの組**を決める（テーブル） |
| **デインターリーブ** | 深度を 4×4 の 16 層（テクスチャ配列）に分けるパスを足す。**各層は同じ向きの組で計算** |
| **フル解像度 ＋ バイラテラル ブラー** | 最後に**深度を考慮したぼかし**で、層の境目を消す |

## よくあるミス

??? failure "ライブラリに、射影行列やメートル換算を、正しく渡さない"
    位置の復元がずれ、**AO の強さ・半径が意図と違い**ます。**シーンの単位**（1 ＝ 1 メートルか）を、ライブラリに伝えます。

??? failure "AO を、直接光にも乗算してしまう"
    HBAO+ の**出力を環境光のパスだけ**に使います（[理論](theory.md)）。

??? failure "透明物の深度が書かれず、半透明の後ろに AO が付く"
    HBAO+ には、**不透明物の深度**だけを渡します。透明物は**別の扱い**（[半透明](../index.md)）。
