# ESM

VSM は分散を使うので遮蔽物が重なる所に光漏れが出ます。もっと単純な形でフィルタできるシャドウ マップはないでしょうか。深度を指数関数に通して保存すると、「受け手と遮蔽物の深度の差」が、掛け算で表せてぼかしやミップもそのまま使えます。

<strong>ESM（指数シャドウ マップ）は深度 `z` の代わりに `exp(c · z)` を保存します</strong>。1 チャンネルで済んで実装も簡単です。ただし、`c` の選び方で影の柔らかさが決まり浮動小数点のあふれに注意が要ります。ぼかしで影の端がずれる性質もあります。このページでは式、`c` と柔らかさの関係（数字つき）、あふれの上限、フィルタで起きるずれ（実測つき）、ログ空間でのぼかし実装、欠点を説明します。

!!! tip "ポイント"
    - ESM は `exp(c · z)` を保存して、比較は `exp(c · z) × exp(−c · t)` です。`t` は受け手の深度です。
    - `c` が大きいと影が硬く、小さいと柔らかくなります。`c = 40` なら 100 m の範囲で、影が薄れる幅は約 5.8 m です。
    - `exp(c)` が浮動小数点の上限を超えないようにします。32 ビットなら `c < 88.7`、16 ビットなら `c < 11.1` です。
    - ぼかすと影の領域がぼかしの半径ぶん縮みます。1 次元の実測で半径 8 テクセルなら影の端が 8 テクセル内側へ動きました。
    - 浮動小数点の 32 ビットが無難です。ぼかしはログ空間で行うとあふれません。

## 考え方: 深度を指数に変える {#idea}

ESM（Exponential Shadow Maps、Annen ら 2008）は深度 `z` の代わりに `exp(c × z)` を保存します。`c` は大きな正の定数（20〜80 など）です。

通常の影の判定は `t ≤ z_保存` なら光が当たる（1）、そうでなければ影（0）、という階段関数です。これを指数関数で近似します。

```text
通常:   lit = (t ≤ z) ? 1 : 0
ESM:    lit = saturate( exp(c × z) × exp(−c × t) ) = saturate( exp(c × (z − t)) )
```

`z` はシャドウ マップが持つ遮蔽物の深度です。`t` は受け手（影を判定する画素）の深度です。

- 画素が遮蔽物より手前なら `z − t > 0` で、`exp(c(z − t))` は 1 以上です。`saturate` で 1 になって光が当たります。
- 画素が遮蔽物と同じ位置なら `z − t = 0` で、1 です。境界で光が当たります。
- 画素が遮蔽物の奥（影の中）なら `z − t < 0` で、0 に近づきます。`c` が大きいほど急に 0 になります。

`c` が大きいと階段関数に近づいて、影の縁が鋭くなります。小さいとなめらかですが影が薄れます。

## `c` と影の柔らかさ {#c}

遮蔽物から深度で `Δ` だけ奥の画素の明るさは、`exp(−c × Δ)` です。明るさが 0.1（十分に暗い）になるまでの深度の幅は、`ln(10) / c` です。

- `c = 10` で深度の幅が 0.230 です。100 m の範囲なら約 23 m です。
- `c = 20` で 0.115 です。約 11.5 m です。
- `c = 40` で 0.058 です。約 5.8 m です。
- `c = 80` で 0.029 です。約 2.9 m です。

遮蔽物のすぐ後ろ（数メートル以内）は、`c = 80` でも影が薄れたままです。足元の影が薄く物が浮いて見えるのは、このためです（[Peter Panning](../bias/peter-panning.md) に似た見え方です）。`c` を上げれば濃くなりますが、あふれの危険があります。深度の範囲を狭めると（near と far を詰める）、同じ `c` でもワールドでの薄れる幅が小さくなります。

## あふれの上限 {#overflow}

`exp(c × z)` は `z = 1` で `exp(c)` になります。32 ビット浮動小数点の上限は約 3.4 × 10³⁸ で、`c` の上限は `ln(3.4 × 10³⁸) ≒ 88.7` です。`c = 80` なら `exp(80) ≒ 5.5 × 10³⁴` で収まります。16 ビット浮動小数点の上限は 65504 で、`c` の上限は `ln(65504) ≒ 11.09` です。`c` を 11 以下にしなければならないので、影が薄れる幅が約 21 m（100 m の範囲）と広くなります。浮動小数点の 32 ビットが無難です。

さらに、ぼかしでは足し算で値が大きくなるので、余裕を見ます。`c` を 20〜80 の範囲で、深度を 0〜1 に正規化して使います。

## ぼかしで起きること {#filter}

シャドウ マップをガウスぼかしでやわらかくしたくなります。`exp(c · z)` を平均すると「周りの遮蔽物の深度の指数による平均」になります。ところが、この平均は大きい値（遠い深度）に引っ張られます。

具体的に測りました。1 次元で x < 0 に遮蔽物（深度 0.3）、x ≥ 0 は何もない（深度 1.0、背景）とします。受け手の深度を 0.5（x < 0 は遮蔽物の奥なので、影）として半径 8 テクセルのぼかしで、ESM の明るさを求めて PCF（真の割合）と比べました。

結果は `c = 10`、`20`、`40`、`80` のどれでも同じでした。ESM の明るさが 0.5 を超える位置は x = −8 で、PCF は x = 0 でした。遮蔽物の内側 8 テクセル（ぼかしの半径）から、明るくなっています。原因は平均に混ざる背景の texel（深度 1.0）の指数が、遮蔽物の texel（深度 0.3）の指数に比べて、桁違いに大きいことです。背景が 1 つでも混ざると平均が背景に支配されて、明るさが 1 に飽和します。

つまり、ESM のぼかしは影の縁をやわらかくせず影の領域をぼかしの半径ぶん縮めます。半径 8 テクセルで範囲 100 m、解像度 2048 なら 1 テクセルが約 4.9 cm で、縮みは約 39 cm です。柔らかさは前の節の `c` で決まる受け手と遮蔽物の深度の差による薄れだけです。ぼかしの半径を大きくするほど影の端が内側へ寄ります。

## 実装 {#implementation}

まず、シャドウ パスで指数を書き出します。

```hlsl
static const float kExponent = 40.0;          // c。20〜80。深度は 0..1 に正規化する

// シャドウ パス: exp(c × z) を書き出す（R32_FLOAT のレンダー ターゲット）
float EsmWritePS(float4 pos : SV_Position) : SV_Target {
  return exp(kExponent * pos.z);              // pos.z は 0..1 の深度
}
```

次に、ぼかしです。`exp` の値をそのまま足すと大きくなるので、ログ空間で行います。`log(Σ w_i · exp(c · z_i))` を中心の `z_0` を基準に `c · z_0 + log(Σ w_i · exp(c · (z_i − z_0)))` と書き換えます。指数の中が `z_i − z_0`（小さな数）になって、あふれません。シャドウ マップには `c · z` を保存しておいて、ぼかす前後で `exp` をかけます。

```hlsl
Texture2D<float> g_log_shadow : register(t0);         // c × z を保存したマップ
SamplerState g_point_clamp : register(s0);

cbuffer BlurConstants : register(b0) {
  float2 g_blur_direction;    // (1/幅, 0) か (0, 1/高さ)。分離ガウスの 1 パス
  float2 _pad0;
};

static const int kRadius = 4;                          // 9 タップ
static const float kWeights[5] = {0.2270, 0.1946, 0.1216, 0.0541, 0.0162};   // ガウス（σ ≒ 2）の片側

// ログ空間のぼかし。log(Σ w · exp(v_i)) を、中心の v0 を基準に安定して計算する
float LogBlurPS(float4 pos : SV_Position, float2 uv : TEXCOORD0) : SV_Target {
  float v0 = g_log_shadow.SampleLevel(g_point_clamp, uv, 0);
  float sum = kWeights[0];                              // 中心は exp(v0 − v0) = 1
  [unroll] for (int i = 1; i <= kRadius; ++i) {
    float vp = g_log_shadow.SampleLevel(g_point_clamp, uv + g_blur_direction * i, 0);
    float vn = g_log_shadow.SampleLevel(g_point_clamp, uv - g_blur_direction * i, 0);
    sum += kWeights[i] * (exp(vp - v0) + exp(vn - v0));  // exp の中が小さい数なので、あふれない
  }
  return v0 + log(sum);                                  // c × z の形に戻す
}
```

`vp - v0` が大きな正の数（背景が遮蔽物より `c × Δz` だけ大きい）になると、`exp` があふれます。実際は、`vp - v0` を `min(…, 80)` などで制限します。ログ空間でぼかしても前の節の「影が縮む」性質は変わりません。あふれを防ぐだけの工夫です。

最後に、メイン パスで受け手の深度と比べます。

```hlsl
Texture2D<float> g_esm_map : register(t1);            // ぼかした c × z（ログ空間）
SamplerState g_linear_clamp : register(s1);

cbuffer LookupConstants : register(b1) {
  float4x4 g_world_to_light;
  float g_c;                   // kExponent と同じ値
  float3 _pad1;
};

float4 EsmLookupPS(float3 world_pos : TEXCOORD0) : SV_Target {
  float4 clip = mul(float4(world_pos, 1.0), g_world_to_light);
  float3 ndc = clip.xyz / clip.w;
  float2 uv = float2(ndc.x * 0.5 + 0.5, 0.5 - ndc.y * 0.5);

  float stored = g_esm_map.SampleLevel(g_linear_clamp, uv, 0);        // c × z（ぼかし後）
  // lit = exp(c × (z − t))。ログ空間のまま引き算してから exp にする（あふれない）
  float lit = saturate(exp(stored - g_c * ndc.z));
  return float4(lit, lit, lit, 1.0);
}
```

ログ空間で保存しておくと `exp(c z) × exp(−c t)` が、`exp(c z − c t)` になって 1 回の `exp` で、あふれずに計算できます。ミップやバイリニアもそのまま使えます。

!!! note "確かめた範囲"
    HLSL は `fxc` で `EsmWritePS`、`LogBlurPS`、`EsmLookupPS`（`ps_5_0`）をコンパイルしてエラーが出ないことを確かめました。`c` と柔らかさあふれの上限、ぼかしによる影の縮みは Python の 1 次元の計算（64 ビット浮動小数点）の結果です。GPU での描画は確認していません。

## 長所と短所 {#pros-cons}

長所は 1 チャンネルでメモリが小さいことです。VSM のように分散を使わないので、重なりによる光漏れは起きません。実装が簡単でぼかしもミップも使えます。

短所は遮蔽物のすぐ後ろで影が薄いことです。`c` の調整が必要で（大きすぎるとあふれ小さすぎると影が薄い）、深度の範囲にも依存します。ぼかすと影の領域が縮みます。

遮蔽物のすぐ近く（同じ面の少し奥）では、`z − t` が小さいので `exp(c(z − t))` は 1 に近くて、影が薄くなります。遮蔽物から十分に離れた所で初めて濃い影になります。対策は `c` を大きくするか EVSM（2 つの指数で影を補強）にすることです（[EVSM](evsm.md)）。

## よくあるミス {#mistakes}

??? failure "`c` を大きくしすぎて、オーバーフローして真っ白になる"
    原因は `exp(c)` が浮動小数点の上限を超えることです。32 ビットで `c < 88.7`、16 ビットで `c < 11.1` です。`c` を 20〜80 にして 32 ビット浮動小数点で保存して、深度を 0〜1 に正規化します。

??? failure "ぼかしを強くしたら、影が小さくなった"
    原因は指数の平均が遠い深度に支配されることです。実測でぼかしの半径ぶん影の領域が縮みました。ぼかしの半径を小さくするか `c` の効きで柔らかさを作ります。EVSM や MSM など別の方式も検討します。

??? failure "足元の影が薄くて、物が浮いて見える"
    原因は遮蔽物のすぐ後ろで `exp(−c Δ)` が、1 に近いことです。`c` を上げるか深度の範囲を詰めます。接地が重要ならコンタクト シャドウで補います。
