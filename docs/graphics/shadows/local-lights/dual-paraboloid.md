# Dual Paraboloid

<strong>キューブ マップは 6 回描画</strong>しますが、デュアル パラボロイドは、放物面（お椀型）に投影する 2 枚のマップで、全方向を覆い描画を 2 回に減らす手法です。かつてモバイルなどで使われましたが、歪みが大きく現代ではあまり使われません。このページでは仕組み・利点と欠点を説明します。

!!! tip "ポイント"
    - デュアル パラボロイド ＝ 放物面に投影する 2 枚のマップで、全方向を覆う。
    - 描画が 6 回 → 2 回に減る。
    - 欠点：ジオメトリが歪み（頂点シェーダーで投影）、テッセレーションが細かくないと破綻。
    - 現代ではキューブ マップ ＋ カリングが主流。

## デュアル パラボロイド
<strong>パラボロイド</strong>（放物面）で、半球ごとを1 枚に写す方式です。2 枚で全方向を覆えます。

| 項目 | キューブ | デュアル パラボロイド |
| --- | --- | --- |
| 枚数 | 6 | 2 |
| 描画回数 | 6 | 2 |
| 歪み | なし（直線のまま） | 強い（頂点の写像が非線形） |
| 注意 | 面の境界 | 三角形が大きいと歪みで破綻（テッセレーションが必要）。境界の継ぎ目 |

描画回数が少ない利点がありますが、歪みが扱いにくいため現在はキューブが主流です。

## 考え方：6 面を 2 面に

キューブマップは <strong>6 面</strong>を、描くので重いです。放物面マッピング（Brabec ら、2002）は全方向を 2 枚のテクスチャで、覆います。前半球と後半球を放物面（パラボロイド）で、それぞれ 1 枚に投影します。描画は 2 回で済みます。

```text
 光を中心に:
   前半球 → 放物面 1（1 枚のテクスチャ）
   後半球 → 放物面 2（1 枚のテクスチャ）
```

放物面への投影は 頂点シェーダーで、行います。方向ベクトルから 2D 座標に、変換します。

```hlsl
// 前半球の、放物面投影。dir は、光から頂点への、単位方向（光の座標系）。
float2 ParaboloidProject(float3 dir) {
  // dir.z が、前向き（+Z）の半球。
  return dir.xy / (1.0 + dir.z);        // 放物面の、写像（−1〜1 の範囲に収まる）
}
```

## 頂点シェーダー

```hlsl
cbuffer ParaboloidCB : register(b0) {
  float4x4 g_world_to_light;     // ワールド → 光の座標系（位置だけ引いて、向きを合わせる）
  float g_light_range;
  float g_direction_sign;        // +1 = 前半球、−1 = 後半球
  float2 pad;
};

struct VSOut {
  float4 position : SV_Position;
  float clip_z : TEXCOORD0;      // 半球の外（反対側）を、クリップするため
};

VSOut main(float3 position : POSITION) {
  float3 p = mul(float4(position, 1.0), g_world_to_light).xyz;       // 光の座標系での、頂点位置
  float dist = length(p);
  float3 dir = p / dist;
  dir.z *= g_direction_sign;                                          // 後半球は、反転して、前半球と同じ式で

  VSOut o;
  float2 xy = dir.xy / (1.0 + dir.z);                                 // 放物面投影
  o.position = float4(xy, dist / g_light_range, 1.0);                 // z には、光からの距離（0〜1）
  o.clip_z = dir.z + 0.0;                                             // 半球の外は、クリップ（負の値）
  return o;
}
```

| 要素 | 内容 |
| --- | --- |
| `dir.xy / (1 + dir.z)` | 放物面の写像。`dir.z = 1`（真正面）で `xy = dir.xy / 2`、`dir.z = 0`（真横）で `xy = dir.xy`（円周） |
| 深度 | 光からの距離（`dist / range`）を直接、書く（放物面は透視投影の深度が、定義できないため） |
| 半球のクリップ | `dir.z < 0` の頂点は、反対側の半球なのでクリップ |

## 長所と短所

| | 内容 |
| --- | --- |
| 長所 | 描画が 2 回（キューブマップは 6 回）。シャドウ パスが安い |
| 長所 | メモリが小さい（2 枚）。キューブマップの 1/3 |
| 短所 | 非線形な投影を、頂点シェーダーで行う。三角形が直線でなく曲線に変形されるのに、頂点だけ変換するので大きな三角形で歪む。メッシュを細かく（テッセレーション）、する必要 |
| 短所 | 解像度が不均一（中心で高く縁で、低い） |
| 短所 | 半球の境界（真横）で、継ぎ目ができる |
| 短所 | ハードウェアの、比較サンプラー（PCF）が使えない（距離を、保存するため） |
| 短所 | 現代ではあまり、使われない（キューブマップの描画が、ジオメトリ シェーダーや 1 回のインスタンス描画で、効率化できるため） |

### 歪みの問題

<strong>放物面の投影</strong>は 直線を曲線に、変換します。ところが、ラスタライザーは投影後の頂点を結ぶ、直線の三角形として描きます。大きな三角形（地面）では頂点間の曲線が直線で、近似され影が歪みます。

| 対策 | 内容 |
| --- | --- |
| メッシュを細分化 | 大きな三角形を細かく、分割する（テッセレーションで、シャドウ パスだけ） |
| 影を落とす物を細かいメッシュに限る | 地面などは影を、落とさない（受けるだけ）にする |

## キューブマップとの比較

| | キューブマップ | 放物面（デュアル） |
| --- | --- | --- |
| 描画回数 | 6（面ごとに、視錐台カリングで減らせる） | 2 |
| 歪み | なし（通常の透視投影） | あり（細分化が、必要） |
| PCF（ハードウェア） | 使える | 使えない（距離保存） |
| 精度 | 面の全体で比較的、均一 | 中心が高く縁が低い |
| 実装 | 簡単 | やや複雑（頂点シェーダー、クリップ） |
| 現状 | 標準 | 古い手法。メモリが厳しい古い環境で使われた |

<strong>現在のゲーム</strong>では キューブマップが標準で、放物面はほとんど使われません。歴史的な手法として知っておく程度で、十分です。

## よくあるミス

??? failure "大きな三角形が、投影で歪んで影が崩れる"
    <strong>細かいテッセレーション</strong>が必要。通常はキューブ マップを使う。
