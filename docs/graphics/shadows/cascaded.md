# Cascaded Shadow Maps (CSM)

<strong>広い屋外</strong>で太陽の影を、1 枚のシャドウ マップで覆うと、画面の近くの影が粗く（ギザギザ）なります。カメラの近くは、細かく、遠くは粗くて十分なのにマップが全体を均等に覆っているからです（遠近エイリアシング）。カスケード シャドウ マップ（CSM、Cascaded Shadow Maps）は、カメラの視錐台を奥行き方向に複数に分割し、分割ごとに別のシャドウ マップを用意します。近い範囲ほど、小さな領域を細かく、遠い範囲は広い領域を粗く覆うので、画面でほぼ一定の細かさの影になります。屋外の太陽の影の標準的な方式です。

!!! tip "ポイント"
    - 視錐台を<strong>奥行きで N 個（3〜4）に分割</strong>。<strong>各分割（カスケード）に、シャドウ マップ</strong>を 1 枚。
    - 分割の位置は、対数と一様の中間（PSSM）で決める。
    - 各カスケードの光の正射影は、その分割をちょうど覆うように決める。球で包むと回転に強く安定。
    - テクセルのスナップで、カメラが動いても影の縁がちらつかない。
    - 描画時、画素の深度から、カスケードを選ぶ。境目はブレンドする。
    - 影を落とす物は、視錐台の外（光に近い側）にもある。範囲を光の方向に広げる。

## 分割の決め方

<strong>視錐台の近クリップ面 `n` から遠クリップ面 `f`</strong> までを、N 個に分けます。一様に分けると近くの細かさが足りず、対数で分けると近くが極端に狭くなります。中間（PSSM、Parallel-Split Shadow Maps）が、実用的です。

<div class="formula">C_i = λ · n · (f / n)^(i/N) + (1 − λ) · ( n + (i/N) · (f − n) )　（i = 1 … N）</div>

記号の意味です。C_i は i 番目の分割の奥側の境界（カメラからの距離）です。λ は 0 で一様、1 で対数の分割になる混合比で、0.5〜0.9 程度を使います。n と f は近・遠クリップ面ですが、影を描く最大距離を f の代わりに短めに設定することが多いです。

一様な分割は遠くを細かく取りすぎて近くが足りなくなり、対数分割は近くに偏りすぎて遠くが足りなくなります。両者を混ぜる λ の方式（Zhang らの PSSM、2006）が実用的な落としどころです。

```cpp
std::array<float, kCascadeCount + 1> SplitDistances(float n, float f, float lambda) {
  std::array<float, kCascadeCount + 1> splits;
  splits[0] = n;
  for (int i = 1; i <= kCascadeCount; ++i) {
    float t = static_cast<float>(i) / kCascadeCount;
    float log_split = n * std::pow(f / n, t);
    float uniform_split = n + (f - n) * t;
    splits[i] = lambda * log_split + (1.0f - lambda) * uniform_split;
  }
  return splits;
}
```

影の最大距離（`f`）は、遠クリップ面より短くします（遠すぎる影は見えないので描画しない）。100〜300 m程度が、多くのゲームの設定です。

## 各カスケードの光の射影

<strong>各分割の視錐台</strong>（8 つの角）を、光の視点から、ちょうど覆う正射影を作ります。

正射影の作り方は 2 通りあります。AABB でフィットする方法は、分割の 8 つの角を光空間に変換して、最小の AABB で包みます。小さく効率的ですが、カメラが回転すると AABB の大きさが変わり、影がちらつきます。球でフィットする方法は、8 つの角を包む最小の球を求め、球の直径を正射影の大きさにします。回転しても大きさが変わらず、安定します。やや無駄があり、解像度が少し下がるのが代償です。

安定性を優先して、球でのフィットが実用的です。

```cpp
Vector3 center = Vector3::Zero;
for (const auto& corner : frustum_corners) center += corner;
center /= 8.0f;

float radius = 0.0f;
for (const auto& corner : frustum_corners) radius = std::max(radius, (corner - center).Length());
radius = std::ceil(radius * 16.0f) / 16.0f;
```

コードの要点です。`radius` の切り上げは、わずかなカメラの動きで半径が変わらないよう、粗い刻みで丸める処理で、ちらつきを防ぎます。中心は、分割の視錐台の中心（8 角の平均）で、光空間の位置合わせは次の節で行います。

## テクセルのスナップ

カメラが動くと<strong>シャドウ マップの範囲</strong>も動きます。範囲の位置がテクセルの境界とずれていくと影の縁がちらちらと揺れます（テクセルをまたぐたびに、サンプルの位置が変わる）。範囲の位置をテクセル単位に揃える（スナップ）と、縁が動かず、ちらつきが止まります。

```cpp
float texel_size = (radius * 2.0f) / shadow_resolution;

Vector3 center_ls = Vector3::Transform(center, light_view);
center_ls.x = std::floor(center_ls.x / texel_size) * texel_size;
center_ls.y = std::floor(center_ls.y / texel_size) * texel_size;
Vector3 snapped_center = Vector3::Transform(center_ls, light_view.Invert());
```

テクセル スナップの手順です。中心を光のビュー空間へ変換します。x と y を `texel_size` の倍数に丸めます。丸めた中心から、元の空間へ戻して射影行列を作ります。こうすると、カメラが動いても、シャドウ マップのテクセルが常にワールドの同じ格子に乗るので、影の縁が泳ぎません。

回転に強い（球でのフィット）と、スナップを併用します。

## 深度範囲：視錐台の外の遮蔽物

<strong>影を落とす物体</strong>は、視錐台の外（光に近い側）にもあります。視錐台の中だけを覆う正射影では、その物体がシャドウ マップに入らず、影が欠けます。

影を落とす物体が視錐台の外にある問題には、3 つの対処があります。1 つ目は、正射影の近クリップ面を光に近い側へ延ばして、カスケードの外の物体も含めることです。2 つ目は深度クランプ（Pancaking）で、近クリップ面より手前の物体を近クリップ面に押し付けて描きます（`DepthClipEnable = FALSE`）。近クリップ面を狭くでき、深度の精度が上がりますが、物体がクリップ面に押し付けられます。3 つ目は、影を落とす物体の AABB を光空間で包んで近クリップ面を決める方法です。

```cpp
D3D11_RASTERIZER_DESC desc = {};
desc.DepthClipEnable = FALSE;
```

深度クランプでシャドウ マップの深度範囲を、その分割に必要な分だけにできます。

## カスケードの選択

描画時、<strong>各画素のカメラからの深度</strong>（ビュー空間の z）を、分割の境界と比べ、どのカスケードを使うかを決めます。

```hlsl
int SelectCascade(float view_depth) {
  int cascade = 0;
  [unroll] for (int i = 0; i < kCascadeCount - 1; ++i) {
    cascade += (view_depth > cascade_splits[i]) ? 1 : 0;
  }
  return cascade;
}
```

カスケードの選び方は 2 つあります。深度で選ぶ方式は、`view_depth` と分割の距離を比べるだけで簡単です。シャドウ マップの範囲で選ぶ方式は、各カスケードの uv が範囲内（0〜1）に入るかを、細かい順に調べ、入った最初のものを使います。範囲を安全に使えるので、ブレンドと相性が良いです。

### シャドウ マップを選んで引く

```hlsl
float CascadeShadow(float3 world_pos, float view_depth) {
  int c = SelectCascade(view_depth);
  float4 light_clip = mul(float4(world_pos, 1.0), cascade_view_projection[c]);
  float3 ndc = light_clip.xyz / light_clip.w;
  float2 uv = ndc.xy * float2(0.5, -0.5) + 0.5;
  return shadow_array.SampleCmpLevelZero(shadow_sampler, float3(uv, c), ndc.z - bias);
}
```

カスケードはテクスチャ配列（`Texture2DArray`）に入れるとインデックスで切り替えられて便利です（1 つの SRV）。

## カスケード間のブレンド

<strong>カスケードの境界</strong>でシャドウ マップが切り替わると、解像度の違い（ぼけの違い）により、影が突然、変わって見えます。境界の近くで隣のカスケードと混ぜます。

ブレンドの方法も 2 つあります。カスケードの奥側 10 % 程度で、次のカスケードの結果と `lerp` する方法。もう 1 つは、シャドウ マップの端（uv が 0 や 1 に近い）で、次の粗いカスケードへ移行する方法です。

```hlsl
float shadow = CascadeShadow(world_pos, c);
float blend = saturate((view_depth - blend_start[c]) / blend_width[c]);
if (blend > 0.0) {
  shadow = lerp(shadow, CascadeShadow(world_pos, c + 1), blend);
}
```

ブレンドは境界の画素だけで、2 回サンプルするので、わずかにコストが増えます。

## 最大距離でのフェード

<strong>影の最大距離</strong>を超えた先は、影なしになります。突然、影が消えると目立つので、最大距離の手前でフェードします。

```hlsl
float fade = saturate((max_shadow_distance - view_depth) / fade_length);
shadow = lerp(1.0, shadow, fade);
```

## カスケードごとの調整

| 項目 | 内容 |
| --- | --- |
| バイアス | テクセルの大きさが違うので、カスケードごとに調整（[Shadow Bias](bias/index.md)）。ワールド単位のテクセル サイズに比例させる |
| PCF のぼけの幅 | カスケードで、1 テクセルの大きさが違うので、カーネルをスケールして、ワールドでの幅をそろえる |
| LOD・カリング | 遠いカスケードは、低い LOD・小さい物を省く |
| 更新頻度 | 遠いカスケードは、数フレームに 1 回更新（[影のコスト](../../rendering/shadows.md)） |

## カスケードごとのカリング

各カスケードは、<strong>別の視錐台（光の正射影）</strong>で、シーンを描きます。カスケードごとに視錐台カリングを行い、そのカスケードに入る物体だけを描きます。

| 最適化 | 内容 |
| --- | --- |
| カスケードごとのカリング | そのカスケードの箱に入る物体だけ |
| 小さい物の除外 | 遠いカスケードでは、小さな物体を影から外す |
| インスタンシング・GPU Driven | カスケードごとの描画を、まとめて（[GPU Driven](../../rendering/gpu-driven.md)） |
| 1 回の描画で全カスケード | ジオメトリ シェーダーや、ビュー インスタンシングで、1 回のドローで複数のカスケードへ。ただし、効果は環境による |

## 設計のパラメータ

| パラメータ | 目安 |
| --- | --- |
| カスケード数 | 3〜4（モバイルは 1〜2） |
| <strong>解像度（各）</strong> | 1024〜2048（高品質は 4096） |
| 最大距離 | 100〜300 m |
| λ（分割の混合） | 0.5〜0.9 |
| ブレンド幅 | 各カスケードの 5〜10% |
| フォーマット | D32_FLOAT（または D16 で帯域を半分に） |

## 長所と短所

| 長所 | 短所 |
| --- | --- |
| 画面全体でほぼ一定の影の細かさ | N 回、シーンを描く（コスト・メモリが N 倍） |
| 屋外の太陽に最適 | 境界のアーティファクト（ブレンドで軽減） |
| 実装が標準的で資料が豊富 | ちらつき対策（スナップ・球フィット）が要る |
| PCF などとそのまま組み合わせられる | 遠くは粗い（距離の限界） |

## よくあるミス

??? failure "カメラが動くと、影の縁がちらちらする"
    テクセルのスナップと球でのフィットを入れます。

??? failure "近くの影が粗く、遠くが無駄に細かい"
    カスケードに分割します。λ で近くを細かく。

??? failure "カスケードの境目で、影が突然変わる"
    境界でブレンドします。

??? failure "視錐台の外にある、影を落とす物体の影が欠ける"
    近クリップ面を光の方向に延ばすか、深度クランプを使います。

??? failure "バイアスを、全カスケードで同じにして、遠いカスケードでアクネ・近いカスケードで浮く"
    テクセルの大きさに比例させます。

??? failure "全カスケードを、毎フレーム フル品質で描いて、重い"
    遠いカスケードは、更新頻度・LOD・カリングで軽くします。

## これだけ覚える

!!! abstract "まとめ"
    - [x] CSM ＝ 視錐台を奥行きで分割し、分割ごとにシャドウ マップ。近いほど、細かい
    - [x] 分割は対数と一様の中間（PSSM、λ）。影の最大距離を決める
    - [x] 各カスケードの射影は、分割を覆う球（安定）。テクセルのスナップでちらつきを止める
    - [x] 視錐台の外の遮蔽物のため、光の方向に範囲を延ばす（深度クランプ）
    - [x] 境界はブレンド、最大距離はフェード、カスケードごとにバイアス・PCF を調整
