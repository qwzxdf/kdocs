# Probe Operation

反射プローブを1つ置けばその周りの反射は出ます。ところが、実際のシーンには部屋が複数あり屋外がありプローブは何十個にもなります。そこで問題になるのはプローブの境目をまたぐ物の反射です。境目で急に切り替わると反射がぱっと変わり（ポップ）、混ぜようとして重みの合計で割ると、範囲の端でほぼ全部が 1 つのプローブになったり範囲の外で黒になったりします。このページでは影響範囲の重み優先度つきの「残りの重み」方式、クラスターごとのプローブの探索、ベイクと動的更新のメモリとコストを HLSL と C++ の数字で説明します。旧版にあった重みの合計で割る書き方が、なぜ危ないかも数字で見ます。

!!! tip "ポイント"
    - プローブごとに影響範囲の箱と面から内側へのブレンド距離を持つ。重みは面で 0、ブレンド距離以上内側で 1。
    - 重みの合計で割る方式は範囲の端の 0.01 m で、黒から 100 % の色へ跳ぶ。範囲の外では黒になる。優先度順に残りの重みを使い残りを空で埋める方式なら跳びは 0.0007 以下に収まる。
    - プローブは範囲の小さい順（部屋の中が先）に並べ外側のグローバルな空のキューブマップを最後の受け皿にする。
    - 128×128 のプローブ 1 つは、RGBA16F でミップ込み 1,024 KiB。64 個で 64 MiB。BC6H なら 1 つ 128 KiB、64 個で 8 MiB。
    - 動的に撮り直すときは 1 フレームに 1 面。プローブごとにずらすと全プローブが同じ面を同時に撮らない。

## 複数のプローブを置く理由 {#why}

1 つのプローブは撮影した点の周りの景色だけを持ちます。部屋が違えば景色が違うので場所ごとにプローブを置き物の位置に応じて使い分けます。これを成り立たせるために各プローブに次の 3 つを持たせます。

- **影響範囲。** 箱（または球）で範囲の中の表面にだけ使います。
- **ブレンド距離。** 範囲の端から内側へ重みが 0 から 1 に立ち上がる幅です。突然切り替わらないようにします。
- **優先度。** 部屋の中の小さなプローブを外の大きなプローブより優先します。

加えてシーン全体を覆う粗いグローバルなプローブ（空と遠景）を受け皿として 1 つ置きます。

## 影響範囲の重み {#weight}

```hlsl
// 反射プローブの混ぜ方: 影響範囲の重み、優先度つきの「残りの重み」方式、視差補正、クラスターのリスト、更新の分割。
// 座標は左手系・Y-up。「足した」と書いた値は、このページが説明のために決めたもの。

TextureCubeArray<float4> g_probe_cubes : register(t0);     // 全プローブのキューブマップ（ミップつき）
TextureCube<float4> g_sky_cube : register(t1);             // グローバルなフォールバック（空・遠景）
SamplerState g_linear_clamp : register(s0);

struct ProbeData {
  float3 position;        // プローブの位置（撮影した点）
  float blend_distance;   // 箱の面から内側へ、重みが 0 → 1 に立ち上がる幅 [m]
  float3 box_min;         // 影響範囲の箱
  uint cube_index;        // キューブマップ配列の番号
  float3 box_max;
  float mip_count;        // ミップの段数
};
StructuredBuffer<ProbeData> g_probes : register(t2);

cbuffer ProbeCB : register(b0) {
  float g_sky_mip_count;  // 空のキューブマップのミップの段数
  float3 g_pad;
};

// ================= ① 影響範囲の重み =================

// 箱の内側で、最も近い面までの距離 d を blend_distance で割った値。
// 面の上で 0、blend_distance 以上内側で 1、箱の外では 0。smoothstep で立ち上がりをなめらかにする（足した選択）。
float ProbeWeight(float3 world_pos, ProbeData p) {
  float3 inside = min(world_pos - p.box_min, p.box_max - world_pos);   // 各軸で、最も近い面までの距離（内側が正）
  float d = min(min(inside.x, inside.y), inside.z);
  float t = saturate(d / max(p.blend_distance, 1e-3));
  return t * t * (3.0 - 2.0 * t);
```

`ProbeWeight` は物の位置 `world_pos` が箱の内側にあるとき最も近い面までの距離 `d` を求めます。`d` を `blend_distance` で割って `saturate` し、`smoothstep` で立ち上がりをなだらかにします。面の上で 0、ブレンド距離以上内側で 1、箱の外では負の距離が 0 に飽和するので 0 です。`smoothstep` を使うのは重みの傾きが両端で 0 になり境目の折れ目が目立たないからです（足した選択）。

ブレンド距離は境目で切り替わる幅を決めます。小さいと反射が急に変わります。大きいとプローブが本来カバーしたい範囲の端まで弱くなります。部屋の壁際で反射が弱くならないよう壁の外側にブレンド領域を張り出す作り方もあります。

## 重みの合計で割るとなぜ危ないか {#normalized}

複数のプローブの範囲が重なる所では重みで混ぜます。素朴な書き方は重みの合計で割ることです。

```hlsl
// ================= ③ 混ぜ方 A: 重みを正規化する（問題のある書き方）=================

// 重みの合計で割ると、重みが小さい所でも 1 つのプローブが 100 % になる。範囲の外では黒になる。
float3 BlendNormalized(float3 world_pos, float3 r, float roughness, uint count, uint indices[8]) {
  float3 sum = 0;
  float wsum = 0;
  for (uint i = 0; i < count; ++i) {
    ProbeData p = g_probes[indices[i]];
    float w = ProbeWeight(world_pos, p);
    if (w <= 0.0) continue;
    float3 dir = ParallaxCorrect(r, world_pos, p);
    sum += g_probe_cubes.SampleLevel(g_linear_clamp, float4(dir, p.cube_index), roughness * (p.mip_count - 1)).rgb * w;
    wsum += w;
  }
  return sum / max(wsum, 1e-4);                                        // 範囲の外では 0 / 1e-4 = 黒
}
```

この書き方は 2 つの問題を持ちます。1 つ目は範囲の端で重みが小さくても、そのプローブが 100 % になることです。重みが 0.007 でも合計が 0.007 なら割ると 1 になります。2 つ目は範囲の外では合計が 0 で、`max(wsum, 1e-4)` の下限により色が黒になることです。

C++ で 1 次元の例を作りました。プローブ A は範囲 [0, 10]、色 1.0。プローブ B は [8, 20]、色 0.4。ブレンド距離は両方 2、空の色は 0.1 です。範囲の左端 x = 0 の近くで、正規化する方式の結果は x = −0.5 で 0.000（黒）、x = 0.001 で 0.007、x = 0.1 で 1.000 でした。**0.1 m 進むだけで黒から A の色に切り替わります。** 0.001 刻みで全体を歩いた最大の飛びは 0.157 で、x = 0.011 でした。x = 20.5（B の範囲の外）でも 0.000 の黒です。

## 優先度つきの「残りの重み」 {#remaining}

正規化の代わりに重みの合計が常に 1 になる使い方をします。優先度の高い（範囲の小さい）プローブから順に残っている重みの範囲で取ります。残った重みはグローバルな空のキューブマップで埋めます。

```hlsl
// ================= ④ 混ぜ方 B: 優先度つきの「残りの重み」=================

// indices は優先度順（範囲の小さい順）。各プローブは、残っている重みの範囲でだけ寄与する。
// 最後に残った重みは、グローバルな空のキューブマップで埋める。合計は常に 1 で、正規化の割り算はない。
float3 BlendWithRemaining(float3 world_pos, float3 r, float roughness, uint count, uint indices[8]) {
  float3 sum = 0;
  float remaining = 1.0;
  for (uint i = 0; i < count && remaining > 0.0; ++i) {
    ProbeData p = g_probes[indices[i]];
    float w = min(ProbeWeight(world_pos, p), remaining);               // 残りを超えて取らない
    if (w <= 0.0) continue;
    float3 dir = ParallaxCorrect(r, world_pos, p);
    sum += g_probe_cubes.SampleLevel(g_linear_clamp, float4(dir, p.cube_index), roughness * (p.mip_count - 1)).rgb * w;
    remaining -= w;
  }
  // 空のキューブマップは視差補正しない（無限遠）。残りの重みで足す。
  sum += g_sky_cube.SampleLevel(g_linear_clamp, r, roughness * (g_sky_mip_count - 1)).rgb * remaining;
  return sum;
}
```

`w = min(ProbeWeight, remaining)` で残りを超えて取りません。取った分を `remaining` から引き `remaining` が 0 になったら止めます。ループのあと残りの重みで空のキューブマップを足します。空は無限遠なので視差補正せずに反射ベクトルでそのまま引きます。合計は常に 1 で割り算がありません。

同じ例で範囲の左端は x = −0.5 で 0.100（空）、x = 0.001 で 0.100、x = 0.1 で 0.107、0.5 で 0.241、1.0 で 0.550、2.0 で 1.000 と空から A の色へなめらかに上がりました。最大の飛びは 0.0007 です。重なる範囲（x = 8.5 や 9.5）では、2 つの方式は一致します（0.906 と 0.494）。B の右端（x = 18.5〜19.9）では、残りの重み方式は B の色 0.4 から空の 0.1 へなめらかに下がります（0.353、0.102）。正規化する方式は 20.5 で突然黒に落ちます。

この例では重みの和は 0.000〜1.000 に収まりました。ただし、重なる範囲がブレンド距離より広いと和は 1 を超えます。残りの重み方式は和が 1 を超えても、`min(…, remaining)` で受け止めるので合計がずれません。

## 視差補正 {#parallax}

プローブはキューブマップですが、その景色が撮影した点の周りの箱だと仮定して、反射ベクトルを補正します。補正がないと床の反射が浮いて見えます。

```hlsl
// ================= ② 視差補正 =================

// 箱に対する視差補正（詳しくは Parallax Correction のページ）。反射ベクトル r を、プローブから見た向きに直す。
float3 ParallaxCorrect(float3 r, float3 world_pos, ProbeData p) {
  float3 inv_r = 1.0 / (r + float3(r == 0.0) * 1e-6);                  // 0 割りを避ける（足した処理）
  float3 t1 = (p.box_max - world_pos) * inv_r;
  float3 t2 = (p.box_min - world_pos) * inv_r;
  float3 t_far = max(t1, t2);
  float t = min(min(t_far.x, t_far.y), t_far.z);                       // 箱の内側から出る最初の面までの距離
  float3 hit = world_pos + r * t;
  return hit - p.position;
}
```

物の位置から反射ベクトルの向きに進み箱の内側から出る最初の面までの距離 `t` を求めます。その交点からプローブの位置へ向かうベクトルをキューブマップの向きに使います。詳しい式と注意は [Parallax Correction](parallax.md) にあります。**プローブごとに箱が違うので、補正もプローブごとに行います。** 空のキューブマップは補正しません。

## クラスターごとの探索 {#cluster}

物ごとに全プローブを調べるのは、数百個あると重すぎます。画面を奥行きも含めて細かい区画（クラスター）に分け各区画に影響するプローブのリストを持ちます。ライトのクラスター分けと同じ構造です（[Tiled and Clustered](../../pipeline/light-culling.md)）。

```hlsl
// ================= ⑤ クラスターごとのプローブのリスト =================

StructuredBuffer<uint> g_cluster_probe_offset : register(t3);          // クラスターごとの先頭
StructuredBuffer<uint> g_cluster_probe_count : register(t4);           // クラスターごとの個数
StructuredBuffer<uint> g_cluster_probe_list : register(t5);            // プローブ番号（優先度順に並べておく）

float3 ShadeReflection(float3 world_pos, float3 r, float roughness, uint cluster) {
  uint n = min(g_cluster_probe_count[cluster], 8u);                    // 1 画素あたり最大 8 個（足した上限）
  uint idx[8];
  uint base = g_cluster_probe_offset[cluster];
  [unroll] for (uint k = 0; k < 8; ++k) idx[k] = (k < n) ? g_cluster_probe_list[base + k] : 0;
  return BlendWithRemaining(world_pos, r, roughness, n, idx);
}
```

リストは優先度順（範囲の小さい順）に並べて作ります。1 画素で読むプローブは最大 8 個にしています（足した上限）。1 画素あたり読むプローブの数だけキューブマップ配列のサンプルが増えます。2〜4 個が普通です。

プローブはキューブマップ配列（`TextureCubeArray`）に入れて、番号で選びます。同じ配列の中でキューブマップの大きさとミップの数は揃えます。

## ベイクと動的更新 {#bake}

プローブの中身は事前に撮ってベイクするか実行中に撮り直します。

- **ベイク。** ビルド時に撮影してフィルタをかけておきます。実行時のコストはほぼなく静的な背景に向きます。
- **実行時に更新。** 時間帯が変わる場合や動く物を映したい場合に使います。1 フレームに 1 面ずつ撮り直して、6 フレームで 1 周するように分散します。
- **毎フレーム更新。** 重いので車のミラーのように重要な 1 か所だけです。

事前フィルタ（ミップの作成）はベイクなら事前、動的ならコンピュート シェーダーで毎回行います。コストが大きいので更新頻度を下げるのが普通です。分散の仕方は次の関数のようにプローブ番号を足して、同じフレームに全プローブが同じ面を撮らないようにします（足した工夫）。

```hlsl
// ================= ⑥ 更新の分割 =================

// 動的に撮り直すとき、1 フレームに 1 面だけ。6 フレームで 1 周する。
uint FaceToUpdate(uint frame_index, uint probe_index) {
  return (frame_index + probe_index) % 6u;                             // プローブごとにずらして、同じフレームに全プローブが同じ面にならないようにする（足した工夫）
}
```

メモリはキューブマップ配列の大きさで決まります。C++ でミップを全部持つ場合（面積 × 4/3）を計算しました。

128×128 のプローブは RGBA16F（1 テクセル 8 バイト）で 1,024 KiB、BC6H（1 バイト）で 128 KiB です。64 個ならそれぞれ 64 MiB と 8 MiB です。64×64 なら 256 KiB と 32 KiB、256×256 なら 4,096 KiB と 512 KiB です。解像度を 2 倍にするとメモリは 4 倍になります。圧縮は動的に撮り直すなら使えない（描き込めない）ので、ベイクしたプローブだけに使います。

## 空との関係 {#sky}

屋外の遠い景色（空）は視差を気にしなくてよい（無限遠）ので、グローバルなプローブとして全シーンに適用します。局所のプローブは近くの景色だけを持てばよくなります。ここまでの混ぜ方では残りの重みを空で埋める形にこれが含まれています。

## 動く物の扱い {#dynamic}

動く物（車、キャラクター）は位置が変わるので、使うプローブも変わります。毎フレーム、位置から使うプローブを選び重みを計算します。小さい物は位置を物の中心 1 点で決めて、1 つの反射にすることが多いです。大きい物は画素ごとに位置で混ぜます。

// プローブの混ぜ方を 1 次元で比べる。
//   [1] 2 つのプローブ（A: 0〜10、B: 8〜20）とグローバルな空。重みを正規化する方式と、残りの重み方式の連続性
//   [2] メモリ: キューブマップ配列
#include <algorithm>
#include <cmath>
#include <cstdio>
#include <vector>

struct Probe { double lo, hi, color, blend; };

// HLSL の ProbeWeight（1 次元）。箱の内側の距離 d を blend で割り、smoothstep。
static double Weight(const Probe& p, double x) {
  double d = std::min(x - p.lo, p.hi - x);
  double t = std::clamp(d / p.blend, 0.0, 1.0);
  return t * t * (3 - 2 * t);
}

int main() {
  const Probe A{0, 10, 1.0, 2.0}, B{8, 20, 0.4, 2.0};              // 優先度は範囲の小さい順: A（幅 10）が先、B（幅 12）が後
  const double sky = 0.1;

  // 方式 A: 正規化（問題のある書き方）。範囲の外は 0 / 1e-4 = 黒。
  auto normalized = [&](double x) {
    double sum = 0, w = 0;
    for (const Probe* p : {&A, &B}) { double wi = Weight(*p, x); if (wi > 0) { sum += p->color * wi; w += wi; } }
    return sum / std::max(w, 1e-4);
  };
  // 方式 B: 残りの重み。優先度順に取り、残りは空で埋める。
  auto remaining = [&](double x) {
    double sum = 0, rem = 1.0;
    for (const Probe* p : {&A, &B}) {
      double w = std::min(Weight(*p, x), rem);
      if (w <= 0) continue;
      sum += p->color * w; rem -= w;
    }
    return sum + sky * rem;
  };

  std::printf("[1] probes A [0,10] color 1.0, B [8,20] color 0.4, blend distance 2; sky color 0.1\n");
  std::printf("x       wA     wB     normalized   remaining\n");
  for (double x : {-0.5, 0.001, 0.1, 0.5, 1.0, 2.0, 5.0, 8.5, 9.5, 10.5, 15.0, 18.5, 19.9, 20.5}) {
    std::printf("%6.3f  %.3f  %.3f  %9.3f    %9.3f\n", x, Weight(A, x), Weight(B, x), normalized(x), remaining(x));
  }

  // 連続性: 0.001 刻みで走査して、隣り合う値の最大の差（= 最大の飛び）を見る
  double max_jump_n = 0, max_jump_r = 0, at_n = 0, at_r = 0;
  double prev_n = normalized(-5), prev_r = remaining(-5);
  for (double x = -5; x <= 25; x += 0.001) {
    double n = normalized(x), r = remaining(x);
    if (std::fabs(n - prev_n) > max_jump_n) { max_jump_n = std::fabs(n - prev_n); at_n = x; }
    if (std::fabs(r - prev_r) > max_jump_r) { max_jump_r = std::fabs(r - prev_r); at_r = x; }
    prev_n = n; prev_r = r;
  }
  std::printf("\nmax jump between samples 0.001 apart: normalized = %.3f at x = %.3f, remaining = %.4f at x = %.3f\n", max_jump_n, at_n, max_jump_r, at_r);

  // 重みの合計の範囲
  double min_sum = 1e9, max_sum = 0;
  for (double x = 0; x <= 20; x += 0.01) {
    double s = Weight(A, x) + Weight(B, x);
    min_sum = std::min(min_sum, s); max_sum = std::max(max_sum, s);
  }
  std::printf("sum of weights wA + wB over x in [0, 20]: min %.3f, max %.3f (the remaining method never divides by it)\n", min_sum, max_sum);

## よくあるミス {#mistakes}

??? failure "プローブの境界で、反射が急に切り替わる"
    ブレンド距離が 0、または小さすぎる。範囲の端から内側へフェードさせる。

??? failure "プローブの範囲の外が真っ黒になる"
    重みの合計で割っていて、合計が 0。残りの重みを空のキューブマップで埋める。

??? failure "範囲の端で、薄い重みのプローブが全部の色になる"
    同じく正規化している。優先度つきの残りの重み方式にする。

??? failure "部屋の中に外の反射が入ってくる"
    優先度が逆（大きいプローブが先）になっている。範囲の小さい順に並べる。

??? failure "全プローブが同じフレームに同じ面を更新して、フレーム時間が跳ねる"
    プローブ番号を足して、ずらす。
