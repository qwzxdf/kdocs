# Artifacts and Evaluation

<strong>SSR には決まった「弱点」があります</strong>。これを知っておくと見た目の不具合の原因が、すぐに分かります。このページでは SSR の代表的な問題点（アーティファクト）と、長所・短所の整理を説明します。

!!! tip "ポイント"
    - 画面外・隠れた物は、映らない（最大の弱点）。
    - 画面の端で反射が欠ける。
    - 薄い物を飛び越える・裏が映る（厚み）。
    - 動くとちらつく。
    - 長所はシーンが複雑でも、コストがほぼ一定。

## 問題点（アーティファクト）
| 症状 | 原因 | 対策 |
| --- | --- | --- |
| 反射が画面の端で消える・切れる | 画面外のものは、映らない | エッジ フェード・フォールバック |
| <strong>反射に「穴」「縞」</strong> | 歩幅が大きすぎて、薄い物を飛び越す | 歩幅を小さく・厚みの調整・Hi-Z（[Hi-Z SSR](../ssr-hiz.md)） |
| 反射が物の裏側を映さない | 深度バッファは、手前の面だけ | 仕様。フォールバック |
| 物の反射が引き伸ばされる | 厚みが大きすぎて、手前の物に当たり続ける | 厚みの調整 |
| 動く物体にずれ・ゴースト | 前フレームの色を使う | 動きベクトルで再投影 |
| 反射する物体自身が映る | レイが自分の面に当たる | 始点を法線方向に少しずらす |
| 透明物が映らない | 半透明は深度に書かれない | 仕様。別扱い |
| 粗い面の反射がくっきりしすぎる | 粗さを考慮していない | ぼかし・確率的 SSR（[Stochastic SSR](../ssr-stochastic.md)） |


反射が画面の端で消える・切れるのは、画面外のものが映らないためで、エッジ フェードとフォールバックで対処します。反射に穴や縞が出るのは歩幅が大きすぎて薄い物を飛び越すためで、歩幅を小さくする厚みを調整する、Hi-Z を使う（[Hi-Z SSR](../ssr-hiz.md)）といった対策があります。物の裏側が映らないのは深度バッファが手前の面しか持たないための仕様で、フォールバックで補います。反射が引き伸ばされるのは厚みが大きすぎて手前の物に当たり続けるためで、厚みを調整します。動く物体にずれやゴーストが出るのは、前フレームの色を使うためで動きベクトルで再投影して対処します。反射する物体自身が映り込むのは、レイが自分の面に当たるためで、始点を法線方向に少しずらします。透明物が映らないのは半透明が深度に書かれないための仕様で、別扱いにします。粗い面の反射がくっきりしすぎるのは、粗さを考慮していないためでぼかしや確率的 SSR（[Stochastic SSR](../ssr-stochastic.md)）で対処します。

反射が画面の端で消える・切れるのは、画面外のものが映らないためで、エッジ フェードとフォールバックで対処します。反射に穴や縞が出るのは歩幅が大きすぎて薄い物を飛び越すためで、歩幅を小さくする厚みを調整する、Hi-Z を使う（[Hi-Z SSR](../ssr-hiz.md)）といった対策があります。物の裏側が映らないのは深度バッファが手前の面しか持たないための仕様で、フォールバックで補います。反射が引き伸ばされるのは厚みが大きすぎて手前の物に当たり続けるためで、厚みを調整します。動く物体にずれやゴーストが出るのは、前フレームの色を使うためで動きベクトルで再投影して対処します。反射する物体自身が映り込むのは、レイが自分の面に当たるためで、始点を法線方向に少しずらします。透明物が映らないのは半透明が深度に書かれないための仕様で、別扱いにします。粗い面の反射がくっきりしすぎるのは、粗さを考慮していないためでぼかしや確率的 SSR（[Stochastic SSR](../ssr-stochastic.md)）で対処します。

## 長所と短所
| 長所 | 短所 |
| --- | --- |
| 追加のシーン描画なし（軽い） | 画面に映らない物は、反射しない |
| あらゆる形の面・動く物に使える | 厚み・歩幅の調整が難しい |
| 接地の細かい反射（足元）に強い | 画面端・視点の変化で反射が現れたり消えたり |
| 深度・法線・色があれば作れる | ノイズ・にじみ（粗い面） |


<strong>シーンが複雑でもコストがほぼ一定</strong>であることも、SSR の大きな長所です。レイトレーシングはシーンの三角形が増えるほど遅くなりますが、SSR は画面の画素数と歩数でコストが決まるので、ポリゴン数に左右されません。この性質が SSR を現代のゲームの標準的な反射手法にしました。

## SSR でよく出る見た目の問題

SSR は <strong>画面の情報だけ</strong>で反射を、作るので いくつかの典型的な、見た目の問題が出ます。原因と対策を整理します。

| 症状 | 原因 | 対策 |
| --- | --- | --- |
| 反射が画面の端で途切れる | レイが、画面の外に出る | 端でフェード、プローブで補う |
| 反射が手前の物の裏で欠ける（反射の、穴） | 手前の物に隠れた部分は画面に、無い | プローブで補う厚みの、調整 |
| 反射が引き伸ばされる（縞） | 厚みが、大きすぎ物の縁をまたぐ | 厚みを小さく、当たった面の法線を確認（[Thickness](thickness.md)） |
| 細い物が反射に映らない | ステップが粗く、すり抜ける | ステップを細かく、Hi-Z（[Hi-Z SSR](../ssr-hiz.md)） |
| 反射がちらつく | ステップの位置が、フレームごとにずれるノイズ | ジッターを固定、時間蓄積 |
| 反射がざらざら（ノイズ）（粗い面） | 確率的な、レイ | 時間蓄積 + 空間フィルタ（[Stochastic SSR](../ssr-stochastic.md)） |
| 反射が 1 フレーム遅れる | 前フレームの色を、使っている | 速度バッファで補正、許容 |
| 動く物の反射がゴースト | 前フレームの色が、古い | 速度バッファ、履歴のクランプ |
| 反射が地面の下に突き抜ける | 反射ベクトルが、面の下を向く（法線と視線の角度が、浅い） | 反射ベクトルを法線に、押し戻すレイの始点を面から少し、離す |

## 反射の穴

<strong>反射する面の前に物がある</strong>とき、その物の裏側に映るはずの景色が画面に、無いため反射に穴があきます（黒くなるまたは背景が、見える）。

```text
 カメラ ●
         ╲
          ╲   ┃柱（手前）
           ╲  ┃
        ━━━━╲━┃━━━━━ 床
              ╲┃     床の、柱の裏側にある部分の、反射には、柱の「裏面」が、映るはずだが、画面には、柱の「表面」しか、無い
```

この問題は SSR の根本的な、限界です。反射プローブ（[Combining with SSR](../probes/combine-ssr.md)）で穴を、埋めます。

## 反射の引き伸ばし

<strong>レイが物の縁</strong>（シルエット）で、当たると縁の先の遠くの背景を、物の色で引き伸ばしたような縞が、出ます。

原因は 当たった画素の深度と、レイ上の点の深度の差が厚み以内であれば、当たりと見なすため物の縁のすぐ後ろの、遠い背景まで同じ物に当たったと、誤認することです。

| 対策 | 内容 |
| --- | --- |
| 厚みを小さく（距離に比例） | 偽の当たりが、減る（[Thickness](thickness.md)） |
| 当たった面の法線を確認 | 面が、反射レイの方を向いている場合だけ、有効 |
| 深度の不連続を検出 | 当たった画素の周りの深度が大きく、違う（縁）なら信頼度を下げる |

## 時間方向の問題

| 問題 | 内容 | 対策 |
| --- | --- | --- |
| ちらつき | ジッターが、フレームごとに変わるノイズが、揺れる | ジッターにブルー ノイズ + フレーム番号（TAA で、平均される）。時間蓄積 |
| ゴースト | 前フレームの反射が、今の状態と合わない | 履歴の、クランプ、動き（速度バッファ）の考慮 |
| 反射の遅れ | 前フレームの色を、読むため動く物の反射が遅れる | 速度で補正、または今フレームの色を読む |

## デバッグ

SSR の <strong>問題を見つける</strong>には、中間結果を画面に表示します。

| 表示するもの | 見つかる問題 |
| --- | --- |
| 反射ベクトル（色で方向を表示） | 法線が、間違っている反射の向きがおかしい |
| 当たったか（白 = 当たり、黒 = 外れ） | ステップが、足りない厚みが合わない |
| 当たった位置の uv（色で、表示） | レイが思った場所に、当たっているか |
| 信頼度（フェードの結果） | フェードが、効きすぎ・足りない |
| SSR だけ（プローブなしで、表示） | SSR の本来の品質を、確認 |

```hlsl
// デバッグ: 当たったか否かを、色で表示（緑 = 当たり、赤 = 外れ、青 = 画面の外）。
return hit ? float4(0, 1, 0, 1) : (out_of_screen ? float4(0, 0, 1, 1) : float4(1, 0, 0, 1));
```
