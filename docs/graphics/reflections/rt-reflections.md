# レイトレース反射

**レイトレース反射**は、**画面ではなく、シーン全体**（三角形の BVH）に、**反射のレイを飛ばして**、反射を求める方式です。**画面外・物の裏側・半透明の向こう**まで**正しく映り**、**SSR の最大の限界**を超えます。ただし、**レイトレ対応 GPU が必要**で、**BVH の管理・ヒット位置のシェーディング・ノイズ除去**と**コストが大きい**方式です。このページでは、**レイの飛ばし方・ヒット点の色の求め方・ハイブリッド構成・ノイズ除去**を順に説明します。

!!! tip "ポイント"
    - 画素ごとに<strong>GGX（VNDF）でレイを飛ばす</strong>（<strong>[確率的 SSR](ssr-stochastic.md)と同じ構造</strong>）。<strong>ただし、探索の相手が BVH</strong>。
    - 当たった所の<strong>色（マテリアル ＋ ライティング）を、その場で計算</strong>する。
    - <strong>粗い面はレイを減らす</strong>（粗さのしきい値）。<strong>プローブにフォールバック</strong>。
    - <strong>ハイブリッド</strong>：<strong>画面内は SSR</strong>、<strong>画面外へ出たレイだけレイトレ</strong>。
    - ノイズは<strong>デノイザー</strong>で消す。<strong>ヒット距離</strong>が再投影・フィルタの鍵。
    - <strong>反射の反射</strong>（再帰）は、<strong>1〜2 回</strong>に制限（2 回目以降は、プローブで近似）。

## SSR との違い

| 項目 | SSR | レイトレ反射 |
| --- | --- | --- |
| **探索の相手** | 深度バッファ（画面） | <strong>BVH（シーンの三角形）</strong> |
| **画面外・裏側** | **映らない** | **映る** |
| **半透明の向こう** | 映らない | **映る**（any-hit） |
| **反射の中の反射** | 不可（または 1 回だけ） | **再帰で可能**（コスト増） |
| **必要な機能** | 深度・色 | **レイトレ対応 GPU・BVH** |
| **ヒット点の色** | 画面の画像から取る | **マテリアルと光をその場で評価** |
| **コスト** | 中 | **大** |

## 全体の流れ

| パス | 内容 |
| --- | --- |
| **① レイの生成** | G-Buffer から、**位置・法線・粗さ**を得て、**GGX VNDF** で方向を選ぶ |
| **② BVH のトレース** | **`TraceRay`**（または `RayQuery`）で、**最も近い交点**を求める |
| **③ ヒット点のシェーディング** | <strong>マテリアル（アルベド・粗さ・法線）</strong>と、**直接光（影のレイ）・間接光**で**色を計算** |
| **④ ミス** | 何にも当たらなければ、<strong>空（スカイ）</strong> |
| **⑤ デノイズ** | **空間・時間**でノイズを消す |
| **⑥ 合成** | <strong>BRDF の積分（スケール・バイアス）</strong>を掛ける。**フォールバック**と混ぜる |

## レイの生成

**確率的 SSR と同じ**です（[確率的 SSR](ssr-stochastic.md)）。**画素ごと 1 本**（または**半分の解像度**で 1 本）のレイを、**GGX の可視法線サンプリング**で作ります。

```hlsl
[shader("raygeneration")]
void ReflectionRayGen() {
  uint2 pixel = DispatchRaysIndex().xy;
  float3 p = WorldPosition(pixel);
  float3 n = WorldNormal(pixel);
  float3 v = normalize(camera_pos - p);
  float roughness = Roughness(pixel);

  if (roughness > kMaxRoughness) { output[pixel] = 0; return; }

  float3 h = SampleGGXVNDFWorld(v, n, roughness, Random2(pixel, frame));
  float3 dir = reflect(-v, h);
  if (dot(dir, n) <= 0.0) { output[pixel] = 0; return; }

  RayDesc ray;
  ray.Origin = p + n * kRayBias;
  ray.Direction = dir;
  ray.TMin = 0.0;
  ray.TMax = kMaxRayLength;

  ReflectionPayload payload = (ReflectionPayload)0;
  TraceRay(scene, RAY_FLAG_NONE, 0xFF, 0, 0, 0, ray, payload);

  output[pixel] = float4(payload.color, payload.hit_distance);
}
```

| 点 | 説明 |
| --- | --- |
| **粗さのしきい値** | **粗い面はレイを飛ばさず**、プローブに任せる（コスト削減） |
| **`dot(dir, n) <= 0`** | 地平線の下のレイは、無効 |
| **ペイロード** | **色**と**ヒット距離**（デノイズに使う） |
| **`ray.Origin = p + n·bias`** | 自己交差を避ける |

## ヒット点のシェーディング

**当たった点**の**色**を**その場で計算**します。**最も重い部分**です。

| 方法 | 内容 | コスト |
| --- | --- | --- |
| <strong>クローゼスト ヒット シェーダー（フル）</strong> | ヒット点の<strong>マテリアル（テクスチャ・法線）</strong>を評価し、<strong>ライティング（直接光・影・間接光）</strong>を計算 | **大**（反射の質は最高） |
| **簡易シェーディング** | **ベースカラーと簡易ライト**だけ。テクスチャの解像度を下げる（ミップを粗く） | 中 |
| **ライティング済みの結果を使う**（**ライト キャッシュ**・**G-Buffer のスクリーン空間が使える場合**） | **画面内のヒット**は、**スクリーン空間のライティング結果**を再利用 | 小 |
| **ミス → 空** | スカイ プローブ・スカイ ドーム | 最小 |

### ヒット点でのライティング

| 項目 | 方法 |
| --- | --- |
| **直接光** | ライトごとに**影のレイ**（または影マップ） |
| **間接光** | **ライト プローブ・環境マップ**（近似）。**さらにレイを飛ばさない**（コスト） |
| **反射の反射** | **再帰を 1 回**まで。2 回目は**プローブ**を引く |

```hlsl
[shader("closesthit")]
void ReflectionClosestHit(inout ReflectionPayload payload, BuiltInTriangleIntersectionAttributes attr) {
  SurfaceData surf = EvaluateMaterial(PrimitiveIndex(), attr.barycentrics);
  float3 hit_pos = WorldRayOrigin() + WorldRayDirection() * RayTCurrent();

  float3 color = EvaluateDirectLighting(surf, hit_pos, -WorldRayDirection());
  color += surf.albedo * SampleIrradiance(hit_pos, surf.normal);

  payload.color = color;
  payload.hit_distance = RayTCurrent();
}
```

**マテリアルの評価**（テクスチャの読み込み）は、**画面の外**なので**ミップが決まらない**問題があります（レイは**微分**がない）。**ミップを距離・粗さから推定**します（**レイ コーン**）。

## ハイブリッド構成：SSR とレイトレの組み合わせ

**画面内に当たりがある**場合は、**SSR（Hi-Z）で足りる**ことが多いです。**画面に当たりがない**（画面外・裏側・失敗）レイだけを**レイトレ**にします。

| 手順 | 内容 |
| --- | --- |
| **① SSR（Hi-Z）を先に** | 画面内で当たれば、その色を使う（安い） |
| **② 当たらなかったレイを、レイトレへ** | **画面外へ出たレイ・厚みで弾かれたレイ**だけ |
| **③ 結果を合成** | SSR とレイトレの結果を、画素ごとに選ぶ |

**利点**：**レイトレのレイが大きく減る**（コスト削減）。<strong>SSR は画面内の細かさ（足元の映り込み）</strong>に強い。

**注意**：**SSR とレイトレで見た目（色・ぼけ）が違う**と**境目が見える**。**同じ BRDF・同じ色空間**でそろえます。

## 粗さの扱い

| 粗さ | 対応 |
| --- | --- |
| <strong>低い（鏡面）</strong> | <strong>レイトレ（または SSR）</strong>。ノイズが少なく、効果が高い |
| **中くらい** | レイトレ（確率的）＋デノイズ |
| <strong>高い（粗い）</strong> | **レイを飛ばさない**。**プローブ**・**拡散的な間接光**に任せる |

**粗さのしきい値**（0.4〜0.6 程度）で、**レイの数を絞る**のが一般的です。

## ノイズ除去（デノイズ）

**画素ごと 1 本**では、**ノイズ**が大きすぎます。**デノイザー**で**空間・時間**の平均を取ります。

| 要素 | 内容 |
| --- | --- |
| **時間蓄積** | **再投影**で過去フレームと混ぜる。**反射像はヒット距離**を使って、**仮想的な位置**へ再投影 |
| **空間フィルタ** | **バイラテラル**（深度・法線・粗さ）。**粗さに比例して、広く** |
| **ヒット距離** | <strong>近い当たり（接地部）</strong>は、フィルタを**狭く**、**遠い**当たりは**広く**（反射の見た目が距離でぼけるため） |
| **分散による制御** | **時間的な分散**が大きい画素は、**フィルタを強く**（SVGF の考え方） |
| **ホタル除去** | 極端に明るいサンプルを、制限する |

**代表的なデノイザー**：

| 名前 | 特徴 |
| --- | --- |
| **SVGF**（Spatiotemporal Variance-Guided Filtering） | 分散を使った、**時空間のバイラテラル**。レイトレ反射・GI の**定番** |
| **ReBLUR / ReLAX**（NVIDIA NRD） | **ヒット距離**・**粗さ**を考慮した、実用的なデノイザー群 |
| **自作** | **確率的 SSR のリゾルブ ＋ 時間蓄積 ＋ バイラテラル**を、そのまま流用 |

## 性能の工夫

| 工夫 | 内容 |
| --- | --- |
| **粗さによる、レイの省略** | 粗い面はレイを飛ばさない |
| **半分の解像度** | レイを半分の解像度で飛ばし、**アップサンプル** |
| **レイのソート・まとめ** | **似た方向・似たメッシュ**のレイを**まとめて処理**（コヒーレンス向上）。**シェーダー実行の並べ替え**（SER） |
| **レイの最大距離** | **短く**する（遠くは空・プローブ） |
| **インライン レイトレ**（`RayQuery`） | **コンピュート シェーダーから直接**（ヒット シェーダーなし）。**軽い処理**に向く |
| **LOD・簡易メッシュ** | **BVH 用に軽いメッシュ**を使う |
| **アルファ テスト** | **any-hit** は重い。**葉・フェンス**は必要最小限に |
| **動く物体の BVH 更新** | **リフィット**（再構築より安い）・**更新頻度の削減** |

## BVH の準備

| 項目 | 内容 |
| --- | --- |
| **BLAS**（Bottom-Level AS） | **メッシュごと**の BVH。**静的**メッシュは、1 回作る |
| **TLAS**（Top-Level AS） | **インスタンスの配置**の BVH。**毎フレーム更新** |
| **動く・変形するメッシュ** | **スキニング後の頂点**で、BLAS を<strong>更新（リフィット）</strong>または**再構築** |
| **メモリ** | BVH は**メッシュの数倍**のメモリを食う |

詳しくは、[レイトレーシング入門](../index.md)（予定）で扱います。

## 長所と短所

| 長所 | 短所 |
| --- | --- |
| **画面外・裏側・半透明の向こうまで正確** | **レイトレ対応 GPU が必要** |
| **反射の反射も可能** | **コストが大きい**（BVH・シェーディング・デノイズ） |
| **品質が高い**（ハロー・厚みの問題なし） | **ノイズ**が出る。**デノイザーが必須** |
| **シーン全体を一貫して扱える** | 動く物体の BVH 更新・メモリ |

## よくあるミス

??? failure "粗い面にも、すべてレイを飛ばして、重い"
    **粗さのしきい値**で絞り、プローブに任せます。

??? failure "ヒット点で、フルのシェーダー・全光源を評価して、極端に重い"
    **簡易シェーディング**・**ライト数の制限**・**キャッシュ**を使います。

??? failure "ヒット距離を、デノイザーに渡さず、反射像がぶれる"
    **ヒット距離**を保存して、**再投影・フィルタの強さ**に使います。

??? failure "SSR とレイトレの色・ぼけが違い、境目が見える"
    **同じ BRDF・同じ露出**にそろえます。

??? failure "ミップを決めず、遠い反射のテクスチャが、ちらつく"
    **レイ コーン**で**距離・粗さからミップ**を推定します。
