# Reflection Comparison

<strong>平面反射・リフレクション プローブ・SSR・レイトレース反射</strong>は、それぞれ得意・不得意が違います。実際のゲームは、これらを組み合わせて使います。このページでは、4 方式を原理・品質・コスト・弱点で並べて比べ、どの場面で何を使うか、組み合わせの設計をまとめます。

!!! tip "ポイント"
    - <strong>平面反射</strong>＝正確・平面のみ・重い。<strong>プローブ</strong>＝安い・位置がずれる・動かない。SSR＝画面内の細かい反射・画面外が映らない。レイトレ＝正確・対応 GPU・重い。
    - 粗い反射 → プローブ、近い細かい反射 → SSR、平面 → 平面反射、高品質 → レイトレ。
    - 組み合わせの基本：平面反射 → SSR → ローカル プローブ → グローバル プローブ（上ほど正確、下ほど安定）。
    - 信頼度で滑らかに混ぜ、BRDF の積分を共通に掛ける。

## 総合比較表

| 項目 | 平面反射 | プローブ | SSR | レイトレ反射 |
| --- | --- | --- | --- | --- |
| 景色の出どころ | 鏡映カメラの再描画 | 事前のキューブマップ | 画面の深度・色 | シーンの BVH |
| 画面外・裏側 | 映る | 映る（静的） | 映らない | 映る |
| 対象の面 | 平面のみ | あらゆる面 | あらゆる面 | あらゆる面 |
| 動く物体 | 映る | 映らない（更新必要） | 映る（画面内） | 映る |
| <strong>粗さ（ぼけ）</strong> | ぼかしで近似 | ミップ（事前フィルタ） | 確率的・ミップ | 確率的 |
| 位置の正確さ | 正確 | 視差のずれ（補正） | 正確（画面内） | 正確 |
| ノイズ | なし | なし | あり（確率的） | あり（デノイズ必須） |
| コスト | 大（再描画） | 小 | 中 | 大 |
| 必要なハード | なし | なし | なし | レイトレ対応 GPU |
| 実装の手間 | 小〜中 | 中 | 中〜大 | 大 |
| 主な弱点 | 平面のみ・重い | 視差・動的でない | 画面外が映らない | コスト・ノイズ |

## 場面別の使い分け

| 場面 | おすすめ | 理由 |
| --- | --- | --- |
| <strong>水面（湖・海）</strong> | 平面反射（または SSR ＋ プローブ） | 平面で反射が主役 |
| 鏡（室内・車のミラー） | 平面反射 | 完全な鏡の反射が必要 |
| 磨かれた床・濡れた路面 | SSR ＋ プローブ | 広い面積。平面反射は重い |
| 金属（機械・車体） | プローブ ＋ SSR | 曲面。プローブで基本の映り込み |
| 粗い面（岩・木） | プローブ | 粗いのでぼけた反射で十分 |
| ガラス・窓 | プローブ ＋ 専用の工夫 | 半透明。SSR は使えない |
| 高品質を優先（PC 上位） | レイトレ反射（ハイブリッド） | 画面外・裏側まで |
| モバイル | プローブ（＋簡易な平面反射） | 軽さ優先 |

## 組み合わせの設計

<strong>現実的な構成</strong>は、階層です。

| 優先 | 方式 | 役割 |
| --- | --- | --- |
| 1 | 平面反射 | 水面・鏡など、平面で最も正確に |
| 2 | SSR | 画面内の細かい映り込み（足元・近くの物） |
| 3 | ローカル プローブ | 画面外・粗い反射。部屋・エリア単位で視差補正 |
| 4 | グローバル プローブ | 最後の砦（空・遠景） |
| （高品質） | レイトレ | SSR が失敗したレイを補う（ハイブリッド） |

### 混ぜる原則

| 原則 | 内容 |
| --- | --- |
| 信頼度で滑らかに | 急に切り替えない（[SSR Fallback and Compositing](ssr-fallback.md)） |
| BRDF の積分は、共通 | `F0 · A + B` を最後に 1 回（全方式で同じ） |
| 同じ粗さの対応 | 同じ粗さ→ぼけになるよう、方式間で揃える |
| 同じ露出・色空間 | SSR の入力色・プローブの色を同じ条件にそろえる |
| スペキュラ遮蔽 | プローブ由来の反射に AO ベースで掛ける |

## 粗さごとの得意不得意

| 粗さ | 平面反射 | プローブ | SSR | レイトレ |
| --- | --- | --- | --- | --- |
| <strong>0（鏡）</strong> | ◎ | △（ぼけない解像度が要る） | ○（細かい） | ◎ |
| 低（0.1〜0.3） | ○ | ○ | ◎ | ◎ |
| 中（0.4〜0.6） | △（ぼかしが難しい） | ◎ | ○（ノイズ） | ○（重い） |
| 高（0.7〜） | × | ◎ | △（不安定） | △（コストに見合わない） |

## 画面外・裏側の扱い

| 方式 | 画面外・裏側 |
| --- | --- |
| 平面反射 | 映る（別のカメラから描くため） |
| プローブ | 映る（ただし、ベイク時の位置から。視差補正） |
| SSR | 映らない → フォールバック |
| レイトレ | 映る |

## コストの目安（概算）

<strong>フル HD の目安</strong>です。実装・GPU・設定で大きく変わります。

| 方式 | コストの特徴 |
| --- | --- |
| 平面反射 | シーンの再描画（半分の解像度でもジオメトリ処理は同じ）。数 ms |
| プローブ | キューブマップを引くだけ（画素ごと数回）。0.1〜0.5 ms。更新は別（ミップ作成） |
| SSR | Hi-Z ＋ 確率的で、1〜3 ms（半分の解像度でさらに軽く） |
| レイトレ反射 | レイ ＋ ヒット点のシェーディング ＋ デノイズで、数 ms〜10 ms 以上 |

実際の速さは実機で測ってください（[調査ツール](../../rendering/tools.md)）。

## 設計の流れ

| 手順 | 内容 |
| --- | --- |
| ① プローブから始める | IBL の反射をまず入れる（粗い反射・最後の砦） |
| ② 平面を平面反射に | 水面・鏡があるなら |
| ③ SSR を足す | 接地・近くの細かい反射。信頼度でプローブと混ぜる |
| <strong>④ レイトレを足す（任意）</strong> | 対応 GPU で、SSR の失敗分を補う |
| ⑤ チューニング | 粗さのしきい値・解像度・更新頻度 |

## よくあるミス

??? failure "SSR だけで、反射を済ませようとする"
    画面外・端で反射が消えます。<strong>プローブ</strong>で補います。

??? failure "プローブだけで、近くの細かい映り込み（足元）を期待する"
    プローブには近くの物が映りません。SSR で補います。

??? failure "全ての面に平面反射を使って重い"
    平面（水面・鏡）だけに使います。

??? failure "方式ごとに、BRDF の積分や粗さの対応が違い、境目が見える"
    共通の式・共通の粗さ→ミップに統一します。

??? failure "レイトレを入れたが、ノイズ除去を軽視して、ざらざら"
    デノイザーに時間をかけて設計します。
