# Reflection Comparison

**平面反射・リフレクション プローブ・SSR・レイトレース反射**は、それぞれ得意・不得意が違います。**実際のゲームは、これらを組み合わせて使います**。このページでは、**4 方式を原理・品質・コスト・弱点で並べて比べ**、**どの場面で何を使うか**、**組み合わせの設計**をまとめます。

!!! tip "ポイント"
    - <strong>平面反射</strong>＝正確・平面のみ・重い。<strong>プローブ</strong>＝安い・位置がずれる・動かない。<strong>SSR</strong>＝画面内の細かい反射・画面外が映らない。<strong>レイトレ</strong>＝正確・対応 GPU・重い。
    - <strong>粗い反射 → プローブ</strong>、<strong>近い細かい反射 → SSR</strong>、<strong>平面 → 平面反射</strong>、<strong>高品質 → レイトレ</strong>。
    - <strong>組み合わせの基本</strong>：<strong>平面反射 → SSR → ローカル プローブ → グローバル プローブ</strong>（上ほど正確、下ほど安定）。
    - <strong>信頼度で滑らかに混ぜ</strong>、<strong>BRDF の積分を共通に掛ける</strong>。

## 場面別の使い分け

場面ごとのおすすめを挙げます。水面（湖・海）は、平面が反射の主役なので、<strong>平面反射</strong>（あるいは SSR とプローブの組み合わせ）です。鏡（室内や車のミラー）は、完全な鏡の反射が必要なので、<strong>平面反射</strong>です。磨かれた床や濡れた路面は、面積が広く、平面反射は重いので、<strong>SSR とプローブ</strong>を使います。金属（機械・車体）は曲面なので、<strong>プローブ</strong>で基本の映り込みを作り、<strong>SSR</strong> で細かさを足します。岩や木のような粗い面は、ぼけた反射で十分なので、<strong>プローブ</strong>だけで足ります。ガラスや窓は半透明で、SSR が使えないので、プローブと専用の工夫を組み合わせます。PC の上位環境で品質を優先するなら、<strong>レイトレ反射</strong>（ハイブリッド構成）で、画面外や裏側まで映します。モバイルは軽さが最優先なので、プローブ（と簡易な平面反射）にします。

## 組み合わせの設計

**現実的な構成**は、**階層**です。

現実的な構成は、階層です。最優先は<strong>平面反射</strong>で、水面や鏡のような平面を最も正確に映します。次が <strong>SSR</strong> で、画面内の細かい映り込み（足元や近くの物）を担当します。その次が<strong>ローカル プローブ</strong>で、画面外と粗い反射を、部屋やエリア単位に視差補正付きで担当します。最後の砦が<strong>グローバル プローブ</strong>で、空や遠景を受け持ちます。高品質を求める場合は、<strong>レイトレ</strong>を加え、SSR が失敗したレイを補います（ハイブリッド）。

### 混ぜる原則

階層の方式を混ぜるときの原則があります。第 1 に、<strong>信頼度で滑らかに混ぜる</strong>ことです。方式の切り替えで境目が見えないよう、急に切り替えず、信頼度の重みで混ぜます（[SSR Fallback and Compositing](ssr-fallback.md)）。第 2 に、BRDF の積分は共通にします。`F0 · A + B` の項は、最後に 1 回だけ、全方式で同じものを掛けます。第 3 に、同じ粗さが同じぼけになるよう、方式間で対応を揃えます。第 4 に、SSR の入力色とプローブの色は、同じ露出・同じ色空間にします。第 5 に、プローブ由来の反射には、AO ベースのスペキュラ遮蔽を掛けます。

## 粗さごとの得意不得意

粗さごとの得意不得意を見ます。粗さ 0（鏡）では、平面反射とレイトレが最も得意で、SSR も細かく映せますが、プローブはぼけないだけの解像度が要るので苦手です。粗さが低い（0.1〜0.3）範囲では、SSR とレイトレが最適で、平面反射とプローブもまずまずです。粗さが中（0.4〜0.6）では、ぼかしの難しい平面反射は苦手で、プローブが最適、SSR はノイズが目立ち、レイトレは重くなります。粗さが高い（0.7 以上）では、プローブが最適で、平面反射は不向き、SSR は不安定、レイトレはコストに見合いません。

## 画面外・裏側の扱い

画面外や裏側の扱いは、方式で異なります。平面反射は別のカメラから描くので映ります。プローブも映りますが、ベイク時の位置から見た景色なので、視差補正が必要です。SSR は画面に映っていないものは映せないため、フォールバックが必要です。レイトレはシーン全体を使うので映ります。

## コストの目安（概算）

**フル HD の目安**です。**実装・GPU・設定**で大きく変わります。

コストの特徴をまとめます（フル HD の概算）。平面反射は、シーンの再描画なので、半分の解像度にしてもジオメトリ処理は同じで、数 ms かかります。プローブは、キューブマップを引くだけなので 0.1〜0.5 ms で済みますが、更新（ミップ作成）は別です。SSR は Hi-Z と確率的な手法を使って 1〜3 ms、半分の解像度でさらに軽くできます。レイトレ反射は、レイとヒット点のシェーディングとデノイズで、数 ms から 10 ms 以上になります。

**実際の速さは実機で測ってください**（[調査ツール](../../rendering/tools.md)）。

## 設計の流れ

導入の順番は、手順を踏むのが安全です。最初に、プローブから始めて、IBL の反射を入れます（粗い反射と最後の砦）。水面や鏡があれば、そこを平面反射にします。次に SSR を足し、接地面や近くの細かい反射を出し、信頼度でプローブと混ぜます。対応 GPU があれば、レイトレを任意で足して、SSR が失敗した分を補います。最後に、粗さのしきい値、解像度、更新頻度をチューニングします。

## よくあるミス

??? failure "SSR だけで、反射を済ませようとする"
    画面外・端で反射が消えます。**プローブ**で補います。

??? failure "プローブだけで、近くの細かい映り込み（足元）を期待する"
    プローブには**近くの物が映りません**。**SSR** で補います。

??? failure "全ての面に、平面反射を使って重い"
    **平面（水面・鏡）だけ**に使います。

??? failure "方式ごとに、BRDF の積分や粗さの対応が違い、境目が見える"
    **共通の式・共通の粗さ→ミップ**に統一します。

??? failure "レイトレを入れたが、ノイズ除去を軽視して、ざらざら"
    **デノイザーに時間をかけて**設計します。
