# ゲームバランスの数学

ゲームの面白さは、**数値の設計**に大きく左右されます。レベルが上がるごとの強さ、攻撃と防御の関係、ドロップ率、ガチャの確率といった数値は、**数式で設計**できます。このページは**ダメージ式・成長曲線・確率・期待値**など、バランス調整でよく使う数学をまとめます。感覚で数値を決める前に、**式の性質**を知っておくと、調整が速く、破綻しにくくなります。

!!! tip "ポイント"
    - ダメージ式は<strong>引き算型・割り算型（比率）・割合型</strong>。<strong>それぞれ性質が違う</strong>。
    - 成長は<strong>線形・べき乗・指数</strong>の 3 つを使い分ける。<strong>指数はすぐ手に負えなくなる</strong>。
    - 防御・回避などは<strong>逓減（上限に近づく）</strong>させて、<strong>インフレを防ぐ</strong>。
    - <strong>確率は積</strong>（かつ）と<strong>1 - 余事象</strong>（少なくとも 1 回）で計算する。
    - <strong>期待値</strong>で平均の強さを比べる。<strong>ばらつき</strong>も見る。
    - <strong>天井（ピティ）</strong>で、運の悪さの救済を設計する。

## ダメージ式

### 1. 引き算型

```text
ダメージ = 攻撃力 - 防御力
```

| 特徴 | 説明 |
| --- | --- |
| **単純で分かりやすい** | 数値がダメージにそのまま対応 |
| **防御が攻撃を上回ると 0** | **ダメージが出なくなる**。下限（最低 1 など）が必要 |
| **差が効きすぎる** | わずかな数値の違いでダメージが大きく変わる |
| **インフレに弱い** | 数値が大きくなると調整が難しい |

### 2. 割り算型（比率）

```text
ダメージ = 攻撃力 × 攻撃力 / (攻撃力 + 防御力)
```

| 特徴 | 説明 |
| --- | --- |
| **ダメージが 0 にならない** | 防御が高くても少しは通る |
| **滑らか** | 数値の違いがダメージに**穏やかに**効く |
| **数値が大きくなっても安定** | 比率で決まるのでインフレに強い |

### 3. 割合型（軽減率）

```text
ダメージ = 攻撃力 × (1 - 軽減率)
軽減率 = 防御力 / (防御力 + 定数)
```

| 特徴 | 説明 |
| --- | --- |
| **軽減率は 0〜1 に収まる** | 防御をどれだけ積んでも、100% にならない（**逓減**） |
| **定数が基準** | 「防御がこの値のとき、軽減 50%」を決める |
| **多くの MMO・ARPG で採用** | 防御の効き方を予測しやすい |

```cpp
float DamageReduction(float armor, float constant) {
  return armor / (armor + constant);
}

float FinalDamage(float attack, float armor, float constant) {
  return attack * (1.0f - DamageReduction(armor, constant));
}
```

### 補正（乗算と加算）

ダメージに**複数の補正**（属性・クリティカル・バフ）をかけるときは、**足し算か掛け算か**で結果が大きく変わります。

| 方式 | 計算 | 特徴 |
| --- | --- | --- |
| **加算** | `基礎 × (1 + 補正A + 補正B)` | +50% と +50% で、**2 倍** |
| **乗算** | `基礎 × (1 + 補正A) × (1 + 補正B)` | +50% と +50% で、**2.25 倍**。**積み重ねで爆発** |
| **混在** | 同じ種類は加算、別の種類は乗算 | 多くのゲームで採用（バランスが取りやすい） |

**乗算を多く重ねる**と**ビルドによって極端に強く**なります。**加算の枠をまとめ**、**乗算は少数**に絞ると調整しやすくなります。

### 乱数の幅

| 方法 | 説明 |
| --- | --- |
| **一様な幅** | ダメージを ±10% の範囲で、一様に |
| **正規分布** | 平均付近が多く、極端な値は少ない |
| **クリティカル** | 確率で倍率をかける（例：20% で 1.5 倍） |

## 成長曲線

**レベルが上がるにつれ**、**必要な経験値**や**ステータス**が、どう増えるかを決める式です。

| 種類 | 式 | 特徴 | 使いどころ |
| --- | --- | --- | --- |
| **線形** | `a + b × L` | 一定ずつ増える。**単調で予測しやすい** | ステータスの伸び・単純な成長 |
| <strong>べき乗（多項式）</strong> | `a × L^p` | 増え方がだんだん加速。**p = 2 や 3 が多い** | 必要経験値 |
| **指数** | `a × b^L` | **倍々で増える**。すぐ巨大になる | ロングランのインフレ（放置ゲーム） |
| **対数** | `a × log(L)` | **増え方が鈍る**。頭打ち | 後半の伸びを抑えたいもの |
| <strong>S 字（ロジスティック）</strong> | `K / (1 + e^(-r(L - L0)))` | 序盤はゆっくり、中盤は急、終盤は頭打ち | 習熟度・人口 |

```cpp
int ExpToNextLevel(int level) {
  return static_cast<int>(100.0f * std::pow(static_cast<float>(level), 1.8f));
}
```

| 点 | 説明 |
| --- | --- |
| **指数 `b` の選び方** | 1.05〜1.15 でも、数十レベルで**大きく開く**。**レベルの上限を決めて**確認する |
| **表で作る** | 式で作り、**表にして、手で微調整**する（調整データとして管理） |
| **体感の確認** | <strong>「何分で 1 レベル上がるか」</strong>を、各レベルで見積もる |
| **ステータスと必要量のバランス** | ステータスの伸びと敵の強さの伸びを**同じ形**にすると、体感が揃う |

### 上限と逓減

**防御・回避・クールダウン短縮**などを、**際限なく積めると壊れます**。**逓減**（上限に近づくほど、効きが弱くなる）にします。

```text
効果 = 上限 × x / (x + 定数)
効果 = 1 - exp(-k × x)
```

| 方式 | 説明 |
| --- | --- |
| **`x / (x + c)`** | 双曲線型。**半分の効果になる x が `c`** |
| **指数型** | `1 - exp(-kx)`。すばやく頭打ち |
| **硬い上限** | `min(効果, 上限)`。分かりやすいが上限で急に効かなくなる |
| **段階的な効き** | 一定の値ごとに効果を減らす |

**式の形で後半の必要経験値が大きく変わります**。指数は序盤が緩くて、終盤で急に重くなります。

## 戦闘の指標

| 指標 | 式 | 意味 |
| --- | --- | --- |
| <strong>DPS（秒間ダメージ）</strong> | `1 回のダメージ × 攻撃回数 / 秒` | 武器・スキルの強さの比較 |
| <strong>TTK（倒すまでの時間）</strong> | `敵の HP / DPS` | 戦闘の長さ・緊張感 |
| <strong>TTD（やられるまでの時間）</strong> | `自分の HP / 敵の DPS` | 危険度 |
| **有効 HP** | `HP / (1 - 軽減率)` | 防御を HP に換算した、実質の硬さ |

**TTK と TTD の比**（自分が倒すのが先か、やられるのが先か）で、**戦闘の難しさ**が決まります。**敵ごとの TTK を狙った秒数**（雑魚 3 秒・ボス 60 秒など）にそろえて、**そこから逆算して**ステータスを決めると、調整しやすくなります。

## 確率の計算

### 積と余事象

| 計算 | 式 | 例 |
| --- | --- | --- |
| **両方起こる** | `p1 × p2` | クリティカル 20%・命中 90% → 18% |
| **少なくとも 1 回起こる** | `1 - (1 - p)^n` | 5% を 10 回 → `1 - 0.95^10 = 40%` |
| **ちょうど k 回** | 二項分布 `C(n,k) × p^k × (1-p)^(n-k)` | 10 回中 2 回当たる確率 |
| **n 回目で初めて起こる** | `(1 - p)^(n-1) × p` | 何回目で出るか |
| **平均で何回で起こる** | `1 / p` | 5% なら、平均 20 回 |

```cpp
float ProbabilityAtLeastOnce(float p, int tries) {
  return 1.0f - std::pow(1.0f - p, static_cast<float>(tries));
}
```

!!! note "「100 回引けば確実に当たる」ではない"
    確率 1% を 100 回引いても、**当たらない確率は約 37%**（`0.99^100`）です。**平均 100 回**であって、**100 回で必ず**ではありません。

## 期待値

**期待値**は**繰り返したときの平均**です。

```text
期待値 = Σ (値 × 確率)
```

| 使いどころ | 説明 |
| --- | --- |
| **ダメージの平均** | `通常ダメージ × (1 - クリ率) + クリダメージ × クリ率` |
| **武器の比較** | 「高ダメージ・低命中」と「低ダメージ・高命中」を、期待値で比べる |
| **ドロップの期待数** | `確率 × 試行回数` |
| **ガチャの平均コスト** | `1 / 確率` 回 |

**期待値が同じでもばらつき（分散）が違う**とプレイ感が違います。**安定した武器**と**一発逆転の武器**のように、**期待値をそろえて、ばらつきで個性**を出せます。

### クリティカルの期待値

```cpp
float ExpectedDamage(float base, float crit_rate, float crit_multiplier) {
  return base * (1.0f + crit_rate * (crit_multiplier - 1.0f));
}
```

## 天井（ピティ）と救済

**確率だけ**だと運の悪い人が**いつまでも当たらない**ことがあります。<strong>天井（ピティ）</strong>は、**一定回数で当たりを保証**する仕組みです。

| 方式 | 説明 |
| --- | --- |
| **確定天井** | N 回目で必ず当たる |
| <strong>確率上昇（ソフト天井）</strong> | 外れるたびに確率を少しずつ上げる（**疑似乱数分布**） |
| **カウンターのリセット** | 当たったら、カウンターを 0 に戻す |
| <strong>次回確定（保証）</strong> | 外れの種類のあとは、次を保証 |

```cpp
float PityProbability(float base_rate, int misses, int soft_pity_start, float increment) {
  if (misses < soft_pity_start) {
    return base_rate;
  }
  return std::min(1.0f, base_rate + increment * static_cast<float>(misses - soft_pity_start + 1));
}
```

**実際の確率**（宣伝している値と実質の確率）は**天井を含めると変わります**。**ユーザーに伝えるときは、天井を含めた実質の期待値**を計算して、確認します。

### 偽の乱数（Pseudo-random Distribution）

「**外れが続くほど、次は当たりやすくなる**」ことで**体感の運の偏りを減らす**方式です。**クリティカルが連続で出ない・連続で外れない**ようにしたいときに使います（Dota 2 などで有名）。

| 点 | 説明 |
| --- | --- |
| **実質の確率** | 目標の確率になるように、増分を調整する |
| **体感が安定** | 長く外れにくい・連続しにくい |
| **予測できる** | 連続で外れたら、次は当たる、と**対策**される場合がある |

## 経済（ゴールド・アイテム）

| 考え方 | 説明 |
| --- | --- |
| **流入と流出** | 入ってくるお金と出ていくお金の**バランス**。流入が多すぎるとインフレ |
| <strong>シンク（出口）</strong> | お金を減らす仕組み（消耗品・修理・手数料） |
| **価格の逓増** | 買うたびに値段が上がる（`価格 × 係数^回数`） |
| **売値と買値** | 売値を買値より低くして、**転売で無限に増やせない**ようにする |

## 調整の進め方

| 手順 | 内容 |
| --- | --- |
| **① 目標の体験を決める** | 雑魚は 3 秒・ボスは 60 秒、など |
| **② 式で仮の値を作る** | 成長曲線・ダメージ式でベースを作る |
| **③ 表にして確認** | レベルごとの数値を**スプレッドシート**で俯瞰 |
| **④ シミュレーション** | **プログラムで何万回も戦闘させて**、勝率・TTK を出す |
| **⑤ データ駆動にする** | 数値を**外部ファイル**に出して、**再ビルドなしで**調整 |
| **⑥ プレイして確認** | 数値上は良くても体感が違うことがある |

<strong>調整データはコードに埋め込まず、データ（JSON・CSV など）</strong>にします（[シリアライズ](../engine/serialization/index.md)）。

## よくあるミス

??? failure "引き算型で、防御が攻撃を上回り、ダメージが 0 や負になる"
    下限（最低ダメージ）を設けるか、割り算型にします。

??? failure "乗算の補正を重ねすぎて、後半に爆発する"
    加算の枠にまとめ、乗算を絞ります。

??? failure "指数的な成長で、桁があふれる"
    `int` のオーバーフロー。型を `int64_t` にするか、上限を決めます。

??? failure "「1% を 100 回引けば確実に当たる」と思う"
    当たらない確率は約 37% です。天井で救済します。

??? failure "期待値だけで、強さを比べる"
    ばらつきも体感に大きく影響します。

??? failure "バランスを感覚だけで調整して、後から破綻する"
    式と表で全体を見ます。
