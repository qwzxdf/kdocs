# 浮動小数点と数値の注意

ゲームの計算は、ほとんど `float`（浮動小数点）で行います。しかし、**浮動小数点は実数を近似したもの**で誤差があります。`0.1 + 0.2 == 0.3` が成り立たない、`==` で比べると当たらない、原点から遠くでキャラが震える、といった現象は、どれも浮動小数点の性質から来ます。このページでは、ゲームで困りやすい数値の問題と、その対策をまとめます。

!!! tip "ポイント"
    - `float` は<strong>約 7 桁</strong>の精度。<strong>`double` は約 16 桁</strong>。
    - `==` で小数を比べない。許容誤差（イプシロン）で比べる。
    - 大きな値と小さな値の足し算は、小さい値が消える（桁落ち）。
    - 原点から遠いほど、精度が下がる。ワールドが広いと原点を動かす。
    - NaN・無限大は伝染する。ゼロ除算・負の平方根・`acos` の範囲外に注意。
    - 決定性（毎回同じ結果）が必要なら、固定小数点や環境を固定する。

## 浮動小数点の仕組み

`float`（32 ビット）は、**符号 1 ビット・指数 8 ビット・仮数 23 ビット**で数を表します。科学的記数法（`1.234 × 10⁵`）の 2 進数版です。

| 型 | ビット数 | 有効桁数（10 進） | 表せる範囲 | 使いどころ |
| --- | --- | --- | --- | --- |
| `float` | 32 | 約 7 桁 | 約 ±3.4 × 10³⁸ | ゲームの標準・GPU |
| `double` | 64 | 約 16 桁 | 約 ±1.8 × 10³⁰⁸ | 精度が必要な計算・時刻・大きな座標 |
| `half`（16 ビット） | 16 | 約 3 桁 | 約 ±65504 | GPU の中間値・圧縮 |

### 誤差が出る理由

0.1 は、2 進数で表すと無限に続く小数（0.000110011...）になり、有限のビット数で切る必要があります。そのため、ほんのわずかな誤差を持ちます。

```cpp
float a = 0.1f + 0.2f;
bool same = (a == 0.3f);
```

この `same` は `false` になることがあります。

### 精度は、値の大きさで変わる

浮動小数点の刻み幅は、値が大きいほど粗くなります。

| 値の大きさ | `float` の刻み幅（約） |
| --- | --- |
| 1 付近 | 0.0000001（1.2 × 10⁻⁷） |
| 1,000 付近 | 0.00006 |
| 100,000 付近 | 0.008 |
| 1,000,000 付近 | 0.06 |
| 16,777,216（2²⁴）以上 | 整数でも、1 ずつ数えられない |

原点から 10 km 離れた位置（1 単位 = 1 m）では、`float` の刻みは約 1 mm です。100 km 離れると約 8 mm、1000 km で約 6 cm になります。

float の目盛りは、大きな数ほど粗くなります。誤差の許容値（イプシロン）を値の大きさに合わせる理由はここにあります。

## 比較の方法

### `==` を使わない

```cpp
bool NearlyEqual(float a, float b, float epsilon = 1e-5f) {
  return std::abs(a - b) <= epsilon;
}
```

| 方式 | 説明 |
| --- | --- |
| **絶対誤差** | `|a - b| ≤ ε`。0 付近の比較に向く。値が大きいと厳しすぎる |
| 相対誤差 | `|a - b| ≤ ε × max(|a|, |b|)`。大きな値の比較に向く。0 付近では使えない |
| 組み合わせ | 両方を使う（`abs ≤ ε_abs` または `相対 ≤ ε_rel`） |
| ULP 比較 | 浮動小数点で何個離れているかで比べる（厳密） |

```cpp
bool NearlyEqualRelative(float a, float b, float rel_eps = 1e-5f, float abs_eps = 1e-8f) {
  float diff = std::abs(a - b);
  if (diff <= abs_eps) {
    return true;
  }
  return diff <= rel_eps * std::max(std::abs(a), std::abs(b));
}
```

### 0 との比較

| 目的 | 書き方 |
| --- | --- |
| ほぼ 0 か | `std::abs(x) < 1e-6f` |
| ゼロベクトルか | `LengthSquared() < 1e-12f` |
| 符号の判定 | `x > 0`・`x < 0` は、そのまま使ってよい（誤差による揺れは、境界付近のみ） |

イプシロンの値は、扱う値の大きさで決めます。「長さ 1 の単位」で 1e-5がよく使われる値です。

### 範囲の判定

`x >= 0 && x <= 1` で、境界ぴったりの値が誤差で外れることがあります。わずかな余裕（`-ε`、`1 + ε`）を持たせるか、clamp してから使います。

## 桁落ちと情報落ち

### 情報落ち（大きい値に小さい値を足す）

```cpp
float big = 16777216.0f;
big += 1.0f;
```

`big` は、**16777216 のまま**で、1 が消えます（刻みが 2 になるため）。

| 場面 | 問題 |
| --- | --- |
| 経過時間を `float` の秒で積算 | 長時間（数時間）たつと、1 フレーム分の足し算が、消える（時間が進まなくなる） |
| スコアを `float` で | 大きな値で、1 点が足せなくなる |
| 座標を毎フレーム足す | 原点から遠いと小さな動きが消える（動かないのに見える） |

対策：時間は `double`（または整数のミリ秒・マイクロ秒）で保持し、ゲームの値は `int`（整数）で持ちます。

### 桁落ち（近い値の引き算）

ほぼ同じ値どうしを引くと、有効桁が失われ、誤差が相対的に大きくなります。

| 場面 | 問題 |
| --- | --- |
| 遠い 2 点の差 | 大きな座標どうしを引くと、近い物の相対位置の精度が落ちる |
| 2 次方程式の解の公式 | 条件によって、一方の解の精度が落ちる（別の式に書き換える） |
| `1 - cos(θ)`（小さな θ） | `2 sin²(θ/2)` に書き換える |

### 足し算の順序

`float` の足し算は、順序で結果が変わる（結合法則が成り立たない）。大量の小さな値を足すときは、小さい順に足す、または Kahan 加算（誤差を補正しながら足す）、`double` で足す、といった対策があります。

## 大きなワールドの精度

**原点から遠い位置**でキャラが震える・モデルが歪む・影がずれる問題があります。`float` の刻みが粗くなるためです。

| 対策 | 説明 |
| --- | --- |
| 原点シフト（フローティング オリジン） | プレイヤーが原点から離れたら、世界全体を逆方向へずらして、プレイヤーを原点付近に戻す |
| カメラ相対の座標で描画 | 描画のとき、カメラ位置を引いた座標を GPU へ渡す（引き算を `double` で行う） |
| 座標を `double` で持つ | ワールド上の絶対位置は `double`。GPU 用だけ `float` に変換 |
| セル（区画）＋ ローカル座標 | 位置を区画の番号（整数）と、区画内の座標（`float`）で持つ |
| 物理エンジンの倍精度ビルド | Jolt の `JPH_DOUBLE_PRECISION`（[Jolt](../libs/jolt/index.md)） |

```cpp
struct WorldPosition {
  int64_t cell_x;
  int64_t cell_z;
  Vector3 local;
};
```

## NaN と無限大

| 値 | 発生する場面 |
| --- | --- |
| <strong>`inf`（無限大）</strong> | `1.0f / 0.0f` |
| `NaN`（非数） | `0.0f / 0.0f`・`sqrt(-1)`・`inf - inf`・`acos(1.1)` |

NaN の性質：

| 性質 | 説明 |
| --- | --- |
| 伝染する | NaN を含む計算の結果は、全部 NaN になる |
| 自分自身と等しくない | `nan == nan` は false。`isnan` で調べる |
| 比較はすべて false | `nan < 1`・`nan > 1` も false（`if` の分岐が予想外になる） |
| 1 つの NaN が全体を壊す | キャラの位置が NaN になると、画面から消え、カメラも NaN になる |

```cpp
bool IsValid(float x) {
  return std::isfinite(x);
}
```

### NaN が出やすい箇所

| 箇所 | 対策 |
| --- | --- |
| ゼロベクトルの正規化 | 長さを確認する（[ベクトル公式](vector-recipes.md)） |
| `acos`・`asin` の引数が範囲外 | `std::clamp(x, -1.0f, 1.0f)` |
| `sqrt` に負の値 | `std::max(0.0f, x)` |
| `dt = 0` での割り算 | `dt` が 0 でないか確認 |
| `log(0)`・`pow(0, 負)` | 範囲を確認 |
| 逆補間の `b - a = 0` | 範囲が 0 でないことを確認 |

### デバッグ

| 方法 | 説明 |
| --- | --- |
| `assert(std::isfinite(x))` | 主要な値の更新後に確認する（デバッグビルド） |
| 浮動小数点例外を有効にする | NaN が出たその場で止める（`_controlfp_s` で有効化。Visual Studio で止まる） |
| 発生源を探す | NaN は伝染するので、最初に出た場所を見つける |

## 整数の注意

| 問題 | 説明 |
| --- | --- |
| <strong>オーバーフロー（符号あり）</strong> | `int` の範囲（約 ±21 億）を超えると未定義動作（[未定義動作](../basics/ub.md)） |
| 符号なしの引き算 | `size_t a = 3, b = 5; a - b` は、巨大な値になる |
| 整数の割り算 | `5 / 2 = 2`（切り捨て）。`float` が欲しいなら、キャストする |
| 負の数の `%` | `-7 % 3 = -1`（C++）。正の剰余が欲しいなら、補正する |
| 符号付きと符号なしの比較 | 意図しない変換が起きる。型をそろえる |

```cpp
int PositiveMod(int a, int n) {
  int r = a % n;
  return r < 0 ? r + n : r;
}
```

マップの端でループ（0 の左は最後のセル）させたいときに、`PositiveMod` が必要です。

### 丸め

| 関数 | 動き | -2.5 | 2.5 |
| --- | --- | --- | --- |
| `floor` | 負の無限大方向へ | -3 | 2 |
| `ceil` | 正の無限大方向へ | -2 | 3 |
| `trunc`（`static_cast<int>`） | 0 の方向へ | -2 | 2 |
| `round` | 四捨五入（0 から遠い方へ） | -3 | 3 |
| `nearbyint`・`lrint` | 偶数丸め（銀行丸め） | -2 | 2 |

キャストは `trunc` です。負の数で `floor` が欲しいときは、明示的に `std::floor` を使います。

## 固定小数点と決定性

**同じ入力から、毎回同じ結果**が必要なゲーム（格闘ゲーム・RTS・ロックステップ通信のオンライン対戦）では浮動小数点の違いが問題になります。

| 原因 | 説明 |
| --- | --- |
| CPU・コンパイラの違い | 命令の順序・最適化・FMA で結果がわずかに違う |
| SIMD・x87 の精度 | 中間の精度が違う |
| 三角関数の実装 | ライブラリで末尾の桁が違う |

| 対策 | 説明 |
| --- | --- |
| 固定小数点 | 整数で小数を表す（例：1/65536 単位）。どの環境でも同じ結果 |
| コンパイラの設定を固定 | `/fp:strict`・FMA 無効・同じコンパイラ・同じオプション |
| 整数だけで計算 | ダメージ・位置を整数で |
| 同期用の値は整数 | 状態のハッシュでずれを検出 |

```cpp
using Fixed = int32_t;
constexpr int kFractionBits = 16;

constexpr Fixed ToFixed(float v) { return static_cast<Fixed>(v * (1 << kFractionBits)); }
constexpr float ToFloat(Fixed v) { return static_cast<float>(v) / (1 << kFractionBits); }
constexpr Fixed Mul(Fixed a, Fixed b) { return static_cast<Fixed>((static_cast<int64_t>(a) * b) >> kFractionBits); }
```

| 点 | 説明 |
| --- | --- |
| 乗算は 64 ビットで | 途中でオーバーフローしないように |
| 範囲が狭い | 16.16 形式なら、約 ±32768。範囲を設計する |
| 三角関数などは、テーブル | 事前計算の表を引く（環境に依存しない） |

## 数値の単位

| 点 | 説明 |
| --- | --- |
| **単位を統一** | メートル・秒・ラジアンで（ピクセル・フレーム・度は境界で変換） |
| 大きさの目安 | `float` が得意なのは、0.001〜10000 程度。それを超える単位は避ける（ミリメートル単位で数十 km は、精度が不足） |
| 時間の単位 | 秒（`float` の `dt`）。長期の時刻は `double` や整数 |
