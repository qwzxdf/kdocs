# デザインパターン早見表

**デザインパターン**は、「こういう困りごとには、こういう形で書くとうまくいく」という、先人の経験をまとめた**設計の型**です。覚えるものではなく、**困ったときに「あの型が使えるかも」と思い出す**ためのものです。このカテゴリでは、**ゲームと C++ でよく使うパターン**を選んで、「悪い例 → 何が困るか → 良い例 → いつ使う」の流れで説明しています。まず、この表で「困りごと」から、使えそうなパターンを探してください。

!!! tip "ポイント"
    - パターンは**道具**。使うこと自体が目的ではない。**困りごとが先、パターンはあと**。
    - 迷ったら、**まず一番簡単な書き方**で書く。困ったときにパターンを取り入れる（YAGNI）。
    - C++ では、パターンが**言語や標準ライブラリに入っている**ことも多い（イテレータ、RAII、スマートポインタ、`std::function`）。
    - 1 つのクラスにパターンを何個も詰め込まない。

## パターンの全体像

| 分類 | パターン | 目的 |
| --- | --- | --- |
| **C++ らしい基礎** | [RAII](raii.md)、[PImpl](pimpl.md)、[CRTP・ポリシー](crtp-policy.md) | リソース管理、ビルドの独立、速さ |
| **通知・状態** | [オブザーバー（イベント）](event.md)、[ステートマシン](state-machine.md)、[コマンド](command.md) | 疎結合なやり取り、状態の管理、操作の記録 |
| **構造・データ** | [ECS](ecs.md)、[データ指向](data-oriented.md)、[オブジェクトプール](object-pool.md) | 大量のデータを速く |
| **振る舞いの差し替え・追加** | [ストラテジー](strategy.md)、[デコレータ](decorator.md)、[ビジター](visitor.md)、[イテレータ](iterator-pattern.md) | 機能の組み合わせ、処理の追加 |
| **作り方・つなぎ方** | [ファクトリ](factory.md)、[依存性の注入](dependency-injection.md)、[シングルトン](singleton.md) | オブジェクトの生成と依存の管理 |


## 使うときの考え方

1. **まず、パターンなしで書く**。困りごと（`if` が増えた、コピペが増えた、テストできない）が出てから、パターンを探す
2. **パターンの名前を、チームで共有する**。「ここはステートマシンにしよう」と言えると設計の話が速い
3. **パターンの形をそのまま真似しなくてよい**。ゲームに合わせて、小さく簡単にする
4. <strong>「あとで変わりそう」を理由に先にパターンを入れない</strong>（YAGNI）。変わったときに直す
