# 文字コードの基礎

コンピューターは、数字（バイト）しか扱えません。文字を扱うには、「この文字は、この数字」という**対応表**が必要です。その対応表と、数字をバイトの並びにする規則を合わせて、**文字コード**と呼びます。昔は国ごと・メーカーごとに別々の文字コードがあり（日本ではシフト JIS、EUC-JP など）、それが文字化けの元でした。今は、世界中の文字を 1 つの表で扱う **Unicode**（ユニコード）と、そのバイト表現の **UTF-8** が、事実上の標準です。このページは、C++ でゲームを作るときに必要な、文字コードの基礎をまとめます。

!!! tip "ポイント"
    - <strong>Unicode ＝ 世界中の文字に、番号（コードポイント）を付けた表。</strong>「あ」は <strong>U+3042</strong>。
    - <strong>UTF-8 / UTF-16 / UTF-32 ＝ Unicode の番号を、バイトの並びにする 3 つの方法。</strong>
    - <strong>UTF-8 が標準。</strong>ASCII と互換で、ファイル・通信・Web・ゲームのデータは、ほぼ UTF-8。
    - Windows の内部と API は<strong>UTF-16</strong>。日本語 Windows の古い「ANSI」は<strong>Shift_JIS 系（CP932）</strong>。
    - <strong>1 文字 ＝ 1 バイトではない。</strong>UTF-8 の日本語は 3 バイト。文字数・切り出し・幅に注意。

## Unicode とコードポイント

**Unicode** は、世界中の文字（日本語、絵文字、記号…）に、<strong>一意な番号（コードポイント）</strong>を付けた表です。「U+」に 16 進数で書きます。

| 文字 | コードポイント | 種類 |
| --- | --- | --- |
| `A` | U+0041 | ASCII（半角英字） |
| `あ` | U+3042 | ひらがな |
| `漢` | U+6F22 | 漢字 |
| `ｱ` | U+FF71 | 半角カタカナ |
| `😀` | U+1F600 | 絵文字（BMP の外） |

Unicode は「文字と番号の対応」だけを決めます。**番号を、どうバイトで保存するか**は、別の規則（UTF-8、UTF-16 など）です。

## UTF-8、UTF-16、UTF-32

| 方式 | 1 文字のバイト数 | 特徴 | 使われる場所 |
| --- | --- | --- | --- |
| **UTF-8** | 1〜4 バイト（可変） | **ASCII と同じ**。英語は 1 バイトで小さい。日本語は 3 バイト | ファイル、Web、JSON、Linux、ゲームのデータ。**標準** |
| **UTF-16** | 2 または 4 バイト（可変） | 日本語は 2 バイト。絵文字などは 4 バイト（サロゲート ペア） | **Windows の内部と API**、Java、C#、Qt |
| **UTF-32** | 4 バイト（固定） | 1 文字がいつも 4 バイト。大きい | 内部処理の一部（`char32_t`）。保存には使わない |

### 例：「あ」と「😀」

| 文字 | コードポイント | UTF-8（バイト） | UTF-16（16 ビット） | Shift_JIS |
| --- | --- | --- | --- | --- |
| `A` | U+0041 | `41`（1） | `0041` | `41` |
| `あ` | U+3042 | `E3 81 82`（3） | `3042` | `82 A0` |
| `漢` | U+6F22 | `E6 BC A2`（3） | `6F22` | `8A BF` |
| `😀` | U+1F600 | `F0 9F 98 80`（4） | `D83D DE00`（2 つ） | 表せない |

### UTF-8 のしくみ

UTF-8 は、**最初のバイトを見ると、何バイトで 1 文字か**が分かります。

| コードポイントの範囲 | バイト数 | 最初のバイト |
| --- | --- | --- |
| U+0000 〜 U+007F（ASCII） | 1 | `0xxxxxxx`（`00`〜`7F`） |
| U+0080 〜 U+07FF | 2 | `110xxxxx` |
| U+0800 〜 U+FFFF（日本語の大部分） | 3 | `1110xxxx` |
| U+10000 〜 U+10FFFF（絵文字など） | 4 | `11110xxx` |

2 バイト目以降は、必ず `10xxxxxx`（`80`〜`BF`）です。この性質のおかげで、**文字の途中から読み始めても、先頭を見つけられます**。

<div class="anim" data-label="UTF-8：「あA」のバイト（日本語は 3 バイト、英字は 1 バイト）">
E3 81 82 41 # 「あ」は 3 バイト、「A」は 1 バイト（合計 4 バイト・2 文字）
*E3 *81 *82 41 # 最初のバイト E3（1110xxxx）で「3 バイトで 1 文字」と分かる
E3 81 82 *41 # 次は 41（0xxxxxxx）。ASCII の「A」は 1 バイト
</div>

### UTF-16 とサロゲート ペア

UTF-16 は、**U+FFFF までは 16 ビット 1 つ**で表します。それより大きいコードポイント（絵文字、一部の漢字）は、<strong>2 つの 16 ビット（サロゲート ペア）</strong>で表します。

- 「😀」（U+1F600）は、`D83D DE00` の 2 つ
- そのため、`std::wstring`（Windows では UTF-16）の `size()` は、**絵文字 1 つで 2** になる

## Shift_JIS と CP932（日本語 Windows の「ANSI」）

**Shift_JIS** は、日本の古い文字コードです。<strong>日本語版の Windows の「ANSI」（`A` が付く Windows API が使う文字コード）は、Shift_JIS の拡張版 CP932（Windows-31J）</strong>です。

| 項目 | 内容 |
| --- | --- |
| 1 文字のバイト数 | 半角 1 バイト、全角 2 バイト |
| 表せる文字 | 日本語と英数字。**絵文字や、多くの外国語は表せない** |
| CP932 と Shift_JIS の違い | CP932 は、丸数字（①）、㈱、ローマ数字（Ⅰ）などの拡張を含む |
| 注意：チルダ | 「〜」（U+301C）と「～」（U+FF5E）の変換が、ライブラリによって食い違う |

### 「ダメ文字」の落とし穴

Shift_JIS は、**2 バイト目に `5C`（バックスラッシュ `\` と同じ値）が使われる文字**があります。C++ のソースを Shift_JIS で保存すると、**文字列の中の `\` と誤解されて、おかしくなる**ことがあります。

| 文字 | Shift_JIS のバイト |
| --- | --- |
| ソ | `83 5C` |
| 表 | `95 5C` |
| 能 | `94 5C` |
| 十 | `8F 5C` |

昔のコンパイラでは、`"ソース"` や `"表示"` で、2 バイト目の `5C` が `\` と解釈され、コンパイル エラーや、文字が消える原因になりました（「ダメ文字」と呼ばれます）。**UTF-8 を使えば、この問題は起きません**。

## 文字コードの名前の整理

| 名前 | 何のこと |
| --- | --- |
| **ASCII** | 英数字と記号の 128 文字（7 ビット）。UTF-8 の最初の部分と同じ |
| **Unicode** | 文字と番号の対応表 |
| **UTF-8 / UTF-16 / UTF-32** | Unicode の番号を、バイトにする方式 |
| <strong>Shift_JIS（SJIS）</strong> | 日本の古い文字コード |
| **CP932 / Windows-31J** | Windows の Shift_JIS。日本語版 Windows の ANSI |
| **EUC-JP** | Unix 系の古い日本語コード |
| <strong>ISO-2022-JP（JIS）</strong> | メールで使われた日本語コード |
| <strong>ANSI（Windows の用語）</strong> | **その PC の既定のコード ページ**。日本語版は CP932。**ANSI 規格とは無関係** |
| <strong>ワイド文字（wide）</strong> | `wchar_t`。Windows では UTF-16 |
| **マルチバイト文字** | 1 文字が複数バイトの文字コード（Shift_JIS、UTF-8 など）の総称 |

## BOM（バイト オーダー マーク）

**BOM** は、ファイルの先頭に付ける**目印のバイト**で、「このファイルは、この文字コードです」と示します。

| 文字コード | BOM のバイト |
| --- | --- |
| UTF-8 | `EF BB BF` |
| UTF-16 リトル エンディアン | `FF FE` |
| UTF-16 ビッグ エンディアン | `FE FF` |

| 項目 | 内容 |
| --- | --- |
| UTF-8 の BOM | **付けても付けなくてもよい**が、**付けないのが推奨**。付けると、`#!`（シェバン）や、JSON パーサー、一部のツールが、BOM を文字として読んで壊れる |
| Visual Studio / MSVC | **BOM があれば UTF-8 と自動で認識**する。**BOM がない UTF-8 は、`/utf-8` を付けないと ANSI として読む** |
| UTF-16 | BOM で、バイト順を判断する |

**方針:** ゲームのデータや新しいソースは、<strong>UTF-8（BOM なし）+ `/utf-8`</strong>。例外は、リソース ファイル（`.rc`）や古いツールが、BOM を要求する場合です。

## 改行コード

| 名前 | バイト | 使う OS |
| --- | --- | --- |
| **LF** | `0A` | Linux、Mac、Git の標準 |
| **CRLF** | `0D 0A` | Windows（メモ帳、古いツール） |
| CR | `0D` | 古い Mac |

- 改行コードが混ざると、**差分が全行に出る**、シェル スクリプトが動かない、などの問題が起きます
- **Git で LF に統一**し（`.gitattributes`、[ソースファイルの設定](source-files.md)）、Windows 専用のファイルだけ CRLF にします
- C++ の文字列リテラルの `"\n"` は、**テキスト モードで書き出すとき**、Windows では CRLF に変換されます（[ファイルの入出力](console-file-io.md)）

## 文字数、バイト数、見た目の幅

「文字数」は、数え方で、答えが変わります。

| 数え方 | 「あ」 | 「😀」 | 「か + ゛（結合）」（が） |
| --- | --- | --- | --- |
| **UTF-8 のバイト数** | 3 | 4 | 6 |
| **UTF-16 の 16 ビット単位** | 1 | 2 | 2 |
| **コードポイント数** | 1 | 1 | 2 |
| **見た目の 1 文字**（書記素クラスタ） | 1 | 1 | 1 |

- `std::string::size()` は、**UTF-8 のバイト数**です。日本語 3 文字なら 9
- **コードポイント数**は、「2 バイト目以降（`10xxxxxx`）でないバイト」を数えると求められます
- **見た目の 1 文字**（書記素クラスタ）は、結合文字・絵文字の組み合わせがあり、**ICU などのライブラリ**が必要です
- 画面での**幅**は、全角が 2 桁、半角が 1 桁です。`std::format` の幅指定（`{:>10}`）は、C++23 で、**全角文字を 2 桁として**数えるようになりました（対応するコンパイラで）

```cpp
// UTF-8 の文字列の、コードポイント数を数える（先頭バイトだけを数える）
std::size_t CountCodePoints(std::string_view utf8) {
  std::size_t count = 0;
  for (char c : utf8) {
    if ((static_cast<unsigned char>(c) & 0xC0) != 0x80) {   // 2 バイト目以降ではない
      ++count;
    }
  }
  return count;
}
```

### 文字列を切り取るときの注意

UTF-8 の文字列を、**バイト数で切る**と、**文字の途中で切れて**、壊れた文字列になります。

```cpp
std::string name = "勇者アリス";           // UTF-8：各文字 3 バイト
std::string cut = name.substr(0, 4);       // 4 バイトで切る → 「勇」の後ろに、「者」の 1 バイト目だけ残る（壊れる）
```

切るときは、<strong>文字の境界（先頭バイト）</strong>で切ります。表示用に省略するなら、ICU などを使うか、境界を探す関数（`while ((s[i] & 0xC0) == 0x80) --i;`）で、後ろに戻ります。

## 正規化（NFC と NFD）

同じ見た目の文字でも、**複数のコードポイントの並び方**があります。

| 形式 | 「が」の表し方 |
| --- | --- |
| **NFC**（合成済み） | U+304C（1 つ） |
| **NFD**（分解） | U+304B（か） + U+3099（゛）（2 つ） |

Mac のファイル名は NFD で保存されることがあり、**文字列の比較が、見た目は同じなのに一致しない**ことがあります。外部から文字列を受け取って比較するときは、**NFC に正規化**します（ICU、`utf8proc` など）。ゲームの内部データは、NFC に統一しておくと安全です。

## よくあるミス

??? failure "「文字数」を `size()` で数える"
    `std::string::size()` はバイト数です。日本語では、文字数の 3 倍になります。UI の「最大 10 文字」は、コードポイント数（または書記素クラスタ数）で数えます。

??? failure "UTF-8 の文字列を、バイト数で切り取る"
    文字の途中で切れて、壊れた文字列（文字化け、`�`）になります。文字の境界で切ります。

??? failure "「Shift_JIS だから ANSI」と、決めつける"
    ANSI は、その PC の設定（日本語版 Windows では CP932）です。ほかの国の PC では、別の文字コードになります。データに使ってはいけません。

??? failure "BOM 付き UTF-8 を、データに使う"
    パーサーが、BOM を文字として読んで、エラーになります。データは BOM なしにします。

??? failure "絵文字や、珍しい漢字が、2 文字ぶんになる"
    UTF-16 では、サロゲート ペアの 2 つで 1 文字です。`wstring` の `size()` や添字では、**文字の途中で切る**危険があります。
