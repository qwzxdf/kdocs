# 場面別の直し方

ここまでのページで説明した手法を、**症状から引ける**ようにまとめます。どの手法がどんな場面で効くのかを、一覧で確認するためのページです。

!!! tip "ポイント"
    - 症状から、**ボトルネックの種類**を決め、対応する手法を選ぶ。
    - 手法の詳細は、各ページを見る。

## ゲームでの使いどころ

| 場面 | 直し方 |
| --- | --- |
| 草・木・弾を大量に描く | インスタンシング |
| 2D のスプライトが多い | アトラス + スプライト バッチ |
| 動かない街・地形 | 静的バッチ + 視錐台カリング + LOD |
| 画面いっぱいのエフェクトで、重くなる | 半透明の範囲を減らす。解像度を下げる |
| UI が重い | UI をまとめて 1 つのバッチに。変更がなければ、描画結果を使い回す（キャッシュ） |
| モバイル・低スペック | テクスチャの圧縮、解像度の調整、シェーダーの簡略化 |

## 症状から探す

最適化で最初にやるべきことは、手法を選ぶことではなく、**ボトルネックの種類を特定すること**です。CPU が遅いのか、GPU のピクセル処理か、メモリ帯域か、で効く手法がまったく違います。見分けるための簡単な実験が「解像度を下げてみる」ことで、速くなるなら GPU のピクセル側、変わらないなら CPU 側か頂点側が原因です。

以下の表は、実験の結果と症状から、効く手法とそのページを引けるようにしたものです。

| 症状 | ボトルネック | 効く手法 | ページ |
| --- | --- | --- | --- |
| **解像度を下げても速くならない** | CPU | バッチ・インスタンシング・GPU Driven | [ドロー コール](draw-calls.md)・[GPU Driven](gpu-driven.md) |
| **解像度を下げると速くなる** | GPU（ピクセル） | 低解像度・TAA・シェーダーの軽量化 | [低解像度](low-res-effects.md)・[TAA](taa-upscaling.md)・[シェーダー](shader-cost.md) |
| **ライトを増やすと極端に重い** | GPU（ライティング） | Deferred・Tiled・Clustered | [Forward と Deferred](forward-deferred.md)・[Tiled と Clustered](light-culling.md) |
| **G-Buffer の書き込みが重い** | 帯域幅 | フォーマット・Visibility Buffer | [帯域幅](bandwidth.md)・[Visibility Buffer](visibility-buffer.md) |
| **三角形が非常に多い** | GPU（頂点） | LOD・カリング・Meshlet | [LOD](lod.md)・[Mesh Shader](mesh-shaders.md) |
| **半透明で重くなる** | GPU（ピクセル・帯域） | 縮小バッファ・枚数削減 | [パーティクル](particles.md) |
| **影を付けると重い** | CPU・GPU（頂点） | カスケード・影用カリング・キャッシュ | [影](shadows.md) |
| **VRAM が足りない** | VRAM | 圧縮・ストリーミング | [テクスチャ](texture-streaming.md) |
| **ポストプロセスが重い** | 帯域幅 | パスをまとめる・縮小 | [ポストプロセス](postprocess.md) |
| **フレーム時間が不安定** | 全体 | 動的解像度・予算の設計 | [TAA・アップスケーラ](taa-upscaling.md)・[フレーム時間](../optimize/frame-budget.md) |

## 全体のよくあるミス

??? failure "ボトルネックを調べずに、シェーダーを直す"
    CPU 側が遅いのにシェーダーを最適化しても、速くなりません。まず、CPU と GPU のどちらが遅いかを、解像度の変更やプロファイラーで確かめます。

??? failure "全オブジェクトを、毎フレーム 1 つずつカリング判定する"
    オブジェクトが数万になると、判定自体で CPU が重くなります。空間分割で階層的に判定します。

??? failure "ドロー コールの数だけを見る"
    ドロー コールが少なくても、1 回が非常に重ければ遅いです。GPU 側のプロファイラーで、実際の時間を見ます。

??? failure "テクスチャが大きすぎる"
    必要以上に大きく、圧縮もしていないとメモリ帯域とメモリ使用量の両方で、不利です。

??? failure "最適化のつもりで、見た目が壊れる"
    カリングを強くしすぎて、画面の端でオブジェクトが消える、LOD の切り替えが目立つ、などです。見た目も必ず確認します。
