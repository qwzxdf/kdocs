# オーバードロー

**オーバードロー**は、**同じピクセルに何度も色を計算して、書くこと**です。**手前の物体で隠れてしまう、奥の物体のピクセルシェーダーは、結果が捨てられる**ので**まるごと無駄**です。**ピクセル処理・帯域幅がボトルネック**のときに**効きます**。このページは**オーバードローの何が無駄なのか**、**Early-Z・Z プリパス・並べ替え**、<strong>小さな三角形の無駄（quad overdraw）</strong> を、説明します。

!!! tip "ポイント"
    - <strong>オーバードロー</strong> ＝ <strong>1 ピクセルに、複数回、ピクセルシェーダーを動かす</strong>。<strong>最後に見える、1 回以外は無駄</strong>。
    - <strong>Early-Z</strong>：<strong>ピクセルシェーダーの前に、深度テスト</strong>。<strong>隠れていれば、シェーダーを動かさない</strong>（<strong>ハードウェアの自動の最適化</strong>）。
    - <strong>Early-Z が、効く条件</strong>：<strong>手前から奥の順に描く</strong>。<strong>`discard`・深度の書き換えがない</strong>。
    - <strong>Z プリパス</strong>：<strong>先に深度だけを描き</strong>、<strong>次に色のパスで隠れた所をシェーダーに通さない</strong>。<strong>オーバードローがほぼ、1 になる</strong>。
    - <strong>半透明</strong>は<strong>オーバードローが避けられない</strong>。<strong>パーティクルは、特に重い</strong>。
    - <strong>小さな三角形</strong>は、<strong>2×2 ピクセル単位の実行</strong>のため、<strong>無駄が大きい</strong>（<strong>quad overdraw</strong>）。

**オーバードロー率**（1 ピクセルあたりの平均実行回数）が、**2〜3 倍**なら、**ピクセル処理が、2〜3 倍の無駄**です。**可視化ツール**（PIX・RenderDoc・エンジンのオーバードロー表示）で、**確認**できます。

## Early-Z

**GPU は通常、ピクセルシェーダーの「前」に、深度テスト**を行います。**すでに手前のものが描かれていれば、シェーダーを動かさずに捨てます**。

| 点 | 説明 |
| --- | --- |
| **自動** | **特別なコードは、不要** |
| **描く順番に依存** | **奥から描くと効かない**（まだ、深度が書かれていないため） |
| **効かなくなる条件** | **シェーダー内の `discard`（クリップ）・`SV_Depth` の書き込み・UAV への書き込み**（**Early-Z を無効化**することがある） |

**不透明物を手前から奥へおおまかにソート**すると、**Early-Z がよく効きます**（**ドロー コールのソートとの兼ね合い**。[ドロー コール](draw-calls.md)）。

## Z プリパス（深度プリパス）

<strong>まず、全不透明物を、「深度だけ」</strong>描き（**ピクセルシェーダーなし**、**非常に軽い**）、<strong>次に色のパスで深度テストを「等しい（`EQUAL`）」</strong>にして、**描きます**。

| 段階 | 内容 |
| --- | --- |
| **① 深度パス** | **頂点シェーダーのみ**。**深度バッファを完成させる** |
| **② 色のパス** | **深度が完成済み**なので**見える面だけ**、**ピクセルシェーダーが動く**（**オーバードロー ≒ 1**） |

| 利点 | 欠点 |
| --- | --- |
| **ピクセルシェーダーが重いとき、大きく減る** | **ジオメトリを、2 回、処理する**（頂点・ドロー コールが増える） |
| **Forward+ でほぼ、必須**（深度がライト カリングに必要） | **頂点処理が重いとき、逆効果** |
| **Deferred の、G-Buffer 書き込みも、減る** | |

**Tiled / Clustered**（[ライトのカリング](light-culling.md)）は、**深度を先に使う**ので、**Z プリパスと自然に組み合わさります**。

## 半透明のオーバードロー

**半透明**（煙・炎・ガラス・パーティクル）は、**奥の物を見せる**必要があり、**Early-Z で捨てられません**。**重なった数だけ、計算**されます。

| 問題 | 対策 |
| --- | --- |
| **大きな、パーティクルが画面を覆う** | **縮小バッファに描く**（[縮小バッファの効果](low-res-effects.md)） |
| **枚数が多い** | **枚数を減らす・小さくする** |
| <strong>透明部分が多い（四角の板に小さな煙）</strong> | **ポリゴンを形に沿って、切り詰める**（トリミングしたメッシュ） |
| **シェーダーが重い** | **軽いシェーダー**を使う（**パーティクルは、安く**） |

**半透明のオーバードローを色で可視化**（**重なるほど、明るく**）すると**重い場所**が**一目で分かります**。

## 小さな三角形の無駄（Quad Overdraw）

**GPU はピクセルを、2×2 の、4 ピクセル（クアッド）単位で実行**します（**微分＝ミップ選択のため**）。**三角形が小さい**と、**4 ピクセルのうち、実際に三角形に入るのは、1〜2 個**で**残りは捨てられる、無駄な計算**です。

| 三角形の大きさ | 無駄 |
| --- | --- |
| <strong>大きい（数十ピクセル）</strong> | **ほぼ、なし** |
| **1〜数ピクセル** | **最大 4 倍の無駄**（**1 ピクセルの三角形でも、4 ピクセル分、実行**） |

| 対策 | 説明 |
| --- | --- |
| **LOD** | **遠い物は三角形を減らす**（[カリング](culling.md)） |
| **Visibility Buffer** | **ID パスのシェーダーを、軽く**（[Visibility Buffer](visibility-buffer.md)） |
| **ソフトウェア ラスタライズ** | **コンピュートで小さな三角形を直接、描く**（**Nanite**） |
| **メッシュの設計** | **細長い三角形を避ける**（**クアッドを無駄にしやすい**） |

## タイル型 GPU（モバイル）

**モバイルのタイル型 GPU**は、**タイル内で隠面除去**（**HSR・TBDR**）を行う機種があり、**オーバードローのコストが小さい**です。**ただし、半透明は同じく重い**（[メモリ帯域幅](bandwidth.md)）。

## よくあるミス

??? failure "奥から手前へ、不透明物を描いている"
    **Early-Z が効きません**。**手前から**（おおまかに）描きます。

??? failure "全ての物に、`discard` を使って、Early-Z が無効になる"
    **アルファ テストの物だけ、別に**、**最後に**描きます。

??? failure "頂点が、ボトルネックなのに、Z プリパスを入れる"
    **頂点処理が、2 倍**になり、**逆効果**です。**測って**から。

??? failure "半透明の、パーティクルが画面全体を覆って、重い"
    **縮小バッファ**に描き、**枚数を減らします**。

??? failure "オーバードローを、見ずにシェーダーだけ、最適化する"
    **オーバードロー表示**で**重い場所**を確認します。
