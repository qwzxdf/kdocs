# LOD とインポスター

遠くにある物体は、画面では数ピクセルにしか見えません。それなのに数万個の三角形を持つモデルを描くと、頂点処理も小さな三角形の無駄（[オーバードロー](overdraw.md)）も、見た目に見合わないコストになります。<strong>LOD（Level of Detail）</strong> は、距離に応じて詳細度を下げることで、この無駄を減らします。このページでは、LOD の種類・切り替え方・インポスターを説明します。

!!! tip "ポイント"
    - 目的は<strong>遠くの物体の頂点・ピクセル処理を減らす</strong>こと。
    - 種類は<strong>離散 LOD・インポスター・連続 LOD</strong>。
    - 切り替えは距離ではなく、画面での大きさで決めると安定する。
    - 切り替えのポップは、ディザやヒステリシスで目立たなくする。
    - 三角形が 1 ピクセルより小さくなると、クアッド単位の無駄が大きい。LOD はここにも効く。
    - LOD はメモリを増やす（複数のメッシュを持つ）。

## なぜ LOD が必要か

| 状況 | 起きること |
| --- | --- |
| **遠くのキャラが 3 万三角形** | 画面では 20 ピクセル程度。三角形が 1 ピクセル以下になる |
| 小さな三角形 | GPU は 2×2 単位で動くので、半分以上のピクセル計算が捨てられる |
| 頂点処理 | 見えない細部の頂点まで、全部変換される |
| スキニング | 遠くでもボーン全部を計算している |

## 離散 LOD

**あらかじめ詳細度の違うメッシュを複数作り**、距離で切り替えます。

| レベル | 三角形数の目安 | 使う距離 |
| --- | --- | --- |
| LOD0 | 元のモデル | 近く |
| LOD1 | 約 50% | 中距離 |
| LOD2 | 約 25% | 遠く |
| LOD3 | 約 10%、またはインポスター | 遠く |

| 点 | 説明 |
| --- | --- |
| 作り方 | DCC ツールの手動作成、または自動生成（meshoptimizer の簡略化など） |
| メモリ | 全 LOD を持つので増える（ただし LOD1 以降は小さい） |
| ボーンの削減 | 遠いキャラはボーン数・影響数（4 → 1〜2）も減らす |
| 材質の簡略化 | 遠くは法線マップなどを使わない軽いシェーダーに替える |

### 切り替えの基準

距離で切り替えるとモデルの大きさや FOV の違いで見た目が変わります。画面での大きさ（境界球の半径 ÷ 距離）で判断すると一貫した結果になります。

```cpp
float ScreenCoverage(float bounding_radius, float distance, float fov_y) {
  return bounding_radius / (distance * std::tan(fov_y * 0.5f));
}
```

## 切り替えのポップを隠す

LOD が切り替わる瞬間に形が急に変わって目立つことがあります（**ポップ**）。

| 対策 | 説明 |
| --- | --- |
| ヒステリシス | 切り替えの距離に幅を持たせる。近づく時と離れる時で境目を変える |
| ディザ フェード | 点の模様で新旧のメッシュを数フレームかけて混ぜる |
| クロス フェード | 両方を描いて、アルファで混ぜる（コストが高い） |
| ジオモーフィング | 頂点を補間して、徐々に形を変える |

## インポスター

遠い物体は、<strong>1 枚の画像（板）</strong>で代用できます。

| 種類 | 説明 |
| --- | --- |
| ビルボード | 常にカメラを向く 1 枚の板。木・草・遠景の建物 |
| 多方向インポスター | 複数の角度から撮った画像を見る方向で切り替える（または混ぜる） |
| オクタヘドラル インポスター | 全方向をタイルに焼き、方向に応じて 2〜3 枚を補間。形の自然さが高い |

| 利点 | 欠点 |
| --- | --- |
| 三角形が数個で済む | 近づくと粗さが目立つ |
| ピクセルシェーダーも軽い | 画像のメモリが必要 |
| 大量の木に向く | ライティングが焼き込みになりやすい（法線も焼いて補う） |

画像はビルド時に自動生成します（[ベイク](../optimize/baking.md)）。

## 連続 LOD

離散 LOD は切り替えが不連続ですが、**詳細度を滑らかに変える**方式もあります。

| 方式 | 説明 |
| --- | --- |
| テッセレーション / ディスプレイスメント | 近くだけ三角形を細かく分割する（地形・水面） |
| クラスター階層（Nanite 風） | Meshlet の木構造から、画面での大きさに合った詳細度の塊だけを選ぶ（[Mesh Shader](mesh-shaders.md)） |
| 地形の LOD | 距離でタイルの分割を粗くする（クリップマップ・四分木） |

## 他の最適化との関係

| 関係 | 説明 |
| --- | --- |
| **カリング** | 見えない物は描かない。LOD は見える物の質を下げる（[カリング](culling.md)） |
| 影 | 影用にさらに低い LOD を使う（[影のコスト](shadows.md)） |
| オーバードロー | 小さな三角形の無駄を減らす（[オーバードロー](overdraw.md)） |
| メモリ | LOD ごとにメッシュを持つ。ストリーミングで必要なものだけ読み込む |

## LOD を実装する

### どの LOD を使うか：画面上の大きさで決める

距離だけで決めると、大きな物と小さな物で、見え方がそろいません。<strong>画面上で、その物が何ピクセルに見えるか</strong>で決めます。

```cpp
// 物体の、画面上の直径（ピクセル）を求める。
float ProjectedSize(float bounding_radius, float distance, float screen_height_px, float fov_y) {
  const float world_per_screen = 2.0f * distance * std::tan(fov_y * 0.5f);   // 距離 distance で、画面の縦が覆う長さ
  return (bounding_radius * 2.0f) / world_per_screen * screen_height_px;
}

// しきい値（ピクセル）。画面で大きいほど、細かい LOD。
constexpr float kThresholds[3] = {200.0f, 80.0f, 30.0f};   // LOD0: 200px 以上、LOD1: 80px 以上、LOD2: 30px 以上、それ未満は LOD3

// ヒステリシスつき: 境目で、LOD が、行ったり来たりしない（ちらつかない）ように、少しだけ、余裕を持たせる。
int SelectLod(float projected_px, int current_lod) {
  for (int lod = 0; lod < 3; ++lod) {
    // 現在の LOD から、粗い側へ移るときは、しきい値より少し下で、細かい側へ戻るときは、少し上で。
    const float margin = (lod < current_lod) ? 1.1f : 0.9f;
    if (projected_px >= kThresholds[lod] * margin) return lod;
  }
  return 3;
}
```

しきい値の、前後に 10% の余裕（ヒステリシス）を持たせると、カメラが境目で、止まっても、LOD が、切り替わり続けません。

### 切り替えをディザで、なじませる

LOD が、突然、切り替わると、形がポンと変わります（ポップ）。2 つの LOD を同時に、ディザで、入れ替えながら描くと、目立たなくなります。

```hlsl
// 4×4 のベイヤー行列（0〜1）。ピクセルごとに、違うしきい値を作る。
float Bayer4(uint2 p) {
  static const float m[16] = {0, 8, 2, 10, 12, 4, 14, 6, 3, 11, 1, 9, 15, 7, 13, 5};
  return (m[(p.x & 3) + 4 * (p.y & 3)] + 0.5) / 16.0;
}

// fade: この LOD の、濃さ（0〜1）。切り替え中、LOD A は 1→0、LOD B は 0→1 と変える。
void PSMain(float4 pos : SV_Position /* ... */) {
  clip(g_fade - Bayer4(uint2(pos.xy)));            // しきい値より、fade が小さいピクセルを捨てる
  // 通常のシェーディング
}
```

切り替え中は、LOD A（`fade` が 1 から 0 へ）と LOD B（0 から 1 へ）の両方を描き、ピクセルごとに、一方だけが、残ります。TAA と組み合わせると、ディザが平均されて、なめらかなフェードに見えます（[TAA・アップスケーラ・VRS](taa-upscaling.md)）。

### LOD の作り方：メッシュの簡略化

LOD は、手作業で作るのは、大変なので、自動で、三角形を減らすライブラリを使います。meshoptimizer が、広く使われています。

```cpp
#include <meshoptimizer.h>

// 元のメッシュから、三角形を約 25% に減らした LOD を作る。
size_t target_index_count = (indices.size() / 3) / 4 * 3;          // 三角形の数を 1/4 に
float target_error = 0.01f;                                         // 許す誤差（メッシュの大きさに対する割合）
std::vector<uint32_t> lod_indices(indices.size());
size_t lod_index_count = meshopt_simplify(
    lod_indices.data(), indices.data(), indices.size(),
    &vertices[0].position.x, vertices.size(), sizeof(Vertex),
    target_index_count, target_error, 0, nullptr);
lod_indices.resize(lod_index_count);                                // 実際に、得られた個数
```

LOD ごとに、三角形をおよそ半分から 1/4 に減らして、3〜4 段作るのが一般的です。ビルド時に作って、ファイルに保存します（[ベイク](../optimize/baking.md)）。

## よくあるミス

??? failure "距離だけで切り替えて、見た目が不安定になる"
    FOV やモデルの大きさで変わります。画面での大きさで判断します。

??? failure "LOD の切り替えがポップして目立つ"
    ディザ フェードとヒステリシスを入れます。

??? failure "LOD0 だけ作って、遠くも高密度のまま描く"
    遠景の頂点・クアッドの無駄が大きくなります。

??? failure "遠くでもボーン数・材質を減らさない"
    メッシュだけでなく、スキニングとシェーダーも軽くします。
