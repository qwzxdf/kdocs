# LOD とインポスター

遠くにある物体は、画面では数ピクセルにしか見えません。それなのに数万個の三角形を持つモデルを描くと、頂点処理も小さな三角形の無駄（[オーバードロー](overdraw.md)）も、見た目に見合わないコストになります。<strong>LOD（Level of Detail）</strong> は、**距離に応じて詳細度を下げる**ことで、この無駄を減らします。このページでは、LOD の種類・切り替え方・インポスターを説明します。

!!! tip "ポイント"
    - 目的は<strong>遠くの物体の頂点・ピクセル処理を減らす</strong>こと。
    - 種類は<strong>離散 LOD・インポスター・連続 LOD</strong>。
    - 切り替えは<strong>距離ではなく、画面での大きさ</strong>で決めると安定する。
    - 切り替えの<strong>ポップ</strong>は、ディザやヒステリシスで目立たなくする。
    - 三角形が 1 ピクセルより小さくなると、<strong>クアッド単位の無駄</strong>が大きい。LOD はここにも効く。
    - LOD は<strong>メモリを増やす</strong>（複数のメッシュを持つ）。

## なぜ LOD が必要か

| 状況 | 起きること |
| --- | --- |
| **遠くのキャラが 3 万三角形** | 画面では 20 ピクセル程度。三角形が 1 ピクセル以下になる |
| **小さな三角形** | GPU は 2×2 単位で動くので、半分以上のピクセル計算が捨てられる |
| **頂点処理** | 見えない細部の頂点まで、全部変換される |
| **スキニング** | 遠くでもボーン全部を計算している |

## 離散 LOD

**あらかじめ詳細度の違うメッシュを複数作り**、距離で切り替えます。

| レベル | 三角形数の目安 | 使う距離 |
| --- | --- | --- |
| **LOD0** | 元のモデル | 近く |
| **LOD1** | 約 50% | 中距離 |
| **LOD2** | 約 25% | 遠く |
| **LOD3** | 約 10%、またはインポスター | 非常に遠く |

| 点 | 説明 |
| --- | --- |
| **作り方** | DCC ツールの手動作成、または自動生成（meshoptimizer の簡略化など） |
| **メモリ** | 全 LOD を持つので増える（ただし LOD1 以降は小さい） |
| **ボーンの削減** | 遠いキャラはボーン数・影響数（4 → 1〜2）も減らす |
| **材質の簡略化** | 遠くは法線マップなどを使わない軽いシェーダーに替える |

### 切り替えの基準

距離で切り替えるとモデルの大きさや FOV の違いで見た目が変わります。**画面での大きさ**（境界球の半径 ÷ 距離）で判断すると一貫した結果になります。

```cpp
float ScreenCoverage(float bounding_radius, float distance, float fov_y) {
  return bounding_radius / (distance * std::tan(fov_y * 0.5f));
}
```

## 切り替えのポップを隠す

LOD が切り替わる瞬間に、形が急に変わって目立つことがあります（**ポップ**）。

| 対策 | 説明 |
| --- | --- |
| **ヒステリシス** | 切り替えの距離に幅を持たせる。近づく時と離れる時で境目を変える |
| **ディザ フェード** | 点の模様で新旧のメッシュを数フレームかけて混ぜる |
| **クロス フェード** | 両方を描いて、アルファで混ぜる（コストが高い） |
| **ジオモーフィング** | 頂点を補間して、徐々に形を変える |

## インポスター

非常に遠い物体は、<strong>1 枚の画像（板）</strong>で代用できます。

| 種類 | 説明 |
| --- | --- |
| **ビルボード** | 常にカメラを向く 1 枚の板。木・草・遠景の建物 |
| **多方向インポスター** | 複数の角度から撮った画像を、見る方向で切り替える（または混ぜる） |
| **オクタヘドラル インポスター** | 全方向をタイルに焼き、方向に応じて 2〜3 枚を補間。形の自然さが高い |

| 利点 | 欠点 |
| --- | --- |
| **三角形が数個**で済む | 近づくと粗さが目立つ |
| **ピクセルシェーダーも軽い** | 画像のメモリが必要 |
| **大量の木に向く** | ライティングが焼き込みになりやすい（法線も焼いて補う） |

画像はビルド時に自動生成します（[ベイク](../optimize/baking.md)）。

## 連続 LOD

離散 LOD は切り替えが不連続ですが、**詳細度を滑らかに変える**方式もあります。

| 方式 | 説明 |
| --- | --- |
| **テッセレーション / ディスプレイスメント** | 近くだけ三角形を細かく分割する（地形・水面） |
| <strong>クラスター階層（Nanite 風）</strong> | Meshlet の木構造から、画面での大きさに合った詳細度の塊だけを選ぶ（[Mesh Shader](mesh-shaders.md)） |
| **地形の LOD** | 距離でタイルの分割を粗くする（クリップマップ・四分木） |

## 他の最適化との関係

| 関係 | 説明 |
| --- | --- |
| **カリング** | 見えない物は描かない。LOD は見える物の質を下げる（[カリング](culling.md)） |
| **影** | 影用にさらに低い LOD を使う（[影のコスト](shadows.md)） |
| **オーバードロー** | 小さな三角形の無駄を減らす（[オーバードロー](overdraw.md)） |
| **メモリ** | LOD ごとにメッシュを持つ。ストリーミングで必要なものだけ読み込む |

## よくあるミス

??? failure "距離だけで切り替えて、見た目が不安定になる"
    FOV やモデルの大きさで変わります。画面での大きさで判断します。

??? failure "LOD の切り替えがポップして目立つ"
    ディザ フェードとヒステリシスを入れます。

??? failure "LOD0 だけ作って、遠くも高密度のまま描く"
    遠景の頂点・クアッドの無駄が大きくなります。

??? failure "遠くでもボーン数・材質を減らさない"
    メッシュだけでなく、スキニングとシェーダーも軽くします。
