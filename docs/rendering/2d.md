# 2D ゲームの描画

2D ゲームは、3D に比べて頂点が少ない一方で、**スプライトの数が非常に多く**なりやすいです。1 枚ずつ描くとドロー コールが数千になります。また、画面を覆う透明なスプライトが重なると、オーバードローも増えます。このページでは、2D ゲームの描画を軽くする工夫を説明します。

!!! tip "ポイント"
    - 目的は<strong>ドロー コールの削減</strong>と<strong>無駄なピクセルの削減</strong>。
    - <strong>アトラス</strong>にまとめて、1 回のドロー コールで多数のスプライトを描く。
    - <strong>画面外は描かない</strong>。タイルマップは<strong>チャンク</strong>単位にまとめる。
    - UI は<strong>変更がなければ使い回す</strong>。

## 工夫の一覧


| 工夫 | 説明 |
| --- | --- |
| **画面外のスプライトを描かない** | カメラの範囲外は、スキップ |
| **スプライトをアトラスにまとめてバッチ** | 1 回のドロー コールで、数千個 |
| **タイルマップをチャンクごとに 1 つのメッシュに** | タイル 1 枚ずつ描かない |
| **透明部分が大きいスプライトの、余白を切る** | 無駄なピクセルを減らす（オーバードロー） |

## スプライト バッチ

同じテクスチャ（アトラス）を使うスプライトは、**1 つの頂点バッファにまとめて、1 回のドロー コール**で描けます。

| 点 | 説明 |
| --- | --- |
| **アトラス** | 複数の画像を 1 枚にまとめ、UV で切り出す。テクスチャの切り替えがなくなる |
| **描画順** | 奥から手前の順（アルファ ブレンドのため）。同じテクスチャが連続するように、レイヤーとテクスチャでソートする |
| **頂点データ** | スプライトごとに位置・UV・色の 4 頂点を動的バッファに書く |
| **インスタンシング** | 1 つの四角形メッシュを使って、スプライトごとの情報（位置・UV・色）をインスタンス データにする方法もある |

## タイルマップ

| 工夫 | 説明 |
| --- | --- |
| **チャンクにまとめる** | 16×16 タイルなどを 1 つのメッシュにして、変更があったときだけ作り直す |
| **範囲外をスキップ** | カメラの範囲に入るチャンクだけ描く |
| **レイヤーを分ける** | 背景・地面・前景で別のメッシュにする |
| **シェーダーでの描画** | タイル ID の配列を 1 枚のテクスチャにして、ピクセルシェーダーでタイルを選ぶ方式もある |

## UI の描画

| 工夫 | 説明 |
| --- | --- |
| **バッチにまとめる** | 同じテクスチャ・同じ状態の UI 部品を連続して描く |
| **変更がなければキャッシュ** | 複雑なパネルをテクスチャに描いて使い回す |
| **フォントはアトラス** | 文字を 1 枚のテクスチャにまとめる |
| **クリッピング** | シザー矩形ではみ出しを切る（ドロー コールが分かれる点に注意） |

## オーバードロー

| 点 | 説明 |
| --- | --- |
| **透明な余白** | スプライトの周りの透明部分を切り詰める（メッシュ化して形に沿う） |
| **背景の重ね描き** | 全画面の背景を何枚も重ねない |
| **半透明エフェクト** | 大きなものは縮小バッファに（[パーティクルと半透明](particles.md)） |

## よくあるミス

??? failure "スプライトを 1 枚ずつドロー コールしている"
    アトラスとバッチにします。

??? failure "画面外のスプライト・タイルも描いている"
    カメラ範囲でカリングします。

??? failure "テクスチャを頻繁に切り替える順序で描いている"
    テクスチャ（アトラス）でソートします。ただし描画順（奥から手前）との兼ね合いを見ます。

??? failure "UI を毎フレーム全部作り直している"
    変更がない部分を使い回します。
