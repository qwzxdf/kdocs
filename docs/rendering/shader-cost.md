# シェーダーのコスト

ピクセル数が多い、頂点数が多い、といった**量の問題**を減らしても、1 回あたりのシェーダーが重いと、GPU は遅いままです。このページはシェーダーの何が重いのか（演算・メモリ読み込み・分岐・レジスタ）と、それぞれの軽くする方法を説明します。ピクセル処理がボトルネックのときに効きます（[何が重いのか](bottlenecks.md)）。

!!! tip "ポイント"
    - シェーダーのコスト ＝ <strong>演算（ALU）・メモリ読み込み（テクスチャ・バッファ）・分岐・レジスタ使用量</strong>。
    - <strong>現代の GPU では、演算よりもメモリ読み込み（待ち）が重い</strong>ことが多い。
    - テクスチャの読み込みを減らす・近くを読む（キャッシュに乗せる）。
    - 分岐：同じ組（ウェーブ）の、全スレッドが同じ方へ進めば、安い。バラバラだと両方を実行（ダイバージェンス）。
    - レジスタが多いと同時に動かせる、ウェーブが減り（占有率の低下）、待ちを隠せなくなる。
    - 半精度（FP16）・事前計算（LUT・ベイク）・頂点側へ移す、が、定番の対策。

## 何が重いのか

| 要素 | 説明 |
| --- | --- |
| <strong>ALU（演算）</strong> | 加減乗除・内積・`pow`・`sqrt`・`sin` など。特殊関数（`pow`・`sin`）は、重い |
| テクスチャ読み込み | メモリからの読み込み。待ち時間が長い。キャッシュに乗るかが重要 |
| バッファ読み込み | 構造化バッファ・定数バッファ。ライト リストなど |
| 分岐・ループ | スレッドの足並みに影響 |
| レジスタ | シェーダーが使う、一時変数の数。多いと占有率が下がる |
| 帯域幅 | RT・UAV への書き込み（[メモリ帯域幅](bandwidth.md)） |

## メモリ読み込みを減らす

| 工夫 | 説明 |
| --- | --- |
| **テクスチャをまとめる** | 粗さ・金属・AO を 1 枚のチャンネルに詰める（R・G・B に 1 つずつ）（[PBR](../3d/pbr.md)） |
| 圧縮フォーマット | BC1〜BC7。読み込む量が減る |
| ミップマップ | 遠い物は小さな画像（キャッシュに乗りやすい） |
| 読み込みの局所性 | 隣のピクセルは、隣のテクセルを読む。ランダムな読み込みは、遅い |
| 同じものを何度も読まない | ループの外で、1 回読み、変数に保持 |
| 依存した読み込みを避ける | 読み込み結果で次の座標を決める（依存）と、待ちが直列に |

| 点 | 説明 |
| --- | --- |
| 一様な分岐は安い | 定数・全ピクセル共通の値での分岐 |
| バラバラな分岐 | 両方の道を実行し、不要な側をマスク |
| 重い処理を分岐で囲む | 全員が通らないなら、飛ばせる（ライトの数がピクセルごとに違うなど） |
| `[branch]` / `[flatten]` | HLSL のヒント。短い分岐は、`flatten`（両方計算して選ぶ） |

詳しい分岐の話は、[分岐と仮想関数](../optimize/branching-virtual.md)（CPU 側）も、参照してください。

## 占有率（オキュパンシー）

**GPU はあるウェーブがメモリを待つ間、別のウェーブを実行**して、待ち時間を隠します。同時に動かせる、ウェーブの数が占有率です。

| 制限する要素 | 説明 |
| --- | --- |
| レジスタ数 | 1 スレッドが多くのレジスタを使うと、同時に載るウェーブが減る |
| groupshared メモリ | コンピュートで多く使うとグループ数が減る |
| スレッド グループ サイズ | 小さすぎる・大きすぎる |

| 対策 | 説明 |
| --- | --- |
| 変数を減らす・寿命を短く | レジスタを節約 |
| 巨大なシェーダーを分割 | パスを分ける |
| ツールで確認 | PIX・Nsight・Radeon GPU Profiler で、レジスタ・占有率を確認 |

## 演算を軽くする

| 工夫 | 説明 |
| --- | --- |
| **`pow`・`sin`・`exp` を避ける** | 近似式・テーブル（LUT） に置き換える |
| `normalize` の、減らす | すでに正規化済みなら、不要 |
| 除算を乗算に | **`x / 2.0` → `x * 0.5`（コンパイラが自動でやることも多い**） |
| `mad`（乗算＋加算）を意識 | 1 命令でできる形 |
| 半精度（FP16・`min16float`） | レジスタ・演算が半分（対応 GPU。精度に注意） |
| 定数の事前計算 | CPU 側・ベイクで計算し、シェーダーには、結果だけ（[ベイク](../optimize/baking.md)） |

## 計算を頂点側へ移す

**ピクセルは頂点より、はるかに多い**のでピクセルごとに同じ値になる計算は、頂点（またはその前）へ移します。

| 計算 | 移す先 |
| --- | --- |
| ライトの方向・ビュー方向（ゆっくり変化） | 頂点シェーダー（補間で十分） |
| 同じ値の計算 | CPU・定数バッファ |
| ピクセルごとに変わらない処理 | ピクセルシェーダーの外 |

ただし、補間では精度が足りないもの（鏡面ハイライトなど）は、ピクセルで計算します。

## シェーダーのバリアント

**マクロで機能のオン・オフを切り替える**と組み合わせの数だけ、シェーダーが増えます。

| 問題 | 対策 |
| --- | --- |
| バリアントの爆発 | 本当に必要な組み合わせだけをビルド |
| 動的な分岐（`if (use_feature)`） | 一様なら、安い。バリアントを減らせる |
| コンパイル時間・メモリ | 使わない組み合わせは、作らない（[ビルド時間](../optimize/build-time.md)） |

## 測り方

| ツール | 見るもの |
| --- | --- |
| <strong>PIX（DX）</strong> | シェーダーごとの時間・占有率・メモリ待ち |
| RenderDoc | ドロー コールごとの状態・オーバードロー |
| Nsight Graphics / Radeon GPU Profiler | ベンダー固有の詳細（レジスタ・ウェーブ占有率） |
| シェーダーを一時的に単純化 | 「このシェーダーを空にしたら、速くなる？」で、原因を切り分け（[何が重いのか](bottlenecks.md)） |

## よくあるミス

??? failure "演算ばかり減らして、テクスチャ読み込みがボトルネックのまま"
    **メモリ待ち**を確認します。

??? failure "ピクセルごとに、バラバラな条件で重い処理を分岐で囲む"
    ダイバージェンスで全員が両方実行します。

??? failure "巨大な、1 つのシェーダーに全機能を詰め込む"
    レジスタが増え、占有率が落ちます。

??? failure "FP16 を位置・深度の計算に使って、精度が足りない"
    色・ライティングの一部に限定します。

??? failure "`pow(x, 2.0)` をそのまま書く"
    **`x * x`** にします。

## これだけ覚える

    - [x] コスト ＝ 演算・メモリ読み込み・分岐・レジスタ。メモリ待ちが重いことが多い

    - [x] 分岐は、そろっていれば、安い。バラバラだと両方実行
    - [x] レジスタが多いと、占有率が下がる。巨大なシェーダーを避ける
