# サウンド（XAudio2・miniaudio・FMOD・Wwise）

ゲームの音は、効果音、BGM、ボイスの 3 つに分かれ、それぞれ性質が違います。効果音は、短くて何度も重ねて鳴らします。BGM は、長くて 1 つずつ。ボイスは、途中で止められたり、字幕と合わせたりします。1 つの音をただ鳴らすのは簡単でも、20 個を同時に鳴らし、距離で音量を変え、ステージが変わったら入れ替える、となると、仕組みが要ります。

ここでは、音を鳴らす基本の考え方と、使えるライブラリ（XAudio2、miniaudio、FMOD、Wwise）の選び方を説明します。

!!! tip "ポイント"
    - 音は、PCM（サンプルの並び）としてバッファに入れ、サウンド カードが定期的に読んでいく。読み出しに間に合わないと、音が途切れる
    - 効果音はまるごとメモリに読み込む。BGM は、少しずつ読み込みながら鳴らす（ストリーミング）
    - 同時に鳴らす数の上限を決める。上限を超えたら、重要度の低いものから止める
    - 最初の 1 本としては miniaudio が手軽。大規模なら FMOD か Wwise
    - 3D の音は、距離による減衰と、左右の定位で作る

## 音が鳴る仕組み {#basics}

音は、1 秒間に数万回の「波の高さ」を並べた数字の列（PCM）で表されます。サンプリング レート 48000 Hz なら、1 秒に 48000 個です。2 チャンネル（ステレオ）なら、その倍になります。

サウンド カードは、この数字の列を、定期的にバッファから読み出して、スピーカーに送ります。ゲーム側の仕事は、バッファが空にならないように、数字を送り続けることです。間に合わないと、音がぷつぷつ途切れます（バッファ アンダーラン）。

複数の音を同時に鳴らすときは、それぞれの数字を足し合わせて（ミキシング）、1 つの列にします。この足し算を、ライブラリが行います。音量は、数字に係数を掛けるだけです。

## 効果音と BGM の違い {#sfx-bgm}

効果音は、短い（数秒）ので、ファイルを全部読んで、デコードしてメモリに置きます。鳴らすときは、メモリ上のデータを読むだけなので、遅延がありません。

BGM は、数分あり、全部をデコードすると数十 MB になります。そこで、ファイルを少しずつ読んで、デコードしながら鳴らす、ストリーミング再生にします。メモリに置くのは、数秒分のバッファだけで済みます。

形式は、圧縮された OGG Vorbis などを使うのが普通です。WAV は容量が大きく、短い効果音に向きます。

## ライブラリの選び方 {#choose}

| ライブラリ | 特徴 | 向く場面 |
| --- | --- | --- |
| XAudio2 | Windows 標準の低レベル API。ミキシングの部品を自分で組む | Windows 専用で、音の仕組みを学びたいとき |
| miniaudio | ヘッダー 1 つの軽いライブラリ。再生、3D の音、ストリーミングまで | 個人や学生のゲーム。最初の 1 本 |
| OpenAL（OpenAL Soft） | 3D の音の API。移植性が高い | 他の OS にも出したいとき |
| FMOD | 音の制作ツールとセットのミドルウェア。個人は無料の範囲がある | 音響担当と分業するとき |
| Wwise | FMOD と同種。業界での採用例が多い。無料の範囲がある | 大規模な商業ゲーム |

学生の制作では、miniaudio で十分です。1 つのヘッダーを足すだけで始められます。FMOD と Wwise は、音響担当者が専用のツールで、音の組み合わせや変化を作り、プログラムは「イベントを呼ぶ」だけにする、という分業のための道具です。個人制作には大がかりですが、チーム制作で音響担当がいるなら、検討します。

### miniaudio で鳴らす {#miniaudio}

`miniaudio.h` を置いて、1 つの `.cpp` で実装を取り込みます。

```cpp
#define MINIAUDIO_IMPLEMENTATION
#include "miniaudio.h"

int main() {
  ma_engine engine;
  if (ma_engine_init(nullptr, &engine) != MA_SUCCESS) return 1;  // 既定の出力デバイスで初期化

  ma_engine_play_sound(&engine, "jump.wav", nullptr);  // 効果音をその場で鳴らす（読み込みも自動）

  ma_sound bgm;
  ma_sound_init_from_file(&engine, "bgm.ogg", MA_SOUND_FLAG_STREAM, nullptr, nullptr, &bgm);
  ma_sound_set_looping(&bgm, MA_TRUE);  // ループ再生
  ma_sound_start(&bgm);

  // …ゲームのループ…

  ma_sound_uninit(&bgm);
  ma_engine_uninit(&engine);
}
```

`ma_engine_play_sound` は、ファイルを読み込んで鳴らす、手軽な関数です。毎回ファイルを開くので、頻繁に鳴らす効果音には向きません。繰り返し使う効果音は `ma_sound` として一度読み込み、再利用します。

`MA_SOUND_FLAG_STREAM` は、BGM のストリーミング再生の指定です。

## 3D の音 {#spatial}

音の位置と聞き手の位置から、音量と左右の定位を決めます。主な要素は 2 つです。

- 距離による減衰：遠いほど小さくなる。最小距離（これより近いと最大音量）と最大距離（これより遠いと聞こえない）を決める
- 定位：聞き手の向きに対して、音がどちら側にあるかで、左右の音量を変える

miniaudio では、`ma_sound_set_position` で位置を、`ma_engine_listener_set_position` で聞き手の位置を渡します。毎フレーム、ゲーム内の座標を渡して更新します。座標系は、このサイトの規約（右手系・Y-up）と、ライブラリの規約が合っているか確認します。

## 同時発音数の管理 {#voices}

同時に鳴る音の数には、上限を設けます。敵が 50 体いて、全員が足音を鳴らすと、処理が重くなり、音が混ざって聞き取れなくなります。

上限を超えたときは、<strong>優先度の低い音から止める</strong>のが普通です。ボイスと BGM は優先度が高く、足音や環境音は低くします。同じ効果音を同時に何個も鳴らす場合は、1 つにまとめる（同じ音は最大 3 個まで、など）と、聞き取りやすくなります。

## よくあるミス {#mistakes}

??? failure "音が途切れる、ぷつぷつ鳴る"
    ゲームのメイン スレッドが重くて、バッファに数字を送れていません。ライブラリが専用のスレッドで鳴らしているかを確認します。ファイルの読み込みとデコードは、メイン スレッドの外で行います。

??? failure "効果音を鳴らすたびに、ファイルを開いて、ゲームが固まる"
    効果音は起動時に読み込み、メモリ上のものを使い回します。

??? failure "ステージを切り替えても、前のステージの音が残る"
    音のハンドルを解放していません。シーンごとに、鳴らしたものを記録して、遷移で止めます。

## これだけ覚える {#summary}

- 効果音はメモリに、BGM はストリーミングで
- 同時発音数に上限を決め、優先度の低いものから止める
- 最初は miniaudio。音響担当と分業するなら FMOD や Wwise
