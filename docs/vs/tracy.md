# Tracy（ゲーム向けのプロファイラ）

Visual Studio のプロファイラーは、「プログラム全体で、どの関数が時間を食うか」を集計して見せてくれます。でもゲームで困るのは、多くの場合、平均ではなく<strong>特定のフレームだけ重い</strong>ことです。1 秒間に 60 回のうち、たまに 1 回だけ 40 ms かかる、といった現象は、集計では埋もれます。

Tracy は、<strong>フレームごとに、どの処理がいつ始まり、どれだけかかったかを時間軸で見せる</strong>プロファイラです。コードに計測の印を入れ、実行中のゲームから別のビューアーへリアルタイムで流します。

!!! tip "ポイント"
    - 計測したい関数に `ZoneScoped;` と書くだけで、区間が記録される
    - フレームの区切りに `FrameMark;` を書くと、フレームごとの時間が棒グラフになる
    - ゲームを動かしながら、別プロセスのビューアーで見る。負荷は小さい
    - 計測は Release 構成。計測用のマクロは、`TRACY_ENABLE` を定義したときだけ有効になる

    - [パフォーマンス プロファイラー](profiler.md)（Visual Studio の標準機能）

## 導入 {#setup}

vcpkg で入ります。

```json
{
  "dependencies": ["tracy"]
}
```

ビューアー（`Tracy-profiler.exe`）は、GitHub のリリースページ（wolfpld/tracy）から、ビルド済みのものをダウンロードして使います。ライブラリとビューアーのバージョンが合っていないと接続できないので、同じバージョンにそろえます。

計測を有効にするには、プロジェクトのプリプロセッサ定義に `TRACY_ENABLE` を追加します。出荷用のビルドからは外しておくと、マクロが空になり、負荷が消えます。

## 基本の使い方 {#basic}

```cpp
#include <tracy/Tracy.hpp>

void UpdateEnemies() {
  ZoneScoped;  // この関数の実行時間を記録する
  // ...
}

void RenderScene() {
  ZoneScopedN("RenderScene");  // 名前を指定する
  {
    ZoneScopedN("Shadow");     // 入れ子にもできる
    // 影の描画
  }
  {
    ZoneScopedN("Main");
    // 本体の描画
  }
}

int main() {
  while (running) {
    UpdateEnemies();
    RenderScene();
    FrameMark;  // ここでフレームが終わる
  }
}
```

`ZoneScoped` は、書いたスコープに入ってから抜けるまでを 1 つの区間として記録します。関数の先頭に書けば関数全体、波括弧で囲めば、その部分です。`ZoneScopedN("名前")` は、区間に名前を付けます。ビューアーの表示に出るので、見分けやすくなります。

`FrameMark` は、フレームの区切りです。これを入れると、ビューアーの一番上にフレームごとの時間が並びます。重いフレームはすぐ分かるので、クリックでそのフレームの内訳に飛べます。

## ビューアーの見方 {#viewer}

ゲームを起動した状態で `Tracy-profiler.exe` を開き、「Connect」を押します。

- 上部のフレーム時間のグラフで、背の高い棒が重かったフレーム
- 中央のタイムラインは、スレッドごとに区間が並ぶ。長い区間は、時間を使っている所
- 区間をクリックすると、その合計や回数が出る。「Statistics」で、全区間の集計表が出る

スレッドごとの表示は、[マルチスレッド](../optimize/multithreading.md) の調整に便利です。ジョブがどのスレッドで、どのタイミングで動いているか見えます。

## GPU の計測と追加の機能 {#more}

- <strong>GPU の区間</strong>: DX11 / DX12 / Vulkan のタイムスタンプクエリと連携できる。CPU と GPU の時間を同じ画面に並べられる
- <strong>メモリ</strong>: `TracyAlloc` と `TracyFree` で、確保と解放を記録できる。リークの場所の特定に使える
- <strong>プロット</strong>: `TracyPlot("名前", 値)` で、任意の数値（エネルギー、敵の数など）をグラフにできる
- <strong>メッセージ</strong>: `TracyMessageL("文")` で、タイムラインにログを重ねられる

## 計測の注意 {#caveat}

計測そのものにもコストがかかります。1 フレームに数万の区間を入れると、計測のコストが目立ちます。ホットな小さい関数の中には入れず、<strong>処理のまとまり</strong>（システムの更新、パスの描画）に付けるのが目安です。

Debug 構成の結果は、最適化がないので、実際のゲームとは別物です。計測は Release で行います。

## よくあるミス {#mistakes}

??? failure "ビューアーに接続できない"
    ビューアーとライブラリのバージョンが違うか、`TRACY_ENABLE` が定義されていません。ファイアウォールが通信を止める場合もあります。

??? failure "計測のせいでゲームが重くなった"
    小さい関数に `ZoneScoped` を付けすぎています。外側の大きなまとまりだけに付けます。

## これだけ覚える {#summary}

- ゲームの問題は「特定のフレームが重い」。時間軸で見られる Tracy が向く
- `ZoneScoped` で区間、`FrameMark` でフレームの区切り
- 計測は Release で、粒度は処理のまとまりごと
