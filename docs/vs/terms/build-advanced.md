# ビルドの発展（増分ビルド、pch、並列、コマンド ライン）

[ビルド](build.md)の基本（前処理 → コンパイル → リンク）が分かったら、次は「ビルドを速くする」「画面を使わずにビルドする」です。変更した所だけ作り直す仕組み、プリコンパイル済みヘッダー、並列ビルド、コマンド ラインからのビルドを説明します。

!!! info "このページを読む前に"
    - [ビルド](build.md)

## 変更があった分だけ作る仕組み（増分ビルド） {#incremental}

Visual Studio は毎回、全部を作り直すわけではありません。**どのファイルを読んで何を作ったか**を `.tlog` というファイルに記録しています。次のビルドのときに読んだファイルの更新時刻が成果物より新しいものだけを作り直します。

- `game.cpp`: `game.cpp` だけをコンパイルして、リンクし直す
- `game.h`（それを `#include` している `.cpp` が 10 個）: その 10 個の `.cpp` をコンパイルして、リンクし直す
- `pch.h`（全員が使う）: すべての `.cpp`
- プロパティ（コンパイラのオプション）: すべての `.cpp`

ヘッダーを 1 行変えただけで、数十個の `.cpp` が作り直されることがあります。ビルドを速くするにはヘッダーの `#include` を減らすのが、一番効きます。

- ヘッダーには `#include` ではなく、前方宣言（`class Player;`）で済ませられるものは、前方宣言にする
- 大きなヘッダー（`<windows.h>`、`<d3d11.h>`）を `.h` の中で読み込まず `.cpp` の中に書く
- 変更の多いヘッダーとほとんど変わらないヘッダーを分ける

## プリコンパイル済みヘッダー（pch） {#pch}

標準ライブラリや `<windows.h>` のようなほとんど変わらないヘッダーを <strong>一度だけ解析して、結果を保存しておく</strong>仕組みです。これで `.cpp` ごとに数万行を読み直す手間が省けます。

### 使い方

1. `pch.h` を作って変わらないヘッダーを書く

```cpp
// pch.h
#pragma once

#include <algorithm>
#include <cstdint>
#include <memory>
#include <print>
#include <string>
#include <vector>

#include <d3d11.h>
```

2. `pch.cpp` を作って `pch.h` だけを書く

```cpp
// pch.cpp
#include "pch.h"
```

3. プロジェクトのプロパティ → C/C++ → プリコンパイル済みヘッダーを設定する

- <strong>プロジェクト全体</strong>: 設定: プリコンパイル済みヘッダー。値: 使用する（`/Yu`）
- <strong>プロジェクト全体</strong>: 設定: プリコンパイル済みヘッダー ファイル。値: `pch.h`
- <strong>`pch.cpp` だけ</strong>: 設定: プリコンパイル済みヘッダー。値: 作成する（`/Yc`）

4. すべての `.cpp` の一行目に `#include "pch.h"` を書く

!!! warning "pch.h は、`.cpp` の一番最初に書く"
    `/Yu` を使うと`#include "pch.h"` より前にあるものは、すべて無視されます。一行目より前に `#include <vector>` などを書くとその行が消えたように扱われ不思議なエラーになります。

### 向かないもの

`pch.h` には「ほとんど変わらないもの」だけを入れます。自分のゲームのヘッダーを入れると、そのヘッダーを変えるたびにすべての `.cpp` を作り直すことになります。逆効果です。

## 並列ビルド {#parallel}

- <strong>`/MP`</strong>: 場所: C/C++ → 全般 → 複数プロセッサによるコンパイル。効果: **1 つのプロジェクトの中の** `.cpp` をコアの数だけ並列にコンパイルする
- <strong>プロジェクトの並列ビルド</strong>: 場所: ツール → オプション → プロジェクトおよびソリューション → ビルドして実行 → 並列プロジェクト ビルドの最大数。効果: プロジェクト同士を並列に作る

この 2 つは別の設定です。両方を有効にしておきます。`/MP` は `/Gm`（最小リビルド）と同時には使えません。新しいプロジェクトでは `/Gm` は既定で無効になっています。

## コマンド ラインでビルドする {#cli}

IDE を使わずコマンド ラインでもビルドできます。**CI や自動ビルドで使います。** 準備として Visual Studio の Developer Command Prompt（スタート メニューの「x64 Native Tools Command Prompt for VS」）を開きます。ここで開くと `cl.exe` などへのパスが設定済みです。

### cl で直接ビルドする

```bash
cl /std:c++latest /EHsc /utf-8 /W4 /O2 main.cpp game.cpp /Fe:Game.exe
```

- `/std:c++latest`: 最新の C++ の機能を有効にする（[C++23 を使えるようにする設定](../settings.md)）
- `/EHsc`: C++ の例外処理を有効にする。付けないと警告が出る
- `/utf-8`: ソースと実行時の文字コードを UTF-8 にする（[文字コードを UTF-8 にしよう](../utf8.md)）
- `/W4`: 警告レベル 4
- `/O2`: 速度を優先して最適化する
- `/Fe:Game.exe`: 出力する実行ファイルの名前
- `/c`: コンパイルだけ行う（リンクしない）。`.obj` ができる
- `/Zi`: デバッグ情報（`.pdb`）を作る
- `/MD`: ランタイム ライブラリを DLL で使う
- `/I パス`: インクルード ディレクトリを追加する
- `/D 名前`: マクロを定義する（`/DNDEBUG` など）
- `/link ...`: これ以降をリンカーに渡す

`cl` に `.cpp` を複数渡すと前処理・コンパイル・リンクを続けて行います。`/c` を付けて `link` を別に呼ぶと段階を分けて実行できます。

```bash
# 段階を分けて実行する
cl /c /std:c++latest /EHsc /utf-8 main.cpp game.cpp
link main.obj game.obj /OUT:Game.exe
```

### msbuild でソリューションをビルドする

```bash
msbuild MyGame.sln /p:Configuration=Release /p:Platform=x64 /m /v:minimal
```

- `/p:Configuration=Release`: 構成（[構成](configuration.md#cli)）
- `/p:Platform=x64`: プラットフォーム
- `/m`: プロジェクトを並列にビルドする
- `/v:minimal`: 出力の詳しさ（`quiet`、`minimal`、`normal`、`detailed`、`diagnostic`）
- `/t:Rebuild`: リビルドする（`Build`、`Clean`、`Rebuild`）

`msbuild` が `'msbuild' は、内部コマンドまたは外部コマンド…として認識されていません` と言うときは Developer Command Prompt で開いていません。

## ビルドの出力を詳しく見る {#log}

ビルドがうまくいかないとき出力ウィンドウの詳しさを上げると、**実際にコンパイラに渡されたコマンド**が見えます。

1. ツール → オプション → プロジェクトおよびソリューション → ビルドして実行
2. 「MSBuild プロジェクトのビルド出力の詳細度」を 詳細（または、診断）にする

出力には `cl.exe` に渡されたすべてのオプションが出ます。プロパティ画面の設定が本当にコマンドに反映されているか確認できます。

ヘッダーの読み込み状況を調べるときは、`/showIncludes` を使います。どのヘッダーが何から読み込まれているか一覧で見えます。

```text
C/C++ → コマンド ライン → 追加のオプション:  /showIncludes
```
