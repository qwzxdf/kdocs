# プラットフォーム（x64 / Win32 / ARM64）

プラットフォームは <strong>作った実行ファイルがどの種類の CPU 向けか</strong>を決める設定です。画面上の「x64」の部分です。いまの Windows ゲームはほぼ x64（64 ビット）で作ります。Win32（32 ビット）という名前は、「Windows 32 ビット」の名残です。64 ビットの Windows でもこの名前のまま残っています。

!!! tip "ポイント"
    - 新しく作るなら <strong>x64</strong>。Win32（x86）は古い環境向け
    - プラットフォームが違うとポインターの大きさ（8 バイトと 4 バイト）、使えるメモリの量、呼び出しの約束が変わる
    - <strong>`.lib` と `.dll` はプラットフォームごとに別のもの</strong>。ビット数が違うものはリンクも読み込みもできない
    - ARM64 は Snapdragon を積んだ Windows PC 向け。x64 とは別にビルドする
    - 「Any CPU」は C# 用で、C++ にはない

## このページを読む前に

- [構成（Configuration）](configuration.md)

## 3 つのプラットフォーム {#list}

| 表示 | CPU の種類 | ポインター | 使いどころ |
| --- | --- | --- | --- |
| **x64** | Intel / AMD の 64 ビット（x86-64） | 8 バイト | 現在の標準。ゲームはこれで作る |
| Win32（x86） | Intel / AMD の 32 ビット | 4 バイト | 古い PC、古いライブラリの維持 |
| ARM64 | ARM の 64 ビット | 8 バイト | Arm 版 Windows（Copilot+ PC など） |
| ARM64EC | x64 と ARM64 を混ぜる形式 | 8 バイト | 既存の x64 のライブラリを少しずつ ARM に移すとき |

新しいプロジェクトを作ると既定では「x64」が選ばれます。プロパティ画面の「プラットフォーム」は、`.vcxproj` の `<Platform>` に対応しています（[プロジェクト](project.md)）。

## x64 と Win32 の違い {#diff}

### ポインターと `size_t`

| 型 | x64 | Win32 |
| --- | --- | --- |
| ポインター | 8 バイト | 4 バイト |
| `size_t`、`ptrdiff_t` | 8 バイト（`unsigned long long`） | 4 バイト（`unsigned int`） |
| `int` | 4 バイト | 4 バイト |
| `long` | 4 バイト | 4 バイト |
| `long long` | 8 バイト | 8 バイト |

**Windows では x64 でも `long` は 4 バイトのままです。** Linux や macOS の 64 ビットでは `long` は 8 バイトなので、同じコードが OS によって別の大きさになります。「`long` をポインターを入れる箱にする」と x64 の Windows で、上の 4 バイトが切り捨てられます。大きさが大事なときは `<cstdint>` の `std::int32_t`、`std::int64_t`、`std::uintptr_t` を使います。

```cpp
#include <cstdint>
#include <print>

int main() {
  std::println("void* : {} バイト", sizeof(void*));
  std::println("size_t: {} バイト", sizeof(std::size_t));
  std::println("long  : {} バイト", sizeof(long));

  // ポインターを整数に入れるときは、uintptr_t を使う。
  int value = 0;
  std::uintptr_t address = reinterpret_cast<std::uintptr_t>(&value);
  std::println("アドレス: {:#x}", address);
}
```

```text title="実行結果（x64）"
void* : 8 バイト
size_t: 8 バイト
long  : 4 バイト
アドレス: 0xb1d2fff8d4
```

アドレスの値は実行のたびに変わります。Win32 でビルドすると最初の 2 行が 4 と 4 になります。

### 使えるメモリ

| | x64 | Win32 |
| --- | --- | --- |
| プロセスが使える仮想アドレス空間 | 約 128 TB（Windows の仕様） | 2 GB（大きいアドレスに対応した exe なら、64 ビット OS の上で 4 GB） |
| 実際に使える量 | 搭載メモリとディスクの上限まで | 2 GB に届く前にアドレス空間が断片化して足りなくなる |

ゲームのテクスチャやメッシュはすぐに数 GB になります。Win32 ではどうしても足りなくなります。 これが x64 にする最大の理由です。

### 呼び出し規約

関数を呼ぶときの引数の渡し方の約束です。

| | x64 | Win32 |
| --- | --- | --- |
| 種類 | 1 種類（Microsoft x64） | `__cdecl`、`__stdcall`、`__fastcall` などがある |
| 引数の渡し方 | 先頭の 4 つをレジスターで渡す | 主にスタックで渡す |
| `__stdcall` と書くと | 無視される | 呼び出し規約が変わる |

Win32 では Windows API の `__stdcall` と普通の関数の `__cdecl` を取り違えると、スタックが壊れます。x64 ではそもそも規約が 1 つなので、この種類の事故がありません。コードの書き方は変わりませんが、`.dll` から関数を取り出すときなどに違いが出ます。

### 命令セットと例外

| | x64 | Win32 |
| --- | --- | --- |
| SSE2 | 必ず使える（浮動小数点の標準の演算が SSE2） | 使えるとは限らない（古い CPU に配慮するなら `/arch:IA32`） |
| レジスターの数 | 汎用 16 個 | 汎用 8 個 |
| 例外処理 | テーブル方式。例外が起きないときのコストがほぼゼロ | スタックにフレームの鎖を作る方式。毎回、わずかなコストがかかる |

浮動小数点の計算が x64 では SSE2 の命令になるので、結果の再現性が上がります。Win32 の古い方式（x87）は計算の途中で、80 ビットの精度が使われ最適化の違いで結果が変わることがありました。

## どのプラットフォームでもそろえるもの {#match}

プログラムを作るときに関わるものは、**すべて同じプラットフォームでそろえる**必要があります。

| 関わるもの | 例 | 違うとどうなるか |
| --- | --- | --- |
| 自分のプロジェクト | `Game`、`Engine` | 構成マネージャーでずれる |
| 外部ライブラリ | `fmt.lib`、`SDL2.lib`、`DirectXTK.lib` | `LNK4272`、`LNK1112` |
| 実行時に読む DLL | `SDL2.dll`、`xinput1_4.dll` | `0xc000007b` で起動できない |
| プラグイン | ゲームが読み込む `.dll` | 読み込みに失敗する |

### 典型的なエラーメッセージ

| メッセージ | 意味 |
| --- | --- |
| `LNK4272: ライブラリのコンピューターの種類 'x86' は、ターゲットのコンピューターの種類 'x64' と競合しています` | x86 用の `.lib` を x64 のビルドでリンクした |
| `LNK1112: モジュールのコンピューターの種類 'x64' は、ターゲットのコンピューターの種類 'X86' と競合しています` | x64 のオブジェクトを x86 のビルドに混ぜた |
| `アプリケーションを正しく起動できませんでした (0xc000007b)` | 実行ファイルと DLL のビット数が違う（32 と 64 の混在） |
| `LNK2001` / `LNK2019`（外部シンボルが解決できません） | ライブラリは入っているが、別のプラットフォーム用の名前になっている |

`LNK4272` が出たらまず `.lib` をどこから持ってきたかを確認します。`vcpkg` で入れるなら `x64-windows` のものが、x64 のビルドで使われます。

### vcpkg では「トリプレット」で選ぶ

vcpkg はライブラリを「プラットフォームと構成の組み合わせ」ごとに別の場所にビルドします。この組み合わせの名前がトリプレットです。

| トリプレット | 意味 |
| --- | --- |
| `x64-windows` | x64、動的ライブラリ（DLL）、動的 CRT |
| `x64-windows-static` | x64、静的ライブラリ、静的 CRT（`/MT`） |
| `x64-windows-static-md` | x64、静的ライブラリ、動的 CRT（`/MD`） |
| `x86-windows` | Win32（32 ビット） |
| `arm64-windows` | ARM64 |

Visual Studio の中で vcpkg を有効にしていると、プロジェクトのプラットフォームに合うトリプレットが自動で選ばれます（[外部ライブラリの入れ方](../libraries.md)）。

## プラットフォームを追加する {#add}

いまのソリューションに x64 が無いときは、追加します。

1. ビルド → **構成マネージャー**を開く
2. 「アクティブ ソリューション プラットフォーム」→ 新規作成
3. 新しいプラットフォームに x64 を選ぶ
4. 「設定のコピー元」に Win32 を選ぶ
5. 「新しいプロジェクト プラットフォームを作成する」にチェックを付けて OK

コピー元の設定がそのまま引き継がれます。そのあとでプロパティ画面を開いて、x64 の設定を見直す必要があります。特に、次の 2 つはプラットフォームごとの値です。

| 設定 | x64 で確認すること |
| --- | --- |
| リンカー → 追加のライブラリ ディレクトリ | x64 版のライブラリ フォルダーを指しているか |
| デバッグ → 環境（`PATH`） | x64 の DLL のフォルダーになっているか |

## コードの中でプラットフォームを見分ける {#macros}

コードの中でプラットフォームによって処理を分けるときは、コンパイラが定義するマクロを使います。

| マクロ | 定義されるとき |
| --- | --- |
| `_WIN64` | 64 ビットの Windows 向け（x64、ARM64） |
| `_WIN32` | Windows 向け（32 ビットでも 64 ビットでも定義される） |
| `_M_X64` | x64 |
| `_M_IX86` | Win32（x86） |
| `_M_ARM64` | ARM64 |

`_WIN32` は**64 ビットでも定義されます**。「Windows かどうか」を調べるときに使います。ビット数を調べるなら `_WIN64`、あるいは `sizeof(void*)` を使います。

```cpp
#include <print>

int main() {
#if defined(_M_X64)
  std::println("x64 でビルドされています");
#elif defined(_M_ARM64)
  std::println("ARM64 でビルドされています");
#elif defined(_M_IX86)
  std::println("Win32 (x86) でビルドされています");
#endif

  // 「ビット数」だけを知りたいなら、マクロより sizeof が確実。
  static_assert(sizeof(void*) == 8, "このゲームは 64 ビット専用です");
}
```

## DirectX とプラットフォーム {#directx}

DirectX 11 のコードは x64 でも Win32 でも同じように書けます。ただし、次の点に注意します。

| 注意点 | 内容 |
| --- | --- |
| DirectXMath の SIMD | x64 では SSE2 が前提なので、`XMVECTOR` が高速に動く。Win32 でも使えるが引数の渡し方が違う（`FXMVECTOR` などの型を使う理由） |
| アライメント | `XMMATRIX` などは 16 バイト境界が必要。x86 では `new` が 8 バイト境界の可能性がありクラスに `XMMATRIX` を持つとクラッシュすることがある |
| 大きなリソース | 数 GB のテクスチャやバッファは、x64 でないとアドレス空間が足りない |

x64 で作るならこれらの心配はほとんど要りません。

## よくあるミス

??? failure "x64 を選んだのに、`LNK4272` が出る"
    `.lib` が x86 用です。ライブラリを x64 でビルドし直すか x64 版をダウンロードし直します。`追加のライブラリ ディレクトリ` の指す先が `lib\x86` になっていないかも確認します。

??? failure "プロジェクトの設定で、Win32 だけ設定して x64 が空のまま"
    「構成」を選ぶときプラットフォームも「すべてのプラットフォーム」に切り替えます。そうでないと x64 に書き込まれずビルドの設定が欠けたままです（[C++23 を使えるようにする設定](../settings.md#open)）。

??? failure "Debug では x64 で動くのに、ツールが 32 ビットのままで、`0xc000007b` になる"
    プロジェクトごとのプラットフォームがバラバラです。構成マネージャーですべてのプロジェクトが `x64` になっているか確認します（[ソリューション](solution.md#config-manager)）。

??? failure "`long` をアドレスやファイルのサイズを入れる変数に使っている"
    x64 の Windows では、`long` は 4 バイトです。4 GB を超えるサイズやアドレスが切り捨てられます。`std::size_t`、`std::uintptr_t`、`std::int64_t` を使います。
