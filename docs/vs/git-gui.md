# SourceTree と GitHub Desktop（画面で Git を使う）

コマンドで Git を使うと、`git status` と `git log` を何度も打って頭の中で履歴を組み立てることになります。ブランチが 3 本を超えたあたりから、いまどこにいるのか分からなくなる人が多いです。SourceTree や GitHub Desktop は、履歴を線とコミットの図で見せ、ボタンで操作できるようにした Git の画面です。中身は同じ Git なので、コマンドの意味を知っていれば、画面の表示もそのまま読めます。

!!! tip "ポイント"
    - 画面ツールが実行しているのは、普通の Git コマンド。ボタンの名前は、コマンド名とほぼ対応している
    - 事故のもとは、画面の便利さで確認が減ること。「何をどこに」を毎回、目で見てから押す
    - detached HEAD、`force push`、巨大ファイルのコミットが初心者の三大事故
    - 迷ったら、一度ツールを閉じて `git status` を見ると状態が分かる

!!! info "このページを読む前に"
    - [Git の基礎](git.md)（コミット、ブランチ、マージ、リモートの言葉）

## 2 つのツールの違い {#compare}

GitHub Desktop は、画面が少なく、できることも絞ってあります。GitHub を使う前提で、clone、commit、push、プルリクエストの作成まで、迷わず進められます。一方で、特定のコミットだけを取り込む（cherry-pick）や、履歴の整理などの細かい操作は、あまり出てきません。

SourceTree は、Atlassian の無料ツールで、画面は多いですが、ほとんどの Git の操作を画面から呼べます。GitHub 以外のサーバーも扱えます。そのかわり、最初は画面が情報だらけに見えます。

最初の 1 本としては GitHub Desktop が楽です。ブランチを多用する、履歴を整理する、といった場面で足りなくなったら、SourceTree に移ります。リポジトリは同じものなので、どちらで開いても、途中で乗り換えられます。

## 画面の見方（SourceTree） {#sourcetree}

画面は、おおよそ 3 つの領域に分かれます。

| 領域 | 見えるもの | 対応するコマンド |
| --- | --- | --- |
| 左のサイドバー | ブランチ、タグ、リモートの一覧 | `git branch`、`git tag`、`git remote` |
| 中央の履歴 | コミットの一覧と、枝分かれ・合流の線 | `git log --graph` |
| 下の変更欄 | 変更したファイルと、差分 | `git status`、`git diff` |

ファイルの変更は、「ステージにないファイル」から「ステージ済みのファイル」へ移すと add になります。メッセージを書いて「コミット」を押すと commit です。上部のツールバーの「プッシュ」「プル」「フェッチ」「ブランチ」「マージ」は、名前どおりのコマンドを呼びます。

フェッチ（`git fetch`）は、リモートの新しい記録を取り込む手前の段階で、自分の作業フォルダーは変えずに、リモートの様子だけを更新します。プルは「フェッチしてマージ」です。他人が何をしたか先に見たいときは、フェッチだけにしておくと安全です。

## 画面の見方（GitHub Desktop） {#github-desktop}

上部の 3 つの欄を使います。「Current repository」（どのリポジトリか）、「Current branch」（どの枝か）、「Fetch / Push / Pull」（共有のボタン）です。左の列に変更したファイルが並び、チェックボックスで add する、しないを選べます。左下にメッセージを書き、「Commit to ブランチ名」を押します。

ボタンに現在のブランチ名が出ているので、<strong>違う枝にコミットしてしまう事故</strong>を押す前に防げます。押す前に必ず、ボタンの枝の名前を見てください。

## 事故と対処 {#accidents}

### detached HEAD {#detached}

履歴のコミットをダブルクリックして「チェックアウト」すると、どの枝にもいない状態になります。画面の上部に枝名ではなく、コミットの ID が出ます。この状態でコミットしても、枝に戻るとそのコミットを見失います。

見失う前なら、その場で「ブランチ」を押し、新しい枝名を付けて作ります。これでコミットに名前が付き、残ります。

### force push {#force}

push が拒否されたとき、ツールは「強制プッシュ（force push）しますか」と聞くことがあります。これは、リモートの履歴を自分のもので<strong>上書きする</strong>操作です。他人のコミットが消えます。

共有している枝では使いません。まず pull して、他人のコミットを取り込んでから push します。自分一人しか使っていない枝を整理した場合だけ、`--force-with-lease`（他人の push があれば失敗する版）を選びます。

### 巨大ファイルをコミットした {#bigfile}

100 MB を超えるファイルは GitHub が受け付けず、push が失敗します。しかも、コミットした時点で、履歴に入っています。ファイルを消して別のコミットを作っても、履歴の中には残るので、push は失敗し続けます。

まだ push していないなら、`git reset --soft HEAD~1` で直前のコミットを取り消し、ファイルをステージから外して、コミットし直します。画面では、履歴で 1 つ前のコミットを右クリックして「このコミットまで巻き戻す（ソフト）」を選びます。大きなバイナリを今後も扱うなら、[Git LFS](git-lfs.md) を使います。

### 他人の変更とぶつかった {#conflict}

マージでコンフリクトが起きると、ファイルに「競合あり」の印が付きます。SourceTree は右クリックから「マージツールで解決」で 3 画面の比較を開きます。GitHub Desktop は、エディターを開くボタンを出します。直し終えたら、ファイルを add して、コミットします。

## 使い分けの目安 {#choose}

- 一人で GitHub に載せるだけなら、GitHub Desktop
- 枝が増える、履歴を整理したい、GitHub 以外のサーバーを使うなら、SourceTree
- Visual Studio の中で済ませたいなら、Visual Studio の「Git の変更」ウィンドウ（機能は、GitHub Desktop に近い）

## よくあるミス {#mistakes}

??? failure "違う枝にコミットしていた"
    押す前にボタンの枝名を見る習慣がないと起きます。コミット済みで push 前なら、正しい枝へ移ってから `cherry-pick` するか、元の枝で `reset --soft HEAD~1` して、やり直します。

??? failure "「全部ステージ」を押して、不要なファイルまで入れた"
    ビルド生成物が入るのは、`.gitignore` が無いか不足しているからです。[Git の基礎](git.md#gitignore) を見直してください。

## これだけ覚える {#summary}

- 画面ツールは、Git のコマンドを呼ぶ道具。ボタンの意味はコマンドと同じ
- 押す前に枝の名前と、ステージの中身を見る
- 共有の枝に `force push` はしない
