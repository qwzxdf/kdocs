# C++ のエラーメッセージの読み方

C++ のエラーは、ときに画面を埋め尽くす長さで出ます。`std::vector<std::pair<int, std::basic_string<char, std::char_traits<char>, ...>>>` のような型が並び、どこを見ればいいのか分かりません。初心者の多くは、ここで読むのをやめてしまいます。

実は、長いエラーでも、<strong>読む場所は決まっています</strong>。最初の 1 行と、自分のコードの行番号が出ている所、それだけです。ここでは、読む順番と、よく出るエラーの型を説明します。

!!! tip "ポイント"
    - エラーが多数出ても、最初の 1 つだけ読んで直す。後ろは、最初のエラーの連鎖であることが多い
    - 長い表示の中で、自分のファイルの行番号が出ている所を探す。標準ライブラリの内部は、とりあえず飛ばす
    - テンプレートのエラーは、「何を渡して」「何が足りないか」の 2 点だけ読む
    - エラー番号（`C2065` など）で検索すると、説明が見つかる
    - エラー一覧は、「ビルド + IntelliSense」から「ビルドのみ」に切り替えると、見やすい

!!! info "このページを読む前に"
    - [よくあるエラー](errors.md)（リンク エラーや文字化けなどの、個別の対処）

## 読む順番 {#order}

1. <strong>最初のエラーだけ</strong>を見る。「出力」ウィンドウで、上から最初の `error` を探す
2. 自分のファイル名と行番号を探す。`MyGame\Player.cpp(42,10): error C2065: ...` のように、自分のファイルが出ている行
3. エラーの種類（番号と短い文）を読む
4. 説明が足りなければ、続く行（`note:`、`see reference to ...`）を読む
5. 直したら、すぐにビルドし直す。1 つ直すと、大量のエラーが一度に消えることがある

最初のエラーを直さずに、後ろを読んでも意味がありません。たとえば `#include` を忘れて型名が不明になると、その型を使う場所のすべてで、エラーが連鎖します。

## よく出るエラーの型 {#common}

### 名前が見つからない（C2065、C3861、C2039） {#undeclared}

```text
error C2065: 'Player': 宣言されていない識別子です
```

使っている名前がそこから見えていません。原因は、次のいずれかです。

- `#include` を忘れた
- 名前空間が違う（`std::` を付け忘れた）
- 綴りの間違い
- 宣言の順序が逆（使う場所より、後ろで宣言している）

### 型が合わない（C2440、C2664） {#type-mismatch}

```text
error C2664: 'void Draw(const Sprite &)': 引数 1 を 'Sprite *' から 'const Sprite &' に変換できません
```

関数の引数に型が違う物を渡しています。ポインタを渡すべきところに実体を実体を渡すべきところにポインタをが典型です。メッセージの「から」と「に」で、渡した型と、期待された型が分かります。

### 関数が呼べない（C2661、C2672） {#no-matching}

```text
error C2661: 'Player::Player': オーバーロードされた関数は 2 個の引数を使用できません
```

引数の数や型がどの宣言にも合いません。メッセージに続けて、候補が並ぶので、期待された引数と、渡した引数を見比べます。

### `const` の問題（C2662、C3490） {#const}

```text
error C2662: 'void Player::Heal(int)': 'this' ポインターを 'const Player' から 'Player &' に変換できません
```

`const` のオブジェクトから、`const` でない関数を呼んでいます。呼ぶ関数が中身を変えないなら、関数の末尾に `const` を付けます。変えるなら、呼ぶ側の `const` を外します。

### リンク エラー（LNK2019、LNK2001） {#link}

コンパイルは通ったが、リンクで関数の実体が見つからないエラーです。詳しくは [よくあるエラー](errors.md) を見てください。宣言だけして、定義を書いていない、`.lib` を追加していない、が典型です。

## テンプレートのエラーを読む {#template}

STL を使うと、テンプレートの長いエラーに出会います。

```text
error C2672: 'std::sort': 一致するオーバーロードされた関数が見つかりませんでした
note: テンプレート引数の推定/置換に失敗しました
note: 'std::list<int>::iterator' は 'std::random_access_iterator' を満たしません
```

長い表示の中で、読む場所は 2 つです。

- 最初の `error` 行：どの関数で、何が起きたか（`std::sort` が呼べない）
- 後ろの `note` の中の、「満たしません」「見つかりません」などの、理由の行：ここに原因が書いてある（`list` のイテレーターは、ランダム アクセスではない）

この例は、`std::list` に `std::sort` を使った間違いで、`list` のメンバー関数の `sort` を使う、が正しい直し方です。

C++20 以降の `concept` を使う標準ライブラリでは、エラーが「何の条件を満たさないか」をより分かりやすく示すようになっています。

### 自分のコードの行を探す {#find-yours}

テンプレートのエラーは、標準ライブラリの内部のファイル（`xutility`、`vector` など）の行番号で出ますが、原因は自分の呼び出しにあります。表示の中を下にたどり、`see reference to function template instantiation ... being compiled` の後に出てくる、<strong>自分のファイル</strong>の行を見ます。そこが、問題の呼び出しです。

## Visual Studio での見方 {#vs}

- 「エラー一覧」でエラーをダブルクリックすると、該当の行に飛ぶ
- 「ビルド + IntelliSense」を「ビルドのみ」にすると、コンパイラの本物のエラーだけが表示される（IntelliSense の仮のエラーが混ざらない）
- 「出力」ウィンドウには、エラーの全文（`note` を含む）が出る。エラー一覧では、省略されることがある
- エラー番号にカーソルを合わせて、F1 を押すと、ヘルプが開く

## 直すときの考え方 {#approach}

- 一度に 1 つだけ直して、ビルドする。まとめて直すと、どの直しが効いたか分からない
- 直らないときは、直前に変えた箇所を戻して、差分を見る（[Git の基礎](git.md) で、こまめにコミットしておくと戻れる）
- 型の名前が長いときは、`using` で別名を付けると、メッセージが読みやすくなる
- どうしても分からないときは、エラー全文（番号付き）を検索する

## これだけ覚える {#summary}

- 読むのは最初のエラーだけ。自分のファイルの行番号を探す
- 「から」「に」の型の組、`note` の理由の行に答えがある
- テンプレートのエラーは、`see reference to ...` の後の、自分の行を見る
