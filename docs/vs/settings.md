# C++23 を使えるようにする設定

プロジェクトを作った直後は、C++14 や C++17 の設定になっています。このサイトのサンプルを動かすには、**C++ 言語標準を C++23 に変える**必要があります。あわせて、**文字コード（`/utf-8`）と警告レベル**も最初に設定しておくと、あとで困りません。

!!! tip "ポイント"
    - プロパティを開くときは、左上の **構成**を「**すべての構成**」、**プラットフォーム**を「**すべてのプラットフォーム**」にしてから変更する（Debug だけ変えて Release が C++14 のまま、を防ぐ）。
    - **C/C++ → 言語 → C++ 言語標準** を **ISO C++23 標準**（または **ISO C++ Latest 標準**）にする。
    - **C/C++ → コマンド ライン** に **`/utf-8`** を足して、日本語の文字化けを防ぐ。
    - **警告レベル** は <strong>レベル 4（/W4）</strong>。まず警告を読む癖をつける。
    - 設定は**プロジェクトごと**。新しいプロジェクトを作ったら、毎回やる（または [プロパティ シート](#property_sheet) を使い回す）。

## プロパティを開く

1. ソリューション エクスプローラーで、**プロジェクト名**を右クリック → **プロパティ**（または Alt + Enter）
2. 左上の **構成** を **すべての構成**、**プラットフォーム** を **すべてのプラットフォーム**（または x64）に切り替える
3. 左のツリーから項目を選んで、右側で値を変える
4. **適用** → **OK**

!!! warning "構成を切り替えてから変更する"
    プロパティ画面を開いた直後は、「アクティブ（Debug）」と「x64」だけが選ばれていることが多いです。そのまま変えると、**Release ビルドには反映されません**。必ず、先に「すべての構成」に切り替えます。

## C++ 言語標準

| 場所 | 値 |
| --- | --- |
| **C/C++ → 言語 → C++ 言語標準** | <strong>ISO C++23 標準 (/std:c++23preview)</strong> または <strong>ISO C++ Latest 標準 (/std:c++latest)</strong> |

| Visual Studio のバージョン | 選ぶもの |
| --- | --- |
| 2022（17.x） | <strong>ISO C++ Latest 標準（/std:c++latest）</strong>。新しいバージョンでは「ISO C++23 標準（/std:c++23preview）」もある |
| 2026（18.x） | <strong>ISO C++23 標準（/std:c++23）</strong> |

`/std:c++latest` は「そのバージョンで使える、一番新しい機能を全部有効にする」設定です。C++23 の機能（`<print>`、`<expected>`、`std::flat_map` など）を、コンパイラが対応している範囲で使えるようになります。

同じ画面の、**準拠モード**（`/permissive-`）は「**はい**」のままにします（規格に厳密になり、あいまいなコードがエラーになる）。

!!! note "使える機能は Visual Studio のバージョンで変わる"
    `/std:c++latest` にしても、Visual Studio 自体が古いと使えない機能があります。

    | 機能 | 使える Visual Studio |
    | --- | --- |
    | `<print>` / `std::println` | 2022 17.7〜 |
    | `<expected>` | 2022 17.3〜 |
    | `<mdspan>` | 2022 17.9〜 |
    | `std::flat_map` / `std::flat_set` | 2026 18.x（バージョンは各ページで確認） |
    | `std::generator` | 2022 17.6〜 |

    各ページの「コンパイラ対応」の表も見てください。

## 文字コード（/utf-8） {#utf8}

C++ のソースコードに日本語を書くと、MSVC は**既定ではソースファイルを Shift_JIS（CP932）として読みます**。ファイルが UTF-8 で保存されていると、日本語の文字列が文字化けしたり、`warning C4819`（ファイルは現在のコードページで表示できない文字を含んでいます）が出たりします。

**`/utf-8`** オプションを付けると、ソースも実行時の文字コードも **UTF-8** になり、このサイトのサンプルが期待どおり動きます。

| 場所 | 入れる値 |
| --- | --- |
| **C/C++ → コマンド ライン → 追加のオプション** | `/utf-8` |

- 文字列リテラルは UTF-8 になります。`std::println("こんにちは")` が正しく出ます
- コンソール（黒い画面）が文字化けするときは、実行する前に `chcp 65001` を打つか、Windows Terminal を使います（[よくあるエラー](errors.md#mojibake)）
- ソースファイルを UTF-8（BOM なし）で保存します。「ファイル → 名前を付けて保存 → 保存 ▼ → エンコード付きで保存」で選べます。`.editorconfig` で統一もできます（[便利な機能](tips.md#editorconfig)）

## 警告レベル

| 場所 | 値 |
| --- | --- |
| **C/C++ → 全般 → 警告レベル** | <strong>レベル 4 (/W4)</strong> |
| C/C++ → 全般 → 警告をエラーとして扱う | 最初は「いいえ」。慣れたら「はい (/WX)」 |

- 警告（`warning C4xxx`）は、**バグの予告**です。`int` と `size_t` の比較（符号の違い）、使っていない変数、`float` への暗黙の変換、などが出ます
- 外部ライブラリのヘッダが大量に警告を出すときは、**ライブラリのヘッダを `外部インクルード ディレクトリ` に置いて、外部ヘッダの警告を無効にします**（[外部ライブラリの入れ方](libraries.md#external_include)）

## その他のよく変える設定

| 場所 | 設定 | おすすめ | 意味 |
| --- | --- | --- | --- |
| C/C++ → 全般 | マルチ プロセッサによるコンパイル | <strong>はい (/MP)</strong> | 複数のコアで並列にコンパイルして、ビルドが速くなる |
| C/C++ → 全般 | SDL チェック | はい (/sdl) | セキュリティのチェックを足す。学生のうちは「はい」でよい |
| C/C++ → 最適化 | 最適化（Debug） | 無効 (/Od) | デバッグしやすい（変数が消えない） |
| C/C++ → 最適化 | 最適化（Release） | 速度を優先 (/O2) | 製品用。速い |
| C/C++ → コード生成 | ランタイム ライブラリ | Debug は /MDd、Release は /MD | ライブラリとそろえる（[よくあるエラー](errors.md#runtime_library)） |
| C/C++ → 全般 | アドレス サニタイザーを有効にする | Debug だけ「はい」 | メモリのバグを実行時に見つける（[デバッグ](debugging.md#asan)） |
| リンカー → システム | サブシステム | コンソール (/SUBSYSTEM:CONSOLE) | `main` から始める。ウィンドウだけなら「Windows」 |
| 全般 | 出力ディレクトリ | `$(SolutionDir)bin\$(Configuration)\` | 実行ファイルの置き場所 |
| 全般 | 中間ディレクトリ | `$(SolutionDir)obj\$(ProjectName)\$(Configuration)\` | 途中のファイルの置き場所 |

## 構成とプラットフォーム

画面上の工具バーに「**Debug**」「**x64**」というドロップダウンがあります。

| 構成 | 目的 | 特徴 |
| --- | --- | --- |
| **Debug** | 開発中 | 最適化なし。デバッグ情報あり。`assert` が有効。**遅いが、バグを見つけやすい** |
| **Release** | 製品・速度の確認 | 最適化あり。`assert` が無効。**速い** |

- **x64** を選びます。Win32（32 ビット）は、古い環境向けです
- **Debug で動くのに Release でおかしくなる**ときは、初期化していない変数や、未定義動作を疑います（[未定義動作](../basics/ub.md)）
- ゲームの速さを測るのは、**必ず Release** で行います（Debug は何倍も遅くなります）

## プロパティ シートで設定を使い回す {#property_sheet}

プロジェクトを作るたびに同じ設定をするのは大変です。**プロパティ シート**（`.props` ファイル）に設定を書いて、複数のプロジェクトで共有できます。

1. メニュー → **表示 → その他のウィンドウ → プロパティ マネージャー**
2. プロジェクトを右クリック → **新しいプロジェクト プロパティ シートの追加** → `Common.props` という名前で保存
3. 作った `Common.props` を右クリック → プロパティ → 上の設定（C++23、/utf-8、/W4 など）を入れる
4. ほかのプロジェクトでは、プロパティ マネージャーで **既存のプロパティ シートの追加** から、同じ `Common.props` を選ぶ

## 設定が反映されているか確認する

プロジェクトのプロパティ → **C/C++ → コマンド ライン** を開くと、実際にコンパイラに渡されるオプションが一覧で見えます。`/std:c++latest` と `/utf-8`、`/W4` が入っていれば成功です。

次のコードがビルドできて、実行すると文字が出れば、C++23 と `/utf-8` が効いています。

```cpp
#include <print>

int main() {
  std::println("C++23 で日本語が出ました");
}
```

```text title="実行結果"
C++23 で日本語が出ました
```

- `error C2039: 'println': は 'std' のメンバーではありません` や、`<print>` が開けないと言われたら、**C++ 言語標準**が古いか、Visual Studio が古いです
- 日本語が `繧ｳ繝ｳ` のような文字になったら、`/utf-8` が効いていません（[文字化け](errors.md#mojibake)）
