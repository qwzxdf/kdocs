# 座標系

3D の世界の位置を数字で表すには、**座標系**（軸の決め方）が必要です。ところが、座標系には**いくつかの流儀**があり、ゲーム エンジンやライブラリごとに違います。X が右、Y が上、Z が前（奥）なのか、手前なのか。回転の正の向きは、どっち回りか。これが食い違うと、**左右が反転する、モデルが裏返る、回転が逆になる**といった、不思議なバグになります。このページは、座標系の流儀を整理し、**自分のゲームで何を使うかを決めて、そろえる**ための知識をまとめます。

!!! tip "ポイント"
    - <strong>左手系 / 右手系</strong>と、<strong>どの軸が上か</strong>（Y-up か Z-up か）の、2 つを決める。
    - <strong>Direct3D 自体は、手系を決めていない。</strong><strong>DirectXMath は左手・右手の両方</strong>、<strong>SimpleMath と OpenGL と glm の既定は右手系・Y-up</strong>、<strong>Unity は左手系・Y-up</strong>、<strong>Unreal は左手系・Z-up</strong>、<strong>Blender は右手系・Z-up</strong>。
    - <strong>外から読み込んだモデルや数式は、座標系が違う</strong>ことがある。<strong>境界で変換</strong>する。
    - <strong>行列の規約</strong>（行ベクトルか列ベクトルか）も、座標系とは別に、そろえる。
    - ゲーム内の<strong>単位</strong>（1 ＝ 1 メートル）も、最初に決める。

## 右手系と左手系

3 つの軸（X、Y、Z）の向きを、**手の形**で覚えます。

| 系 | X | Y | Z | 覚え方 |
| --- | --- | --- | --- | --- |
| **左手系** | 右 | 上 | **奥**（画面の向こう） | 左手の親指＝X、人差し指＝Y、中指＝Z。**Z が奥へ伸びる** |
| **右手系** | 右 | 上 | **手前**（自分の方） | 右手で同じ。**Z が手前へ伸びる** |

```text
左手系（Unity など）         右手系（OpenGL / SimpleMath。Blender は Z-up）
        Y                                Y
        │   Z（奥）                       │
        │  /                              │
        │ /                               │______ X
        └────── X                        /
                                        /  Z（手前）
```

**同じ座標 (1, 2, 3) でも、系が違えば、別の場所**を指します。系を変換するには、**どれか 1 つの軸を反転**します（たとえば Z の符号を逆にする）。

## 回転の向き

| 系 | 正の回転 |
| --- | --- |
| **右手系** | 軸の**正の方向から見て、反時計回り**（右ねじの向き） |
| **左手系** | 軸の正の方向から見て、**時計回り** |

座標系を変えると、**回転の向きも逆になります**。右手系のライブラリが出した「+30 度」を、左手系にそのまま使うと、逆向きに 30 度になります。

## 上方向の軸（Y-up と Z-up）

| 流儀 | 上 | 前 | 使われているもの |
| --- | --- | --- | --- |
| **Y-up** | Y | Z（左手系は奥、右手系は手前） | DirectX、OpenGL、Unity、Godot、多くのゲーム |
| **Z-up** | Z | Y または X | Unreal Engine、Blender、CAD、3ds Max |

Z-up は、「床の平面が XY」で、地図のように考えやすい流儀です。Y-up は、「ゲームのキャラは Y が上」と直感的です。

## エンジン・ツールごとの座標系

| 名前 | 系 | 上 | 前（カメラが見る方向） | 備考 |
| --- | --- | --- | --- | --- |
| **DirectXMath** | **`LH` と `RH` の両方の関数がある**（選ぶ） | Y | LH なら +Z、RH なら −Z | 行ベクトル |
| **SimpleMath**（DirectX Tool Kit） | **右手系**（既定） | Y | **−Z**（`Vector3::Forward`） | 行ベクトル |
| **OpenGL** | **右手系** | Y | **−Z** | 列ベクトル。ビュー空間では、カメラは −Z を見る |
| **glm** | 右手系（既定）。`GLM_FORCE_LEFT_HANDED` で左手系 | Y | −Z | 列ベクトル |
| **Unity** | 左手系 | Y | +Z | |
| **Unreal Engine** | 左手系 | **Z** | +X | 単位は cm |
| **Godot** | 右手系 | Y | −Z | |
| **Blender** | 右手系 | **Z** | +Y（正面ビュー） | glTF にエクスポートすると Y-up に変換される |
| **glTF**（形式） | 右手系 | Y | +Z（モデルの正面） | |
| **FBX** | ツール次第（保存時の設定に、軸の情報が入る） | | | 読み込み時に、変換が必要なことが多い |

## 変換する

### 左手系 ⇔ 右手系

**1 つの軸を反転**します。普通は Z を反転します（Y-up の場合）。

```cpp
// 右手系 → 左手系（Y-up の場合）：Z の符号を反転
Vector3 RightToLeft(const Vector3& p) {
  return Vector3(p.x, p.y, -p.z);
}
```

| 変換するもの | やること |
| --- | --- |
| **頂点の位置・法線** | Z を反転（法線も同じ） |
| **三角形の巻き方向** | **反転する**（頂点の順序を入れ替える）。鏡像になるので、表裏が逆になるため |
| <strong>回転（クォータニオン）</strong> | 反転した軸に垂直な成分の符号を反転する（Z を反転するなら、x と y の符号を反転）。または、行列で変換 |
| **行列** | 座標系の変換行列で、前後から挟む（変換行列を S として、S × M × S） |

### Z-up ⇔ Y-up

```cpp
// Z-up（Blender）の右手系 → Y-up の右手系：Y と Z を入れ替えて、符号を調整する
Vector3 ZUpToYUp(const Vector3& p) {
  return Vector3(p.x, p.z, -p.y);   // (x, y, z) → (x, z, -y)：Z が上 → Y が上
}
```

実際は、**モデルを読み込むときに、1 回だけ**変換します（アセット変換ツールで、あらかじめ変換しておくのが、おすすめです）。

## 三角形の表裏（巻き方向）

3D のモデルは、三角形でできています。**どちら側が表か**は、頂点の<strong>並び順（巻き方向）</strong>で決まります。

| 規約 | 表の見え方 |
| --- | --- |
| **時計回り（CW）が表** | Direct3D の既定（`FrontCounterClockwise = FALSE`）、左手系でよく使う |
| **反時計回り（CCW）が表** | OpenGL の既定。右手系でよく使う。**このカテゴリはこちら**（Direct3D では `FrontCounterClockwise = TRUE`） |

座標系を変換したら、**巻き方向も反転**します。そうしないと、**表と裏が逆**になり、バックフェイス カリングで、モデルが消えたり、内側が見えたりします。

## 規約をそろえる

| 決めること | 例 |
| --- | --- |
| **座標系** | 右手系・Y-up |
| **単位** | 1 ＝ 1 メートル |
| **行列の規約** | 行ベクトル（`v * M`）か、列ベクトル（`M * v`）か（[行列](matrices.md)） |
| **三角形の巻き方向** | 反時計回りが表 |
| **前方向** | −Z（SimpleMath の `Vector3::Forward`） |
| **回転の単位** | ラジアン（度は、入力と表示だけ） |
| **オイラー角の順序** | Y → X → Z など（[回転](rotation.md)） |

この**決まりを、文書（README や CLAUDE.md）に書いておく**と、チームで迷いません。

## ゲームでの使いどころ

| 場面 | 方法 |
| --- | --- |
| Blender のモデルを、DirectX のゲームに読み込む | エクスポート時に、軸を合わせる（Y-up、前方向）。または、読み込み時に変換 |
| 外部の物理エンジン（Jolt は右手系）を、左手系のゲームで使う | 境界で、Z を反転する。または、物理側も左手系として扱う（座標の意味を、そろえる） |
| 数式を、本から写す | 本の座標系（右手系が多い）と、自分のエンジンが違うことに注意 |
| カメラの前方向 | 右手系は −Z、左手系は +Z。ビュー行列の関数（`LookAtRH` / `LookAtLH`）が違う |
| ImGuizmo | 右手系・列優先を想定（[ImGuizmo](../libs/imgui/imguizmo.md)）。SimpleMath（右手系・行ベクトル）なら、行列を**転置して**渡す |

## よくあるミス

??? failure "モデルが、左右反転して見える"
    座標系が違うモデルを、そのまま読み込んでいます。Z（または X）を反転します。そのとき、**三角形の巻き方向も反転**します。

??? failure "モデルが、裏返って（内側が見える・消える）"
    座標系を変換したのに、巻き方向を変えていません。または、カリングの設定（CW / CCW）が、モデルと合っていません。

??? failure "回転が、逆向きに回る"
    右手系と左手系で、正の回転方向が逆です。ライブラリの規約を確認し、角度の符号を合わせます。

??? failure "モデルが、横に倒れて読み込まれる"
    Z-up のモデルを、Y-up のエンジンに読み込んでいます。軸を入れ替えます（X 軸まわりに 90 度回転）。

??? failure "ライブラリごとに、規約が違うのに、混ぜて使う"
    SimpleMath（右手・行ベクトル）と、左手系の DirectXMath の関数（`...LH`）や、glm（列ベクトル）を混ぜると、混乱します。1 つに決めて、境界で変換します。
