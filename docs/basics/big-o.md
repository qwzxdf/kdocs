# 計算量（O 記法）

<div class="page-badges" markdown>
<span class="rank rank-often">よく使う</span>
</div>

**計算量**は、データの数 n が増えたときに、処理時間がどのくらい増えるかを表す目安です。`O(n)`（オーダー n）のように書きます。`O(1)` なら n が 100 でも 100 万でも時間はほぼ同じ、`O(n)` なら n が 10 倍になると時間も 10 倍、`O(n²)` なら 100 倍になります。コンテナや関数を選ぶときに「データが増えても大丈夫か」を判断するのに使います。

!!! tip "ポイント"
    - 速い順に <strong>O(1) < O(log n) < O(n) < O(n log n) < O(n²)</strong>。
    - ゲームで気をつけるのは、**毎フレーム O(n²) になっていないか**（全員と全員を比べる当たり判定、ループの中で find / erase）。
    - 計算量は「増え方」の目安。n が小さいとき（数十個）は、O(n) の vector が O(1) のハッシュ表より速いことも普通にある。
    - 「償却 O(1)」は「たまに重いけど、平均すると O(1)」という意味（vector の push_back）。

## 基本

| 計算量 | 呼び方 | n = 1,000 のときの手間 | 例 |
| --- | --- | --- | --- |
| O(1) | 定数時間 | 1 | vector の `[]`、`push_back`、unordered_map の検索 |
| O(log n) | 対数時間 | 約 10 | map の検索、ソート済みの二分探索 |
| O(n) | 線形時間 | 1,000 | vector の `find`、全員の更新 |
| O(n log n) | | 約 10,000 | `sort` |
| O(n²) | 2 乗時間 | 1,000,000 | 全員と全員の当たり判定、ループ中の erase |
| O(2ⁿ) | 指数時間 | とても大きい | 全部の組み合わせを試す |

```cpp
#include <print>

int main() {
  for (int n : {10, 100, 1000, 10000}) {
    long long n2 = static_cast<long long>(n) * n;
    std::println("n = {:>5}: O(n) = {:>5} / O(n²) = {:>9}", n, n, n2);
  }
}
```

```text title="実行結果"
n =    10: O(n) =    10 / O(n²) =       100
n =   100: O(n) =   100 / O(n²) =     10000
n =  1000: O(n) =  1000 / O(n²) =   1000000
n = 10000: O(n) = 10000 / O(n²) = 100000000
```

1 フレームは 60 FPS なら約 16 ミリ秒です。O(n²) で n が 1 万だと 1 億回の処理になり、とても間に合いません。

## 詳しく

### コードから計算量を読む

```cpp
// O(1): n に関係なく 1 回
int first = v[0];

// O(n): n 回のループ
for (const auto& e : enemies) {
  e.Update();
}

// O(n²): ループの中にループ
for (auto& a : enemies) {
  for (auto& b : enemies) {
    CheckCollision(a, b);
  }
}

// O(n²) に見えにくい例: ループの中で O(n) の関数を呼ぶ
for (int id : ids) {
  auto it = std::ranges::find(enemies, id, &Enemy::id);  // これ自体が O(n)
}
```

最後の例は、`enemies` を `std::unordered_map<int, Enemy>` にすれば、`find` が O(1) になって全体で O(n) になります。

#### O(1)（定数時間） {#o1}

**データが何個あっても、手間が変わらない**ことです。1000 個でも 100 万個でも、1 回の `[]` アクセスは同じ速さです。「O(1) = 1 回しか計算しない」という意味ではなく、数が増えても増えないという意味です。

- 例: `vector` の `v[i]`、`unordered_map` の検索（平均）、`push_back`（償却）
- 注意: O(1) でも、1 回が重いことがあります（ハッシュの計算が重い、など）。O(1) ＝ いつでも速い、ではありません。

#### O(log n)（対数時間） {#ologn}

データが 2 倍になっても、手間が 1 回ぶんしか増えないことです。1000 個で約 10 回、100 万個でも約 20 回です。半分ずつに絞っていく探し方（二分探索）がこれです。

- 例: `std::map` の検索、`lower_bound`（整列済みの配列での二分探索）、`priority_queue` の `push` / `pop`

#### O(n)（線形時間） {#on}

データが 2 倍になると、手間も 2 倍になることです。全員を 1 回ずつ見る処理がこれです。

- 例: `std::find`、全員の更新ループ、`vector` の `insert` / `erase`（後ろをずらすため）、`std::count_if`

#### O(n log n) {#onlogn}

O(n) より少し重く、O(n²) よりずっと軽い計算量です。「全員を、半分ずつに分けながら処理する」整列がこれです。

- 例: `std::sort`、`std::stable_sort`

#### O(n²)（2 乗時間） {#on2}

データが 2 倍になると、手間が 4 倍になることです。全員と全員を組み合わせる処理がこれです。n が 1 万を超えると、1 フレームでは終わりません。

- 例: 全員と全員の当たり判定、ループの中で毎回 `vector::erase` する、ループの中で毎回 `find` する

### 償却 O(1) {#amortized}

vector の `push_back` は、容量が足りなくなると全要素を引っ越すので、その 1 回だけは O(n) かかります。でも容量は 2 倍ずつ増えるので、引っ越しはめったに起きず、平均すると 1 回あたり O(1) になります。これを「償却 O(1)」と言います。

ゲームでは「平均は速くても、たまに 1 フレームだけ重い」とカクつきになるので、[`reserve`](../stl/containers/vector.md#reserve) で引っ越しを先に済ませておくのが定番です。

### 平均と最悪

| コンテナ | 検索（平均） | 検索（最悪） |
| --- | --- | --- |
| `unordered_map` | O(1) | O(n)（ハッシュがぶつかりまくったとき） |
| `map` | O(log n) | O(log n) |
| `vector`（ソートなし） | O(n) | O(n) |

### 計算量だけで決めない

- キャッシュ効率: vector はデータが連続しているので、O(n) でもとても速く回せます。list や map は O(1) / O(log n) でも、メモリを飛び回るので遅くなりがちです（[キャッシュ効率](cache.md)）。
- 定数倍: O(1) でも、ハッシュの計算に時間がかかれば、n が小さいうちは O(n) の線形探索に負けます。
- n の大きさ: 敵が最大 20 体なら、O(n²) の当たり判定（400 回）でも全然問題ありません。

迷ったら、Release ビルドで実際に時間を測ります。

## ゲームでの例

| 処理 | よくある計算量 | 改善の方向 |
| --- | --- | --- |
| 全オブジェクトの更新 | O(n) | これ以上は減らせない。vector で持つ |
| 当たり判定（総当たり） | O(n²) | 空間分割（グリッド、四分木）で近いものだけ調べる |
| ID で探す | O(n) | `unordered_map<Id, Index>` で O(1) |
| 描画順のソート | O(n log n) | 毎フレームでなく、変化したときだけ |
| ループ中の erase | O(n²) | `std::erase_if` で O(n) |

## よくあるミス

??? failure "ループの中で O(n) の関数を呼ぶ"
    `find`、`erase`、`insert`、`count` などをループの中で使うと、全体が O(n²) になります。

??? failure "計算量の小さいコンテナが必ず速いと思う"
    要素数が少ないと、vector の線形探索のほうが map / unordered_map より速いことはよくあります。

## これだけ覚える

!!! abstract "まとめ"
    - [x] O(1) < O(log n) < O(n) < O(n log n) < O(n²)
    - [x] 毎フレームの O(n²) に注意（ループの中のループ・ループの中の find）
    - [x] 償却 O(1) は「たまに重い」。reserve でカクつきを防ぐ
    - [x] 最後は測って決める
