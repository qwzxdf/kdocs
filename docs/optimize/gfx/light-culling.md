# Tiled と Clustered

[Forward と Deferred](forward-deferred.md)で見たように、**ライトが、多い**と、<strong>「ピクセル × 全ライト」</strong>の計算が、**重く**なります。**ほとんどのライトは、その場所のピクセルに、届かない**（遠い）のに、**全部を、計算**しているからです。<strong>画面を、小さな領域に分けて、「その領域に、影響するライトだけ」</strong>のリストを、**先に作る**——これが、**ライト カリング**です。**Tiled**（画面を、2 次元のタイルに分ける）、**Clustered**（**奥行き方向も、分けて、3 次元**）の、**2 つの方式**を、**Forward と Deferred**の、**それぞれに**適用できます。このページは、**何が、改善するのか**、<strong>目的（計算と帯域）</strong>、**仕組み**、**使い分け**を説明します。

!!! tip "ポイント"
    - 目的：<strong>ピクセルごとに、「近くにあるライトだけ」を、計算</strong>する（<strong>計算量の、削減</strong>）。<strong>G-Buffer を、1 回だけ読む</strong>（<strong>帯域の、削減</strong>）。
    - <strong>Tiled</strong>：<strong>画面を、16×16 ピクセルなどの、タイルに分け</strong>、<strong>タイルごとに、影響するライトの、リスト</strong>を作る（<strong>コンピュート シェーダー</strong>）。
    - <strong>タイルの、奥行きの範囲（最小・最大の深度）</strong>で、さらに絞る。<strong>弱点：奥行きが、大きく変わるタイル（物体の縁）</strong>で、<strong>ライトが、多く残る</strong>。
    - <strong>Clustered</strong>：<strong>奥行き方向も、スライスに分け、3 次元の「クラスター（セル）」</strong>ごとに、ライトのリスト。<strong>奥行きの、不連続に強い</strong>。<strong>半透明・Forward にも、使いやすい</strong>。
    - <strong>Tiled / Clustered Deferred</strong>：<strong>ライティングを、コンピュートで、1 パスで</strong>（<strong>G-Buffer を、1 回だけ読む</strong>）。
    - <strong>Tiled / Clustered Forward</strong>（Forward+）：<strong>Forward で、タイル／クラスターの、ライト リスト</strong>を使う（<strong>MSAA・半透明が、使える</strong>）。

## なぜ、絞るのか

**100 個のライトが、あるシーン**で、**あるピクセルに、実際に届くライトは、数個**です。**全 100 個を、計算するのは、無駄**です。

| **スケーラビリティ** | **ライトを、数千個**にしても、**ピクセルあたりの、負担が増えない** |

## Tiled（タイル分割）

### 仕組み

n cull ライトを_タイルの形と判定 3 1

</div>

| 手順 | 内容 |
| --- | --- |
| **1. 画面を、タイルに分ける** | **16×16 ピクセル**が、定番（**1920×1080 なら、約 8000 タイル**） |
| **2. タイルの深度の範囲を、求める** | **タイル内の、最小深度・最大深度**（**コンピュート シェーダーで、リダクション**） |
| **3. タイルの形（視錐台）を作る** | **タイルの 4 辺と、最小・最大深度**で囲まれた、**小さな視錐台** |
| **4. ライトを、判定** | **各ライト（球）が、タイルの視錐台と、交わるか** |
| **5. リストに、追加** | **交わるライトの番号を、タイルのリスト**に（共有メモリ → バッファ） |
| **6. ピクセルは、リストを読む** | **自分のタイルの、ライトだけ**を、計算 |

**コンピュート シェーダー**で、**タイル ＝ 1 つのスレッド グループ**として、<strong>共有メモリ（groupshared）</strong>に、**リストを作ります**。**スレッドが、手分けして、ライトを判定**するので、**速い**です。

### 利点

| 利点 | 説明 |
| --- | --- |
| **計算が、劇的に減る** | **ピクセルあたり、数個のライト** |
| **Deferred：G-Buffer を、1 回だけ読む** | **ライティング パスが、1 つ**（コンピュートで、全ライトを、まとめて処理）。**ライトごとの、フルスクリーン ブレンドが、不要** |
| **ブレンド（加算）が、不要** | **ピクセルが、全ライトの合計を、レジスタ内**で、計算し、**1 回だけ、書き込む**（**帯域**） |

### 弱点

| 弱点 | 説明 |
| --- | --- |
| **深度の不連続** | **タイル内に、近い物と遠い物**（物体の縁）があると、**最小〜最大の深度が、広く**なり、**ライトが、多く残る**（**無駄が、出る**） |
| **半透明** | **深度バッファが、不透明のみ**なので、**半透明の位置は、考慮されない**（**別の対策が、必要**） |
| **奥行きの情報が、粗い** | **2.5 次元**（画面方向のみ、奥行きは、min/max の 1 区間） |

**この弱点を、解決するのが、Clustered** です。

## Clustered（クラスター分割）

**画面を、2 次元のタイルだけでなく、奥行き方向にも、分割**します。<strong>3 次元の、小さなセル（クラスター）</strong>ごとに、**ライトのリスト**を持ちます。

### 奥行きの分け方

**奥行きは、対数スケール**で、スライスに分けます。**近くは細かく、遠くは粗く**（**見た目の、大きさに合わせる**）。

```text
スライス番号 ＝ floor( log(z / near) / log(far / near) × スライス数 )
```

| 項目 | 説明 |
| --- | --- |
| **スライス数** | **24〜32** が、よく使われる |
| **対数分割の、理由** | **透視投影で、遠くは、ピクセルあたりの奥行きが大きい**ため、**画面上の、均等な大きさに、近づく** |
| **クラスターの総数** | **例**：**タイル 120×68 × 24 スライス ＝ 約 20 万**（**タイルを大きくして、減らす**ことも） |

### 利点

| 利点 | 説明 |
| --- | --- |
| **奥行きの不連続に、強い** | <strong>「近い物」と「遠い物」が、別のセル</strong>になるので、**ライトが、無駄に残らない** |
| **深度プリパスが、不要** | **タイルの min/max 深度を、求める必要が、ない**（**画面の位置と深度から、セルが決まる**） |
| **半透明が、扱える** | **半透明の、深度から、セルを引ける**（**不透明の深度に、依存しない**） |
| **Forward と、相性が良い** | **Forward でも、セルのライト リストを、読むだけ** |
| **ボリューム効果にも使える** | **霧・ボリュメトリック ライト**の、計算単位にも |

### 弱点

| 弱点 | 説明 |
| --- | --- |
| **メモリが、増える** | **クラスターの数 × リストの大きさ** |
| **構築のコスト** | **クラスターごとに、ライトを判定**（**数が多い**）。**コンピュートで、並列化** |
| **実装が、やや複雑** | **スライスの計算・リストの管理** |

## ライト リストの、データ構造

**クラスター／タイルごとに、ライトの番号の、リスト**を持ちます。

| 構造 | 内容 |
| --- | --- |
| **ライト バッファ** | **全ライトの、情報**（位置・色・半径）の配列 |
| **ライト インデックス リスト** | <strong>「セルごとの、ライト番号」を、1 本の配列に、詰めたもの</strong> |
| **グリッド** | <strong>セルごとに、「リストの開始位置」と「個数」</strong> |
| <strong>カウンター（UAV）</strong> | **コンピュートが、リストに、書き込む位置**（アトミック加算） |

```text
グリッド[セル] → (開始位置, 個数)
ライト インデックス リスト[開始位置 .. 開始位置+個数] → ライト番号 → ライト バッファ[ライト番号]
```

<strong>ピクセルシェーダー（またはコンピュート）</strong>は、**グリッドを引いて、リストを読み、ライトを計算**します。

## 4 つの組み合わせ

| | **Forward 系**（色を、物体を描きながら） | **Deferred 系**（G-Buffer から） |
| --- | --- | --- |
| **Tiled** | <strong>Tiled Forward（Forward+）</strong>：**深度プリパス → ライト カリング（コンピュート）→ Forward 描画**。**MSAA・半透明が、使える** | **Tiled Deferred**：<strong>G-Buffer → ライト カリング ＋ ライティング（コンピュート 1 パス）</strong> |
| **Clustered** | **Clustered Forward**：**クラスターのライト リストを、Forward で読む**。**半透明に強い** | **Clustered Deferred**：**G-Buffer ＋ クラスターで、ライティング** |

### それぞれの使いどころ

| 方式 | 向く場面 |
| --- | --- |
| **Tiled Deferred** | **PC・コンソール**の、**不透明中心**。**帯域に、余裕がある** |
| <strong>Tiled Forward（Forward+）</strong> | **MSAA が欲しい・材質を、自由に**したい |
| **Clustered Forward** | **半透明・ボリューム効果**を、ライトに反応させたい。**VR** |
| **Clustered Deferred** | **大規模・ライトが、非常に多い** |

**現在の多くのゲームは、Clustered（または Tiled）を、Forward か Deferred と組み合わせて**います。**ハイブリッド**（**不透明は Deferred、半透明は Clustered Forward**）も、**一般的**です。

## 実装の注意

| 注意 | 説明 |
| --- | --- |
| **コンピュート シェーダーが、必要** | **DX11 は、コンピュート シェーダー（`CSMain`）を使える**（**Feature Level 11 以上**） |
| **タイルの大きさ** | **16×16 が、多い**。**小さい**と、**精度が上がるが、タイル数が増える** |
| **ライトの上限** | **タイル／クラスターあたりの、最大ライト数**を決める（**超えたら、切り捨て**） |
| **ライトの半径** | <strong>「影響範囲」</strong>を、**適切に決める**（**大きすぎる**と、絞れない） |
| **影** | **影付きライトは、別に**（**影マップの、コスト**。[そのほかの最適化](others.md)） |
| <strong>半透明（Tiled）</strong> | **深度の範囲が、不透明のみ**。**半透明は、全ライト、または、Clustered** |

## 手法の進化と、改善点（まとめ）

| 手法 | ピクセルあたりの、ライティング | G-Buffer の読み込み | 弱点 |
| --- | --- | --- | --- |
| **Forward** | <strong>全ライト（オーバードロー込み）</strong> | なし | **ライトが、多いと、重い** |
| <strong>Deferred（ライト ボリューム）</strong> | **範囲内のライト** | **ライトごとに、読み直し** | **帯域**・MSAA・半透明 |
| **Tiled Deferred** | **タイルのライト** | **1 回** | **深度の不連続** |
| **Clustered** | **セルのライト** | **1 回**（Deferred の場合） | **メモリ・構築コスト** |

<strong>「ライトを、絞る」「G-Buffer を、1 回だけ読む」</strong>——この**2 つの積み重ね**で、**数千のライト**に、**対応**してきました。

## よくあるミス

??? failure "タイルの深度範囲に、半透明を、含めて、計算が崩れる"
    **不透明の深度**だけで、**min/max**を作ります。**半透明は、別処理**。

??? failure "ライトの半径を、大きくしすぎて、リストが、あふれる"
    **影響範囲を、実際の減衰に合わせて、小さく**します。**上限の数も、確認**します。

??? failure "Tiled で、物体の縁に、ライトの、ちらつきが出る"
    **深度の不連続**が原因のことがあります。**Clustered**にする、**タイルを小さく**する。

??? failure "クラスターのスライスを、線形に分けて、近くが粗くなる"
    **対数スケール**で、分けます。

??? failure "ライト リストの、書き込みで、競合する"
    **アトミック加算**（`InterlockedAdd`）で、**位置を確保**します。
