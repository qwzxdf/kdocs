# オーバードロー

**オーバードロー**は、**同じピクセルに、何度も、色を計算して、書くこと**です。**手前の物体で、隠れてしまう、奥の物体の、ピクセルシェーダーは、結果が、捨てられる**ので、**まるごと、無駄**です。**ピクセル処理・帯域幅が、ボトルネック**のときに、**効きます**。このページは、**オーバードローの何が、無駄なのか**、**Early-Z・Z プリパス・並べ替え**、<strong>小さな三角形の無駄（quad overdraw）</strong> を、説明します。

!!! tip "ポイント"
    - <strong>オーバードロー</strong> ＝ <strong>1 ピクセルに、複数回、ピクセルシェーダーを動かす</strong>。<strong>最後に見える、1 回以外は、無駄</strong>。
    - <strong>Early-Z</strong>：<strong>ピクセルシェーダーの前に、深度テスト</strong>。<strong>隠れていれば、シェーダーを、動かさない</strong>（<strong>ハードウェアの、自動の最適化</strong>）。
    - <strong>Early-Z が、効く条件</strong>：<strong>手前から奥の順に、描く</strong>。<strong>`discard`・深度の書き換えが、ない</strong>。
    - <strong>Z プリパス</strong>：<strong>先に、深度だけを描き</strong>、<strong>次に、色のパスで、隠れた所を、シェーダーに通さない</strong>。<strong>オーバードローが、ほぼ、1 になる</strong>。
    - <strong>半透明</strong>は、<strong>オーバードローが、避けられない</strong>。<strong>パーティクルは、特に重い</strong>。
    - <strong>小さな三角形</strong>は、<strong>2×2 ピクセル単位の実行</strong>のため、<strong>無駄が、大きい</strong>（<strong>quad overdraw</strong>）。

**オーバードロー率**（1 ピクセルあたりの、平均実行回数）が、**2〜3 倍**なら、**ピクセル処理が、2〜3 倍の無駄**です。**可視化ツール**（PIX・RenderDoc・エンジンの、オーバードロー表示）で、**確認**できます。

## Early-Z

**GPU は、通常、ピクセルシェーダーの「前」に、深度テスト**を行います。**すでに手前のものが描かれていれば、シェーダーを、動かさずに、捨てます**。

| 点 | 説明 |
| --- | --- |
| **自動** | **特別なコードは、不要** |
| **描く順番に、依存** | **奥から描くと、効かない**（まだ、深度が、書かれていないため） |
| **効かなくなる条件** | **シェーダー内の `discard`（クリップ）・`SV_Depth` の書き込み・UAV への書き込み**（**Early-Z を、無効化**することがある） |

**不透明物を、手前から奥へ、おおまかに、ソート**すると、**Early-Z が、よく効きます**（**ドロー コールの、ソートとの、兼ね合い**。[ドロー コール](draw-calls.md)）。

## Z プリパス（深度プリパス）

<strong>まず、全不透明物を、「深度だけ」</strong>描き（**ピクセルシェーダーなし**、**非常に軽い**）、<strong>次に、色のパスで、深度テストを「等しい（`EQUAL`）」</strong>にして、**描きます**。

| 段階 | 内容 |
| --- | --- |
| **① 深度パス** | **頂点シェーダーのみ**。**深度バッファを、完成させる** |
| **② 色のパス** | **深度が、完成済み**なので、**見える面だけ**、**ピクセルシェーダーが、動く**（**オーバードロー ≒ 1**） |

| 利点 | 欠点 |
| --- | --- |
| **ピクセルシェーダーが、重いとき、大きく減る** | **ジオメトリを、2 回、処理する**（頂点・ドロー コールが、増える） |
| **Forward+ で、ほぼ、必須**（深度が、ライト カリングに、必要） | **頂点処理が、重いとき、逆効果** |
| **Deferred の、G-Buffer 書き込みも、減る** | |

**Tiled / Clustered**（[ライトのカリング](light-culling.md)）は、**深度を、先に使う**ので、**Z プリパスと、自然に、組み合わさります**。

## 半透明のオーバードロー

**半透明**（煙・炎・ガラス・パーティクル）は、**奥の物を、見せる**必要があり、**Early-Z で、捨てられません**。**重なった数だけ、計算**されます。

| 問題 | 対策 |
| --- | --- |
| **大きな、パーティクルが、画面を覆う** | **縮小バッファに、描く**（[縮小バッファの効果](low-res-effects.md)） |
| **枚数が、多い** | **枚数を、減らす・小さくする** |
| <strong>透明部分が、多い（四角の板に、小さな煙）</strong> | **ポリゴンを、形に沿って、切り詰める**（トリミングしたメッシュ） |
| **シェーダーが、重い** | **軽いシェーダー**を、使う（**パーティクルは、安く**） |

**半透明の、オーバードローを、色で可視化**（**重なるほど、明るく**）すると、**重い場所**が、**一目で、分かります**。

## 小さな三角形の無駄（Quad Overdraw）

**GPU は、ピクセルを、2×2 の、4 ピクセル（クアッド）単位で、実行**します（**微分＝ミップ選択のため**）。**三角形が、小さい**と、**4 ピクセルのうち、実際に、三角形に入るのは、1〜2 個**で、**残りは、捨てられる、無駄な計算**です。

| 三角形の大きさ | 無駄 |
| --- | --- |
| <strong>大きい（数十ピクセル）</strong> | **ほぼ、なし** |
| **1〜数ピクセル** | **最大 4 倍の、無駄**（**1 ピクセルの三角形でも、4 ピクセル分、実行**） |

| 対策 | 説明 |
| --- | --- |
| **LOD** | **遠い物は、三角形を、減らす**（[カリング](culling.md)） |
| **Visibility Buffer** | **ID パスのシェーダーを、軽く**（[Visibility Buffer](visibility-buffer.md)） |
| **ソフトウェア ラスタライズ** | **コンピュートで、小さな三角形を、直接、描く**（**Nanite**） |
| **メッシュの設計** | **細長い三角形を、避ける**（**クアッドを、無駄にしやすい**） |

## タイル型 GPU（モバイル）

**モバイルの、タイル型 GPU**は、**タイル内で、隠面除去**（**HSR・TBDR**）を行う機種があり、**オーバードローの、コストが、小さい**です。**ただし、半透明は、同じく重い**（[メモリ帯域幅](bandwidth.md)）。

## よくあるミス

??? failure "奥から手前へ、不透明物を描いている"
    **Early-Z が、効きません**。**手前から**（おおまかに）描きます。

??? failure "全ての物に、`discard` を使って、Early-Z が、無効になる"
    **アルファ テストの物だけ、別に**、**最後に**描きます。

??? failure "頂点が、ボトルネックなのに、Z プリパスを、入れる"
    **頂点処理が、2 倍**になり、**逆効果**です。**測って**から。

??? failure "半透明の、パーティクルが、画面全体を覆って、重い"
    **縮小バッファ**に描き、**枚数を、減らします**。

??? failure "オーバードローを、見ずに、シェーダーだけ、最適化する"
    **オーバードロー表示**で、**重い場所**を、確認します。
