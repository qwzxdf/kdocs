# Hi-Z とスクリーン空間トレース

<strong>Hi-Z（階層的な深度、HZB）</strong> は、**深度バッファを、ミップマップのように、縮小していった、階層構造**です。<strong>縮小するときに、「4 画素のうち、最も奥（最大）の深度」</strong>を取るので、<strong>「この範囲の中に、これより手前の物は、ない」</strong>ことが、**1 回の読み込みで**、分かります。この性質が、**2 つの用途**を、支えます。**① オクルージョン カリング**（物体が隠れているか）、**② スクリーン空間レイトレース**（SSR・AO の、高速な、光線の進行）。このページは、**Hi-Z の作り方**、**カリングでの使い方**、**トレースでの使い方**を、説明します。

!!! tip "ポイント"
    - <strong>Hi-Z</strong> ＝ <strong>深度の、ミップ チェーン</strong>。<strong>各レベルが、「その範囲で、最も奥の深度」</strong>（<strong>最大</strong>）。
    - <strong>カリング</strong>：<strong>物体の境界を、画面に投影し、適切なミップを 1〜4 回読む</strong>だけで、<strong>「完全に、隠れているか」</strong>が、分かる。
    - <strong>トレース</strong>：<strong>光線が、深度の、どこにも当たらない範囲を、一気に飛ばせる</strong>（<strong>大きなミップで、大股に進み</strong>、<strong>近づいたら、細かいミップに、降りる</strong>）。
    - 目的：<strong>1 ピクセルずつ、細かく歩く（リニア マーチ）の、サンプル数を、激減</strong>。
    - 注意：<strong>前フレームの深度を使うと、遅れる</strong>（<strong>2 パス</strong>で解決）。<strong>画面外・隠れた物は、分からない</strong>（<strong>スクリーン空間の、限界</strong>）。

## Hi-Z の作り方

**深度バッファから、コンピュート シェーダーで、ミップを、1 段ずつ、作ります**。**各ミップの 1 ピクセルは、下の段の、2×2 の、最大深度**です。

| 点 | 説明 |
| --- | --- |
| **最大（最も奥）を取る** | <strong>「隠れている」判定を、保守的（安全）に</strong>するため |
| **リバース Z の場合** | **深度の向きが、逆**なので、**最小**を取る |
| **作成コスト** | **全ミップで、約 0.1〜0.3 ms**（**1080p**・目安） |
| **非 2 のべき乗** | **奇数サイズ**の端に、**注意**（縁の画素を、取りこぼさない） |

## オクルージョン カリングでの使い方

**物体の境界（球・箱）を、画面に投影**し、**画面上の、大きさ**を求め、**それに、見合うミップを、読みます**。

| 手順 | 内容 |
| --- | --- |
| **① 投影** | **境界箱の 8 頂点を、画面に投影**し、**画面上の、矩形と、最も手前の深度**を得る |
| **② ミップを選ぶ** | **矩形が、1〜2 画素に収まる**ミップを選ぶ（`log2(矩形の大きさ)`） |
| **③ 読む** | **矩形の、4 隅（最大 4 回）のサンプル**の、**最大深度**を得る |
| **④ 比較** | **物体の、最も手前の深度 ＞ Hi-Z の最大深度** なら、**完全に隠れている** → **除外** |

**境界箱 1 つの判定が、数回の、テクスチャ読み込み**で、済みます。**GPU Driven で、数万個を、並列に判定**できます（[GPU Driven](gpu-driven.md)・[カリング](culling.md)）。

**前フレームの深度**を使うときは、**カメラの動きによる遅れ**に、**注意**（**2 パス**で、解決）。

## スクリーン空間トレースでの使い方

**SSR（画面内の反射）・SSAO・SSGI・コンタクト シャドウ**などは、**画面の深度バッファの上で、光線を進めて、当たりを探します**。

| 方法 | 説明 |
| --- | --- |
| **リニア マーチ** | **一定の歩幅で、少しずつ進める**。**歩幅が大きいと、薄い物を、すり抜ける**。**小さいと、サンプル数が、爆発** |
| **Hi-Z トレース** | **大きなミップで、大股に進み、障害物に近づいたら、細かいミップに、降りる** |

| 点 | 説明 |
| --- | --- |
| **空いた空間は、飛ばす** | <strong>「この範囲に、障害物はない」</strong>と、**1 回で分かる** |
| **障害物の近くだけ、細かく** | **サンプル数が、画面の複雑さに、比例**（**距離に、比例しない**） |
| **効果** | **SSR の光線あたりの、サンプル数が、数十 → 数回** |

### スクリーン空間の限界

| 限界 | 説明 |
| --- | --- |
| **画面外の情報は、ない** | **画面の端で、反射・AO が、消える** |
| **隠れた物の、情報は、ない** | **柱の裏側など、見えない面**は、**分からない**（**厚みの、仮定が必要**） |
| **深度の薄い物** | **すり抜けやすい** |

**足りない部分は、環境マップ（キューブマップ）・レイトレーシング**で、**補います**。

## 縮小バッファと、組み合わせる

**SSR・AO は、半分解像度**で、**Hi-Z トレース**を行い、**深度を考慮して拡大**すれば、**さらに安くなります**（[縮小バッファの効果](low-res-effects.md)）。

## よくあるミス

??? failure "Hi-Z に、最小を取って（向きを間違えて）、カリングが、不正確になる"
    **深度の向き**（通常 Z / リバース Z）に、**合わせます**。

??? failure "前フレームの Hi-Z で、急な動きに、ポップインする"
    **2 パス方式**にします（[GPU Driven](gpu-driven.md)）。

??? failure "SSR で、画面端に、不自然な、欠けがある"
    **画面端で、フェード**させ、**環境マップへ、切り替え**ます。

??? failure "リニア マーチの歩幅が、大きく、薄い物を、すり抜ける"
    **Hi-Z トレース**、または、**厚みの、仮定**を、入れます。
