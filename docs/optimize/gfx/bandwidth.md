# メモリ帯域幅

**メモリ帯域幅**（バンド幅、bandwidth）は、**GPU が、メモリ（VRAM）と、データをやり取りできる、速さ**（1 秒あたりの量。たとえば **256 GB/s**）です。**描画が重い**理由の、**大きな割合**が、**計算ではなく、メモリの読み書き**です。**Deferred・G-Buffer・高解像度・ポストエフェクト**が、**帯域を、食う**ので、**多くの最適化**（**Tiled・Visibility Buffer・低解像度・フォーマットの工夫**）の**目的は、「帯域を、減らす」こと**です。このページは、**帯域とは何か**、**何が帯域を使うか**、**計算の仕方**、**減らす方法**をまとめます。

!!! tip "ポイント"
    - 帯域は<strong>「1 フレームで、メモリを、読み書きできる量」の上限</strong>。<strong>60 FPS で、256 GB/s なら、1 フレームあたり約 4.3 GB</strong>。
    - 帯域を使うもの：<strong>レンダーターゲットの書き込み・読み込み、G-Buffer、テクスチャ、頂点・インデックス、深度、ポストエフェクト</strong>。
    - <strong>ピクセルあたりのバイト数 × ピクセル数 × 回数</strong>で、<strong>概算</strong>できる。
    - 減らし方：<strong>フォーマットを小さく・パッキング・圧縮・低解像度・読み書き回数を減らす・キャッシュに乗せる</strong>。
    - <strong>モバイル GPU（タイル型）</strong>は、<strong>帯域が、さらに貴重</strong>（<strong>オンチップ メモリ</strong>を活かす）。
    - <strong>「計算を、増やして、メモリを減らす」</strong>が、近年の<strong>定番の方針</strong>。

## 帯域とは

**GPU が、1 つのピクセルを塗るためには、メモリから、データを読み**（テクスチャ・G-Buffer）、**結果を、メモリに書き**（レンダーターゲット）ます。**この「運ぶ量」が、帯域の消費**です。

| 用語 | 意味 |
| --- | --- |
| <strong>帯域幅（GB/s）</strong> | **1 秒に、運べる、データの量** |
| **レイテンシ** | **データが、届くまでの待ち時間**（帯域とは別） |
| **オンチップ** | **GPU の中にある、小さくて、超高速なメモリ**（キャッシュ・タイルメモリ） |
| **VRAM** | **GPU の外にある、大容量メモリ**（帯域が、ボトルネック） |

## 帯域を使うもの

| 項目 | 内容 |
| --- | --- |
| **カラー（RT）の書き込み** | **ピクセル × フォーマットのバイト数**（RGBA8 は 4 バイト、RGBA16F は 8 バイト） |
| <strong>ブレンド（半透明）</strong> | **読み込み ＋ 書き込み**（**2 倍**） |
| **深度の読み書き** | **深度テスト（読み）・書き込み** |
| **G-Buffer** | **複数のレンダーターゲットを、同時に書き込み**（Deferred） |
| **G-Buffer の読み込み** | **ライティングの、たびに読む** |
| **テクスチャ** | **サンプリングごとの読み込み**（**ミップ・圧縮で、軽減**） |
| **頂点・インデックス** | **ジオメトリの読み込み** |
| **ポストエフェクト** | **フルスクリーンごとに、画面全体を、読んで書く** |
| **MSAA** | **サンプル数 × 書き込み・読み込み** |

## 数字で見積もる

<strong>1920×1080（約 207 万ピクセル）</strong>で、**目安**を計算します。

| 項目 | 計算 | 1 フレームの量 |
| --- | --- | --- |
| **カラー RGBA8 の書き込み 1 回** | 207 万 × 4 B | 約 8 MB |
| **カラー RGBA16F の書き込み 1 回** | 207 万 × 8 B | 約 16 MB |
| **深度 D32 の書き込み 1 回** | 207 万 × 4 B | 約 8 MB |
| **G-Buffer（RGBA8 × 4 枚）の書き込み** | 207 万 × 16 B | **約 33 MB** |
| **G-Buffer ＋ 深度の読み込み 1 回** | 207 万 × 20 B | **約 41 MB** |
| <strong>フルスクリーン ポスト（RGBA16F を、読んで書く）</strong> | 207 万 × 16 B | 約 33 MB |

**60 FPS なら、1 秒あたり**、**33 MB × 60 ＝ 約 2 GB/s**（G-Buffer の書き込みだけで）。**ライトごとに、G-Buffer を、フルスクリーンで読む**と、**41 MB × ライト数 × 60 FPS**——**100 ライトなら、約 246 GB/s**で、**帯域が、尽きます**。**これが、Tiled（G-Buffer を、1 回だけ読む）が、生まれた理由**です（[Tiled と Clustered](light-culling.md)）。

!!! note "あくまで、目安"
    **実際の GPU は、キャッシュ・圧縮・タイル処理**で、**この数字より、少なく**なります。**ただし、「増えると、効いてくる」傾向**は、同じです。

## 減らす方法

### 1. フォーマットを、小さくする

| 用途 | 大きい選択 | 小さい選択 |
| --- | --- | --- |
| **HDR のカラー** | RGBA16F（8 B） | <strong>R11G11B10_FLOAT（4 B）</strong>（アルファなし・精度は少し落ちる） |
| **法線** | RGBA16F | **R10G10B10A2_UNORM**、または<strong>オクタヘドロン法線（2 チャンネル）</strong> |
| **ベースカラー** | RGBA16F | **RGBA8_UNORM_SRGB** |
| **AO・粗さ・金属度** | **別々の RT** | **1 枚に、パッキング**（R8G8B8A8） |
| **深度** | D32_FLOAT_S8 | **D32_FLOAT**（ステンシル不要なら） |

### 2. 詰め込む（パッキング）

**G-Buffer の項目を、少ない RT に、詰め込みます**。

| 工夫 | 説明 |
| --- | --- |
| **法線のオクタヘドロン エンコード** | **3 成分の法線を、2 成分**に（精度は、ほぼ同じ） |
| **位置を、保存しない** | **深度から、再構築**（**ビュー行列の逆**）。**G-Buffer に、位置を、持たない** |
| **粗さ・金属度・AO を、1 つの RT に** | **チャンネルを、共有** |
| **YCoCg など、色の変換** | **色を、少ないビットで** |

### 3. 圧縮

| 圧縮 | 説明 |
| --- | --- |
| <strong>テクスチャ圧縮（BC1・BC5・BC7）</strong> | **メモリと帯域を、1/4〜1/8**に（[ベイク](../baking.md)） |
| <strong>DCC（デルタ カラー圧縮）</strong> | **GPU が、自動で、RT を圧縮**（ハードウェア）。**RT の使い方次第で、効く・効かない** |
| **深度の圧縮** | **GPU が、自動**。**深度バッファを、読み書き以外に使うと、圧縮が、解除されることがある** |

### 4. 解像度を、下げる

**低解像度のバッファ**（AO・霧・ブルーム）は、**ピクセル数が、1/4**です（[低解像度のエフェクト](low-res-effects.md)）。

### 5. 読み書きの回数を、減らす

| 工夫 | 説明 |
| --- | --- |
| **パスを、まとめる** | **フルスクリーン パスを、1 つにまとめ**（ポストエフェクトを、1 つのシェーダーに） |
| **Tiled / Clustered** | **G-Buffer を、1 回だけ読む**（ライトごとに、読まない） |
| **Visibility Buffer** | **G-Buffer を、三角形の ID だけ**に（[Visibility Buffer](visibility-buffer.md)） |
| **ブレンドを、減らす** | **半透明の、重なりを、減らす**（読み書きが、倍） |
| **不要な RT クリアを、避ける** | **`DiscardView` で、内容を、破棄**（**中身が、不要なら**） |

### 6. キャッシュに、乗せる

| 工夫 | 説明 |
| --- | --- |
| **テクスチャを、小さく・ミップを使う** | **遠くは、小さなミップ**で、**キャッシュに、収まる** |
| **アクセスの局所性** | **隣のピクセルは、隣のテクセルを読む**（**ランダムアクセスを、避ける**） |
| **サンプラーのフィルター** | **異方性を、高くしすぎない**（読み込みが、増える） |

## モバイル（タイル型 GPU）の場合

**スマートフォンなどの GPU は、画面を、小さなタイルに分けて、描画**し、**タイルの内容を、オンチップ メモリ**に置きます。**メインメモリへの書き込みは、タイルの完了時だけ**で、**帯域を、節約**できます。

| 注意 | 説明 |
| --- | --- |
| **オンチップの活用** | **1 つのパス内で、完結**させる（**パスを、またぐと、メモリに書き出す**） |
| **Deferred は、不利**になりがち | **G-Buffer の、メインメモリへの書き出し**（**ただし、タイルメモリで、完結させる方式**もある） |
| **ロード・ストア操作** | <strong>「クリア」「破棄」</strong>を、**明示**して、**不要な読み書きを、避ける** |

**PC のデスクトップ GPU は、基本的に即時型**（タイル型ではない）ですが、**近年の GPU は、内部で、タイルに近い処理**を使うことがあります。

## 計算でメモリを減らす（再計算）

**メモリに保存して、読むより、必要なとき、再計算する**ほうが、**速い**ことが、**増えて**います。

| 例 | 説明 |
| --- | --- |
| **位置を、深度から、再構築** | **G-Buffer に位置を、保存しない** |
| **法線を、再計算** | **テクスチャの 2 成分から、3 成分目を、計算** |
| **テーブルを、やめる** | **LUT のメモリ読みより、数式の計算が、速い**こともある（[コンパイル時の計算](../compile-time.md)） |

**計算は、安く、メモリが高い**——という**GPU の性質**を、**活かします**。

## よくあるミス

??? failure "G-Buffer に、RGBA32F を、何枚も使う"
    **帯域が、尽きます**。**フォーマットを、小さく・パッキング**します。

??? failure "ポストエフェクトを、1 つずつ、フルスクリーンで、行う"
    **読み書きが、重なります**。**まとめる・低解像度**にします。

??? failure "深度を、わざわざ、色の RT にも、書く"
    **深度バッファから、読める**ようにします（**SRV 経由**）。

??? failure "帯域が足りないのに、計算を、最適化する"
    **ボトルネックが、違います**。**メモリの読み書きを、減らします**。

??? failure "MSAA を、Deferred で、無理に使う"
    **G-Buffer が、サンプル数倍**になります。**TAA などの、別の手法**を、検討します。
