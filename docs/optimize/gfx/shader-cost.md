# シェーダーのコスト

ピクセル数が多い、頂点数が多い、といった**量の問題**を減らしても、**1 回あたりのシェーダーが重い**と、**GPU は遅いまま**です。このページは、**シェーダーの何が重いのか**（演算・メモリ読み込み・分岐・レジスタ）と、**それぞれの、軽くする方法**を、説明します。**ピクセル処理が、ボトルネックのとき**に、効きます（[何が重いのか](bottlenecks.md)）。

!!! tip "ポイント"
    - シェーダーのコスト ＝ <strong>演算（ALU）・メモリ読み込み（テクスチャ・バッファ）・分岐・レジスタ使用量</strong>。
    - <strong>現代の GPU では、演算よりも、メモリ読み込み（待ち）が、重い</strong>ことが多い。
    - <strong>テクスチャの読み込みを、減らす・近くを読む</strong>（キャッシュに乗せる）。
    - <strong>分岐</strong>：<strong>同じ組（ウェーブ）の、全スレッドが、同じ方へ進めば、安い</strong>。<strong>バラバラだと、両方を、実行</strong>（ダイバージェンス）。
    - <strong>レジスタが、多い</strong>と、<strong>同時に動かせる、ウェーブが減り（占有率の低下）</strong>、<strong>待ちを、隠せなくなる</strong>。
    - <strong>半精度（FP16）</strong>・<strong>事前計算（LUT・ベイク）</strong>・<strong>頂点側へ移す</strong>、が、定番の対策。

## 何が、重いのか

| 要素 | 説明 |
| --- | --- |
| <strong>ALU（演算）</strong> | **加減乗除・内積・`pow`・`sqrt`・`sin` など**。**特殊関数（`pow`・`sin`）は、重い** |
| **テクスチャ読み込み** | **メモリからの、読み込み**。**待ち時間が、長い**。**キャッシュに乗るか**が、重要 |
| **バッファ読み込み** | **構造化バッファ・定数バッファ**。**ライト リストなど** |
| **分岐・ループ** | **スレッドの、足並み**に、影響 |
| **レジスタ** | **シェーダーが、使う、一時変数の数**。**多いと、占有率が下がる** |
| **帯域幅** | **RT・UAV への、書き込み**（[メモリ帯域幅](bandwidth.md)） |

## メモリ読み込みを、減らす

| 工夫 | 説明 |
| --- | --- |
| **テクスチャを、まとめる** | **粗さ・金属・AO を、1 枚の、チャンネルに、詰める**（R・G・B に 1 つずつ）（[PBR](../../3d/pbr.md)） |
| **圧縮フォーマット** | **BC1〜BC7**。**読み込む量が、減る** |
| **ミップマップ** | **遠い物は、小さな画像**（**キャッシュに、乗りやすい**） |
| **読み込みの、局所性** | **隣のピクセルは、隣のテクセル**を読む。**ランダムな読み込みは、遅い** |
| **同じものを、何度も読まない** | **ループの外で、1 回読み、変数に、保持** |
| **依存した読み込みを、避ける** | **読み込み結果で、次の座標を決める**（依存）と、**待ちが、直列**に |

| 点 | 説明 |
| --- | --- |
| **一様な分岐は、安い** | **定数・全ピクセル共通の値**での分岐 |
| **バラバラな分岐** | **両方の道を、実行**し、**不要な側を、マスク** |
| **重い処理を、分岐で、囲む** | **全員が、通らない**なら、**飛ばせる**（**ライトの数が、ピクセルごとに、違う**など） |
| **`[branch]` / `[flatten]`** | **HLSL の、ヒント**。**短い分岐は、`flatten`**（両方計算して選ぶ） |

詳しい分岐の話は、[分岐と仮想関数](../branching-virtual.md)（CPU 側）も、参照してください。

## 占有率（オキュパンシー）

**GPU は、あるウェーブが、メモリを待つ間、別のウェーブを実行**して、**待ち時間を、隠します**。**同時に動かせる、ウェーブの数**が、**占有率**です。

| 制限する要素 | 説明 |
| --- | --- |
| **レジスタ数** | **1 スレッドが、多くのレジスタを使う**と、**同時に載るウェーブが、減る** |
| **groupshared メモリ** | **コンピュートで、多く使う**と、**グループ数が、減る** |
| **スレッド グループ サイズ** | **小さすぎる・大きすぎる** |

| 対策 | 説明 |
| --- | --- |
| **変数を、減らす・寿命を、短く** | **レジスタを、節約** |
| **巨大なシェーダーを、分割** | **パスを、分ける** |
| **ツールで確認** | **PIX・Nsight・Radeon GPU Profiler** で、**レジスタ・占有率**を、確認 |

## 演算を、軽くする

| 工夫 | 説明 |
| --- | --- |
| **`pow`・`sin`・`exp` を、避ける** | <strong>近似式・テーブル（LUT）</strong> に置き換える |
| **`normalize` の、減らす** | **すでに、正規化済みなら、不要** |
| **除算を、乗算に** | **`x / 2.0` → `x * 0.5`<strong>（</strong>コンパイラが、自動でやることも、多い**） |
| **`mad`（乗算＋加算）を、意識** | **1 命令で、できる形** |
| <strong>半精度（FP16・`min16float`）</strong> | **レジスタ・演算が、半分**（**対応 GPU**。**精度に、注意**） |
| **定数の事前計算** | **CPU 側・ベイク**で計算し、**シェーダーには、結果だけ**（[ベイク](../baking.md)） |

## 計算を、頂点側へ移す

**ピクセルは、頂点より、はるかに多い**ので、**ピクセルごとに、同じ値になる計算は、頂点（またはその前）へ**移します。

| 計算 | 移す先 |
| --- | --- |
| <strong>ライトの方向・ビュー方向（ゆっくり変化）</strong> | **頂点シェーダー**（補間で、十分） |
| **同じ値の計算** | **CPU・定数バッファ** |
| **ピクセルごとに変わらない処理** | **ピクセルシェーダーの外** |

ただし、**補間では、精度が足りない**もの（**鏡面ハイライトなど**）は、**ピクセルで、計算**します。

## シェーダーの、バリアント

**マクロで、機能の、オン・オフを、切り替える**と、**組み合わせの数だけ、シェーダーが、増えます**。

| 問題 | 対策 |
| --- | --- |
| **バリアントの爆発** | **本当に、必要な組み合わせだけ**を、ビルド |
| <strong>動的な分岐（`if (use_feature)`）</strong> | **一様なら、安い**。**バリアントを、減らせる** |
| **コンパイル時間・メモリ** | **使わない組み合わせは、作らない**（[ビルド時間](../build-time.md)） |

## 測り方

| ツール | 見るもの |
| --- | --- |
| <strong>PIX（DX）</strong> | **シェーダーごとの、時間・占有率・メモリ待ち** |
| **RenderDoc** | **ドロー コールごとの、状態・オーバードロー** |
| **Nsight Graphics / Radeon GPU Profiler** | **ベンダー固有の、詳細**（**レジスタ・ウェーブ占有率**） |
| **シェーダーを、一時的に、単純化** | <strong>「このシェーダーを、空にしたら、速くなる？」</strong>で、**原因を切り分け**（[何が重いのか](bottlenecks.md)） |

## よくあるミス

??? failure "演算ばかり減らして、テクスチャ読み込みが、ボトルネックのまま"
    **メモリ待ち**を、確認します。

??? failure "ピクセルごとに、バラバラな条件で、重い処理を、分岐で囲む"
    **ダイバージェンス**で、**全員が、両方実行**します。

??? failure "巨大な、1 つのシェーダーに、全機能を、詰め込む"
    **レジスタが増え、占有率が、落ちます**。

??? failure "FP16 を、位置・深度の計算に、使って、精度が、足りない"
    **色・ライティングの一部**に、限定します。

??? failure "`pow(x, 2.0)` を、そのまま書く"
    **`x * x`** にします。
