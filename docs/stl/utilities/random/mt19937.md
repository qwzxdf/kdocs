# std::mt19937

<div class="page-badges" markdown>
<span class="rank rank-must">必須</span>
<span class="ver ver-11">C++11</span>
`#include <random>`
</div>

ゲームには、乱数が欠かせません。ダメージの幅、アイテムのドロップ、敵の動き。`rand()` は手軽ですが、品質が低く、エンジンの状態をプログラム全体で 1 つしか持てません。`std::mt19937` は、品質が高く、速く、周期が長い乱数エンジンで、ゲームの乱数なら、まずこれを選べば困りません。

!!! tip "ポイント"
    - エンジンは 1 つ作って使い回す。状態が約 5KB あるので、関数ごとに作らない。
    - 種（シード）を固定すると、同じ乱数列が出る。リプレイやテストに使える。
    - エンジンは生の整数を出すだけ。必要な範囲に変えるのは分布（`uniform_int_distribution` など）の役目。

!!! info "このページを読む前に"
    乱数の全体像は [乱数](../random.md) を先に読んでください。エンジンと分布の役割分担が分かります。

## 関数の詳しい説明

### std::mt19937 {#mt19937}

```cpp
using mt19937 = std::mersenne_twister_engine<std::uint_fast32_t, 32, 624, 397, 31,
                                              0x9908b0df, 11, 0xffffffff, 7, 0x9d2c5680, 15, 0xefc60000, 18, 1812433253>;
using mt19937_64 = /* 64 ビット版 */;
```

| 引数 | 型 | 意味 | 省略すると |
| --- | --- | --- | --- |
| `seed` | `unsigned` | 乱数の出発点。同じ種なら同じ列が出る | `5489` |

コンストラクターに種を渡します。`std::mt19937 rng(42);` のように整数を渡すと、毎回同じ乱数列が出ます。引数を省略すると、既定の種 5489 が使われるので、毎回同じ列になります。

実行ごとに違う列が欲しいときは、`std::random_device{}()` を種に使います。`random_device` は OS のランダムさを使う、非決定的な乱数源です。ただし環境によっては毎回同じ値になる実装もあります。

エンジンの出力は `rng()` で得られる 32 ビットの整数です。そのまま使わずに、`uniform_int_distribution` などの分布に渡します。64 ビットの値が必要なら、`std::mt19937_64` を使います。

- 戻り値: `operator()` で 32 ビット整数（`mt19937_64` なら 64 ビット整数）を返す
- 計算量: O(1)

```cpp
#include <print>
#include <random>

int main() {
  std::mt19937 a(1);
  std::mt19937 b(1);
  std::println("同じ種なら同じ値？ {}", a() == b());

  std::mt19937 c;  // 種を省略すると 5489
  std::println("{}", c());

  std::mt19937_64 d;  // 64 ビット版
  std::println("{}", d());
}
```

```text title="実行結果"
同じ種なら同じ値？ true
3499211612
14514284786278117030
```

### seed, discard {#seed}

```cpp
void seed(result_type value);
void discard(unsigned long long z);
```

| 引数 | 型 | 意味 |
| --- | --- | --- |
| `value` | `result_type` | 新しい種 |
| `z` | 整数 | 読み飛ばす回数 |

`seed` は、エンジンの状態を種から作り直す関数です。`rng.seed(100)` のあとは、`std::mt19937 rng(100)` で作ったときと同じ列になります。ゲームの「ステージごとに同じ乱数列を再現する」場面で使います。

`discard(n)` は、乱数を n 個だけ読み捨てて、位置を進めます。セーブデータから途中の状態を再現したいときに使います。ただし、状態の保存は、エンジンを `<<` で書き出して `>>` で読み込むほうが簡単です。

- 戻り値: なし
- 計算量: seed は O(624)、discard は O(z)

## しくみ

メルセンヌ・ツイスターは、624 個の 32 ビット整数を状態として持ち、一定の間隔で全体をかき混ぜ直しながら、1 つずつ出力します。かき混ぜ直す処理は 624 個に 1 回しか起きないので、平均すると 1 個あたりの計算は軽くなります。

周期が 2 の 19937 乗 − 1 というのは、同じ列に戻るまでの長さです。ゲームの寿命で使い切ることはありません。

欠点は、状態が大きいことと、種が 1 つの 32 ビット整数だけだと、初期状態の候補が 40 億通りしかないことです。暗号の用途には向きません。ゲームの乱数なら十分ですが、セキュリティが必要な乱数（トークンなど）には使わないでください。


## ゲームでの使いどころ

リプレイの再現やバグの再現に種の固定が役立ちます。ステージの開始時に種を決めてセーブデータに保存しておけば、同じ種から同じ乱数列を再現できます。バグが起きたときの種をログに出しておけば、同じ状況を再現できます。

乱数エンジンは、役割ごとに分けて持つと便利です。戦闘の乱数と、見た目だけのエフェクトの乱数を同じエンジンで共有すると、エフェクトの数が変わるだけで戦闘の結果が変わり、リプレイがズレます。戦闘用とエフェクト用にエンジンを分けます。

マルチスレッドでは、1 つのエンジンを複数スレッドで共有しません。エンジンは内部状態を書き換えるので、競合して壊れます。スレッドごとに別のエンジンを持たせます。

## よくあるミス

??? failure "関数のたびにエンジンを作る"
    `int Roll() { std::mt19937 rng(std::random_device{}()); ... }` は、呼ぶたびに約 5KB の状態を作り、`random_device` にも問い合わせるので遅くなります。エンジンはメンバー変数や `static` に 1 つだけ持ちます。

??? failure "種を省略して、毎回同じ乱数になる"
    `std::mt19937 rng;` は種が固定の 5489 なので、起動のたびに同じ乱数列が出ます。開発中の再現には便利ですが、製品では `random_device` から種を作ります。

??? failure "スレッドの間でエンジンを共有する"
    複数のスレッドから同じエンジンを呼ぶと、データ競合で未定義動作になります。`thread_local` にするか、スレッドごとに持たせます。

??? failure "エンジンの出力をそのまま範囲に使う"
    `rng() % 6` は偏りが出ます。範囲への変換は、`uniform_int_distribution` に任せます。
