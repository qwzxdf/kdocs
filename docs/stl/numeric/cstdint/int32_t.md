# std::int32_t

<div class="page-badges" markdown>
<span class="rank rank-often">よく使う</span>
<span class="ver ver-11">C++11</span>
`#include <cstdint>`
</div>

`int` の大きさは、環境で違うことがあります。ファイルに書いた数値を別の環境で読んだら、桁数が合わない、という事故は、ゲームのセーブデータや通信でよく起きます。

`std::int32_t` は、<strong>ちょうど 32 ビットの符号つき整数</strong>を表す型です。どの環境でも大きさが同じなので、ファイルや通信のデータ形式に使えます。

!!! tip "ポイント"
    - ちょうど 32 ビットの符号つき整数。範囲は −2,147,483,648 〜 2,147,483,647
    - `<cstdint>` で定義される（C++11 から）
    - 普通の計算には `int` で足りる。ファイル・通信・ビット操作で、大きさを固定したいときに使う
    - 該当する型がない環境では定義されない（ただし、実際のゲーム用の環境にはある）

!!! info "このページを読む前に"
    [`<cstdint>`](../cstdint.md) の概要を先に読むと分かりやすいです。

## 関数の詳しい説明

### std::int32_t {#int32_t}

<span class="ver ver-11">C++11</span>

```cpp
using int32_t = /* 32 ビットの符号つき整数型 */;
```

`std::int32_t` は型の別名（`using`）で、実体は環境の整数型です。多くの環境では `int` と同じです。幅がちょうど 32 ビットで、符号つき整数であることが保証されます。範囲は −2,147,483,648 〜 2,147,483,647 です。

符号つきの型は、2 の補数表現であることも保証されます。

落とし穴は、範囲を超える計算です。符号つき整数のオーバーフローは未定義動作なので、範囲ぎりぎりの値を足し算するときは、広い型に直してから計算します。

「`optional` な型」と呼ばれるのは、ちょうど 32 ビットの整数型を持たない環境では、この型が定義されない、という意味です。PC やコンソールでは、実際に定義されないことはまず無いので、ゲームではそのまま使えます。

大きさが環境で変わらないので、`sizeof` に頼らずデータ形式を決められます。ただし、ファイルに書く場合は、バイト順（エンディアン）の違いは別に考える必要があります。

## 実際に動かしてみる

```cpp
#include <cstdint>
#include <limits>
#include <print>

int main() {
  std::println("{} ビット", sizeof(std::int32_t) * 8);
  std::println("最小 {}", static_cast<long long>(std::numeric_limits<std::int32_t>::min()));
  std::println("最大 {}", static_cast<unsigned long long>(std::numeric_limits<std::int32_t>::max()));
}
```

```text title="実行結果"
32 ビット
最小 -2147483648
最大 2147483647
```

## ゲームでの使いどころ

ファイルや通信の整数フィールド。環境によらず 32 ビット。

```cpp
std::int32_t score = 100000;   // セーブデータのスコア
```

計算の途中では、`int` や `float` で足ります。ファイルの形式、通信のパケット、ビット演算のように、大きさが意味を持つ場面だけで固定幅の型を使います。

## よくあるミス

??? failure "普通の計算まで固定幅の型にして、読みにくくなる"
    ループの回数や一時変数は `int` で足ります。

??? failure "符号なしの引き算で負の値を期待する"
    符号なしの 0 − 1 は最大値になります。
