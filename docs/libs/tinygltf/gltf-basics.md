# glTF の基本と規約

glTF とは何か、ファイルの形、**座標系・規約**、拡張、ほかのライブラリとの比較をまとめます。

## glTF とは

| 項目 | 内容 |
| --- | --- |
| **正式名称** | GL Transmission Format |
| 作った所 | Khronos Group（OpenGL / Vulkan の団体）。オープンな規格 |
| バージョン | 2.0 が、現在の標準 |
| 特徴 | 軽量。PBR のマテリアル（金属度・粗さ）に対応。ボーン・アニメーションも持てる |
| 向き | ゲーム・Web・アプリへの、配布・受け渡し |
| 拡張子 | `.gltf`（JSON + 外部ファイル）、`.glb`（1 ファイルにまとめたバイナリ） |

## ファイルの形

| 形式 | 構成 | 特徴 |
| --- | --- | --- |
| **`.gltf`** | JSON ＋ `.bin`（バイナリ）＋ 画像（`.png` など） | ファイルが分かれる。中身を、テキストエディターで見られる |
| `.glb` | すべてを 1 つにまとめたバイナリ | 1 ファイルで、扱いやすい。配布向き |
| 埋め込み `.gltf` | JSON の中に、データを `base64` で入れたもの | 1 ファイルだが、サイズが大きくなる |


## glTF の座標系・規約

3D モデルの取り込みで一番つまずくのは、**座標系の違い**です。glTF は右手系で、このサイトのゲームは左手系なので、何も考えずに読み込むと、モデルが左右反転したり、裏返ったりします。下の表で、項目ごとの違いを確認し、そのあとに具体的な変換の方法を説明します。

| 項目 | glTF | このサイトの規約（左手系・DX11） |
| --- | --- | --- |
| 座標系 | 右手系 | 左手系（ルートに X 反転の行列を掛けて取り込む） |
| 上方向 | +Y | +Y（同じ） |
| 前方向 | +Z が「正面向き」（モデルが、+Z を向いて作られる） | カメラの前は +Z。X を反転するので、正面は +Z のまま（[座標系](../../gamemath/coordinate-systems.md)） |
| 単位 | メートル | メートル（同じ） |
| UV の原点 | 左上（V は下向き） | 左上（DirectX と同じ。反転は不要） |
| 三角形の表 | 反時計回り（CCW） | 時計回り（CW）（`FrontCounterClockwise = FALSE`）。インデックスの 2 番目と 3 番目を入れ替える |
| 回転（クォータニオン） | `(x, y, z, w)` の順 | 同じ並び。ノードの値は変換せず、ルートの行列でまとめて反転 |
| 行列 | 列優先（column-major）の 16 個 | 行ベクトル規約（行優先）。転置と同じ並びなので、そのまま `memcpy` できる（[データの取り出し方](reading.md)） |

## 左手系へ変換する {#to-left-handed}

glTF は右手系、このサイトは左手系なので、**取り込むときに座標系をそろえます**。標準の方法は、X 軸を反転する行列を、モデルのルートに 1 回だけ掛けることです（[座標系](../../gamemath/coordinate-systems.md#right-to-left)）。

```cpp
inline const Matrix kRightToLeft = Matrix::CreateScale(-1.0f, 1.0f, 1.0f);

Matrix draw_world = node_world * kRightToLeft * entity_world;
```

| 変換するもの | やること |
| --- | --- |
| 頂点の位置 | そのまま（ルートの行列で反転される） |
| 法線 | 位置と同じワールド行列で変換する（`mul(float4(normal, 0), world)`）。ルートの `kRightToLeft` が一緒に反転するので、ライティングは逆にならない |
| ノードの移動・回転・拡大、`matrix` | そのまま（`node_world` は、glTF の値だけで求める） |
| スキンの逆バインド行列・アニメーション | そのまま |
| 三角形のインデックス | 読み込み時に 1 回、三角形ごとに 2 番目と 3 番目を入れ替える（CCW → CW） |
| 接線の `w` | 反転する（`kRightToLeft` は鏡像なので） |

```cpp
void FlipWinding(std::vector<uint32_t>& indices) {
  for (size_t i = 0; i + 2 < indices.size(); i += 3) {
    std::swap(indices[i + 1], indices[i + 2]);
  }
}
```

!!! tip "X を反転する理由"
    glTF は、モデルの正面が **+Z** です。**X だけを反転**すれば、上（+Y）も前（+Z）も変わらないので、キャラクターが `kForward` の向きを向いたままになります。Z を反転すると、正面が −Z になり、180 度回す必要が出ます。

!!! note "変換しない読み方との違い"
    何もせずに左手系として読む（右手系のデータをそのまま使う）と、モデルは左右が反転した鏡像になります。巻き方向は偶然合いますが、文字・左利きの物・非対称な傷などが、逆になります。このサイトでは、ルートに `kRightToLeft` を掛けて、鏡像にならないようにします。

手書きの変換コードを、頂点・ノードごとに書かないのが利点です。変換は、行列 1 つと、インデックスの入れ替えで終わります（[ベイク](../../optimize/baking.md)で、ビルド時に済ませてもよい）。

## 拡張（extensions）

glTF は、**拡張**で機能を足せます。未対応の拡張は、`warning` に出ます。

| 拡張 | 内容 | tinygltf の対応 |
| --- | --- | --- |
| `KHR_materials_*` | クリアコート・透過・光沢などの、マテリアルの追加機能 | 値は読める（`extensions` に入る。解釈は自分で） |
| `KHR_texture_transform` | UV の移動・回転・拡大 | 値は読める。自分で適用 |
| `KHR_lights_punctual` | ライト | 読める |
| `KHR_draco_mesh_compression` | Draco による、メッシュ圧縮 | デコードしない（別のライブラリが必要） |
| `EXT_meshopt_compression` | meshopt による圧縮 | デコードしない |
| `KHR_texture_basisu` | KTX2（Basis）のテクスチャ圧縮 | 画像として読めない（別のライブラリが必要） |

圧縮された glTF は、tinygltf だけでは、頂点が取り出せません。書き出しのときに、圧縮を使わない設定にするのが、いちばん簡単です。


## ほかの選択肢

| ライブラリ | 特徴 |
| --- | --- |
| **tinygltf** | ヘッダのみ・使いやすい。構造がそのまま見える。学習・小規模向き |
| fastgltf | 速い（simdjson 使用）。C++17 以降。大きなデータ向き |
| cgltf | C 言語の、単一ヘッダ。軽い。構造がポインタで辿れる |
| Assimp | 多くの形式に対応（glTF・FBX・OBJ…）。重い |

学習・普通のゲームなら、tinygltfが、理解しやすいです。
