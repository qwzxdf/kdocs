# Resources and Views

<div class="page-badges" markdown>
<span class="rank rank-must">必須</span>
</div>

DirectX では、GPU 上の、データを、<strong>リソース</strong>（バッファ、テクスチャ）と、<strong>ビュー</strong>（その、見方）に、<strong>分けて</strong>、扱います。リソースは、「GPU メモリの、実体」で、ビューは、「そのメモリを、<strong>どう、解釈して、どの用途で、使うか</strong>」の、記述です。同じ、テクスチャを、「描き込み先」と「読み取り」の、両方で、使えるのは、この、分離の、おかげです。

!!! tip "ポイント"
    - リソース ＝ メモリの実体（バッファ、1D・2D・3D テクスチャ）。
    - ビュー ＝ リソースの、見方。<strong>RTV</strong>（描き込み先）、<strong>SRV</strong>（読み取り）、<strong>UAV</strong>（読み書き）、<strong>DSV</strong>（深度）、<strong>CBV</strong>（定数バッファ）、サンプラー。
    - パイプラインに、つなぐのは、リソースではなく、<strong>ビュー</strong>。
    - 1 つの、リソースに、複数の、ビューを、作れる（別の形式、別のミップ）。
    - 作成時に、使う予定の、ビューの、種類を、リソースに、宣言する（`BindFlags`、`ALLOW_*`）。

## なぜ、分けるのか

GPU は、「このメモリを、描き込み先として、使う」「このメモリを、テクスチャとして、読む」で、<strong>別の、最適化</strong>を、します。描き込み先は、圧縮や、キャッシュを、書き込みに、最適化し、読み取りは、フィルタリングに、最適化します。リソースを、「何に、使うか」の、ビューで、区別すると、GPU が、その用途に、合った、扱いを、選べます。

```text
1 つのテクスチャ（リソース）
   ├─ RTV  → ピクセル シェーダーの出力先（書く）
   ├─ SRV  → 次のパスで、読む（読む）
   └─ UAV  → 計算シェーダーで、読み書き
```

## ビューの、種類

| ビュー | 略 | 用途 | HLSL |
| --- | --- | --- | --- |
| レンダー ターゲット ビュー | RTV | ピクセル シェーダーの、出力先 | `SV_Target` |
| シェーダー リソース ビュー | SRV | シェーダーが、読む | `Texture2D`、`StructuredBuffer`（`t#`） |
| アンオーダード アクセス ビュー | UAV | シェーダーが、読み書き（順序なし） | `RWTexture2D`、`RWStructuredBuffer`（`u#`） |
| 深度ステンシル ビュー | DSV | 深度・ステンシルの、書き込み | （固定機能） |
| 定数バッファ ビュー | CBV | シェーダーに、パラメータを渡す | `cbuffer`（`b#`） |
| サンプラー | — | テクスチャの、読み方の、設定 | `SamplerState`（`s#`） |

シェーダーの、レジスタの、接頭辞（`b`、`t`、`u`、`s`）が、ビューの、種類に、対応します。

## ビューは、リソースを、参照する

ビューは、リソースを、<strong>参照するだけ</strong>で、データの、コピーでは、ありません。リソースを、解放すると、ビューは、無効になります。

```text
ビュー（小さな、記述）  ──参照──▶  リソース（GPU メモリの実体）
 ・フォーマット                    ・大きさ
 ・見せる範囲（ミップなど）          ・データ
```

ビューは、数十バイトの、小さな、データで、作るのは、軽いです。

## 1 つのリソースに、複数のビュー

同じリソースに、<strong>別の見方</strong>の、ビューを、複数、作れます。

| 例 | ビュー |
| --- | --- |
| 深度バッファ | DSV（深度として、書く）+ SRV（`R32_FLOAT` として、読む） |
| ミップ付きテクスチャ | 全ミップの SRV + ミップごとの UAV |
| 配列テクスチャ | 全体の SRV + 1 面ずつの RTV（キューブ シャドウ マップの、6 面） |
| シーンの色 | RTV（描く）+ SRV（ポスト プロセスで読む）+ UAV（計算シェーダーで書く） |

深度のように、<strong>書く時と、読む時で、フォーマットが、違う</strong>場合は、typeless（型なし）で、リソースを、作ります（[Formats and Typeless](formats.md)）。

## 用途の、宣言

リソースを、作るとき、<strong>どんな、ビューを、作る予定か</strong>を、宣言します。

| API | 宣言 |
| --- | --- |
| DirectX 11 | `BindFlags`（`D3D11_BIND_RENDER_TARGET`、`SHADER_RESOURCE`、`UNORDERED_ACCESS`、`DEPTH_STENCIL`） |
| DirectX 12 | `D3D12_RESOURCE_FLAGS`（`ALLOW_RENDER_TARGET`、`ALLOW_UNORDERED_ACCESS`、`ALLOW_DEPTH_STENCIL`） |

宣言しなかった、種類の、ビューは、<strong>あとから、作れません</strong>。GPU が、その用途に、合わせた、メモリの、配置を、リソースの作成時に、決めるためです。

## パイプラインに、つなぐのは、ビュー

描画や、計算の、前に、パイプラインに、<strong>ビューを、つなぎ</strong>ます。リソースを、直接、渡すことは、ありません。

| つなぐ | 内容 |
| --- | --- |
| RTV・DSV | 出力マージャーに（描き込み先） |
| SRV | シェーダーに（読み取り） |
| UAV | 計算シェーダー（またはピクセル シェーダー）に（読み書き） |
| CBV | シェーダーに（パラメータ） |
| サンプラー | シェーダーに（テクスチャの読み方） |

DirectX 11 は、コンテキストの、`…Set…` で、ビューを、パイプラインに、<strong>直接、束ね</strong>ます。DirectX 12 は、ビューを、<strong>ディスクリプタ</strong>として、ヒープに、並べ、ルート シグネチャを、通して、渡します。呼び方は、違いますが、考え方は、同じです。

## 同時に、読み書き、できない

<strong>同じ、リソースを、同時に、書き込みと、読み取りには、使えません</strong>。「書いた、結果を、次の、パスで、読む」ときは、<strong>書き込みの、利用を、終えて</strong>から、読み取りに、切り替えます。

| API | 切り替えの、方法 |
| --- | --- |
| DirectX 11 | ドライバーが、自動で、順序を、保証する。ただし、同時に、束ねる（RTV と SRV）と、読む側が、黙って、外れる |
| DirectX 12 | <strong>リソース バリア</strong>で、状態を、明示的に、遷移させる |

詳しくは、[Why Synchronization](synchronization.md) です。

## リソースの、種類

| 種類 | 内容 | 例 |
| --- | --- | --- |
| バッファ | バイトの列 | 頂点、インデックス、定数、構造化バッファ |
| 1D テクスチャ | 1 次元の画像 | グラデーションの、LUT |
| 2D テクスチャ | 2 次元の画像 | 絵、レンダー ターゲット、深度、G バッファ |
| 3D テクスチャ | 3 次元の画像 | ボリューム フォグ（froxel）、ボクセル、3D LUT |
| キューブマップ | 6 面の、2D テクスチャの配列 | スカイボックス、反射プローブ |

## よくあるミス

??? failure "リソースを、作ったのに、ビューが、作れない"
    作成時に、その用途の、宣言（`BindFlags`、`ALLOW_*`）を、していない。あとから、足せない。

??? failure "読もうとした、テクスチャが、真っ黒"
    同じリソースが、まだ、書き込み用（RTV・DSV・UAV）として、使われている。書き込みを、終えて、読み取りに、切り替える。

??? failure "リソースを、解放したら、後で、クラッシュする"
    ビューは、リソースを、参照している。GPU が、まだ、使っている間に、解放した。GPU の、完了を、待ってから、解放する。

??? failure "深度を、SRV で、読めない"
    深度を、`D32_FLOAT` で、作った。`R32_TYPELESS` で作り、DSV と SRV で、型を、分ける。

    - [x] ビューは、RTV・SRV・UAV・DSV・CBV・サンプラー。用途ごとに、作る
