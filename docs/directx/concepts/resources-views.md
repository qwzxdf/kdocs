# Resources and Views

<div class="page-badges" markdown>
<span class="rank rank-must">必須</span>
</div>

DirectX では GPU 上のデータを <strong>リソース</strong>（バッファ、テクスチャ）と ビュー（その見方）に 分けて、扱います。リソースは「GPU メモリの実体」でビューは「そのメモリを どう解釈してどの用途で使うか」の、記述です。同じテクスチャを「描き込み先」と「読み取り」の両方で、使えるのはこの分離のおかげです。

!!! tip "ポイント"
    - リソース ＝ メモリの実体（バッファ、1D・2D・3D テクスチャ）。
    - ビュー ＝ リソースの見方。<strong>RTV</strong>（描き込み先）、<strong>SRV</strong>（読み取り）、UAV（読み書き）、DSV（深度）、CBV（定数バッファ）、サンプラー。
    - パイプラインにつなぐのは、リソースではなく ビュー。
    - 1 つのリソースに複数のビューを作れる（別の形式、別のミップ）。
    - 作成時に使う予定のビューの種類をリソースに宣言する（`BindFlags`、`ALLOW_*`）。

## なぜ分けるのか

GPU は「このメモリを描き込み先として、使う」「このメモリをテクスチャとして、読む」で <strong>別の最適化</strong>をします。描き込み先は圧縮やキャッシュを書き込みに最適化し読み取りは、フィルタリングに最適化します。リソースを「何に使うか」のビューで、区別すると GPU がその用途に合った扱いを選べます。

```text
1 つのテクスチャ（リソース）
   ├─ RTV  → ピクセル シェーダーの出力先（書く）
   ├─ SRV  → 次のパスで、読む（読む）
   └─ UAV  → 計算シェーダーで、読み書き
```

## ビューの種類

| ビュー | 略 | 用途 | HLSL |
| --- | --- | --- | --- |
| レンダー ターゲット ビュー | RTV | ピクセル シェーダーの、出力先 | `SV_Target` |
| シェーダー リソース ビュー | SRV | シェーダーが、読む | `Texture2D`、`StructuredBuffer`（`t#`） |
| アンオーダード アクセス ビュー | UAV | シェーダーが、読み書き（順序なし） | `RWTexture2D`、`RWStructuredBuffer`（`u#`） |
| 深度ステンシル ビュー | DSV | 深度・ステンシルの書き込み | （固定機能） |
| 定数バッファ ビュー | CBV | シェーダーにパラメータを渡す | `cbuffer`（`b#`） |
| サンプラー | — | テクスチャの読み方の設定 | `SamplerState`（`s#`） |

シェーダーのレジスタの接頭辞（`b`、`t`、`u`、`s`）がビューの種類に対応します。

## ビューはリソースを参照する

ビューはリソースを <strong>参照するだけ</strong>で、データのコピーではありません。リソースを解放するとビューは無効になります。

```text
ビュー（小さな、記述）  ──参照──▶  リソース（GPU メモリの実体）
 ・フォーマット                    ・大きさ
 ・見せる範囲（ミップなど）          ・データ
```

ビューは数十バイトの小さなデータで、作るのは軽いです。

## 1 つのリソースに複数のビュー

同じリソースに <strong>別の見方</strong>のビューを複数、作れます。

| 例 | ビュー |
| --- | --- |
| 深度バッファ | DSV（深度として、書く）+ SRV（`R32_FLOAT` として、読む） |
| ミップ付きテクスチャ | 全ミップの SRV + ミップごとの UAV |
| 配列テクスチャ | 全体の SRV + 1 面ずつの RTV（キューブ シャドウ マップの、6 面） |
| シーンの色 | RTV（描く）+ SRV（ポスト プロセスで読む）+ UAV（計算シェーダーで書く） |

深度のように 書く時と読む時で、フォーマットが違う場合は typeless（型なし）で、リソースを作ります（[Formats and Typeless](formats.md)）。

## 用途の宣言

リソースを作るとき <strong>どんなビューを作る予定か</strong>を宣言します。

| API | 宣言 |
| --- | --- |
| DirectX 11 | `BindFlags`（`D3D11_BIND_RENDER_TARGET`、`SHADER_RESOURCE`、`UNORDERED_ACCESS`、`DEPTH_STENCIL`） |
| DirectX 12 | `D3D12_RESOURCE_FLAGS`（`ALLOW_RENDER_TARGET`、`ALLOW_UNORDERED_ACCESS`、`ALLOW_DEPTH_STENCIL`） |

宣言しなかった種類のビューは あとから作れません。GPU がその用途に合わせたメモリの配置をリソースの作成時に決めるためです。

## パイプラインにつなぐのはビュー

描画や計算の前にパイプラインに <strong>ビューをつなぎ</strong>ます。リソースを直接、渡すことはありません。

| つなぐ | 内容 |
| --- | --- |
| RTV・DSV | 出力マージャーに（描き込み先） |
| SRV | シェーダーに（読み取り） |
| UAV | 計算シェーダー（またはピクセル シェーダー）に（読み書き） |
| CBV | シェーダーに（パラメータ） |
| サンプラー | シェーダーに（テクスチャの読み方） |

DirectX 11 はコンテキストの `…Set…` で、ビューをパイプラインに 直接、束ねます。DirectX 12 はビューを ディスクリプタとしてヒープに並べルート シグネチャを通して渡します。呼び方は違いますが考え方は同じです。

## 同時に読み書きできない

<strong>同じリソースを同時に書き込みと読み取りには使えません</strong>。「書いた結果を次のパスで読む」ときは、書き込みの利用を終えてから、読み取りに切り替えます。

| API | 切り替えの方法 |
| --- | --- |
| DirectX 11 | ドライバーが自動で順序を保証する。ただし、同時に束ねる（RTV と SRV）と読む側が黙って外れる |
| DirectX 12 | リソース バリアで状態を明示的に遷移させる |

詳しくは[Why Synchronization](synchronization.md) です。

## リソースの種類

| 種類 | 内容 | 例 |
| --- | --- | --- |
| バッファ | バイトの列 | 頂点、インデックス、定数、構造化バッファ |
| 1D テクスチャ | 1 次元の画像 | グラデーションの LUT |
| 2D テクスチャ | 2 次元の画像 | 絵、レンダー ターゲット、深度、G バッファ |
| 3D テクスチャ | 3 次元の画像 | ボリューム フォグ（froxel）、ボクセル、3D LUT |
| キューブマップ | 6 面の 2D テクスチャの配列 | スカイボックス、反射プローブ |

## よくあるミス

??? failure "リソースを作ったのにビューが作れない"
    作成時にその用途の宣言（`BindFlags`、`ALLOW_*`）をしていない。あとから足せない。

??? failure "読もうとしたテクスチャが真っ黒"
    同じリソースがまだ書き込み用（RTV・DSV・UAV）として、使われている。書き込みを終えて読み取りに切り替える。

??? failure "リソースを解放したら後でクラッシュする"
    ビューはリソースを参照している。GPU がまだ使っている間に解放した。GPU の完了を待ってから解放する。

??? failure "深度を SRV で読めない"
    深度を `D32_FLOAT` で作った。`R32_TYPELESS` で作り DSV と SRV で型を分ける。
