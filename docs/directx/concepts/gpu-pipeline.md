# GPU Pipeline Overview

<div class="page-badges" markdown>
<span class="rank rank-must">必須</span>
</div>

<strong>GPU は頂点の列を受け取り画面の、ピクセルの色に変える工場</strong>です。この工場は 決まった順序の工程（パイプライン）で、できていて工程ごとに プログラムできる（シェーダー）工程と、固定機能の（設定だけ）工程があります。DirectX 11 でも 12 でも、この工程は同じです。API の関数の名前は「どの工程を設定するか」を表しています。

!!! tip "ポイント"
    - パイプラインの流れは、<strong>入力 → 頂点シェーダー → ラスタライザー → ピクセル シェーダー → 出力マージャー</strong>。
    - プログラムできるのは、<strong>頂点シェーダー・ピクセル シェーダー</strong>（と、ハル・ドメイン・ジオメトリ、メッシュ）。
    - ラスタライザーと、出力マージャー（深度・ブレンド）は、固定機能でステートで設定する。
    - 計算シェーダーは、このパイプラインとは 別に自由に動く。
    - GPU は 大量の、スレッドを並列に動かす。1 つの頂点・ピクセルは独立に処理される。

## 全体の流れ

```text
頂点データ（位置・法線・uv）
   │
   ▼ ① 入力アセンブラー（IA）      頂点とインデックスを読み、三角形に組み立てる
   ▼ ② 頂点シェーダー（VS）        頂点ごとに、位置を、クリップ空間へ変換        ← プログラム可能
   ▼ （③ ハル / ドメイン / ジオメトリ / メッシュ）  任意。三角形の、分割・生成     ← プログラム可能（任意）
   ▼ ④ ラスタライザー（RS）        三角形を、ピクセルに、分解（クリッピング、カリング、ビューポート）
   ▼ ⑤ ピクセル シェーダー（PS）   ピクセルごとに、色を計算                       ← プログラム可能
   ▼ ⑥ 出力マージャー（OM）        深度テスト・ブレンドして、レンダー ターゲットへ書く
   │
画面（レンダー ターゲット）
```

## 各段の役割

### ① 入力アセンブラー（IA）

頂点バッファとインデックス バッファから頂点を読み、<strong>三角形（または線・点）に組み立てます</strong>。入力レイアウトで頂点の並び（位置は、何バイト目、など）を教えます。固定機能です。

### ② 頂点シェーダー（VS）

頂点 1 つにつき 1 回、実行され頂点の位置を クリップ空間に変換します（ワールド・ビュー・射影の行列を掛ける）。法線や uv をそのままあとの段へ渡します。頂点の数だけ並列に実行されます。

### ③ ハル・ドメイン・ジオメトリ・メッシュ（任意）

三角形を細かく分割したり（テッセレーション）、新しい三角形を生成したり（ジオメトリ シェーダー）する、任意の段です。メッシュ シェーダーは頂点シェーダー以前を置き換える新しい方式です。

### ④ ラスタライザー（RS）

三角形を 画面のピクセルに分解します。クリッピング（画面の外を切る）、カリング（裏面を捨てる）、ビューポート変換（クリップ空間 → ピクセル座標）を行い、三角形の内側の各ピクセルを列挙します。頂点シェーダーの出力（色、uv）は三角形の中で 補間されて、ピクセルごとの値になります。固定機能でラスタライザー ステートで、設定します。

### ⑤ ピクセル シェーダー（PS）

ピクセル 1 つにつき 1 回、実行されそのピクセルの色を計算します。テクスチャを読みライティングを計算します。画面のピクセルの数だけ並列に実行され普通、最も重い段です。

### ⑥ 出力マージャー（OM）

ピクセル シェーダーの色をレンダー ターゲットに書く、最後の段です。深度テスト（手前の物が勝つ）、ステンシル テスト、ブレンド（半透明）を行います。固定機能で深度ステンシル ステート、ブレンド ステートで設定します。

## シェーダーと固定機能

| 段 | プログラム可能？ | 設定の、方法 |
| --- | --- | --- |
| 入力アセンブラー | 固定機能 | 入力レイアウト、トポロジー |
| 頂点・ハル・ドメイン・ジオメトリ・メッシュ・ピクセル | <strong>シェーダー</strong>（HLSL） | シェーダーを設定 |
| ラスタライザー | 固定機能 | ラスタライザー ステート、ビューポート |
| 出力マージャー | 固定機能 | 深度ステンシル、ブレンド、レンダー ターゲット |

## 計算シェーダー

<strong>計算シェーダー</strong>はこのパイプラインの、外にあります。頂点もピクセルも関係なく自由に並列計算を行い結果をバッファや、テクスチャに書きます。ぼかしヒストグラム、パーティクル、カリングなど画像処理や GPU 上の、汎用計算に使います。

## 並列に動く GPU

GPU は数千〜数万のスレッドを同時に、動かします。頂点シェーダーは各頂点をピクセル シェーダーは、各ピクセルを <strong>互いに独立</strong>に、処理します。独立しているので並列にできます。逆に、「前のピクセルの結果を使う」ような依存は、書けません（計算シェーダーの、共有メモリ、UAV で特別に扱います）。

```text
画面 1920×1080 ＝ 約 200 万ピクセル → ピクセル シェーダーが、約 200 万回、並列に実行
```

スレッドは 32 または 64 個で、1 組（ウェーブ、ワープ）になり同じ命令を同時に、実行します（SIMD）。組の中で `if` の分岐が分かれると両方の枝を実行するため遅くなります（分岐の発散）。

## 描画の 1 回

1 回の描画命令（`Draw`）は次のことを行います。

```text
Draw(3, 0):
  頂点バッファから、3 頂点を読む
  頂点シェーダーを、3 回実行（頂点ごと）
  3 頂点で、1 つの三角形を、組み立てる
  三角形を、ピクセルに分解
  各ピクセルで、ピクセル シェーダーを、実行
  深度テスト・ブレンドして、レンダー ターゲットに、書く
```

## 1 フレームのパイプライン

ゲームの 1 フレームはこのパイプラインを <strong>何十回も使い回して</strong>、作ります。

| パス | 内容 |
| --- | --- |
| シャドウ | 光から見た深度を描く（ピクセル シェーダーなし） |
| G バッファ | 不透明な物の、アルベド・法線・深度を複数のターゲットに描く |
| ライティング | 画面全体にライティングを計算（フルスクリーン） |
| 半透明 | 深度テストだけで、重ねる |
| ポスト プロセス | ブルーム、トーン マッピングなど（計算シェーダーや、フルスクリーン） |

各パスの 出力が次のパスの入力になります（レンダー ターゲットをテクスチャとして読む）。このつなぎ目がリソース（バッファ・テクスチャ）と、ビューの役割で同期の考え方と、つながります（[Resources and Views](resources-views.md)、[Why Synchronization](synchronization.md)）。

## よくあるミス

??? failure "「ピクセル シェーダーで頂点を操作しよう」と考える"
    頂点の操作は頂点シェーダー。ピクセル シェーダーはピクセルの色を計算するだけ。

??? failure "「ピクセル シェーダーの負荷は、頂点の数に比例する」と考える"
    ピクセル シェーダーは、三角形が覆うピクセルの数に比例（オーバードローも、含む）。頂点シェーダーは頂点の数に比例。

??? failure "分岐（`if`）を多用して遅くなる"
    ウェーブ内で分岐が発散すると両方を実行する。同じウェーブが同じ枝に進むよう条件を考える。
