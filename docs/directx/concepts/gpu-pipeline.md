# GPU Pipeline Overview

<div class="page-badges" markdown>
<span class="rank rank-must">必須</span>
</div>

<strong>GPU は、頂点の列を、受け取り、画面の、ピクセルの色に、変える、工場</strong>です。この工場は、<strong>決まった順序の、工程</strong>（パイプライン）で、できていて、工程ごとに、<strong>プログラムできる（シェーダー）工程</strong>と、<strong>固定機能の（設定だけ）工程</strong>が、あります。DirectX 11 でも 12 でも、この工程は、同じです。API の、関数の、名前は、「どの工程を、設定するか」を、表しています。

!!! tip "ポイント"
    - パイプラインの、流れは、<strong>入力 → 頂点シェーダー → ラスタライザー → ピクセル シェーダー → 出力マージャー</strong>。
    - プログラムできるのは、<strong>頂点シェーダー・ピクセル シェーダー</strong>（と、ハル・ドメイン・ジオメトリ、メッシュ）。
    - ラスタライザーと、出力マージャー（深度・ブレンド）は、<strong>固定機能</strong>で、ステートで、設定する。
    - 計算シェーダーは、このパイプラインとは、<strong>別</strong>に、自由に、動く。
    - GPU は、<strong>大量の、スレッドを、並列に</strong>、動かす。1 つの頂点・ピクセルは、独立に、処理される。

## 全体の、流れ

```text
頂点データ（位置・法線・uv）
   │
   ▼ ① 入力アセンブラー（IA）      頂点とインデックスを読み、三角形に組み立てる
   ▼ ② 頂点シェーダー（VS）        頂点ごとに、位置を、クリップ空間へ変換        ← プログラム可能
   ▼ （③ ハル / ドメイン / ジオメトリ / メッシュ）  任意。三角形の、分割・生成     ← プログラム可能（任意）
   ▼ ④ ラスタライザー（RS）        三角形を、ピクセルに、分解（クリッピング、カリング、ビューポート）
   ▼ ⑤ ピクセル シェーダー（PS）   ピクセルごとに、色を計算                       ← プログラム可能
   ▼ ⑥ 出力マージャー（OM）        深度テスト・ブレンドして、レンダー ターゲットへ書く
   │
画面（レンダー ターゲット）
```

## 各段の、役割

### ① 入力アセンブラー（IA）

頂点バッファと、インデックス バッファから、頂点を、読み、<strong>三角形（または、線・点）に、組み立てます</strong>。入力レイアウトで、頂点の、並び（位置は、何バイト目、など）を、教えます。固定機能です。

### ② 頂点シェーダー（VS）

<strong>頂点 1 つにつき 1 回</strong>、実行され、頂点の位置を、<strong>クリップ空間</strong>に、変換します（ワールド・ビュー・射影の、行列を、掛ける）。法線や uv を、そのまま、あとの段へ、渡します。頂点の数だけ、並列に、実行されます。

### ③ ハル・ドメイン・ジオメトリ・メッシュ（任意）

三角形を、細かく、分割したり（テッセレーション）、新しい三角形を、生成したり（ジオメトリ シェーダー）する、任意の段です。メッシュ シェーダーは、頂点シェーダー以前を、置き換える、新しい、方式です。

### ④ ラスタライザー（RS）

三角形を、<strong>画面の、ピクセルに、分解</strong>します。<strong>クリッピング</strong>（画面の外を、切る）、<strong>カリング</strong>（裏面を、捨てる）、<strong>ビューポート変換</strong>（クリップ空間 → ピクセル座標）を、行い、三角形の、内側の、各ピクセルを、列挙します。頂点シェーダーの、出力（色、uv）は、三角形の中で、<strong>補間</strong>されて、ピクセルごとの、値に、なります。固定機能で、ラスタライザー ステートで、設定します。

### ⑤ ピクセル シェーダー（PS）

<strong>ピクセル 1 つにつき 1 回</strong>、実行され、そのピクセルの、色を、計算します。テクスチャを、読み、ライティングを、計算します。画面の、ピクセルの数だけ、並列に、実行され、普通、<strong>最も、重い段</strong>です。

### ⑥ 出力マージャー（OM）

ピクセル シェーダーの、色を、レンダー ターゲットに、書く、最後の段です。<strong>深度テスト</strong>（手前の、物が、勝つ）、<strong>ステンシル テスト</strong>、<strong>ブレンド</strong>（半透明）を、行います。固定機能で、深度ステンシル ステート、ブレンド ステートで、設定します。

## シェーダーと、固定機能

| 段 | プログラム可能？ | 設定の、方法 |
| --- | --- | --- |
| 入力アセンブラー | 固定機能 | 入力レイアウト、トポロジー |
| 頂点・ハル・ドメイン・ジオメトリ・メッシュ・ピクセル | <strong>シェーダー</strong>（HLSL） | シェーダーを、設定 |
| ラスタライザー | 固定機能 | ラスタライザー ステート、ビューポート |
| 出力マージャー | 固定機能 | 深度ステンシル、ブレンド、レンダー ターゲット |

## 計算シェーダー

<strong>計算シェーダー</strong>は、このパイプラインの、外にあります。頂点も、ピクセルも、関係なく、自由に、並列計算を、行い、結果を、バッファや、テクスチャに、書きます。ぼかし、ヒストグラム、パーティクル、カリングなど、画像処理や、GPU 上の、汎用計算に、使います。

## 並列に、動く、GPU

GPU は、数千〜数万の、スレッドを、同時に、動かします。頂点シェーダーは、各頂点を、ピクセル シェーダーは、各ピクセルを、<strong>互いに、独立</strong>に、処理します。<strong>独立している</strong>ので、並列に、できます。逆に、「前のピクセルの、結果を、使う」ような、依存は、書けません（計算シェーダーの、共有メモリ、UAV で、特別に、扱います）。

```text
画面 1920×1080 ＝ 約 200 万ピクセル → ピクセル シェーダーが、約 200 万回、並列に実行
```

スレッドは、32 または 64 個で、1 組（ウェーブ、ワープ）に、なり、同じ命令を、同時に、実行します（SIMD）。組の中で、`if` の分岐が、分かれると、両方の、枝を、実行するため、遅くなります（分岐の発散）。

## 描画の、1 回

1 回の、描画命令（`Draw`）は、次のことを、行います。

```text
Draw(3, 0):
  頂点バッファから、3 頂点を読む
  頂点シェーダーを、3 回実行（頂点ごと）
  3 頂点で、1 つの三角形を、組み立てる
  三角形を、ピクセルに分解
  各ピクセルで、ピクセル シェーダーを、実行
  深度テスト・ブレンドして、レンダー ターゲットに、書く
```

## 1 フレームの、パイプライン

ゲームの、1 フレームは、この、パイプラインを、<strong>何十回も、使い回して</strong>、作ります。

| パス | 内容 |
| --- | --- |
| シャドウ | 光から見た、深度を、描く（ピクセル シェーダーなし） |
| G バッファ | 不透明な物の、アルベド・法線・深度を、複数のターゲットに、描く |
| ライティング | 画面全体に、ライティングを、計算（フルスクリーン） |
| 半透明 | 深度テストだけで、重ねる |
| ポスト プロセス | ブルーム、トーン マッピングなど（計算シェーダーや、フルスクリーン） |

各パスの、<strong>出力が、次の、パスの、入力に、なります</strong>（レンダー ターゲットを、テクスチャとして、読む）。この、つなぎ目が、リソース（バッファ・テクスチャ）と、ビューの、役割で、同期の、考え方と、つながります（[Resources and Views](resources-views.md)、[Why Synchronization](synchronization.md)）。

## よくあるミス

??? failure "「ピクセル シェーダーで、頂点を、操作しよう」と、考える"
    頂点の操作は、頂点シェーダー。ピクセル シェーダーは、ピクセルの色を、計算するだけ。

??? failure "「ピクセル シェーダーの、負荷は、頂点の数に、比例する」と、考える"
    ピクセル シェーダーは、三角形が、覆う、ピクセルの数に、比例（オーバードローも、含む）。頂点シェーダーは、頂点の数に、比例。

??? failure "分岐（`if`）を、多用して、遅くなる"
    ウェーブ内で、分岐が、発散すると、両方を、実行する。同じ、ウェーブが、同じ枝に、進むよう、条件を、考える。
