# SourceTree の画像を撮り直す（docs/git/ 用）

`docs/git/` は、SourceTree の画面を前提に書いてある。画像（`docs/git/img/st-*.png`）は、**スクリプトで撮る**。人が（または私が）画面を見ながらクリックして撮らない。理由は、速さと鮮明さ。

## 使い方

```
python tools/st_shoot.py setup C:/sample3        # 練習用リポジトリを作る（まだ無いフォルダーを指定）
python tools/st_shoot.py run   C:/sample3        # 全部撮る（SourceTree が起動していること）
python tools/st_shoot.py run   C:/sample3 stash tag   # 段階を選んで撮る
```

- `setup` は、`remote.git`（共有場所の役）、`MyGame`（自分）、`Friend`（別の人）を作る。履歴は 2 コミット。
- 段階は `tabs` `commit` `push` `branch` `conflict` `undo` `stash` `tag` `misc` の順。**途中からの撮り直しは、前の段階が終わった状態が要る**。迷ったら、新しいルートで最初から走らせる（同じルートでは、コミット済みの変更が残る）。
- 撮った画像は `docs/git/img/<名前>.png`。1 枚が 5〜30 KB（256 色の PNG）。
- 古い練習用フォルダーは、安全確認で `rm -rf` が止められるので、消さずに、毎回新しいルートを使う。ユーザーが自分で消す。

## ファイル

- `st_lib.py` … `ST` クラス。UI Automation（pywinauto）で SourceTree を操作する部品と、実寸の `shot()`
- `st_shoot.py` … 撮影の台本（`setup`、`run`、前半の段階）
- `st_stages.py` … 台本の後半（マージ、コンフリクト、戻す、スタッシュ、タグ、メニュー）
- `st_cap.py` … 最初に作った、単純なウィンドウ キャプチャ（`ST` を使わない）

`pywinauto` は `pip install --user pywinauto`。

## 画面を撮る方法（なぜ画面取得ツールを使わないか）

computer-use の `screenshot` と `zoom` は、1920×1080 の画面を 1456×819 に縮めて、JPEG で返す。UI の文字がぼやける。**`ST.shot()` は、画面のピクセルをそのまま PNG で保存する**。

`shot(名前, モード)` のモード:

- `main` … 本体のウィンドウ（1200×800。`place()` で位置と大きさを固定する）
- `top` … 手前のダイアログだけ切り抜く（SourceTree 3.4 のダイアログは、本体の中に重ねて描かれる。クラス名が `…Dialog` の部品の、中身の外接四角形から求める）
- `menu` … 開いている右クリック メニュー（サブメニューも）だけ

## 落とし穴

- **ボタンは実際にクリックする（`click_input`）。** UI Automation の `Invoke` は、効かないボタンがある。ブランチ作成の「ブランチを作成」で起きて、コミットが main に載った。押したあとは、`git branch` などで結果を確かめる
- **ダイアログは別ウィンドウではない。** `app.windows()` には出ない。`ST.overlay()` で探す。「マージで競合」のメッセージだけは、別ウィンドウ（`ST.dialog()`）
- **右クリック メニューの項目は、本体の子孫の `MenuItem`。** メニュー バーの項目は、AutomationId が `Menu` で始まるので、除く
- **プッシュが拒否されると、プッシュのダイアログがもう一度出る。** 「閉じる」のあとに「キャンセル」を押す
- **リポジトリは `SourceTree.exe -f <フォルダー>` で開く。** 「追加」画面への入力は、UI Automation では効かない
- **Alt キーで前面に出さない。** 「ファイル」メニューが光って写る。`SwitchToThisWindow` を使う（`ST.front()`）
- **オプションの「全般」タブは撮らない。** ユーザーの本名とメールアドレスが写る。「Git」タブは撮ってよい
- **外で git を動かしたら、`ST.refresh()`（F5）で画面に反映してから撮る**
- UI の文字は日本語（SourceTree の言語が「自動」）。ボタン名を `title=` で探す。分からない部品は `ST.dump()` で一覧にする

## 速くするコツ

- 1 操作ごとに画面を見ない。台本にして、1 回で走らせる
- 結果の確認は、画像を開くより、`git` の状態と、ファイルの大きさ（極端に小さい・大きい画像は失敗）で行う。見るのは、数枚を抜き取りで
- 長く走らせるときは、バックグラウンドで実行する（120 秒を超える）

## 画像に番号の枠を付ける（初心者向けの印）

`python tools/st_mark.py` は、`docs/git/img/` の主な画像（ツールバー・サイドバー・ファイルステータスなど）に、番号つきの赤い枠を描く。本文の「①②③」は、この番号に対応する。画像を撮り直したら、もう一度 `st_mark.py --all` を走らせる（撮り直した画像は枠が消えている。枠のあるまま重ねて走らせると、二重に描かれる）。

## ターミナルの開き方（記録）

ツールバーの「ターミナル」は、Git Bash（mintty）を、開いているリポジトリのフォルダーで開く。`ST` から押せる（`s.toolbar('ToolbarTerminal')`）。

## 裏画面（隠れたまま）で撮る
`s.shot(name, 'bg')` は、`PrintWindow`（PW_RENDERFULLCONTENT）で本体ウィンドウを撮る。他のウィンドウの後ろにあっても、実寸のまま写る（最小化中は不可）。前面に出さないので、他のアプリの重なり（画面隅の別ウィンドウなど）も写らない。ただし、右クリックメニューのような別ウィンドウのポップアップは写らないので、メニューの画像は従来の `main`/`menu` を使う。
